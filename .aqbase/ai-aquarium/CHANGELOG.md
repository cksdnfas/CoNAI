# AI 어항 변경 기록

## 3.26.0: 판단 입력을 필요한 것만, 채팅방 고정 지시는 기록 밖으로

- 일상·전투·대화 진행·방송 응답 판단이 요약 안 된 기억 원문 전체와 키워드가 걸린 로어 전체를 넣던 것을 없앴어. 판단에는 캐릭터(프로필 한 줄 소개·페르소나·켜진 텍스트 구역), 기억 요약, 판단 창(프로필 판단 프리셋의 방 창, 없으면 12줄)만큼의 최근 기억, 이 상황에 맞는 로어, 결정에 필요한 상태와 선택지만 가.
- 로어는 항상 적용 항목과, 호스트 공통 설정 "선택 로어 상위 개수"(설정 › 채팅 › 자원 › 기억)만큼의 키워드 항목만 골라. 키워드는 그 로어북에서 드물수록 높게 쳐서 `마을`·`광장`처럼 많은 항목에 붙은 일반어로는 거의 모든 로어가 들어오지 않아. 채팅·GM 입력과 채팅방 첫 문맥도 같은 기준을 써.
- 일상 판단에 선택지·장소 질문과 겹치는 상품 목록·시장 재고·장소 목록을 보내지 않고, 전투 판단은 선택지를 상태와 질문에 두 번 보내지 않아. 휴식·수면 선택지마다 반복되던 기상 안내는 지시문에 한 번만 넣어.
- 주민 채팅방의 고정 지시(마을 상황·허용 교류·도구 형식·외형 태그·추가 설정)는 호스트 `chat.instructions` 훅으로 답변마다 붙이고 대화 기록에는 쌓지 않아.
- 기억 정리가 로어 키워드로 어디에나 나오는 일반어를 쓰지 않도록 지시해.
- 기억 정리가 프로필 최대 출력 토큰 전체를 답변 자리로 비워두지 않아. 출력 상한은 상한일 뿐이라 답변 자리는 남는 문맥의 절반까지만 잡고 나머지는 사건에 써. 상한이 문맥 크기에 가까운 프로필(예: 260000 / 262144)에서 사건 하나도 못 넣고 "문맥 초과"로 멈추던 문제가 없어져.
- 업데이트된 호스트가 필요해(`llm.profiles()`의 `details`·`loreSelectionLimit`). 이전 호스트에서는 페르소나 없이, 로어 개수 제한 없이 동작해.

## 3.24.5: 대화 중 교류 기록에 상대 이름 표시

- 대화 도구로 고른 교류 제안 기록이 상대를 프로필 번호 대신 주민 이름으로 보여줘.
- 반복 대사로 방 기록을 지우면 그 입력이 전한 기억·세계관 갱신과 자기 교류 기록도 같이 사라지므로, 다음 차례에 전체 문맥을 다시 보내.
- 여러 명이 나눈 대화도 참여자 쌍마다 쉬기와 직전 마지막 말을 기록해. 쉬는 상대는 교류 대상·대화 합류 후보에서 빠지고, 지난 쉬기 기록은 정리돼.
- 반복 비교는 주민 이름 대신 프로필 번호로, 공백·유니코드 형태 차이를 무시하고 해.

## 3.24.4: 반복 대사를 방 기록에서 지우고 쉬기

- 똑같은 대사로 거절한 차례는 호스트 `llm.discard`로 그 실행의 입력·답변을 주민 채팅방 기록에서도 지워, 다음 차례가 그 대사를 다시 베끼지 않게 해. 이미 적용한 교류·상태 효과는 그대로야. 업데이트된 호스트가 필요해.
- 반복으로 대화를 마친 주민들은 게임 시간 6시간 동안 서로 새 대화를 열지 않아, 같은 요청이 곧바로 반복되지 않게 해.

## 3.24.3: 같은 대사 반복 차단

- 주민의 답이 이번 대화나 같은 주민끼리의 직전 대화에서 자기가 한 말과 똑같으면 그 차례를 실패로 처리하고 대사·기억에 기록하지 않은 채 대화를 마쳐. 반복 대사가 기억과 다음 대화 문맥에 다시 쌓여 모델이 계속 베끼던 고리를 끊어. 채팅방 자체에 이미 저장된 답변은 메인 엔진 기록이라 남아.

## 3.24.2: 같은 주민끼리 다시 대화할 때 이어 말하기

- 대화가 끝나면 참여 주민 조합별로 마지막 말 4줄을 남겨, 같은 주민끼리 새 대화를 열 때 "지난번 마지막 말을 되풀이하지 말고 새 일이나 다른 화제로" 시작하게 해. 같은 시작 지시와 채팅방 기록 때문에 모델이 예전 대사를 그대로 반복하던 문제를 줄여.
- 교류 도구의 `detail`은 대사가 아니라 교류 목적 한 구절이라고 형식 안내에 적어.

## 3.24.1: 대화 도구 안내와 그림 외형

- 대화 차례 안내에 `p_ai_aquarium_turn`의 kind별 인자 형식을 그대로 적어, 모델이 형식을 추측하다 실패하지 않게 해.
- 대화·방송 프롬프트에 등장 주민의 프로필 외형 태그를 넣어, 프로필 이미지 도구가 인물을 프로필 외형대로 그리게 해.
- 방송 프롬프트의 "이미지와 로어는 네 프로필 도구를 사용해"를 대화와 같은 "프로필 도구와 판단 설정대로 사용해"로 바꿔, 판단 결과와 무관하게 매번 그리도록 유도하지 않아.

## 3.24.0: 메인 채팅 엔진으로 주민 대화 통합

- 슬롯 초기화/삭제는 취소 작업의 terminal 상태와 마지막 전달 영수증을 최대 10초씩 확인한 뒤 자동화 채팅방을 정리해. 사람이 직접 쓴 방은 연결만 해제해 일반 채팅으로 남기고, 순수 자동화 방만 자체 로어·외관과 함께 삭제해. 제목에는 슬롯 이름을 붙이고 방 조회는 주민 실행 잠금을 기다리지 않아. 사라진 방을 대기 작업이 다시 만들지 않으며 취소 대기는 취소 순간의 작업만 따라가.

- `pluginTools`/`roomKey`/`expectedThreadId`와 `llm.room`/`llm.forgetRooms`, 실행 identity·전달 영수증을 지원하는 업데이트된 호스트·SDK가 필요해. 이전 호스트는 입력을 400으로 거부해. manifest는 최소 호스트 버전 필드를 지원하지 않아.

- 대화·방송을 네이티브 프로필 실행으로 바꿔 프로필 도구·이미지/로어 판단·생성 프리셋·훅·로어를 일반 채팅과 같은 경로로 실행해. 네이티브 후속 답변도 같은 실행의 말로 모으고 다음 발언자 선택만 어항이 맡아.
- 교류·요청 답변·종료·상태 변경은 호스트 실행 identity/리비전과 기존 권한·멱등 규칙을 확인하는 turn 도구만 추가해. 슬롯 초기화/삭제는 옛 방을 정리하고 세대를 바꿔. 고정 문맥은 매번 포함하고 실제 threadId 변경에는 요약/로어를 다시 보내. 전달 커서·로어는 취소에서도 단조 병합해. 첫 답변 뒤 전역 슬롯을 반환하고 방 잠금은 후속/중단 완료까지 유지해. 후속 단계 기한 만료는 첫 발언을 보존하지만 명시 취소는 그대로 취소야.
- 방 이력은 메인 엔진이 관리하고 어항은 새 외부 기억과 로어 갱신만 보태. 대화 이미지·지연 생성 결과는 기존 앨범 수집기로 모아.
- 어항 전용 주민 그림 행동·설정·UI·3분 제한·배지·게임 그림 이관 코드를 제거했어. 길드의 별도 게임 그림 설정과 생성은 유지해.

## 3.23.1: 행동 개수 한도 제거

- 3.23.0에서 마을 기본 행동이 15개로 늘어, 추가 행동이 있는 슬롯은 "행동 ID 중복 또는 분류별 16개 한도야."로 설정 전체가 거부되고 마을이 멈췄어. 분류별 16개·전체 48개 한도를 없앴어(호스트 판단도 선택지 수 제한이 없어). 같은 분류 안의 ID 중복만 거절해.

## 3.23.0: 주민 모델 행동·호출 규칙 통합

- 생활·교류뿐 아니라 음식·상점·제작법·장비·보급품·근무·신탁 방문·수면·기상·원정 출발을 주민 자기 모델이 골라. 실제 효과·비용·대상을 선택지에 함께 넣고 임계값·자동 구매·자동 착용·시간표 강제로 대신하지 않아.
- 던전에서는 이동 목적지·쉼터 이용·물약·귀환과 전투 스킬·물약 종류까지 모델이 정해. 모델 응답을 기다리는 주민 차례만 멈추며 몬스터와 다른 주민은 계속 진행해. 한도·오류·시간 초과 때 자동 공격이나 후퇴는 없어.
- 호출 설정은 **일상·요청(village)**, **전투·탐사(combat)**, **대화·방송·신탁(social)** 세 줄로 통합해. judge/chat, 실제 최소 간격, 주민별 게임 시간당·슬롯 공용 UTC 하루 한도를 같은 예약·환불 경로로 적용해. 새 슬롯의 세 줄은 시간당·하루 **무제한(null/빈 값)**이고 일상 기본 간격은 20초야. 0은 호출 중지이며 기존 저장 한도는 유지해. `agentVersion:5`로 규칙 모드를 judge로 이관하고 별도 구형 전투 한도는 combat 하루 한도에 합쳐. 구형 off/boss 설정은 모든 전투 차례 모델 판단으로 바꾸고 설정·AI 행동에 한 번 안내해. 확인한 안내는 저장되어 다시 나오지 않아.
- 방송 답변 여부와 다음 대화 상대·종료도 모델이 골라. 임의 반응 주민 추첨, 강제 요청 발언자, 낮은 확률만으로 대화 종료하는 분기를 없앴어.
- 동시 사회 행동은 먼저 확정된 상대 예약 하나만 허용해. 상대가 오래 불가능하면 기록을 남기고 새 판단으로 돌아가며, 상대 대기와 실제 이동 시간을 따로 계산해.
- 대기 기록은 같은 상태의 횟수·기간으로 합치고 재시도 사유가 매 틱 번갈아 쌓이지 않게 했어. 판단 기록 창은 갱신해도 펼침 상태를 유지해. 어시스턴트에는 최근 5개의 선택 결과·선택지 수만 제공하고 모델 출력을 안전한 기본형으로 정리해.
- 판단의 큰 기억 원문은 기존 압축 payload 스냅샷에만 두고 매 틱 저장에는 참조만 남겨. 재시작한 다음 발언자 판단도 같은 기억을 복원해.
- 받은 요청의 수락·거절도 일상 선택지와 함께 제시해. 먼저 답할지 다른 일을 할지는 모델이 정하며 요청 만료는 유지해.
- 신탁의 class·skill kind를 누락하거나 잘못 답했을 때 전사·기본 공격을 대신 고르지 않아. 기존 능력을 보존하고 실패·대기를 기록해. 초기 주민도 코드가 전투 계열이나 스킬을 배정하지 않아.
- 목표·설명·지시문·신탁·기억·번역의 임의 글자 수 제한을 제거했어. 실제 프로필 문맥·출력, 호스트 전송/대화 항목 계약, 페이지 compact projection과 실행/저장 목록 개수의 자원 보호만 유지해.
- 실패한 완료 작업은 새 요청 ID로 재시도하고, 취소·주민 제거 뒤의 늦은 답은 적용하지 않아. 던전 시설 이용도 사용자가 정한 한 걸음 시간을 소비하며 같은 차례에 이동을 겹쳐 실행하지 않아.
- 모델 입력은 공통 JSON 정리 경로로 보내. 호스트의 숫자 오류 상태로 접수 거절과 접수된 모델 실패를 구분하고, 409 버전 변경은 환불·새 요청 ID, 429 혼잡은 환불·짧은 고정 재시도로 처리해.
- 방송 응답 여부는 비차단 실행·조회 방식과 5분 유효기간을 적용해. 판단 중 마을이 멈추지 않고, 기억은 한 번만 꾸미며 중단 뒤 늦게 접수된 작업도 취소해. 신탁 호출 한도 대기는 공유 GM 대기열을 비워 공사 등 다른 일을 막지 않아.
- 선물·거래·부탁은 대상 이름·물품·종류·수량/금액·지불자를 함께 골라. 유효한 의뢰에만 유물/기록실 이용을 제시하고, 직원 급여는 실제 근무를 선택한 주민에게만 지급해.
- 요청 만료는 남은 시간으로, 출발은 지역 레벨·위험·전투 호출 가능 여부로, 이동은 일관된 좌표·거리·미탐색·출구 정보로 설명해. 효과 없는 aggressive 전술은 없앴어. 신탁 방문에는 신관 근무 상태를 알려줘.
- 일상·전투·탐사 입력과 선택지 카탈로그 전체를 지연 로딩 payload에 두어 저장 행에는 참조만 남겨. 전체 판단 기록은 주민 창을 열 때만 조회하고 일반 상태에는 작은 요약만 보내. 목표도 안전하게 투영하며 종류별 기록 이름을 표시해.
- 대화 한 차례의 사전 판단·발언·사후 판단·다음 상대 선택은 실제 모델 호출마다 시간당·하루 한도를 예약하고 최소 간격만 한 차례에 한 번 적용해. 호출 한도나 끝난 답변 오류·반복 접수 실패로 진행할 수 없는 대화는 양쪽 판단 기록에 종료 이유를 남기고 해제해. 긴 의뢰 설명은 스키마에서도 길이로 제한하지 않아.
- 수면·휴식은 다음 아침·피로 회복·새 호명/요청 등의 종료 조건을 모델이 선택해. 조건 전에는 20초마다 잠을 다시 고르지 않아. 조건 충족이나 관련 상황 변화도 자동 기상이 아닌 새 모델 판단을 요청해.
- 접수 환불은 400·403·404·409·413·429만 적용해. 408 시간 초과와 제공자 오류는 실제 호출로 남기고 일상 재시도 간격은 실패 완료 시점부터 지켜. 방송의 실패/취소 판단과 중단된 전투·탐사 판단은 새 요청 ID를 사용해.
- 일상 판단에 모든 수량을 매번 묻거나 선택지를 상태에 중복하지 않아. 수량이 필요한 교류를 선택한 경우에만 그 행동에 가능한 수량/가격을 후속 모델 호출로 정하고 동일한 호출 한도를 적용해.
- 청혼·초대·부탁 답변은 자연스러운 효과·물품 이름·지불자를 설명하고 휴식 등 생활 행동이 근무를 끝낸다는 지시를 맞췄어. 대화 원문·방송 반응·시청자 글도 페이지 상태에는 안전하게 투영해.

## 3.22.5: 페이지 상태의 보호 항목 오류 수정

- GM 창이 어시스턴트에 넘기는 대화 상태에 요청 진단 객체(`inputTokens`)가 그대로 들어가, 호스트가 "보호된 페이지 항목이야: inputTokens"로 페이지 상태 전체를 거부하던 문제를 고쳤어. 진단 값의 키는 `inputSize`로 바꾸고, GM 대화 상태에는 진단 객체 대신 진단 문구(`budget`)만 넣어. 이전 세이브에 남은 `inputTokens`도 문구로만 표시돼.

## 3.22.4: 요청 원문 손상 격리·기억 측정 보정

- 누락되거나 손상된 요청 스냅샷 하나 때문에 슬롯·저장 목록 전체가 열리지 않던 문제를 고쳤어. 해당 요청만 복구 필요 표시로 읽고 한 번 경고해. 옛 ID로 다른 입력을 보내지 않으며 요청 소유자가 종료/보류 후 원래 자료에서 새 ID로 재구성해.
- 기억 사건의 JSON 구분자 비용을 포함하고, 선택한 묶음을 호스트에서 먼저 측정해. 실제 초과량에 해당하는 끝 사건만 빼고 같은 처리 안에서 다시 측정하므로 정상적인 추정 차이는 실패/반 묶음 재시도를 소비하지 않아.
- 방송 대기 수에는 접수 대기·바쁜 대기열의 보류 항목·실행 항목을 모두 세어. 로어는 실제 접수 시에만 만들고 대기열 거절로 기다리는 항목에는 큰 요청 스냅샷을 남기지 않아.
- 떠난 주민/바뀐 GM의 보류 기억은 작업을 취소하고 보류 상태·스냅샷·오류를 정리해. 사건 원문은 지우지 않아.
- 읽은 요청 스냅샷은 소유자/참조별로 캐시하고 변경 가능한 복사본만 호출자에게 줘. 매 read의 압축 해제를 없애고 존재 확인은 `SELECT 1`만 사용해.
- 호스트 업데이트 등으로 취소되고 결과가 없는 GM 생활 계획·공사 심사·층 설계는 일일 사용량을 세지 않아. 실제 실패 답변의 기존 비용 보호는 유지해.

## 3.22.3: 호출 비용 보호·기억 공정성·저장 크기 보정

- GM 생활 계획·공사 심사·층 설계는 접수된 작업이 끝나면 결과 적용 성공 여부와 무관하게 해당 일일 한도를 정확히 한 번 사용해. 부지·중복 이름·재고/자금·정의 개수 등 게임 검증은 유지하며 잘못된 답을 같은 날 무한 재생성하지 않아. 모델 호출 전 시작 거절만 사용량에서 제외해.
- 제공자·조회 실패 기억 묶음은 주민별로 보관하고 단일 실행 슬롯을 비워 다른 주민/GM을 순환 처리해. 만료/없는 작업(404/410), 버전 충돌(409)은 같은 사건을 새 요청 ID로 다시 접수하고 원문을 건너뛰지 않아.
- 기억의 입력 묶음은 알려진 프로필 출력 상한만큼 문맥을 남겨. 출력 상한이 없으면 필수 입력을 뺀 공간을 사건과 답변에 절반씩 배분하며 `maxTokens`는 보내지 않아. 공용 예산은 비어 있는 기억/로어 몫을 작업 자료에 돌려줘.
- 합친 `history`를 원본 로어 목록과 함께 저장하지 않아. 접수 확인 전 요청 예산/재전송 자료는 소유자별 별도 압축 행에 한 번 보관하고 tick 상태에는 참조만 저장해. 같은 자료를 매 tick 다시 쓰지 않으며 jobId를 받으면 원본 목록·재전송 복사본과 쓰지 않는 행을 정리해.
- 방송 대기열 부족은 항목의 원래 만료 시각 안에서 지수 대기 후 다시 접수해. 기다리는 동안 방송 실행 슬롯을 비워.
- 층 설계 기록·기억 근거 발췌는 기존 저장 범위를 넘을 때 `…`를 남겨. 답변 대기 기본값과 judge 최대 1,800,000ms 문서를 바로잡았어.

## 3.22.2: 검토 보정 — 프로필 기본값, 재접수와 기억 보존

- 답변 대기에 **프로필 기본값**을 추가하고 기본 5분 세이브를 이관해. 명시한 다른 대기는 유지하며 기본값에서는 텍스트/judge의 `timeoutMs`와 플러그인 취소 시계를 만들지 않아.
- 문맥 전체에서 실제 측정한 필수 입력/프로필 비용을 뺀 뒤 선택 자료만 줄여. 첫 문맥 413은 측정한 여유 전체로 다시 맞추고, 달라진 입력에는 새 ID를 써. 접수 응답 유실은 저장한 동일 입력·ID로 확인하며, 문맥/본문/대기열 등 모델 실행 전 거절은 호출권을 돌려줘. 본문 전송 413은 별도로 표시하고 선택 자료를 한 번만 줄인다.
- 기억 묶음은 출력 상한이나 고정 24개가 아니라 입력 문맥의 남은 공간으로 골라. 문맥을 모르면 정리 대상 사건을 모두 보낸다. 내용·JSON 오류만 반 묶음/단일 사건 건너뛰기에 반영하고, 쿼터·인증·연결·시간 초과·접수 대기·조회 실패는 원문과 묶음을 유지한 채 지수 대기해.
- 공사 심사 사유·생활 물품·번역·목표·원정 제목·관계 설명·GM 관리 문장의 기존 저장 범위를 넘는 부분은 `…`로 정규화해. 길다는 이유로 답 전체를 버리거나 실패한 접수에 GM 일일 심사권을 쓰지 않아.
- 대화가 기록된 뒤 judge가 바쁘면 화자 선택 단계만 다시 진행해. 이미 말한 주민의 답을 다시 생성하지 않으며 후속 발언 한도는 유지해. 일부 질문 오류가 있어도 유효한 행동 답은 사용해.
- JSON처럼 생긴 플레이어/장면은 필수 입력으로 유지하고, 빌더가 표시한 선택 자료만 완전한 객체 단위로 줄여. 여러 줄 발언은 한 기록이며 객체/기억 선택은 항목별 누적 크기로 계산해.
- 주민·관리·GM·원정·조사 프롬프트의 고정 개수 선택과 항상 켜진 로어의 7,000/4,000자 예산을 없앴어. 키워드는 전체 질문에서 찾고 GM 입력의 4,000자 제한도 없앴어. GM 로어는 기존 로어 저장 범위인 2,000자를 써. 관리 작업은 앞 24개를 검토/적용하고 나머지는 보류 사유와 함께 다음 차례를 안내해.
- 조사 대기열 부족은 시작 시도를 소모하지 않아. 전투 쿼터·인증 실패는 주민별 대기 중 규칙 전투로 진행하며, 방송 대기열 부족은 반복 접수하지 않고 원래 항목 유효기간 종료를 표시해.
- 새 호스트의 무상한 측정 예약 2,048은 접수 여유나 출력 상한으로 쓰지 않아. 출력 상한이 없으면 접수 여유 0, 진단은 **답: 프로필 기본값**이야. 이전 호스트 전송 범위·네이티브 구조 개수·ID/권한/재고/금액/배치/동의·사용자 호출 한도·NovelAI 1장은 유지해.

## 3.22.1: 최종 호스트 계약 — 네이티브 한도와 대기열

- `llm.measure`가 있는 새 호스트에서는 메시지·기억·스키마·judge 자료에 플러그인 문자/바이트 한도를 두지 않아. 256KiB/64KiB 중간 계약도 적용하지 않아. `measure`가 없는 이전 호스트에서만 16,000/32,000자와 judge 16KiB 전송 호환을 유지해.
- 실제 프로필 문맥만 기준으로 선택해. 설정된 최대 출력 전체 때문에 `available`이 음수여도 요청을 거절하거나 줄이지 않고, 호스트의 최소 출력 접수 여유만 따른다. `maxTokens`는 계속 프로필 기본값이며 명시한 마을 상한만 보내.
- judge 120초/기본 60초 제한을 없애고 요청의 대기 시간을 그대로 전달해(호스트 범위 최대 30분, 생략하면 연결/엔진 설정). 새 호스트에서는 이름·본문·지시·선택 설명도 자르지 않아. 질문·선택지·대화 줄·행동 수와 ID 규칙은 유지해.
- 새 호스트의 텍스트 접수는 네이티브 대기열에 맡겨. 다른 대화/기억/전투가 네 개 실행 중이라는 이유로 주민·전투 요청을 미리 막지 않아. 실제 대기열 가득 참과 네이티브 judge 접수 부족만 기다리고, 제공자 쿼터·인증·연결·시간 초과·JSON 잘림 등은 분류와 호스트 사유를 보여줘.
- 전체 결과를 `llm.get`에서 그대로 받아. 비공개 결과 파일은 호스트가 처리하므로 따로 읽지 않아. 새 호스트의 `truncated`는 실제 출력 길이 종료로 표시하되 받은 원문과 온전한 JSON은 보존해. 조사에서 4,000자 반환 가정을 제거했어.
- 번역 경로의 숫자 인덱스는 SDK에서 허용하지 않으므로 제거했어. 새 호스트는 유효한 wildcard 경로와 호스트 청크 번역을 사용해. 이전 호스트는 요약만 번역하고 항목·키워드는 원문으로 보존해 잎 한도 초과를 피한다.

## 3.22.0: 모델별 문맥 예산과 진행 가능한 기억 정리

- 프로필 기본값을 그대로 써. 기존 세이브도 출력 기본값으로 이관하며, 사람이 숫자를 명시할 때만 추가 maxTokens를 보내. GM·조사·기억·다음 화자 고정 출력 한도와 추정 문맥 설정은 없어.
- 실제로 알려진 프로필 문맥을 넘을 때만 공용 예산으로 완전한 자료를 선택해. 알 수 없는 문맥은 가정하지 않아. measure의 엄격한 입력 계약을 지키고, 알려진 문맥의 413은 새 ID로 최대 두 번 줄여 재시도해.
- 기억 추출은 세계관 없이 사건 묶음을 써. 실패하면 반 묶음 → 단일 사건 → 핵심 요약으로 요청하고, 단일 사건 3회 실패는 원문·사유를 사건 기록에 보존하며 건너뛰어. 미리보기 truncated는 온전한 JSON의 실패가 아니야.
- 대화·생활·전투·원정·방송·세계 만들기·라이브 GM·조사 프롬프트를 직렬화된 문자열 중간에서 자르지 않아. 판단 상태는 16KiB 내로 줄이며 큰 상태 때문에 채팅으로 전환하지 않아.
- 주민의 상태, 현장/관련 주민 관계, 당사자 요청, 간단한 행동 목록만 전달해. GM의 관계·판단 설정·대기 요청도 문맥 정리 순서에 포함해.
- 긴 모델 문장이나 권장 개수 초과 때문에 답 전체를 버리지 않아. 기존 저장 범위를 넘는 설명만 표시를 남겨 정규화해. 번역 경로는 17잎만 선택해. 조사 필수 절을 먼저 완성하고 동등한 제목 서식을 허용해.
- GM은 관련 작업의 상세 스키마만 보내고 입력은 4,000자까지 받아. 전투 대기는 최대 300초. RPG 실패 대기는 해당 작업만 쉬며 다른 활동은 계속해. 제공자 429·쿼터를 슬롯 부족으로 무한 재시도하지 않아. 사용하지 않는 `residentLifeMessage`는 제거했어.

## 3.21.2: 주민 창·AI 행동 화면 보정과 판단 비용·오류 보강

- 모델 실행 슬롯이 차도 규칙 식사·휴식은 계속하고, 기억 정체 중에는 사교 판단 대신 마을 생활을 진행해.
- 물품 요청·선물은 실제 물품 ID를 검증하며, 누락된 물품을 골드 이전으로 해석하지 않아. 골드 선물은 `kind:"gold"`를 명시해.
- 호출 한도는 재시도마다 실제 요청 시도로 집계하고, busy·모델 없음·빈 판단은 차감하지 않아. 원정 출발·계속/귀환 판단은 combat 설정과 예산을 사용해.
- 전투 오류를 `combatError`로 분리하고 성공하면 지워. 기억 정체 동안 대기 제한 시간을 멈추며 재개 시 완료된 답부터 확인해.
- 이전 관계의 자동 이름 갱신을 복구하고, 채팅 상태 제안으로 배고픔·피로를 임의로 낮추지 못하게 해.
- 주민 창은 마을 판단 실패(`agentError`, 재시도 대기 포함)와 모험 판단 실패(`combatError`)를 따로 보여줘. AI 행동의 전투 줄은 전투·원정으로 이름을 바꾸고 원정 판단도 맡는다고 안내해. 물품 없는 선물을 골드로 표시하지 않아.
- 페이지 상태에 상태 값·편집·행동 효과를 `[{id,value}]`/`[{id,delta}]` 목록으로 실어 상태 ID가 보호 키처럼 보여도 어시스턴트 상태가 깨지지 않게 해. 저장과 다른 초안 항목만 싣고 관계·요청·대화 줄을 잘라 페이지 데이터를 작게 유지해.
- 관계는 호감도만 고치면 이름을 보내지 않아 자동 관계 이름이 유지돼. 관계 줄마다 되돌리기를 두고 서버 값과 같아진 편집은 버려. 꺼진 상태의 편집은 버리고, 맞춘 숫자는 저장 값에도 반영해.
- 프로필 고정 필드도 사람(과 그 초안)이 직접 고칠 수 있어. 마을 판단 재시도 대기의 남은 초는 그 자리에서 갱신해. 바쁠 때 누른 요청 취소 버튼은 다시 누를 수 있어.
- 어시스턴트 행동 목록 초안에서 기본 행동의 effect는 무시해. 저장 전 항목의 ID 편집은 저장된 설정에 없는지로 판단해 초안에서 온 항목도 ID를 고칠 수 있어.

## 3.21.1: 판단 계약·교류 종료·호출 비용 안전장치

- 판단 timeout을 1–120초로 제한하고 첫 대화의 빈 before 호출을 생략해. judge 문맥은 화자 기준으로 역할을 나누고 금지/허용의 접두 `*` 패턴과 허용 우선 규칙을 반영해. 마지막 차례에는 after를 호출하지 않고, 연속 발언은 followUp 한도 안에서만 허용해.
- 주민 판단은 공유 실행 여유 안에서 최대 2개까지 진행해. 잠·외출·대화 등으로 사용할 수 없어진 주민의 판단을 취소하고, 기억 정체 때 대화를 해제해. 기억 정리는 대화와 독립적으로 계속하며 던전은 원문 보존을 위해 정체 동안 멈춰.
- 자율 행동의 재시도 기록을 플레이어 명령 기록과 분리해 512건/최대 24시간 순환 보관해. 이전 자율 기록도 이관하며 플레이어의 30일/10,000건 보장은 유지해. 판단 메타데이터는 명령 동일성에서 제외해.
- 교류 요청은 실제 10분·당사자 퇴장 시 expired, 수락 효과 실패 시 failed로 종료해. 취소는 새 `request-cancel` 페이지 요청/GM 카드로 처리해. 새 변경 요청은 `saveId`가 필요해. 명시한 관계 이름은 일반 호감 변화가 덮어쓰지 않아.
- 분류별 `maxCallsPerDay`(UTC 실제 하루, 슬롯 공용, 0–10000)를 추가해. 기본 combat 2000, social/village 300이며 0은 모델 호출을 끄고 규칙으로 진행해. 예전 판단 끄기는 rules로 이관하고 routine rules 행동은 기억을 쌓지 않아.
- 음식·휴식의 서버 규칙 효과는 step과 분리하고, 읽기 전용 프로필 상태는 모델·사용자 정의 효과가 변경하지 못하게 해. 어시스턴트 상태 효과 초안은 `[{id,delta}]` 배열로 사용자 정의 상태도 지원하며 적용 시 슬롯의 실제 숫자 정의를 검증해. 폐기된 판단/대리 프로필 필드는 어시스턴트 스키마에서도 제거했어.

## 3.21.0: 프로필 기반 자율 주민 — 서버 계약

- 주민 자신의 프로필 judge/chat/rules로 생활·교류·전투 행동을 선택해. 별도 판단/대리 전투 프로필 설정을 제거하고 기존 저장을 이관해. 판단 모델이 없으면 같은 주민의 대화 모델로 전환해.
- 슬롯 공용 상태 정의와 주민별 값, 프로필 상태 블록, 시간 변화·식사·휴식·대화 효과, 목표와 관계를 저장해. 행동 카탈로그는 분류별 16개까지, 추가 행동은 서버가 제한한 효과만 실행해.
- 최대 3개 대화를 독립적으로 진행하고 기본 8차례 안에서 대답·후속 질문·주변 주민 참여·종료를 판단해. 프로필 judge preset의 전후 지시와 금지 행동을 적용해. 선물·부탁·청혼·거래는 상대 수락/거절을 기다리고 수락 효과와 요청 종료를 한 트랜잭션에 반영해.
- 기억 정체는 표시하면서 비모델 생활은 유지하고 주민 판단 실패는 개별 대기 상태로 보여줘. GM 검토 카드·조회 MCP와 설정 초안 스키마를 확장해. 서버 요청/상태 계약은 README의 3.21 절을 따라. 신규 페이지 조작 UI는 별도 프론트 구현 대상이야.

## 3.20.0: AI 답변 대기 시간 설정

- **마을 관리 → 마을 → AI 답변 대기**: 답변 한도 옆에서 5–30분을 고른다(기본 5분). 예전 세이브도 5분으로 시작하고 범위 밖 값은 5–30분으로 맞춘다. 어시스턴트 `prepare`도 `replyTimeoutMinutes` 초안을 지원한다. **10분을 넘는 값은 LLM 요청 한도가 30분으로 늘어난 CoNAI 호스트가 필요하다.**
- **요청별 고정**: GM 대화·주민 대화·방송 답장·기억 정리·던전 설계·신탁·원정/생활 판단·그림 외형 설명에 같은 시간을 보낸다. 요청에 시작 당시 시간을 저장해 설정을 바꿔도 진행 중인 답의 한도는 바뀌지 않는다. 플러그인은 그 시간에 확인 여유 30초를 더해 기다리고, 시간 초과 안내에 해당 분 수와 마을 관리 위치를 표시한다.
- **별도 제한 유지**: 전투 AI 대기(`combatWait`), 자료 조사 창의 제한, 이미지 생성 작업 만료 시간은 바꾸지 않는다.

## 3.19.0: 무료 GM 관리와 실제 적용 결과

- **실사용 QA — 대상 이름 해석**: 주민·NPC·시설·물품·층·의뢰·공사 참조는 실제 ID, 이번 대화의 짧은 ID(R1/B1 등), 화면의 이름 전체를 받는다. 대소문자·공백은 무시하고 부분 이름으로 추측하지 않는다. 동명이인은 후보와 위치·짧은 ID를 보여 주며 임의로 고르지 않는다. 카드가 나오기 전에 실제 대상 ID와 이름으로 확정하고 적용 때 다시 검증한다. 이름이 바뀌거나 목록 순서가 달라져도 이미 확인한 제안이 다른 대상으로 옮겨 가지 않는다. 템플릿·그림·장비 개체 참조도 같은 처리를 쓴다.

- **실사용 QA — 골드·사건**: 주민과 생활 NPC 골드는 `add`(지급·회수할 증감량)와 `set`(잔액 지정)을 구분한다. "200 더 줘"는 적용 시점 잔액에 200을 더하고 결과에 전후 잔액을 표시하며 0~10억으로 제한한다. 같은 제안의 관리 작업이 하나라도 실패하면 사건 소식·주민 기억은 건너뛴다. GM 말과 사건 초안은 적용 전 완료형이 아닌 조건부 제안으로 쓰게 한다.
- **실사용 QA — 부지·표시**: 플레이어가 좌표를 주지 않은 신축은 자동 부지를 기본으로 제안한다. `near`에 광장 등 기준 장소를 지정하면 가까운 후보부터 검증하고, 문맥에는 유효 부지와 가까운 장소·방향을 함께 보낸다. 그림 설정 안내는 답변당 한 번, 열린 GM/세계 만들기 화면의 버튼은 하나로 모은다. 결과·작업 요약·GM 기억에는 내부 UUID 대신 이름과 위치를 표시한다.

- **검토 수정 — 문맥·적용 안정성**: 장비는 물품별 수량으로 묶고 목록·그림 참조를 줄인다. 덜 중요한 최근 소식·로어부터 덜어 GM 메시지를 15,000자 안으로 제한한다. 잘못된 응답은 해당 차례만 실패하며, 비동기 설정 확인 전에 차례를 예약해 중복 호출을 막는다. 생활 시간은 적용 트랜잭션 전에 한 번 정산하고, 저장 실패 때 DB뿐 아니라 화면 캐시도 적용 전 상태를 유지한다.
- **검토 수정 — 실제 결과 표시**: 적용·부분 실패·실패 카드의 결과 목록을 숨기지 않고 행을 위아래로 배치한다. 작업은 ID를 이름으로 바꾼 짧은 한국어 문장으로 표시하고 GM 기억 요약도 제한한다. 어시스턴트 조회는 대화 읽기가 끝날 때까지 기다린다. 게임 그림 설정 버튼은 카드당 하나이며 세계 만들기 창에도 표시한다.
- **검토 수정 — 생활 안전**: 마지막 여관·신전 철거를 막고 이동의 부지·출입구·경로 검사를 유지한다. 시설 이름 변경은 주민 경로를 초기화하지 않는다. 골드는 10억까지, 자동 부지 찾기의 경로 검사는 최대 12후보로 제한한다. 길드 자동 의뢰와 이미 취소한 의뢰는 GM 취소 실패로 설명한다. 공사 신청 주민이 없는 자동 계획은 시설만 건너뛰고 새 물품은 유지한다.
- **검토 수정 — 그림 비용·복구**: GM 카드의 새 층·물품·외형 편집·다시 그리기는 모두 자동 그림 하루 한도에서 제외한다. 이미 그림이 있는 동일 외형은 재적용해도 다시 생성하지 않는다. 일시적인 상태 조회 오류로 설정 경고를 고정하지 않고 실제 연결·인증 실패나 반복 접수 실패만 설정 안내로 올리며 후속 성공 때 해제한다. 외형 교체로 불필요해진 실행 중 작업은 호스트 취소 도구에 접수한다.

- **말뿐이던 제안 수정**: GM 카드에 시설 신축·증축·이름·이동·철거, 지도 확장, 즉시 완공·취소, NPC 재고·골드·직장, 주민 골드·가방·창고, 생활 템플릿 물품 생성·편집·지급·회수, 길드 의뢰 등록·취소, 다음 층 즉시 설계·기존 층 이름/테마/몬스터/수호자/전리품/외형 편집, 그림 다시 그리기를 연결한다. 사람이 적용하면 게임 돈·재료·공공 금고를 쓰지 않고 별도 심사·자동 GM 하루 한도 없이 실행한다. 자동 공사·신전 판단·층 설계의 경제와 한도는 유지한다.
- **항목별 영수증**: 각 변경의 실제 결과와 검증 실패를 카드에 남긴다. 일부 실패·전부 실패·빈 제안을 적용 완료로 표시하지 않는다. 사건은 소식·기억, 다음 층 바람은 미래 요청일 뿐이라는 범위도 GM과 카드에 명시한다. ID·부지·경로·수량·보관 한도와 능력치 예산은 그대로 검사한다.
- **게임 그림**: 선택한 NovelAI 또는 사용 가능한 ComfyUI 워크플로우로 새 층·몬스터·아이템 그림을 자동 생성한다. NovelAI 자동 감지는 하지 않는다. 미설정·불완전한 워크플로우·생성 실패는 GM 답과 게임 그림 설정 버튼으로 안내한다. 자동 그림은 하루 한도, GM 직접 다시 그리기는 그 한도 밖이며 모든 NovelAI 요청은 한 장이다. 그림 요청과 완성을 구분하고 이전 그림은 새 그림 완성까지 유지한다.
- **기존 세계 재적용**: 첫 층을 탐험했다는 이유로 설정을 조용히 버리지 않는다. 이름·테마·몬스터·외형은 안전하게 적용하고 지도·전투 능력치·진척을 유지했다고 알려 준다. 자동 생활 계획도 신청 주민이 없으면 시설이 반영되지 않았다고 보고한다. 설정의 GM 한도 설명을 실제 자동 경로의 집계 방식에 맞췄다.
- **어시스턴트**: `gm_open` 조회와 `gm_prepare` 요청 초안, GM 상태·실제 결과를 추가한다. 보내기·적용은 사람이 누른다. 호스트 코드는 바꾸지 않는다.

## 3.18.0: 조사 횟수는 앱 도구 한도를 따름

- **조사 예산 제거**: 주민 한 차례의 API 호출·에이전트 차례·도구 호출 상한과 활동 전체 상한을 없앤다. 조사 횟수는 앱 전역 **도구 호출 반복 한도**(설정 › 채팅 › 자원 › 도구 사용)를 다른 프로필·플러그인과 똑같이 따른다. 플러그인이 자체 상한을 계산해 보내거나, 받은 사용량을 그 상한과 비교해 실패시키지 않는다. 조사 창과 `research_prepare`에는 한 차례·전체 제한 시간만 남는다.
- **이전 데이터**: 이전 세이브·페이지·어시스턴트가 보내는 `perTurnModelCalls`·`perTurnToolCalls`·`totalModelCalls`·`totalToolCalls`는 받기만 하고 무시한다. 진행 중이던 조사는 작업 ID와 제한 시간을 유지한다. 이 동작에는 전역 도구 한도가 들어간 최신 CoNAI가 필요하다.

## 3.17.1: 화면 정리

- **SDK 스타일 순서**: 공용 `conai-plugin.css`를 `style.css`에서 `@import … layer(sdk)`로 불러 낮은 캐스케이드 레이어에 둔다. SDK의 `label > input`·`input:not(…)` 규칙이 선택자 우선순위로 플러그인 모양을 덮던 문제(생활 창 라벨이 한 글자씩 세로로 접힘, 입력칸만 테두리 없는 회색 칸으로 보임)가 사라진다.
- **깨진 배치**: GM 고르기 카드의 소개 문구가 카드 밖으로 한 줄로 뻗던 문제, 세이브 카드 이름이 창 머리 규칙을 물려받아 잘리던 문제, 빠른 메뉴가 넓어진 주민 목록을 덮던 문제, 미니 플레이어 제목이 두 줄로 넘어가 HP·MP 막대와 겹치던 문제를 고친다. 창 안 컨트롤에 포커스가 가도 게임 화면 전체가 옆으로 밀리지 않는다(`overflow: clip`).
- **좁은 화면**: 520px 이하에서는 오른쪽 위 버튼 줄이 두 번째 줄로 내려가 마을 이름·깨우기와 겹치지 않는다. 460px 이하에서는 미니 플레이어가 오른쪽 위로 옮겨 가고, 잠든 마을의 '마을 깨우기' 안내가 떠 있는 동안에는 비켜서서 채팅·확대 버튼이 안내 버튼을 가리지 않는다.
- **정리**: 창 머리 높이(방송 52px)와 어두운 얇은 스크롤바를 맞추고, 내용 없는 상태 점, 설정 단위 열 정렬, 한국어 단어 단위 줄바꿈(`keep-all`), 조사 입력칸 간격, 생활 창 빈 상태 여백, 시설의 '지도에서 보기' 위치(제목 옆)를 정리한다. 설정 창 제목은 HUD 버튼과 같은 '마을 관리'다.

## 3.17.0: 모든 프로필 엔진과 조정 가능한 조사 예산

- **모든 프로필 엔진**: 자료 조사가 주민 프로필에 정해진 기존 엔진(직접 API·Claude Code·Codex·Pi)을 그대로 쓴다. 엔진을 따로 고르지 않는다. 프로필 설정이 조사에 맞지 않으면 앱이 이유와 함께 거절하고 창에 그 사유를 보여 준다. 이 계약이 들어간 최신 CoNAI가 필요하다.
- **조사 예산**: 기존 고정 상한(차례마다 모델 4회·도구 4회) 대신 시작 전에 주민 한 차례의 API 호출·에이전트 차례(2–32회, 기본 8)와 도구 호출(1–100회, 기본 24) 상한을 정한다. 앞의 상한은 직접 API에서는 API 호출, Claude Code·Pi에서는 에이전트 차례를 제한하고, Codex는 안쪽 호출·차례 수를 제한할 수 없어 도구 호출과 시간 상한만 적용된다는 점을 시작 전에 알려 준다. **세부 상한**(접힘)에서 활동 전체 상한(비우면 자동, 요약은 도구를 쓰지 않음)과 한 차례·전체 제한 시간(기본 5분·30분)을 정한다. 창은 시작 전에 서버가 정할 것과 같은 상한과 시간을 보여 준다. 어시스턴트의 `research_prepare`도 `budget`을 채울 수 있지만 실행은 사람이 누른다. 예산이 바뀌면 시작 요청 ID도 새로 만든다. 사용량은 엔진이 알려 준 값만 그 이름대로(API 호출·에이전트 차례) 보여 주고, 알려 주지 않은 값은 0이 아니라 '집계 안 됨'으로 표시한다.
- **부분 발언**: 한 차례의 호출 상한에 닿은 주민의 발언은 부분 발언으로 표시하고, 다른 주민의 차례는 그대로 이어진다.

## 3.16.0: 자료 조사와 주민 토론

- **실제 조사 실행**: 호스트의 기존 LLM 실행기를 사용해 활동별 문맥을 격리하고, 지정한 공개 게시글의 검색·원문 열람만 허용한다. 주민의 주장 대신 실제 도구 응답에서 출처를 기록한다. 직접 API LLM만 지원하며 최신 호스트의 `research` 계약이 필요하다.
- **진행·정리**: 주민 차례당 모델·도구 호출 상한을 적용하고 마지막에 GM(없으면 참여 주민)이 한 번 요약한다. 중복 시작·중단·슬롯 전환·초기화 뒤 늦은 결과를 차단하고 원래 생활로 복귀한다. 요약은 근거·의견 차이·다음 질문을 포함하며 검증된 지식으로 자동 승격하지 않는다.

- **자료 조사 창**: HUD의 조사 버튼으로 연다. 주제(1–500자), 읽을 공개 게시글 ID(1–8개), 참여 주민(2–3명), 토론 회차(1–3)를 정하고 사람이 **조사 시작**을 누른다. 시작 요청은 지금 세이브 슬롯 ID와 마을 리비전을 함께 보내고, 응답을 못 받아 다시 누르면 같은 요청 ID를 쓴다(입력이 바뀌면 새 ID). 주민 프로필은 API LLM 엔진이어야 하며 다른 엔진은 서버가 거절한다. 한 번에 하나만 진행된다.
- **상태 표시**: 진행 중·끝남(검증 전 결과)·중단됨·실패, 토론 회차, 실제 모델·도구 호출 수와 한도, 한도 도달, 실패 사유, 읽은 근거가 없는 경우를 따로 보여 준다. 근거마다 게시글 ID·판·지식 버전·구간·발췌를 보여 주고, 누르면 앱 게시판의 그 글(`/posts?post=<id>`)로 이동한다. 토론은 주민·회차·참조한 근거와 함께 보여 준다. 진행 중에는 **조사 중단**을 누를 수 있다.
- **결과 초안**: 끝난 조사에 초안이 있으면 **결과를 검토 요청으로 보내기**로 게시판의 문서 변경 제안(`POST /api/posts/knowledge/proposals`, 새 문서·`draft` 상태, 출처는 실제로 읽은 발췌)으로 보낸다. 활동별 멱등 키(`research:<activityId>:draft`)를 써서 다시 보내도 제안이 하나만 생긴다. 게시판 지식 기능과 글쓰기 권한이 필요하고, 저장·게시는 게시판의 기존 검토에서 사람이 한다. 보내기 전의 초안은 저장된 글이 아니다. 게시판은 보낼 때 출처를 지금 게시글로 다시 확인하므로, 조사 뒤 근거 글이 수정·비공개·삭제됐으면 거절된다. 이때 거절 사유와 함께 다시 조사하라는 안내를 창에 남기고 결과는 그대로 둔다.
- **다시 준비**: 끝났거나 실패한 조사에서 **이 주제로 다시 준비**를 누르면 주제·게시글·주민·회차를 입력란에 다시 채운다. 실행하지 않으며, 다음 시작은 새 요청 ID를 쓴다. 서버가 끝난 조사의 일부(근거·토론·초안)를 숨기고 사유를 보내면 끝난 상태에서도 그 사유를 보여 준다.
- **생활 중심 보기**: 마을 관리 → 마을 → 화면에서 고른다. 길드 버튼과 LIVE 표시만 숨기고 던전 설정·장비·진행 기록은 바꾸지 않는다. 계정의 플러그인 저장소(`display`)에 저장된다.
- 어시스턴트: `ai-aquarium.research_open`(조회)과 `ai-aquarium.research_prepare`(입력 초안)를 추가했다. 시작·중단·검토 요청은 사람이 누른다. 페이지 상태에 `research`(지금 초안, 활동 상태·근거 발췌·호출 수)와 `display`가 들어간다. 슬롯을 바꾸면 준비한 입력과 재시도 ID를 버린다.

## 3.15.0: 여관과 신전에서 시작하는 마을

- **작게 시작하는 새 마을**: 빈 슬롯·설정만 가져온 슬롯·처음부터 다시 시작한 마을은 여관과 신전만 있는 지도에서 시작한다. 행상·여관 조리사·마을 건축가는 여관에서 일하다가 잡화점·찻집·모험가 길드가 지어지면 그리로 옮긴다. 이미 있던 세이브의 시설은 그대로다.
- **시설이 열어 주는 기능**: 잡화점이 있어야 길드 상점의 물약·장비 진열과 자동 보급이 열리고, 모험가 길드 건물이 있어야 길드 자동 의뢰가 생긴다. 길드 창은 고정 물약 목록 대신 없는 시설을 알려 준다. 지도는 세이브에 있는 시설만 그리고 누를 수 있다(세이브를 받기 전에도 템플릿 시설을 그리지 않는다). 잡화점과 모험가 길드도 공사로 지을 수 있다.
- **신전 발전 헌금**: 신전 시설 상세에서 헌금한다. 헌금은 공공 금고로 들어가고, 줄지 않는 누적 헌금으로도 기록된다. 화면은 누적 헌금·GM이 판단한 몫·판단 대기·공공 금고와 판단 상태를 따로 보여 준다. GM은 하루 한 번까지 누적 헌금과 마을 진척을 보고 공공 시설이나 새 물품을 제안할 수 있다. 보상이나 즉시 공사는 보장하지 않고, 판단 중에 낸 헌금은 다음 판단을 기다린다. 신탁 헌금(신관 몫)과 공공 금고 기부는 누적 헌금과 별개다.
- **신전 클릭**: 모험을 켠 동안에도 지도의 신전은 헌금이 있는 시설 상세를 연다. 신관·직업은 그 화면의 '길드에서 신관·직업 보기'로 연다.
- **마을 키우기 안내**: 잡화점이나 길드가 없으면 생활 창 공사 탭이 첫 돈·재료를 모으는 방법과 시설이 여는 기능을 알려 준다. 길드 상태 표시는 GM 생활 판단과 주민 생활 결정을 원정 준비와 구분한다.
- 어시스턴트: `ai-aquarium.life_prepare`에 `temple-donate`와 잡화점·길드 공사 종류를 추가했다. 신전이 하나면 `buildingId`를 생략할 수 있다. 초안은 여전히 사람이 실행을 눌러야 적용된다. 페이지 상태 `life`에 `donations`와 `facilitiesBuilt`가 들어간다.

## 3.14.0: GM과 마을 생활

- **DM은 GM으로**: 화면·설정·도움말의 DM을 GM(세계와 던전을 함께 맡는 프로필)으로 바꿨다. 세이브와 연결을 위해 설정 키(`dmProfileId`, `dmDailyLimit`), 요청·작업 ID, 화면 요소 ID와 내부 이름은 그대로다. 자율 모험을 꺼도 마을 생활과 GM의 그림 외형 묘사·그림 처리는 계속되고, 원정 출발·전투·의뢰 생성·새 탐험 결정만 멈춘다.
- **세이브마다 실행 지도**: 지도 크기·시설·공사 부지·설치 가구를 세이브에 저장하고, 서버의 걷기·경로·장소와 화면이 같은 실행 지도를 읽는다. 화면은 지도가 바뀔 때(확장, 부지 예약, 완공, 생성 그림 도착)만 다시 그린다. 생성된 시설 그림은 시설 칸 크기에 맞춰 출입구 줄에 붙여 그리고, 없으면 기존 지붕 그림을 쓴다.
- **생활 NPC**: 다람 상인·찻집 장인·마을 건축가가 규칙으로 근무 시간에 자기 자리로 걷는다. 지도에서 점선 토큰을 누르면 역할·영업 상태·남은 재고·자금이 보인다. 재고와 자금은 유한하고, 깨어 있는 5분마다 정해진 만큼만 보충된다.
- **물품 묶음**: 생활 물품은 가방(`stacks`)과 창고(`storedStacks`)에 수량으로 쌓인다. 사기·팔기·사용·보관·꺼내기·제작·근무·납품·설치·기부·휴식 서비스를 생활 창에서 한다. 마을에 돌아온 주민만 행동한다.
- **시설과 공사**: 시설마다 소유(공공/개인)·단계·서비스가 있고 이용료는 소유주나 공공 금고로 간다. 신축·증축·인접 구역 개방(동·남, 최대 세 번)은 견적 → 예치 신청 → GM 심사 → 착공 → 완공 순서다. 거절과 착공 전 취소는 전액, 착공 뒤 취소는 쓰지 않은 만큼만 환불한다. 공사비는 건축가에게 지급되고 건축가가 없으면 소모된다. 공사는 마을이 깨어 있을 때만 진행된다.
- **GM 생활 심사**: GM이 대기 공사를 승인·거절하고, 공공 금고가 넉넉하면 공공 시설이나 기존 기능을 쓰는 새 이름의 물품을 제안한다. 층 설계와 공사 심사는 `dmDailyLimit` 값의 별도 일일 한도, 자율 공공 계획은 하루 한 번으로 구분한다. 생활 요청은 시도부터 차감하고 대기 공사 심사를 자율 계획보다 먼저 처리한다. 주민도 자기 프로필로 생활 행동을 고른다.
- **생활 안전 경계**: 외부 어시스턴트는 조회·견적·화면 초안만 제공하며 직접 생활 변경 MCP는 등록하지 않는다. 생활·의뢰 요청의 중복 방지는 최근 30일 기록 범위이고, 생활 타이머는 최대 5초마다 저장한다(변경·일시정지 전 반영, 비정상 종료 시 미저장 진행 유실 가능). 생활 전용 저장은 던전 다시보기를 만들지 않고 단순 거래·생산 로그는 주민 기억에 반복 삽입하지 않는다.
- **생활 창**: HUD의 생활 버튼, 주민 빠른 메뉴, 지도의 시설·NPC에서 연다. 탭은 주민 생활·상점·NPC·시설·공사·공공이다. 공사 부지는 좌표로 쓰거나 지도에서 고르고(Esc 취소), 신청 전 서버 견적을 보여 준다.
- **중복 결제 방지**: 생활 행동마다 요청 ID를 붙이고, 같은 작업을 다시 보내면 같은 ID를 쓴다. 서버는 처리한 ID를 기억해 두 번 적용하지 않는다.
- 어시스턴트: `ai-aquarium.life_open`(생활 창 조회)과 `ai-aquarium.life_prepare`(생활 행동 초안, 공사는 견적 포함)를 추가했다. 페이지 상태에 `life`가 들어간다. 초안은 사람이 실행이나 공사 신청을 눌러야 적용된다.

## 3.13.0: DM의 기억과 로어북

- **DM도 주민처럼 기억한다**: 마을 DM은 주민 목록에 없지만 기억 체계에는 들어 있다. 플레이어와 나눈 대화, 제안을 적용하거나 거절한 일, 자기가 설계한 층(테마·몬스터·보상), 던전의 큰 일(사망·공략·의뢰 완료·승급·획득·층 이동), 새 주민이 온 일을 기억한다. 주민끼리의 잡담은 넣지 않는다.
- DM의 모든 요청(상시 대화, 층 확장, 그림 묘사)은 주민의 대화처럼 맞는 세계관 항목의 내용, DM 자신의 장기 로어, 최근 기억과 요약을 함께 보낸다. 이전에는 대화가 세계관 제목만 보고, 길드 DM은 기억 없이 답했다.
- 기억 정리(요약·장기 로어 추출)도 주민과 같이 돈다. "마을을 지켜보는 DM"의 관점으로 정리한다. 기억 정리가 밀렸을 때 새 활동을 쉬는 판정에도 DM이 들어간다.
- **기억은 따로**: DM의 기억은 DM 프로필 ID의 음수를 키로 저장한다. 같은 프로필이 주민으로도 초대돼 있어도 주민으로서의 기억과 섞이지 않는다. DM을 다른 프로필로 바꾸면 그 캐릭터의 DM 기억이 따로 쌓인다.
- **DM은 하나**: 대화 DM과 길드 DM(층 확장·그림 묘사)이 같은 설정을 쓴다. DM 창에서 고르면 길드 DM이 되고, 길드 설정에서 바꾸면 대화도 새 DM으로 바뀐다(새 대화로 시작). 둘이 달랐던 이전 저장은 길드 DM을 따르고, 길드 DM이 없으면 대화 DM이 길드 DM이 된다.
- DM 창 머리의 **기억** 버튼으로 주민과 같은 기억 창(최근 기억, 장기 로어북, 사건 기록, 직접 편집)을 연다. 어시스턴트의 로어 조회·편집 도구는 DM 프로필 ID의 음수로 DM의 책을 연다.
- DM의 기억과 장기 로어는 슬롯마다 따로이고, '처음부터'와 슬롯 삭제에서 함께 지워진다. '지금 설정으로 새 슬롯'은 DM 기억을 비운 채 시작한다.

## 3.12.0: 언제든 DM과 대화, 게임 화면 HUD 정리

- **언제든 DM과 대화**: 게임 화면 오른쪽 아래의 DM 버튼으로 연다. 세계가 정해진 뒤에는 같은 대화가 상시 DM이 된다. 잡담과 마을 근황 질문에는 마을 상황·세계관 제목·최근 소식·주민 상태·길드 층을 보고 그대로 답하고, 무언가 바꿀 일이 생기면 바뀌기 전·후를 보여 주는 제안 카드를 붙인다(적용 / 고쳐 줘 / 안 할래). 적용을 눌러야 저장된다.
- 제안할 수 있는 것: 세계 이름, 마을 상황, 세계관 항목 추가·수정·삭제, 지금 일어나는 일(소식과 주민 기억에 들어감), 다음 층 부탁(다음 층 확장에 반영), 주민 지시문, 하루 길이·잠, 모험 켜기·끄기. 서버가 설정 화면과 같은 규칙으로 검사한다.
- DM에게는 최근 메시지 60개(3만 자 이내)만 보낸다. 적용한 변경은 소식 창에 DM 줄로 남는다.
- **HUD**: 위쪽 버튼에 이름을 붙였다(방송·길드·앨범·마을 관리). 깨우기/재우기는 마을 이름 옆 상태 스위치로 옮겼다. 주민 목록은 얼굴 레일로 줄이고, 가리키면 이름이 펼쳐진다.
- **오른쪽 아래 정리**: 확대·축소, 방송 미니 플레이어, DM 버튼을 한 세로 줄로 쌓아 서로 가리지 않게 했다. 소식 창은 그 줄 옆에서 멈춘다. DM 창은 지도 옆 패널로 열리고(폰에서는 아래에서 올라오는 시트), 열려 있는 동안 오른쪽 아래 줄은 숨는다.

## 3.11.0: DM과 세계 만들기, 게임 그림 표시 수정

- **DM과 세계 만들기**: 채팅 프로필 하나를 DM으로 골라 대화하며 세계를 정한다. DM은 자기 말투로 한두 개씩 묻고, 답마다 세계 이름·마을 상황·세계관 항목·첫 층(이름·테마·몬스터·그림 태그)을 정리해 오른쪽 카드에 채운다. 서버가 빠진 필수 항목(세계 이름, 마을 상황, 세계관 항목, 모험을 켜면 첫 층 테마·몬스터)을 매번 DM에게 알려 대화 안에서 자연스럽게 채우게 한다.
- '이대로 시작'은 한 번에 적용한다. 세계 이름은 슬롯 이름, 마을 상황은 마을 설정, 세계관 항목은 세계관 로어북(같은 제목은 갱신, 나머지는 유지)에 들어가고 그 DM이 길드 DM이 된다. 아무도 들어가지 않은 첫 층은 DM이 정한 이름·테마·몬스터·그림으로 바뀐다.
- 첫 화면은 세계 만들기 → 주민 초대 → 깨우기 순서로 안내한다. 빈 새 슬롯을 만들면 바로 열리고, 이야기 탭의 'DM과 세계관 다듬기'로 언제든 다시 연다. 대화는 슬롯에 저장되고, 슬롯을 바꾸면 진행 중인 DM 답은 취소된다.
- **게임 그림 표시 수정**: 몬스터·수호자·장비·물약·스킬 그림이 생성돼도 화면에 도형과 기본 아이콘만 보이던 문제를 고쳤다. 그림을 다른 출처(미디어 주소)에서 CORS 없이 불러와 캔버스가 오염됐고, 배경 제거 후 이미지로 바꾸는 단계가 보안 오류로 매번 실패했다. 이제 CORS로 불러온다.

## 3.10.0: 세이브 슬롯, 새로 시작, 첫 단계 안내

- **세이브 슬롯**: 계정마다 마을을 최대 5개까지 따로 둔다. 주민·설정·시계·월드 채팅·주민 기억·세계관 로어북·길드(모험가·의뢰·던전·상점)·다시보기·앨범이 슬롯마다 분리된다. 기존 마을은 데이터를 옮기지 않고 "첫 번째 마을"(슬롯 1)로 보인다.
- 한 번에 한 슬롯만 깨어 있다. 서버는 플러그인을 켠 계정의 지금 슬롯만 진행하고, 다른 슬롯으로 바꾸면 먼저 지금 마을을 재우며 진행 중인 답변·기억 정리·DM 요청·전투 요청을 취소한다.
- 마을 꾸리기 → **세이브 슬롯** 탭에서 슬롯 목록(주민·마을 날짜·마지막 플레이), 바꾸기, 이름 바꾸기, 지우기를 한다. 지금 슬롯은 지울 수 없고, 지우기는 두 번 눌러야 실행된다.
- **새로 시작**: '지금 설정으로 새 슬롯'은 주민 구성·지시문·마을 설정·세계관 로어북·길드 운영 설정과 역할을 가져오고, 대화·기억·길드 진행은 비운다. '빈 새 슬롯'은 아무것도 가져오지 않는다. 만든 슬롯으로 바로 바뀐다.
- **지금 슬롯 처음부터**: 설정·세계관 로어북·길드 운영 설정은 남기고 대화·주민 기억·길드 진행·다시보기를 지운다. 슬롯 이름을 그대로 입력해야 실행된다.
- 앨범은 슬롯별 라이브러리 그룹이다. 슬롯 1은 기존 `AI 어항`, 새 슬롯은 만들 때 이름으로 `AI 어항 · 이름` 그룹을 쓰며 이름을 바꿔도 그룹은 그대로다. 슬롯을 지우거나 처음부터 해도 라이브러리 이미지는 지우지 않는다.
- HUD 왼쪽 위에 지금 슬롯 이름이 보이고, 누르면 세이브 슬롯 탭이 열린다. 잠든 마을 화면은 주민 초대 → 적용 → 마을 깨우기 단계를 보여 주고 세이브 슬롯으로 가는 링크를 둔다.

## 3.9.5: 기억 정리 알림, 좁은 화면 설정

- 확장을 업데이트하면 메인이 진행 중인 기억 정리를 취소한다. 이걸 "사용자 요청으로 작업이 중단되었습니다" 오류로 띄우던 문제를 고쳤다. 취소된 정리와 대화는 오류 없이 다음 틱에 다시 요청한다.
- 기억 정리 실패는 6초 알림으로 한 번만 띄운다. 다음 성공까지 화면 위에 남지 않는다. 남아 있는 마을 오류 알림은 눌러서 닫을 수 있다.
- 모델이 낸 기억 항목 중 하나가 틀렸을 때(없는 출처, 후보에 없는 ID, 길이 초과, 겹치는 제목) 그 항목만 버리고 나머지와 요약은 저장한다. 같은 오류가 5분마다 반복되지 않는다. 사람이 추출 중에 고친 항목은 이전처럼 전체를 다시 정리한다.
- 주민 탭의 프로필 카드가 좁은 화면에서 납작하게 눌려 이름만 잘려 보이던 문제를 고쳤다. 카드 높이는 내용만큼 유지하고, 폭 760px 이하에서는 두 줄로 놓인다.
- 역할 목록의 직업은 이름 아래에 놓는다. 직업이 길어도 역할 선택이 다음 줄로 밀리지 않는다.
- 폭 760px 이하의 설정 줄은 선택 칸을 150px로 줄여 라벨 옆에 둔다. 들어가지 않는 컨트롤은 라벨 아래 왼쪽에서 시작한다. 근무 시간도 같다.
- 기억 창은 좁은 화면에서 전체 화면으로 열린다. 최근 기억·장기 로어북·사건 기록은 한 줄 글자 탭으로 바꿨고, 원문/번역 전환은 그 줄 끝에 둔다. 앨범도 전체 화면으로 열린다.
- 길드 모험가 탭에서 직원의 근무 시간 줄이 왼쪽 끝에 붙던 문제를 고쳤다.

## 3.9.4: 작은 화면, 버튼 깜빡임, 기억 정리

- 기억 정리 답이 답변 한도(2048토큰)에 걸려 중간에 끊기면, 메인이 끊긴 글에서 첫 장기 기억 항목 하나만 건져 넘겼다. 그래서 "기억 요약 형식이 올바르지 않아" 오류가 났다. 이제 기억 정리는 4096토큰을 요청하고, 항목은 최대 8개·300자 이내로 줄였다. 그래도 끊기면 "중간에 끊겼어"로 알리고 아무것도 저장하지 않는다. 메인도 끊긴 JSON을 거부하도록 고쳤고, 이전 메인에서는 어항이 원문을 다시 확인해 같은 안내를 한다.
- 폭 900px 이하에서 방송 채팅을 손가락으로 밀면 아무것도 움직이지 않던 문제를 고쳤다. 채팅 목록이 스크롤할 게 없는 스크롤 영역으로 남아 있었고, `overscroll-behavior:contain` 때문에 바깥 화면으로 스크롤이 넘어가지 않았다. 이 배치에서는 목록이 줄 수만큼 늘어나고 방송 화면 전체가 스크롤된다.
- 1초 상태 확인이 매번 버튼을 비활성화해서 재우기·새로 확인 버튼이 깜빡이던 문제를 고쳤다. 비활성화는 사람이 누른 동작에만 쓰고, 설정 창은 마을이 바뀐 때만 다시 그린다.
- 접힌 소식창은 최근 줄을 한 줄당 최대 두 줄로 줄이고 원문은 숨긴다. 높이는 최대 170px(작은 화면 130px)이고, 넘치면 위쪽이 잘린다. 펼치면 전부 보인다.
- 폭 760px 이하 또는 높이 560px 이하(폴드 안팎 화면, 가로 휴대폰)에서는 HUD 버튼·글자·주민 얼굴·미니 플레이어(220px)를 줄인다. 미니 플레이어가 떠 있으면 소식창은 그 옆에서 멈추고 확대 버튼은 그 위로 올라간다. 폭 460px 이하에서는 접힌 소식창이 플레이어 위에 쌓인다.
- 길드·설정·방송 창의 휴대폰 배치(전체 화면, 위쪽 가로 탭) 기준을 640px에서 760px로 넓혔다. 설정 줄의 라벨은 최소 8em을 유지하고, 컨트롤이 옆에 안 들어가면 다음 줄로 내려간다. 좁은 상점 탭에서 진열대와 혜택이 겹치던 문제도 고쳤다.
- 로어 조회 키는 제목·키워드·번역 키워드를 접어서(대소문자·유니코드 정규화) 따로 저장하고, 대사 안에 키가 들어 있으면 고른다. 기존 로어는 시작할 때 채운다.
- 언어 표시가 잘못 붙은 기존 대사·기억·로어(번역문이 원문과 같은 글자 체계 등)는 한 번 정리해 번역 표시를 지운다.
- 대리 전투·판정·신탁처럼 다른 주민 대신 답하는 요청에는 답하는 주민 본인의 기억만 붙인다. DM·둘러보기에는 개인 기억을 붙이지 않는다.
- 자동 기억 정리는 자동으로 만든 항목만 고친다. 직접 쓴 항목·이전 요약과 같은 제목이 나오면 덮어쓰지 않고 건너뛴다. 이전 요약이 로어로 옮겨진 뒤에는 같은 요약을 두 번 넣지 않는다.
- 자동 번역이 길이 한도를 넘으면 그 번역만 버리고 원문은 저장한다. 편집기에서 직접 만든 번역이 넘치면 줄일 한도를 알려준다. 키워드 칸은 한 줄에 하나씩 쓰는 여러 줄 칸으로 바꿨다.

## 3.9: 모델 원문과 표시 번역

- 번역 모델이 설정된 프로필은 모델 언어로 대화·기억을 작성하고 표시 언어 번역을 별도로 저장한다. 영어/한국어 설정에서는 영어 대사·요약·로어 제목/키/본문을 모델에 재사용하고 화면에는 한국어 번역을 먼저 보여준다. 마을 대사의 한국어 강제 지시는 제거했다. 행동 ID·수치·출처 ID·이미지 태그는 번역하지 않는다.
- 대화와 기억은 원문을 보존한다. 기억 창의 **원문 보기 / 번역 보기**로 전환하고, 로어 편집기에서 양쪽 제목·키워드·본문을 각각 수정한다. 원문을 수정하면 이전 번역은 무효화한다. **번역 만들기**에서 번역 프로필을 고르면 모델 언어 원문과 표시 번역을 초안에 넣는다. 저장은 기존 버튼으로 한다. 번역 중 닫기는 번역 취소를 요청한다.
- 기존 한국어 기억은 덮어쓰지 않고 언어 미지정 원문으로 유지한다. 필요할 때 편집기에서 번역을 만들어 전환할 수 있으며, 이것은 잃어버린 과거 영어 대사의 복원이 아니다. 모델 번역 실패 시 원문을 그대로 저장·표시하고, 번역은 새 요청이나 명시적 번역 작업에서만 생성한다. 화면 조회마다 모델을 부르지 않는다.
- 세계관 로어북도 같은 원문/번역 형식을 쓴다. 모든 주민에게 모델용 본문을 전달하며 표시 번역은 화면에만 사용한다. 기존 키워드와 번역 키워드 양쪽으로 조회할 수 있다.
- 3.9 ZIP에는 메인의 프로필 번역 연결 업데이트가 필요하다. 이전 메인은 새 `translation` 입력을 지원하지 않는다. 프로필의 번역 모델·모델 언어·표시 언어 설정을 먼저 확인한다.

## 3.8: 세계관 로어북과 주민 장기 기억

- **세 가지 설정을 함께 사용**: 메인 업데이트 후 프로필에 연결한 global·파일 기반 로어북을 기존 선택 규칙으로 읽고, 어항의 세계관과 해당 주민의 장기 기억을 함께 참고한다. 원본 프로필과 다른 채팅은 변경하지 않는다.
- **세계관**: 마을 설정 → 이야기 → **세계관 로어북 관리**. 현재 계정의 어항에서 주민·신관·DM·판단 프로필 모두가 공유한다. 새 항목은 기본으로 항상 적용된다. 키워드 항목은 현재 요청에 맞을 때 적용한다. 저장 후 새 요청부터 반영하고, 이미 접수한 요청의 재시도 입력은 유지한다.
- **주민 기억**: 주민 메뉴 → **기억 보기**에서 최근 기억, 장기 로어북, 사건 기록을 조회한다. 로어북은 제목·키워드·본문·활성·항상 적용·유효/완료/대체 상태를 편집한다. 자동 추출 항목은 출처 발췌를 보여주고, 최근 기억에서는 마지막 요청에 선택한 어항 로어 제목을 확인한다. 사용자 편집 항목과 이전 요약은 자동 추출이 덮어쓰지 않는다.
- **축적**: 미정리 원문이 40줄부터, 최대 24줄·약 6천자 묶음으로 요약과 최대 8개 장기 기억(항목당 300자 이내)을 추출한다. 추출은 기존 프로필 모델을 사용하며, 답변 한도 설정과 별도로 4096토큰을 요청한다(프로필 최대 토큰이 더 작으면 그쪽을 따른다). 전체 장기 기억을 다시 요약해 덮어쓰지 않고 관련 항목을 갱신한다. 출처 ID·버전·처리 커서를 검사하고 한 트랜잭션에 저장한다. 실패·중단·저장 충돌 때 원문을 보존한다. 처리 지연으로 원문이 주민당 2천줄에 도달하면 정리가 따라잡을 때까지 새 활동을 쉬며, 실패 원인을 화면에 표시한다.
- **범위와 상한**: 책당 500개, 항목당 2천자·키워드 20개. 한 요청의 세계관은 8천자, 개인 로어는 5천자, 최근 기억은 1만2천자 안에서 사용한다. 항상 적용 항목의 합계는 제목을 포함해 세계관 7천자·개인 4천자까지다. 키워드는 대소문자 무시 부분 일치이며 정규식·재귀·임베딩 검색은 지원하지 않는다. 사건 묶음은 주민당 최근 200개를 보관하며, 오래된 묶음이 정리돼도 로어에 연결된 출처 발췌는 유지한다. 책이 꽉 차면 자동 삭제하지 않고 정리 오류를 알린다.
- **이전 데이터**: 기존 요약은 최초 조회/요청 시 `이전 기억 요약` 항목으로 한 번 보존한다. 남아 있는 미정리 원문은 순서대로 처리하고, 이미 사라진 원문은 복원하지 않는다. 주민을 목록에서 빼도 기존 기억은 남으며 같은 프로필을 다시 초대하면 이어 쓴다. 플러그인을 제거하면 전용 데이터도 삭제된다.
- **AI 연결**: `ai-aquarium.lore_open`은 세계관(profileId 0)·주민 책을 검색/조회하고, `ai-aquarium.lore_prepare`는 같은 편집기에 초안을 만든다. 저장은 사람이 누른다. 서버 도구 `p_ai_aquarium_lore`도 계정 범위의 페이지 조회를 제공한다. 계정·주민 경계와 항목 버전 충돌 검사는 모든 경로에서 동일하다.
- **적용**: 프로필의 파일 기반 로어북 적용에는 메인 서버 업데이트가 필요하다. 어항 ZIP만 바꾸면 세계관·개인 기억은 사용하지만 이전 메인의 프로필 로어 조회 한계는 남는다.

## 3.7: 창 리뉴얼

- **게임 창**: 길드·설정·방송 창이 게임 화면을 꽉 채운다(가장자리 12px, 휴대폰은 전체). 머리줄 하나에 제목과 텍스트 탭이 있고, 설명은 툴팁으로 옮겼다.
- **길드 한 창**: 의뢰·던전·상점·모험가가 한 창의 탭이다. 모험 정보도 이 창의 모험가 탭으로 열린다. 위쪽 층 칩 줄과 아래쪽 상태 줄을 없애고, 진행 상태는 머리줄 오른쪽 점과 짧은 글(툴팁에 DM 사용량)로 보여준다.
- **던전 탭**: 왼쪽 층 목록(번호·이름·탐색률·안에 있는 주민 얼굴·공략/잠김 표시), 가운데는 방송과 같은 렌더러(`floor-paint.js`)로 그린 층 전체(횃불·적·상자·유물 그림), 오른쪽은 발견률·남은 적·수호자·보물·유물·사망을 아이콘과 숫자로, 그 층 모험가의 최근 소식. 지도 위에 마우스를 올리면 그 칸의 적·물건·주민이 뜨고, 주민을 누르면 고른다. 시야는 길드가 아는 곳·고른 모험가 시야·전체 지도 아이콘 버튼으로 바꾼다. 아래쪽 얼굴 칩에서 바로 방송을 연다. 글자 범례는 없앴다.
- **의뢰 탭**: 의뢰 한 줄에 종류 아이콘·이름·층 칩(누르면 던전)·담당 얼굴·진행 막대·보상. 새 의뢰는 오른쪽 칸에서 쓰고(종류는 아이콘 5개, 목표는 −/+), 목록은 그대로 보인다.
- **상점 탭**: 진열대 격자와 오른쪽 "지금 혜택"(상인·접수원·자동 보급·여관) 아이콘 줄. 자세한 설명은 툴팁.
- **모험가 탭**: 창이 넓으면 상태·장비·원정 기록을 탭 없이 한 화면에 놓는다. 좁으면 예전처럼 탭. 능력치·의뢰·사망 수는 아이콘과 숫자. 직원은 근무 시간을 보여준다.
- **설정 창(마을 설정)**: 왼쪽 목록 주민·지시문·이야기·마을·모험·전투 AI·역할·근무, 오른쪽은 "이름 · 조절기" 줄. 체크박스는 스위치, 숫자는 −/+. 지시문은 주민 목록에서 고르고(지시문이 있으면 점) 넓은 칸에 쓴다. 마을 설정과 모험 설정을 **적용** 하나로 같이 저장하고, **되돌리기**는 둘 다 되돌린다(창은 닫지 않는다). 역할만 바꾸는 어시스턴트 초안은 역할·근무 페이지로 연다.

## 3.7: 게임 그림

DM이 게임에 나오는 모든 것의 겉모습을 정하고, 게임이 그걸 NovelAI나 ComfyUI로 그려서 쓴다.

- **무엇을**: 층마다 몬스터·수호자·전리품, 모든 장비(기본·상인 특제 포함), 회복약·마나약, 신탁 스킬, 층 풍경.
- **DM이 정하는 모습**: 새 층을 설계할 때 `monster.look`·`bossLook`·`item.look`·`visualPrompt`에 영어 태그를 같이 쓴다. 그 밖에 아직 모습이 없는 것(처음부터 있는 층·장비·물약·스킬)은 원정 보낼 주민이 없는 한가한 때에 DM에게 10개씩 묻는다(`{ looks: [{ id, tags }] }`). 같은 것은 두 번까지만 묻는다. 이 요청이 실패해도 게임 AI는 멈추지 않고 10분 뒤 다시 묻는다.
- **그리기**: 모험 설정의 **게임 그림**에서 주민 그림과 따로 방식(안 그림·NovelAI·ComfyUI 워크플로우와 프롬프트 입력칸)을 고른다. 종류마다 고정 화풍 태그가 앞에 붙어 그림체가 하나로 맞는다. NovelAI는 `nai-diffusion-5-full`, 1024×1024(풍경 1216×832), `n_samples: 1`, 몬스터·장비·스킬은 투명 배경(`transparent_background`)이다. ComfyUI는 고른 입력칸에 같은 프롬프트를 넣는다.
- **한도**: 하루 그림 한도(0–200장, 기본 30)를 넘지 않고, 한 번에 2장까지만 큐에 올려 내 생성 작업을 밀어내지 않는다. 실패한 그림은 한 번 더 시도한다.
- **저장**: 라이브러리 그룹 `AI 어항 게임/몬스터`·`/아이템`·`/스킬`·`/풍경`에 들어가고, 게임은 해시만 기억한다. 복사본은 없다.
- **화면**: 방송과 길드 던전 지도에서 적 덩어리 대신 그 층 몬스터 그림이 숨 쉬고, 맞으면 번쩍인다. 수호자는 더 크고 왕관이 붙는다. 방송 전투 막대에 몬스터 얼굴이 뜬다. 길드의 장비·물약·스킬 아이콘, 모험가 상태 탭의 지금 싸우는 몬스터, 던전 탭 오른쪽의 몬스터·수호자·전리품도 그 그림을 쓴다. 그림은 한 장씩 차례로 열고, 못 열면 30초 뒤 다시 시도한다(세 번까지). 배경이 투명하지 않게 나온 그림은 화면이 가장자리 단색 배경을 지우고, 단색 배경도 없으면 둥글게 자른다. 그림이 아직 없으면 예전 모양 그대로다.
- 그림 방식 고르기는 주민 그림과 같은 부품(`draw-picker.js`)을 쓴다.
- 예전에 "새 층 이미지 생성"을 켜 두고 주민 그림 방식을 쓰던 게임은 그 방식을 게임 그림으로 한 번 옮겨 온다. 어시스턴트 `rpg_prepare`에 `gameArt`·`assetDaily`가 추가되고 `art`는 빠졌다.

## 3.7: 화면 개편

- **주민 메뉴**: 주민 목록을 누르면 카드 대신 그 줄 옆에 버튼(방송 보기·지도에서 보기·기억 보기·모험 정보)이 하나씩 튀어나온다. 목록 옆에 고정이라 캐릭터를 따라다니지 않는다. 지도에서 캐릭터를 누르면 같은 버튼이 캐릭터 옆에 붙어 같이 움직인다. 지도에서 보기는 그 주민 쪽으로 확대해서 옮긴다.
- **모험 정보**: 주민은 왼쪽 세로 목록(얼굴·LIVE·레벨·단계·HP 막대)으로, 오른쪽은 이름 옆 직업·레벨·랭크·지금 하는 일 칩, 소지금, HP·MP·EXP 막대, 공격·방어·속도 띠. 탭 아래만 스크롤되고 창 높이는 탭을 바꿔도 그대로다. 원정 중이면 상태 탭 맨 위에 적 HP·적 행동·의뢰 진행이 보인다.
- **장비**: 착용 3칸과 물약, 가방 6칸·창고 40칸 격자. 칸 색이 등급(일반·고급·희귀), E가 입은 것이다. 칸을 누르면 능력치와 같은 부위 착용 장비와의 차이(▲▼)가 보인다.
- **원정 기록**: 결과 색(귀환·의뢰 완료·사망)과 층·처치·피해·물약·이유·시각.
- **상점**: 물건 줄(할인 중이면 원래 값에 줄)과 지금 적용 중인 상인·접수원·자동 보급·여관 혜택.
- **던전 지도**: 지도에 있는 주민을 지도 번호가 붙은 얼굴 칩으로 보여주고, 지도가 창 너비만큼 늘어나지 않는다.
- **모험 설정**: 모험·전투 AI·속도·사망·역할로 묶고, 숫자는 −/+ 조절기로 바꾼다.
- **꾹 누르기**: −/+ 버튼(이야기·모험 설정의 숫자, 지도 확대·축소)을 누르고 있으면 잠깐 뒤부터 계속 오르내리고, 오래 누를수록 빨라진다. 확대·축소는 일정한 속도로 간다. 손을 떼거나 버튼 밖으로 나가면 멈춘다.
- **AI 답변 한도**(설정 › 이야기, 256–4096토큰, 기본 2048): 주민 대화·기억 정리·원정 결정·신탁·DM·중간 판단·전투 AI가 모두 이 한도를 쓴다. 예전에는 요청마다 200–900토큰으로 고정돼 있어서, 생각을 길게 하는 모델은 JSON을 끝맺지 못하고 "프로필 답변 생성에 실패했어"로 끝났다. 호스트는 여기에 프로필의 출력 한도를 한 번 더 적용한다. 어시스턴트 `prepare`에 `replyLength`가 추가됐다. 신탁이 계열을 영어 키 대신 "전사"·"Archer"처럼 쓰거나 빼먹어도 이름·직업·스킬에서 계열을 읽고, 못 읽으면 전사로 친다.

## 3.7: 근무와 요일

- **요일**: 마을 1일째가 월요일이고 7일마다 한 주가 돈다. 시계·마을 소식("2일째 화요일 아침이 밝았어")·주민 대화에 요일이 붙는다.
- **근무 시간**(설정 › 모험 › 근무): 길드 접수원·상인·신관마다 출근·퇴근 시간(30분 단위, 한 시간 이상, 자정을 넘겨도 된다)과 쉬는 요일을 정한다. 요일 버튼은 불이 켜진 날이 일하는 날이다. 기본은 접수원 09:00–18:00 일요일 휴무, 상인 08:00–20:00 수요일 휴무, 신관 06:00–19:00 무휴다. 밤샘 근무는 시작한 날의 요일을 따른다. 어시스턴트 `rpg_prepare`에 `shifts`가 추가됐다.
- **출퇴근**: 근무 시간에는 건물 문 옆 자리로 출근해서 지키고(목록·방송에 "길드 접수원 근무 중"), 끝나면 다른 주민처럼 산책·대화하고 밤에 잔다. 근무 중이 아닐 때는 상인 할인·특제 장비, 접수원 의뢰 보너스가 멈추고, 신탁은 신전이 다시 열릴 때까지 기다린다. 상점 탭에 "상인 OO 쉬는 중 · 근무 시간"이 보인다.
- **돈과 생활**: 일한 근무가 끝나면 일당을 받는다(접수원 30G, 상인 15G, 신관 20G). 상인은 근무 중 판 물건값의 25%, 신관은 신탁마다 모험가가 내는 헌금 10G(가진 돈이 있을 때)를 더 번다. 밤마다 여관비(5 + 레벨×2 G)를 내고 자며, 돈이 모자라면 광장에서 노숙한다. 노숙하는 주민은 지도에 흐리게 남고 아침에 그 자리에서 일어난다.
- 주민 대화에 자기 역할·근무 시간·오늘 근무 여부·가진 돈이 한 줄 들어간다(직원만).
- **방송 채팅 전송 수정**: 플러그인 화면은 폼 제출이 막힌 샌드박스라 보내기 버튼과 Enter가 아무 일도 하지 않았다("Blocked form submission … allow-forms"). 이제 폼 없이 버튼 클릭과 Enter로 보낸다. 한글 조합 중 Enter는 글자만 끝내고 보내지 않는다.
- **방송 목록 끊김 수정**: 채널 목록이 1초마다 카드와 썸네일 캔버스를 통째로 다시 만들고 썸네일을 그때 한 번만 그려서, 썸네일이 1초 간격으로 뚝뚝 움직였다. 이제 카드는 채널마다 하나를 유지하고 바뀐 글자만 고치며, 썸네일은 미니 플레이어처럼 초당 약 15번 그린다(화면 밖 카드는 건너뛴다). 다시보기 목록도 바뀐 게 없으면 다시 만들지 않는다.
- **화면 최적화**: 설정·방송·길드·앨범·기억 창이 열려 있으면 그 뒤의 지도는 위치만 계산하고 다시 그리지 않는다(걷기·생각 중 점 애니메이션도 멈춰, 흐린 배경을 매 프레임 다시 그리지 않는다). 창을 닫으면 그 자리로 바로 옮겨 그린다. 지도는 화면 크기를 크기가 바뀔 때만 읽어서 매 프레임 레이아웃을 다시 계산하지 않는다. 주민 목록은 주민마다 줄을 유지하고 바뀐 글자만 고쳐서 갱신마다 얼굴 사진이 다시 불러와지지 않는다. 마을 소식은 새 줄만 붙인다. 실제 데이터로 잰 메인 스레드 시간(스크립트+스타일+레이아웃): 마을 38→22, 방송 목록 36→11, 방송 시청 40→11 ms/초.

## 3.6.1: 화면 정리

- **대사 표시**: 주민 카드의 대사가 네 줄에서 깔끔하게 잘린다(다섯째 줄이 아래 여백에 비치던 문제). 말풍선과 카드에는 `*행동 묘사*`를 빼고 말한 부분만, 마을 소식과 방송 채팅에는 행동 묘사를 기울임으로 보여준다.
- **방송 화면**: 화면과 채팅 위에 여백이 생겼다. 방송 채팅에 도구 실행 기록이 나오지 않는다. 신탁 전 주민이 "전사"로 나오던 것을 "신탁 전", 접수원·상인·신관은 역할로 보여준다. 보내기 버튼 안내가 위로 열린다.
- **오류 안내**: 길드·방송·설정 창 안에서 난 오류도 창 위에 보인다(전에는 창 뒤에 가려졌다). 채팅·설정 같은 사용자 동작은 마을 갱신이 느려도 실패하지 않고 차례를 기다린다.
- **조사**: 영문·숫자 이름에 "이(가)" 대신 알맞은 조사를 붙인다(Aqua가, Ran이).
- **주민 색**: 설정의 프로필 카드가 마을과 같은 주민 색을 쓴다.
- **프로필 이미지**: 얼굴 크롭으로 확대한 이미지가 주민 목록에서 원 밖으로 넘치던 문제를 고쳤다. 이미지는 늘 자기 틀 안에서 잘린다.
- **말풍선**: 말풍선마다 말한 주민의 이름과 주민 색 띠가 붙는다. 붙어 선 주민의 말풍선은 서로 덮지 않게 옆이나 위로 비킨다. 자리가 없으면 가장 덜 가리는 곳에 두고, 가까운 주민의 말풍선이 앞에 온다. 지도와 방송이 같은 배치(`bubble-layout.js`)를 쓴다. 지도에서는 주민 목록·상단 바·확대 버튼·마을 소식·미니 플레이어 밑으로 들어가지 않고 옆으로 비킨다. 비킬 때는 위아래보다 옆을 먼저 고른다.
- **안내 문구(툴팁)**: 화면 맨 위에 떠서 스크롤 영역이나 창 가장자리에서 잘리지 않는다. 화면 끝에서는 안쪽으로 붙는다(`tip.js`).
- **스크롤바**: 방송의 다른 채널 줄은 가로 스크롤 없이 칸에 맞춰 줄어든다. 방송 화면은 세로가 모자라면 열 전체를 스크롤하지 않고 플레이어가 줄어든다. 길드·모험 정보 창은 화면 높이만큼 커져서 내용이 들어가면 스크롤이 생기지 않는다.

## 3.6: 줌·카메라, 전투 판단 모델, 안정성

- **줌과 카메라**: 마우스 휠이나 두 손가락으로 확대·축소하고, 지도를 끌어서 옮긴다. 오른쪽 가운데의 +, −, 전체 보기 버튼으로도 조작한다. 끌기는 클릭으로 치지 않는다. 보던 위치는 이 브라우저에 기억해 둔다. 처음 여는 세로 화면(휴대폰)은 광장 주변을 2배쯤 확대해서 연다. 확대 중에 목록에서 화면 밖 주민을 고르면 그쪽으로 옮겨 간다.
- **화면 최적화**: 지도 층은 크기를 바꾸지 않고 이동·확대만 해서, 다시 배치하거나 다시 그리지 않는다. 카메라가 그대로면 아무것도 다시 배치하지 않는다. 말풍선은 글이 바뀔 때만 크기를 잰다. 화면 밖 말풍선은 숨긴다. 한낮에는 색 혼합 층을 끈다. 지도 원본 복사본은 버린다.
- **전투 AI 모델**(설정 › 모험): **각자 판단 모델**(기본)은 그 주민 프로필의 판단 모델로 고르고, 판단 모델이 없으면 기본 판단 모델(⚖)을 쓴다. 프로필의 말투는 그대로 따라간다. **각자 프로필**은 그 주민 프로필이 그대로 고르고, 프로필 하나를 고르면 그 프로필이 모든 주민의 전투를 대신 고른다. 판단 모델이 없거나 호스트가 아직 지원하지 않으면 한 번 알리고 10분 동안 각자 프로필로 고른다.
- **전투 AI 하루 한도**(기본 2000회, 0–10000): 넘으면 그날 남은 전투는 규칙으로 진행한다. 설정 칸 옆에 오늘 쓴 횟수가 보인다. 호스트는 플러그인 답변을 동시에 4개, 하루 1만 건까지 받는다. 전투 요청은 동시에 2개까지만 보낸다.
- **스킬 효과**: 신탁이 스킬마다 전투 효과 하나를 같이 정한다. 강한 한 방(1.5배), 두 번 공격(0.85배 두 번), 방어 무시(1.3배, 적 방어 무시), 흡수(1.2배, 준 피해 절반 회복), 치유(HP 30% 회복), 수호(받는 피해 40%로) 중 하나다. 이름과 설명은 그대로 자유 텍스트다. 마법사 계열은 스킬 피해가 25% 더 크다. 규칙이 고를 때는 다친 상태면 회복 스킬을 먼저 쓰고, 아니면 공격 스킬을 번갈아 쓴다. 체력이 가득하면 치유는 쓰지 않는다. 전투 AI에는 스킬마다 효과가 같이 전해진다. 예전 신탁의 스킬은 강한 한 방으로 친다. 모험 정보와 방송에 효과와 회복량(+N)이 보인다.
- **골드 쓸 곳**: 걸어서 돌아온 원정마다 여관비 5 + 레벨×2 G를 낸다. 돈이 없으면 휴식이 두 배로 길다(사망·소환 귀환은 무료). 상인이 있으면 물약이 20% 싸고, 공략한 층마다 그 층 전리품보다 강한 "상인 특제" 장비를 판다(자동 보급이 산다). 접수원이 있으면 의뢰 보상이 20% 늘어난다. 길드 상점 탭에 지금 적용되는 것이 보인다.
- **가방과 창고**: 가방에는 착용 장비와 이번 원정에서 주운 전리품만 들어간다(6칸, 가득 차면 주운 것을 판다). 나머지 장비는 집 창고(40칸)에 둔다. 출정할 때 가방과 창고를 통틀어 가장 좋은 장비를 골라 입고, 돌아오면 전리품을 창고에 넣는다. 창고가 넘치면 가장 약한 여분부터 판다. 물약은 출정 때 3개 이내로만 챙긴다. 모험 정보의 장비·가방 탭에 가방과 창고가 따로 보인다.
- **중간 판단도 판단 모델로**: 중간 판단 프로필에 "각자 판단 모델"을 고를 수 있다. 계속 갈지 돌아갈지를 그 주민 프로필의 판단 모델이 정한다. 판단 모델이 없으면 10분 동안 규칙(예상 피해와 회복약)으로 정한다. 판단 모델이 없어도 게임은 그대로 돌아간다. 판단 모델은 전투 행동과 중간 판단만 맡고, 원정 결정·신탁·DM·마을 대화는 각자 프로필 그대로다.
- **모델에 주는 정보 정리**: 전투 요청에는 내 레벨·공격·방어·HP/MP·전략, 스킬마다 설명과 효과, 물약 수와 효과, 적의 공격·방어·다음 행동, 한 번에 주고받는 피해와 이기는 데·쓰러지는 데 걸리는 턴 수, 지난 턴 결과가 들어간다. 중간 판단에는 스킬, 보이는 적의 능력치(최대 6마리), 최근 원정 3번이 들어간다. 원정 결정에는 직업·스킬·착용 장비 이름이 더해지고, 원정 기록은 최근 3번만 간추려 넣는다. 가방·창고 목록은 모델에 보내지 않는다. 어시스턴트 페이지 상태도 선택한 주민을 이름과 숫자로만 간추려 보낸다. 시험 실행에서 요청 글자 수(프로필 지시문 제외)는 전투 약 700자, 중간 판단 약 900자, 원정 결정 약 1,100자였다.
- **바쁜 호스트**: 답변 칸 4개가 다 차거나 하루 기록 한도에 닿으면 실패로 세지 않고 나중에 다시 보낸다(마을 대화, 방송 채팅, 원정·신탁·DM 요청 모두).
- **실패 처리**: 연속 실패로 멈춘 AI 요청은 10분 뒤 스스로 다시 시작한다. 모델이 답은 했는데 쓸 수 없는 답(없는 층, 너무 긴 스킬 이름 등)이면 그 요청만 다시 기다리고 전체를 멈추지 않는다. 신탁의 긴 이름은 잘라서 쓴다.
- **중간 판단**: 다른 요청에 밀려 30초 넘게 묻지 못한 판단은 예상 피해와 회복약으로 규칙이 정한다.
- **밤의 원정**: 잘 시간이 되면 새 원정 결정이 와도 아침까지 미룬다.
- **기억과 소식 정리**: 조우·일반 처치·물약·상자·함정·적 행동·상점 같은 던전 줄은 방송에만 남기고, 마을 소식과 기억에는 원정마다 "귀환 · N층 처치 · 받은 피해" 한 줄만 남긴다(사망·공략·승급·전리품·출발은 그대로). 기억 정리는 실패한 주민만 기다리고 다른 주민은 계속 정리한다.
- **그 밖에**: 모험 상태를 0.5초마다 통째로 저장하던 것을 바뀐 게 있을 때만 저장한다. 층 지도는 처음 한 번만 통째로 보내고 그 뒤엔 적·탐색 범위만 보낸다. 서버 재시작 뒤 시계가 몇 시간씩 건너뛰지 않는다. 그림 확인이 걷기를 막지 않는다. 신관 프로필을 쓸 수 없으면 신전으로 가지 않는다. 남쪽 문까지 걷는 시간 한도를 5분으로 늘렸다. DM 하루 한도는 실제로 만든 층만 세고 마을 날짜를 쓴다. 열리지 않은 층에는 의뢰를 걸 수 없다. 오래된 의뢰 요청 기록은 30일 뒤 지운다.

전투 판단 모델은 CoNAI 호스트의 플러그인 LLM `model: 'judge'`를 쓴다. 이 호스트 변경이 들어간 백엔드에서만 판단 모델로 간다. 그 전에는 위 안내대로 각자 프로필로 고른다. 어시스턴트 `rpg_prepare`에 `combatModel`(judge/self/profile), `combatProfileId`, `combatDaily`, `judgeModel`(profile/judge)이 추가됐다.

## 3.5: 강변 마을, 시간, 신탁

- **더 큰 마을**: 지도가 52×30칸 강변 마을로 바뀌었다. 북쪽 길에는 모험가 길드·잡화점·여관이 있고, 강 건너에는 신전·작은 서가가 있다. 가운데에 느린 찻집, 곳곳에 집이 있다. 강은 다리 세 개로 건넌다. 길드·잡화점·신전 건물을 누르면 의뢰·상점·모험 정보가 열린다.
- **시간**(설정 › 이야기): 마을에 시계가 생겼다. 하루 길이는 실제 4–240분 중에서 고른다(기본 24분). 시계는 마을이 깨어 있을 때만 간다. 아침·낮·저녁·밤에 따라 지도와 방송 화면의 색이 바뀌고, 저녁부터는 창문과 가로등이 켜진다. 대화 요청에 지금 시각이 들어간다.
- **잠**: 밤을 **잠자기**로 두면 주민은 밤 10시쯤(사람마다 조금씩 다름) 여관에 가서 자고 아침 6시쯤 여관 앞에서 일어난다. 자는 동안은 대화 요청이 없다. 여관 아래에 자는 주민 이름이 보인다. 아침마다 "N일째 아침이 밝았어"가 소식에 남는다. 원정 중인 주민은 원정을 마치고 돌아온 뒤 잔다.
- **걸어서 오가는 원정**: 출정한 모험가는 남쪽 문까지 걸어간 뒤 던전에 들어간다. 돌아오면 남쪽 문에서 광장까지 걸어온다. 사망 후 부활하면 신전 앞에서 시작한다.
- **신관과 신탁**: 역할에 **신관**이 추가됐다(한 명만). 직업 선택은 설정에서 뺐다. 모험가는 신탁을 받지 않았거나 랭크가 올랐을 때 신전으로 걸어가고, 도착하면 신관 프로필이 직업 이름과 스킬(1–4개, 이름·설명 텍스트)을 내려 준다. 직업과 스킬은 텍스트일 뿐 제약이 없다. 내부 전투 계열(전사·궁수·마법사)은 신관이 함께 골라 수치 계산에만 쓴다. 신탁 대사는 마을 대화·말풍선·기억에 남고, 모험 정보에 "신탁 · 직업"과 스킬이 보인다. 신탁 요청이 실패하면 10분 뒤 다시 간다.
- **턴마다 고르는 전투**(설정 › 모험 › 전투 AI): 전투 턴마다 모험가 자신의 프로필이 공격·스킬(받은 스킬 이름)·방어·물약·후퇴 중 하나와 짧은 외침을 고른다. **매 턴**(기본) / **수호자만** / **끔** 중에서 고른다. 답이 **전투 AI 대기**(5–60초, 기본 20초) 안에 오지 않거나 실패하면 그 턴은 규칙대로 진행한다. 피해 계산은 그대로 서버 규칙이다. 방송에는 고르는 동안 "…" 말풍선, 쓴 스킬 이름, 외침이 보인다. 매 턴을 켜면 전투 한 턴마다 모델 호출이 1회 생긴다.
- **귀환 후 휴식**(설정 › 모험): 원정에서 돌아온 뒤 마을에서 쉬는 시간을 10–900초로 정한다(기본 60초).
- **층 지도 전송 줄이기**: 페이지가 가진 층 지도의 해시를 함께 보내면, 서버는 바뀌지 않은 지도를 응답에서 뺀다.

어시스턴트의 `prepare`에 `dayMinutes`·`sleep`, `rpg_prepare`에 `restSeconds`·`combatAi`·`combatWait`가 추가됐다. 역할에는 `oracle`이 추가됐고 `job`은 없어졌다. 지도 버전이 3으로 올라 기존 주민 위치는 새 지도에 맞춰 다시 놓인다.

## 3.4.1: 움직임과 속도 설정

- **이어지는 걸음**: 페이지는 1초마다 상태를 받는다. 그 사이에도 던전 탐험가는 지나온 칸을 따라, 마을 주민은 서버가 정한 경로를 따라 계속 걷는다. 방송은 게임보다 약 1초 늦게 보여 준다. 다시보기도 기록 사이를 이어서 걷는다.
- **멈추지 않는 화면**: 방송 화면이 계속 그려진다. 횃불이 흔들리고, 적은 숨 쉬듯 움직이고, 걷는 캐릭터는 통통 튄다. 공격할 때는 달려드는 동작, 맞을 때는 흔들림과 받은 피해 숫자가 나온다. 미니 플레이어만 떠 있으면 더 적게 그린다.
- **모험 속도 설정**(설정 › 모험): 탐험 한 칸 간격 500–3000ms(기본 1000), 전투 한 턴 간격 500–6000ms(기본 2000). 던전 입장은 탐험 다섯 칸만큼 걸린다. 빠르게 하면 원정이 빨리 끝나서 원정 결정용 모델 호출이 더 자주 생긴다.
- **마을 설정**(설정 › 이야기): 걷는 속도 0.5–4칸/초(기본 1.1), 쉬는 주민 어슬렁/가만히(기본 어슬렁). 어슬렁을 켜면 할 일이 없는 차례에 근처 몇 칸을 걷는다. 모델 호출과 도착 알림은 없다.

## 3.4: 마을에서 여는 팝업과 주민 방송

모험 화면을 별도 탭에서 마을 위 팝업으로 옮겼다. 어항을 열면 항상 마을이 먼저 보인다.

- **진입점**: 주민을 누르면 작은 카드(방송 보기·기억·모험 정보)가 열린다. 길드 건물을 누르면 의뢰, 상점을 누르면 상점, 마을 남쪽 던전 입구를 누르면 방송 채널 목록이 열린다. 상단의 TV 버튼과 숫자는 지금 던전 LIVE 중인 주민 수다.
- **방송**: 주민 한 명이 채널 하나다. 던전에 있는 주민은 **LIVE**, 마을에 있는 주민은 **생활 방송**, 자는 주민은 방송 꺼짐이다. **채널 목록**(전체/던전/생활)에서 고르면 **시청 화면**으로 들어간다. 시청 화면은 플레이어, 방송 제목, 따라가기/전체 보기, 다른 방송 목록, 채팅으로 구성된다. 채팅에는 그 주민의 던전 기록과 그 주민이 말했거나 들었거나 이름이 언급된 마을 대화가 표시된다. 방송을 닫아도 LIVE가 있으면 오른쪽 아래에 미니 플레이어가 남는다. 미니 플레이어는 닫을 수 있고, 새 원정이 시작되면 다시 뜬다.
- **방송 제목**: 원정 결정 응답에 `title`(40자 이내)이 추가됐다. 비어 있으면 층·의뢰 이름으로 제목을 만든다.
- **길드 팝업**: 층 칩 아래에 의뢰/던전/상점 텍스트 탭을 둔다. 의뢰는 한 줄에 하나씩 보여 주고, 담당자·진행·보상·방송 버튼을 표시한다. 운영 설정은 설정 메뉴의 **모험** 탭으로 옮겼다.
- **방송 채팅**: 시청 화면 아래 입력창으로 방송 중인 주민에게 한마디 남긴다. 그 주민이 자기 프로필로 한 번 답한다(채팅 1줄 = 모델 호출 1회). 답장 대기는 최대 3줄이고 4초 간격 제한이 있다. 마을이 깨어 있을 때만 쓸 수 있다. 주고받은 내용은 그 주민의 기억에만 남는다.
- **주민 반응**: 던전에서 사망·층 공략·의뢰 완료·승급·전리품·출발 같은 장면이 나오면, 마을에 있는 주민 한 명(원정 중·근무 중·대화 중 제외)이 방송 채팅에 한 문장 반응을 남기고 말풍선도 띄운다. 반응은 3분에 최대 한 번이다. 마을 대화에는 지금 생중계 중인 장면 한 줄이 함께 들어가서, 추가 호출 없이도 방송 이야기가 나올 수 있다.
- **다시보기**: 영상 녹화가 아니라 게임 리플레이다. 원정마다 시작 시점의 층 정보 한 번과, 움직이거나 싸우거나 상태가 바뀔 때마다 작은 프레임(위치·HP/MP·적 HP·새로 본 칸)과 그 주민의 기록 줄만 남긴다. 원정이 끝날 때 한 줄로 저장하고 계정마다 최근 30개만 둔다. 채널 목록의 **다시보기** 탭에서 고르면 같은 던전 화면으로 재생한다. 재생/일시정지, 위치 이동, 1·2·4·8배속을 지원한다. 서버가 재시작되면 진행 중이던 원정은 재시작 시점부터 기록된다.
- **마을 생활 유지**: 모험 모드에서도 원정 중인 주민(던전 이동·탐험·전투·귀환·부활 대기)만 마을에서 빠진다. 나머지는 계속 산책하고 대화한다. 길드 접수원·상점 주인은 자리를 지킨다. 그래서 모험 모드에서도 마을 대화용 모델 호출이 생긴다.

## 3.3: 길드 화면과 던전 방송

자율 모험이 켜져 있으면 어항을 열 때 **던전 방송**이 먼저 표시된다. 관전 화면을 여는 것만으로 게임을 시작하거나 모델을 호출하지 않는다. 화면 위 **진행 시작/일시정지**는 기존 서버 실행 경로를 사용하며, 자율 모험을 껐을 때는 운영 설정에서 먼저 켠다.

- **방송**: 자동 관전 또는 특정 봇을 선택하고, 봇 따라가기/층 전체 보기를 전환한다. 현재 층·테마·HP/MP·적 HP·퀘스트 진행과 최근 소식을 함께 표시한다. 같은 층의 이동은 짧게 보간하고 실제 전투 결과의 피해 수치를 표시한다. **집중 화면**은 메뉴와 정보 패널을 접는다. 선택한 봇이 귀환하면 길드 대기로 전환하며 정지 상태를 LIVE로 표시하지 않는다. 화면/탭이 숨겨지면 그리기와 애니메이션을 멈춘다. 외부 서비스에 송출하는 기능이 아니라 어항 안의 관전 화면이다.
- **봇 정보**: 마을의 주민을 누르거나 상단 **봇 정보**로 연다. **상태 / 장비·가방 / 원정 기록**을 분리했다. 가방 항목을 펼치면 장비 수치를 확인하고, 폴링 중에도 펼친 항목과 선택 탭을 유지한다. 원정 중인 봇은 **이 봇 관전하기**, **퀘스트 현황**으로 바로 이동한다.
- **퀘스트**: 진행·모집/진행 중/모집 중/완료·취소/전체 필터와 진행 막대를 제공한다. 담당 봇 정보·실시간 관전·던전 지도로 바로 이동한다. **+ 의뢰하기**를 누르면 입력 영역을 열고, 등록 후 진행 목록으로 돌아온다. 모바일에서는 긴 목록 아래로 입력 폼이 밀리지 않도록 작성 화면을 따로 보여준다. 기존 의뢰 취소 제한과 보상 규칙은 유지한다.
- **옵션**: 마을 캐릭터 레이어와 이야기 폼에 중복 사용하던 CSS 클래스를 분리했다. 주민·지시문·이야기 탭은 설정 내용과 겹치지 않는다. 길드는 데스크톱의 고정 메뉴와 모바일의 2행 메뉴로 현재 화면을 구분한다. **주민 설정**과 **운영 설정**을 별도로 표시하며, 진행 중 설정 초안과 포커스를 보존한다.

어시스턴트의 `rpg_open`에 `live` 탭을 추가했고, `watch`의 `profileId`로 특정 봇을 관전한다(0/생략은 자동). 상태에 현재 탭·가방/기록 선택·관전 대상·카메라·퀘스트 필터가 포함된다. UI 변경만이며 기존 캐릭터·던전·의뢰 저장 형식은 바꾸지 않는다.

## 3.2: 원정 준비와 탐험 의뢰

- **원정 기억·재도전**: 캐릭터별 최근 6회 원정의 층·결과·피해·처치·물약·목표 진행과 철수 이유를 보관한다. 출정·중간 판단에 이 기록을 전달한다. 사망·안전 철수·성과 없는 원정은 같은 층 재도전을 1분부터 최대 30분까지 점진적으로 늦춘다. 능력치 전력이 10% 넘게 좋아지면 대기를 해제한다. 완전히 회복된 상태에서 반복 휴식을 고르면 호출 간격도 최대 10분까지 늘린다. 적·유물이 고갈된 층은 해당 의뢰 후보에서 제외하고 재배치 가능할 때 다시 연다.
- **판단 자료**: 발견한 적과 현재 HP/MP에 더해 회복약, 귀환 거리, 일반 공격 기준 예상 전투 턴·피해·남을 HP를 전달한다. 계산은 스킬·치명타를 제외한 근사치이며 모델이 성공을 보장하는 수치가 아니다. 실제 판정과 피해는 서버 전투 규칙을 따른다.
- **길드 상점**: 출정 전 자동 보급은 기본 켜짐이며 설정/어시스턴트 초안에서 끌 수 있다. 주민이 `save`(보급 생략), `balanced`(소지금 40% 이내), `stock`(60% 이내)을 고른다. 추가 상한은 `60 + 레벨×30` 골드다. 장착품을 보존하며 같은 장비의 여분만 매입가의 1/4로 팔고, 회복약 12G·마나약 10G를 보충한 뒤 예산이 남으면 더 좋은 장비 하나를 산다. 상점 장비는 기본 장비와 공략된 층의 드롭 장비다. 장비 평가는 전사의 방어·HP, 궁수·마법사의 공격 비중을 달리한다. 사용자에게 구매 조작을 요구하지 않는다.
- **물약**: 일반 보급은 회복약 2개·마나약 1개(마법사 3개), 충분한 보급은 각각 3개까지 준비한다. HP 45% 이하에서 최대 HP의 45%를 회복하고, MP 4 미만에서는 12를 회복한다. 전투 중 사용하면 그 턴의 공격을 대신하며 적은 정상적으로 행동한다. 소모품은 장비 가방과 별도로 주민 화면에 표시한다.
- **새 의뢰**: `hunt` 토벌 1~20, `clear` 수호자 처치 1, `explore` 지도 탐사 20~100%, `survey` 지하 기록실 조사 1, `recover` 유물 회수 1~3을 등록한다. 종류와 목표는 화면·서버·어시스턴트 계약이 같다. 탐사율은 해당 의뢰를 맡고 직접 확인한 범위를 누적하며 이전 개인 지도만으로 즉시 완료되지 않는다. 기록실은 해당 위치를 방문하고, 유물은 지도상의 물건을 직접 회수한다. 적 처치는 탐사·조사·회수 진행도를 올리지 않는다. 수호자 의뢰는 담당 주민의 실제 처치로 완료되며, 다른 주민의 공략이나 기존 공략 기록만으로 보상을 지급하지 않는다. 모든 보상은 귀환 시 한 번 정산한다.
- **실패와 공유**: 자발적 귀환은 의뢰 진행을 보존한다. 사망은 진행을 초기화하고 회수 중인 유물 예약을 지도에 반환한다. 같은 유물은 한 주민만 회수할 수 있다. 공략된 층의 길드 의뢰는 토벌·탐사·조사·회수를 순환한다. 수행 가능한 사용자 의뢰가 있으면 출정 모델에는 그 의뢰들을 우선 후보로 제공한다. 길드 → 의뢰에서 종류를 고르고 목표 수/탐색률을 입력한다.
- **수호자 패턴**: `charge`는 강공격을 한 턴 예고한 뒤 공격하며 균형·신중 전술은 공격력을 줄여 방어한다. `guard`는 주기적으로 받는 피해를 줄인다. `mend`는 체력이 낮을 때 최대 3번 회복한다. DM이 다음 층의 패턴을 고르며 서버가 허용된 유형만 적용한다. 주민 전투 화면에 다음 적 행동을 표시한다.
- **업데이트**: 기존 v2의 지형·시드·위치·원정·자산을 유지하고 빈 위치에 기록실과 유물 세 개를 추가한다. 진행 중 교전의 기존 일반 행동은 유지한다. 새 소모품은 0개부터 시작하고 출정 전까지 구매하지 않는다. 기존 의뢰 요청 ID와 토벌 기본값은 호환된다. 원정 기억은 갱신 이후부터 쌓이며 과거 상세 피해를 소급 추정하지 않는다.

상점은 관찰용 탭이며 `rpg_open`의 `tab: shop`으로도 연다. `commission`에 `type`과 종류별 `count`를 지정하고, `rpg_prepare.settings.autoSupply`로 자동 보급 초안을 작성한다. 저장·비용·보상은 동일한 서버 트랜잭션 경로를 사용한다. 파티 전투, 제작·강화와 메인의 기본 판단 엔진 직접 연결은 아직 후속 범위다.

## 3.1: 시드 기반 던전 탐험

사용자는 주민을 직접 조작하지 않고 탐험을 관찰하거나 길드에 의뢰를 맡긴다. **길드 → 설정 → 자율 모험**을 적용하고 **마을 깨우기**로 시작한다. 기본값은 꺼짐이다. 전투는 던전 안에서만 발생한다. 서버에서 진행하므로 화면을 닫아도 계속된다.

- **층과 지도**: 새 월드는 1층부터 시작한다. 층 최초 진입 때 저장된 시드·설계로 방과 미로 통로를 생성한다. 작은/중간/큰 층은 각각 15×15, 19×19, 23×23이다. 모든 목표의 연결성을 검사하고 생성기 버전과 확정된 지도를 저장한다. 같은 층은 주민 모두가 공유하며 재접속·재입장으로 지형이 바뀌지 않는다.
- **탐험**: 주민마다 발견 범위를 저장한다. 시야는 통로를 따라 최대 3칸이며 벽을 통과하지 않는다. 발견한 지점과 미탐색 경계를 기준으로 이동하고, 적을 만나면 1:1 전투를 시작한다. 보물상자·일회용 쉼터·함정·수호자·계단이 배치된다. 길드 발견 지도는 주민의 발견 범위를 합친 것이며 개별 AI에는 자기 정보만 전달한다.
- **전투와 귀환**: 약 1초마다 한 칸 이동하고, 전투는 2초마다 공격·스킬·치명타·회피를 계산한다. 같은 적은 한 주민만 교전할 수 있고 HP·처치·보상은 트랜잭션으로 확정한다. 귀환은 발견한 경로를 따라 출구까지 이동한다. 귀환 중에는 재교전하지 않는다. 사망·제거·철수 시 교전 점유를 해제한다. 현재는 개별 원정이며 파티·도발·직업별 명명된 스킬은 없다.
- **중간 판단**: 설정에서 판단용 기존 프로필을 선택하면 수호자 진입과 저체력 시 `continue`/`return`을 결정한다. 원정당 각 조건 1회, 최대 2회다. 응답 대기는 최대 150초이며 실패·시간 초과·사용 불가 시 귀환한다. 응답은 질문 ID와 현재 원정 상태를 확인한 뒤 적용해 늦은 응답으로 귀환을 뒤집지 않는다. 미선택 시 규칙으로 탐험·철수한다. 출발 목적지·의뢰·전술은 주민 프로필이 선택한다. 프로필 실행에는 모델 사용량이 발생한다.
- **공략과 DM**: 수호자 처치가 층 공략 조건이다. 다음 층은 앞 층 공략 후 개방된다. DM은 공략한 마지막 층의 탐색량·이동·피해·사망·후퇴 기록을 보고 다음 층의 테마·규모·구조(미로/방/순환 통로), 일반 적 수 3~10, 몬스터와 장비를 설계한다. 서버는 수치·전력 예산과 행동 유형을 검증하고 수호자 1마리를 추가한다(기본 몬스터 HP 1.5배, 공격 1.15배). DM은 각 층에서 한 번만 확장하며 이미 만들어진 지도는 수정하지 않는다. DM 미선택·실패·한도 도달 시 현재 층에서 계속 활동할 수 있다. 기본 최대 12층(상한 30), UTC 날짜별 DM 요청 3회(상한 10, 실패 포함)다.
- **재탐험**: 공략 전에는 적 피해·상자·쉼터 사용 상태가 유지된다. 공략된 층은 공략/이전 재배치 후 60초가 지났고 아무도 원정 중이지 않을 때 다음 입장에 조우 요소를 다시 배치한다. 위치·지형·발견 지도·공략 완료는 유지하고 적 HP와 상자·쉼터·함정만 초기화한다. 덕분에 공략 후에도 토벌과 성장을 이어갈 수 있다.
- **의뢰와 성장**: 길드는 미공략 층의 수호자 의뢰, 공략된 층의 토벌 의뢰를 공급한다. 사용자는 층·의뢰 종류·목표·제목·내용을 지정한다. 보상은 서버가 정하며 가상 골드다. 귀환해야 완료 보상을 지급한다. 미완료 상태로 자발적으로 귀환하면 토벌 진행을 보존해 다시 맡을 수 있고, 사망하면 진행을 초기화한다. 모집 중인 사용자 의뢰는 취소할 수 있다. HP/MP/EXP, 전사·궁수·마법사, 레벨·F–S 랭크·소지금, 무기·방어구·장신구, 30칸 인벤토리를 사용한다. 장비는 귀환 때 자동 착용하고 가방이 가득 차면 새 전리품을 골드로 환산한다.
- **사망과 NPC**: 기본값은 현재 레벨 경험치·소지금 각각 10% 손실, 10% 확률로 착용 장비 1개 소실, 60초 후 부활이다. 비율·대기는 설정할 수 있다. 접수원·상인 역할은 마을에 고정된다. 상점 보급은 출정 준비에서 자동으로 처리한다.
- **관찰**: 길드의 **던전** 탭에서 층과 길드 발견 범위/선택 주민 시야/전체 지도를 고른다. 주민 탭의 **탐험 보기**도 현재 층을 연다. 숫자는 주민, ×는 적, ◆는 수호자다. 지도·짧은 최근 기록과 기존 스테이터스 화면으로 진행을 확인한다. 전체 지도 관찰이 AI에게 숨은 정보를 전달하지는 않는다.
- **이미지**: 층 이미지 생성을 켜면 기존 NovelAI/ComfyUI 그림 설정·생성 큐·라이브러리 그룹 `AI 어항`으로 풍경을 생성한다. 지형은 코드가 만들며 이미지 생성 성공 여부와 무관하게 탐험한다.

3.0 저장은 처음 읽을 때 v2 던전 상태로 전환한다. 캐릭터 UUID·레벨·장비·돈·경험치·의뢰와 진행 수를 보존하고, 진행 중이던 구형 원정은 보상 없이 귀환시킨다. 기존 지역 ID는 보존하며 레벨 순으로 층을 연결하고 수호자 공략을 새로 시작한다. 구형 DM/출정 응답은 폐기하고 확인 가능한 실행은 다음 서버 진행에서 취소한다. 기존 누적 처치 확장 설정은 제거한다.

상태는 계정별 SQLite `rpg_worlds`, 의뢰 멱등 키는 `rpg_commands`에 저장한다. 활성 주민 최대 6명·보관 캐릭터 60명, RPG AI 동시 실행 1개, 미완료 의뢰 20개·완료 의뢰 최근 20개·로그 최근 60개를 유지한다. 캐릭터를 뺐다가 같은 프로필로 초대해도 성장·장비·개인 탐험 지식을 유지한다. AI/생성 요청 ID를 먼저 저장해 재조회하며 마을 재우기는 진행과 신규 호출을 멈춘다. 연속 AI 실패 3회 시 새 요청을 멈추고 **AI 재시도**로 해제한다.

어시스턴트는 `rpg_open`의 `tab: zones, zoneId`로 관찰 층을 선택하고, 상태에서 층별 발견량·공략·개방과 주민 위치를 확인한다. `commission`, `commission_cancel`, `rpg_prepare`는 초안만 작성하며 사람이 등록/취소/설정을 적용한다. MCP `inspect`도 같은 상태를 조회한다.

**연결 범위:** 어항 플러그인만 변경한다. 중간 판단은 선택한 기존 프로필의 `mode: text` 실행이다. 호스트 TypeSafe/기본 판단 모델을 직접 호출하려면 별도 메인 API 연결이 필요하다. 파티, 층간 직접 하강, 열쇠·잠긴 문·비밀 방, 몬스터 순찰·다양한 행동 패턴, 수동 거래·제작·강화는 아직 없다. 다음 층에는 귀환 후 새 원정으로 진입한다.

## 2.2: 어항 전용 추가 지시문

**마을 꾸리기 → 지시문**에서 초대한 주민을 고르고 역할·말투·행동 규칙을 최대 2,000자로 적은 뒤 **적용**한다. 기존 프로필의 성격·시스템 지시문·작가 노트에 추가되는 설정이며 원본 프로필이나 다른 채팅을 수정하지 않는다. 충돌하는 원본 지시문을 대체하는 기능은 아니다. 엔진·모델은 기존 프로필을 따르며, 이번 변경에 Pi 실행 경로 확장은 포함되지 않는다.

지시문은 해당 계정의 마을에 주민별로 저장되며 그 주민의 새 대화 요청과 기억 요약 요청에만 전달된다. 이미 실행 중인 요청은 기존 입력으로 마무리된다. 빈 내용으로 적용하면 추가 지시문을 지운다. 주민을 빼고 적용하면 그 주민의 추가 지시문도 제거된다. 기존 저장 데이터의 주민은 추가 지시문 없이 그대로 동작한다.

어시스턴트도 `ai-aquarium.prepare`의 `residentInstructions: [{ profileId, instructions }]`로 선택된 주민의 지시문 초안을 편집할 수 있다. 지정하지 않은 주민의 지시문은 유지하며 저장은 사람이 **적용**으로 진행한다. 다른 창에서 설정이 바뀌면 오래된 초안의 적용을 거절한다. 필요한 초안을 복사하고 **취소** 후 다시 열어 최신 설정에서 편집한다.

## 2.1: 주민별 기억과 행동

주민의 한 마디는 `conai.llm.start({ mode: 'text', structuredOutput })` 한 번이다. 프로필의 시스템 프롬프트·로어북·작가 노트는 그대로 적용되고, **채팅방은 만들지 않는다**. 답은 `{ say, action }` JSON이다. `say`는 마을 대화가 되고, `action`이 `draw`면 플러그인이 직접 그림을 접수한다. 모델이 JSON을 무시하고 글로만 답하면 그 글을 대사로 쓴다.

**기억은 주민마다 따로다.** 대화 한 줄은 말한 주민과 들은 주민의 기억에 들어가고, 말한 주민 4칸 안에 있던 주민에게는 "(근처에서 들림)"으로 들어간다. 멀리 있던 주민은 모른다. 3.8부터 요약 + 최근 16줄에 세계관·관련 장기 로어를 함께 전달하며, 오래된 줄에서는 독립적인 장기 기억을 추출한다. 상세 규칙과 보관 상한은 위의 3.8 설명을 따른다. 월드 채팅의 닉네임 메뉴 → **기억 보기**에서 조회한다.

예전 버전이 만든 프로필별 자동화 채팅방은 더 이상 쓰지 않는다. 채팅 목록에서 지워도 된다.
