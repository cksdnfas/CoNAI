# HyperFrames 영상 제작 — hyperframes

공식 번들 플러그인이다. CoNAI 내부 이미지·영상·오디오를 참조해 HyperFrames 영상을 만든다.

## 설치

1. 설정 → 플러그인에서 공식 **HyperFrames 영상 제작**을 켠다. 앱 빌드에 포함되어 꺼진 채 설치되고 앱 업데이트로 제자리 갱신된다. 같은 ID의 개인 패키지 1.x를 ZIP으로 설치해 둔 인스턴스는 제거하지 않는다. 공식 패키지가 그 자리를 갱신하며 켜짐 상태와 데이터(프로젝트 목록·출력 이력·임시 초안)를 유지한다. 이후 ZIP/Git 덮어쓰기·제거는 허용되지 않는다. 빌드 전의 호스트에 시험 설치하려면 `node scripts/build-plugin.mjs hyperframes`로 `build-output/plugins/hyperframes.zip`을 만든다. 실시간 미리보기는 `api.preview`가 있는 CoNAI 호스트가 필요하다. 이전 호스트에서는 출력 플레이어만 나온다. AI 제작은 연결한 프로필의 출력 예산·도구 설정을 그대로 사용하며 플러그인은 토큰·시간 제한을 따로 두지 않는다(완료하거나 취소할 때까지 실행). 생략한 `maxTokens`를 프로필 예산으로, 생략한 `timeoutMs`를 제한 없음으로 처리하는 호스트가 필요하다. 이전 호스트는 생략한 값을 512 토큰·120초로 제한할 수 있다.
2. 확장 → HyperFrames 영상 제작을 연다. 편집과 실시간 미리보기는 렌더러 없이 된다. MP4로 출력하려면 상단 렌더러 배지(또는 출력 버튼)로 렌더러 상태를 열고, 관리자 계정이면 **렌더러 설치**를 누른다. `@hyperframes/producer@0.8.163`을 npm으로 플러그인 데이터 폴더(`renderer/0.8.163`)에 내려받으며 네트워크와 `npm`이 필요하다. 창을 닫아도 계속된다. 플러그인을 끄거나 업데이트해도 이미 시작한 npm 프로세스는 따로 끝나며, 그 결과는 설치로 인정하지 않으므로 다시 설치한다.

렌더러는 별도 컨테이너 없이 CoNAI가 실행되는 곳에서 Node 자식 프로세스로 돈다. Docker 연결(`docker.sock`)은 필요 없다. 필요한 것은 세 가지다.

- **Chromium**: CoNAI Docker 이미지에 `/usr/bin/chromium`과 한글·이모지 폰트가 들어 있다(이 버전부터라 이미지를 새로 빌드해야 한다). 직접 실행할 때는 설치된 Chrome 또는 Edge를 자동으로 찾고, `PUPPETEER_EXECUTABLE_PATH`로 경로를 지정할 수 있다.
- **FFmpeg**: PATH의 `ffmpeg`·`ffprobe`를 쓴다(Docker 이미지에 포함). 다른 위치면 `HYPERFRAMES_FFMPEG_PATH`·`HYPERFRAMES_FFPROBE_PATH`로 지정한다.
- **Node**: CoNAI를 실행한 Node를 쓴다. 단일 실행 파일로 실행 중이면 PATH의 `node`를 쓴다.

**격리가 없다.** 1.3.x의 네트워크 없는 읽기 전용 컨테이너와 CPU·메모리 상한이 사라졌다. 영상 HTML은 CoNAI와 같은 계정·네트워크의 Chromium(`--no-sandbox`)에서 실행된다. 렌더러 프로세스에는 CoNAI 환경 변수를 넘기지 않고 소재 복사본만 있는 작업 폴더를 주지만, 운영체제 수준에서 다른 파일·네트워크 접근을 막지는 않는다. AI나 타인이 만든 HTML을 그대로 출력할 때 이 점을 감안한다.

`installer.mjs`의 `VERSION`을 올리면 새 버전을 다시 설치해야 하고 이전 버전 폴더는 설치할 때 지운다.

## 화면

1.5.0에서 화면을 다시 구성했다(기준 목업: `design/mockups/hyperframes-studio/index.html`).

- **상단 한 줄**: ☰ 프로젝트 서랍(목록, 이 프로젝트의 상태·파일함·저장본 다시 열기·복사본으로 저장), 제목, 저장 상태, `편집`/`결과 보기`, 렌더러 상태(누르면 설치·상태 대화상자), 실행 취소(Ctrl+Z, 최근 50단계), 저장(Ctrl+S), `영상 출력`(초안 화질 / 최종 화질). 안내는 화면을 밀지 않는 알림으로 뜬다.
- **시작 화면**: 손대지 않은 새 프로젝트에서 소재를 담고 한 줄로 설명해 `초안 만들기`(AI 실행), `빈 영상으로 시작`, `HTML 붙여넣기`, 최근 프로젝트 중에서 고른다.
- **왼쪽 소재**: 위쪽 "이 영상의 소재"에 담은 소재의 이름(바꿀 수 있고 프로젝트에 `label`로 저장), 종류, 쓰이는 곳(장면 번호·배경 음악·미사용)이 나온다. 아래는 라이브러리·파일함·장면 설명 검색이고 썸네일을 누르면 담거나 뺀다.
- **가운데**: 실시간 미리보기(재생·일시정지(Space)·탐색·소리)와 타임라인이 항상 보인다. 타임라인에서 장면을 고르고 끌어서 순서를 바꾼다.
- **오른쪽 패널**
  - `AI 지시`: 대화와 입력창. 범위(전체 영상 / 고른 장면 / 표시한 시점)를 고르고 `＠ 소재 넣기`로 소재를 이름으로 가리킨다. 실행 뒤에는 바뀐 내용 목록과 `이 변경 되돌리기`가 나온다.
  - `조정`: 고른 장면의 길이·움직임·전환·자막·자막 위치, 영상 전체의 화면·프레임·자막 크기·자막 색·음악 볼륨, 그리고 프로젝트의 `controls`마다 슬라이더·스위치·색 하나씩("AI가 만든 조정 항목"). HTML이 장면에서 만든 그대로일 때만 장면·스타일 값이 바로 반영되고, 직접 고친 HTML이면 안내와 두 번 누르는 `장면으로 다시 구성`이 나온다.
  - `HTML`: 영상 HTML 직접 편집.
- **결과 보기**: 출력본을 미리보기 자리에서 재생하고, 이 프로젝트의 내 출력(진행 중인 작업 포함)이 버전 띠로 나온다. `이 시점 표시`로 남긴 표시는 다음 AI 지시의 범위로 쓸 수 있고 화면을 닫으면 사라진다.
- **좁은 화면**: 1200px 미만은 소재가 오른쪽 패널의 첫 탭으로 들어가고, 900px 미만은 한 열에 미리보기와 타임라인·소재·AI 지시·조정·HTML 탭이 나온다.

장면에는 `motion`(zoom-in 기본, zoom-out, pan-left, pan-right, none), `transition`(앞 장면에서 넘어오는 교차 전환 0~2초), `captionPosition`(center 기본, top, bottom)을 둘 수 있고, `style`은 `captionSize`(짧은 변의 %, 3~25)·`accent`·`musicVolume`이다. `controls`는 12개까지이며 각 항목은 HTML의 CSS 변수 `--<id>`다. 저장할 때 현재 값이 HTML의 `<style id="hf-controls">` 블록에 들어간다. 옵션을 쓰지 않은 프로젝트의 HTML은 이전 버전과 같다.

장면(`scenes`)은 프로젝트 JSON에 저장되는 스토리보드다. HTML이 장면에서 만든 그대로면 장면을 고칠 때 HTML도 자동으로 다시 만든다. HTML을 직접(또는 AI가) 고친 뒤에는 자동으로 덮어쓰지 않고 `장면으로 다시 구성`을 두 번 눌러야 덮어쓴다.

## 제작

내부 소재 검색에서 이미지·영상의 프롬프트로 찾고 선택한다. AI는 기존 검색 도구의 그룹 필터도 사용할 수 있다. 장면 설명 검색은 기존 이미지 임베딩 설정이 켜져 있어야 한다. 파일함 검색은 이름·추출된 본문을 검색하며 실제 이미지·영상·오디오만 선택한다. 장면 구성은 이미지에 느린 확대, 자막에 떠오르는 효과를 넣은 GSAP 영상을 만든다. 고급 편집은 HTML 탭을 사용한다.

AI 제작·수정은 선택한 CoNAI 프로필을 `mode: profile`로 실행한다. 기존 도구 카탈로그·기능 권한·검토 카드를 공유한다. 프로필에 `search_images`, 필요에 따라 `search_images_by_tags`/`search_images_by_meaning`/`search_files`, `view_images`/`view_media_frames`, 그리고 `p_hyperframes_*` 도구가 허용되어 있어야 한다. 프로필의 이미지·영상 이해 능력과 임베딩 설치 상태는 기존 앱 설정에 따른다. 새 LLM 키나 별도 에이전트 루프를 만들지 않는다.

예시: “내부 라이브러리에서 바다 영상과 해변 이미지를 찾아 20초 여행 소개 영상을 만들어줘. 제목은 여름의 기록.” AI는 검색한 실제 ID를 `inspect_assets`로 확인하고 선택한 원본을 참조한다. 저장 시 원본 fingerprint와 상대 소재 경로를 기록한다. 임시 URL·원본 절대 경로는 프로젝트와 AI 문맥에 저장하지 않는다. 필요하면 오디오 후보 ID도 같은 방식으로 연결한다.

프로젝트는 공유 파일함의 `HyperFrames-…json` 파일이다. 파일 ID·리비전을 유지하며 충돌 시 덮어쓰지 않는다. 기존 파일 편집기·파일 검색·채팅에서도 접근할 수 있다. 선택 소재의 원본이 바뀌면 렌더를 거절하므로 해당 소재를 다시 선택해서 저장한다. 외부 이미지 URL과 CDN에 의존하지 않는다(렌더러가 네트워크를 차단하지는 않지만 출력의 재현성을 보장하지 않는다). GSAP은 `vendor/gsap.min.js`를 쓴다. 한글 폰트 `Noto Sans CJK KR`은 CoNAI Docker 이미지에만 들어 있고, 직접 실행할 때는 그 PC에 설치된 폰트를 쓴다.

편집 결과는 실시간 미리보기에서 바로 확인한다. 브라우저가 렌더러와 같은 HyperFrames 런타임(`vendor/hyperframe.runtime.iife.js`)과 GSAP으로 HTML을 직접 재생하므로 저장·렌더가 필요 없다. 소재는 현재 계정 권한으로 원본을 바로 읽는다. 화면 크기에 맞춰 축소해 보여 주므로 프레임 단위 결과(코덱·화질)는 출력본으로 확인한다. 파일로 필요할 때 초안 출력(초안 화질 MP4) 또는 MP4 출력을 누른다. 초안은 `HyperFrames/미리보기`, 최종본은 `HyperFrames/완성` 그룹에 저장되고 기존 라이브러리에서 관리·삭제한다. 프로젝트 파일은 원본 소재 참조를 보관하고, 작업 결과는 사용한 참조·fingerprint·프로젝트 리비전을 반환한다.

## 프로젝트 저장·관리

- **프로젝트 관리**: 제목 검색, 제작 중·완료·보관 필터, 최근 변경순 20개 페이지 목록. 새로 저장하거나 다시 연 프로젝트를 목록에 등록한다. 기존 1.0.x 파일은 **기존 파일 찾기**로 검색해 한 번 열면 등록된다. 검색은 최대 50개이므로 필요한 제목을 함께 입력한다.
- **저장**: 제목·상태·소재·HTML을 같은 공유 파일 ID에 저장한다. 제목과 상태 변경도 저장해야 목록에 반영된다. `완료`는 사용자가 정한 제작 상태이며 렌더 성공 여부는 출력 이력에서 확인한다. 보관한 프로젝트는 기본 목록에서 숨기고 보관 필터에서 다시 열 수 있다.
- **복사 저장**: 현재 초안을 새 파일에 저장하고 연다. 제목에 `(복사본)`을 붙이고 제작 중 상태로 시작한다. 원본 저장본과 기존 출력 이력은 유지한다. 다른 창·AI와 저장 충돌이 난 초안을 별도 프로젝트로 보존할 때도 사용한다.
- **임시 초안**: 입력을 멈춘 뒤 약 0.8초 후 계정별 복구 슬롯 하나에 보관한다(64KiB). 다시 열면 복구 또는 버리기를 선택한다. 임시 보관은 명시적인 프로젝트 저장과 구분하며, 원래 파일 리비전을 유지해 다른 창이 저장한 내용을 덮어쓰지 않는다. 동시 탭이 복구 슬롯을 바꾸면 자동 보관을 멈추고 안내한다. 슬롯을 읽거나 쓰지 못한 경우와 마지막 보관 전 종료한 편집은 복구를 보장하지 않는다.
- **프로젝트 전환**: 미저장 초안이 있으면 저장 후 계속·초안 버리고 계속·계속 편집을 선택한다. 대기 중인 저장 검토나 AI 작업이 있으면 먼저 마친다. 저장 요청 중 추가한 편집은 초안으로 남는다.
- **내 출력 이력**: 프로젝트·계정별 최근 20개의 작업 ID, 출력 종류, 상태, 사용한 프로젝트 리비전과 라이브러리 영상 참조를 보관한다. 다시 열어 진행 중 작업의 상태를 조회하고 완성본을 라이브러리에서 연다. 이전 저장본의 결과에는 별도 표시가 붙는다. 화면 없는 MCP 출력도 같은 이력을 남긴다. 이력 한도를 넘겨 목록에서 빠진 영상도 라이브러리에는 남는다.
- **파일함에서 관리**: 현재 프로젝트 파일이 있는 폴더를 연다. 실제 파일 이름 변경·이동·삭제와 이전 텍스트 버전 조회·복원은 파일함에서 수행한다. 프로젝트 제목 변경은 JSON 내부 제목만 바꾸며 기존 파일 이름은 유지한다. 파일함에서 직접 편집한 내용은 다시 열 때 목록에 반영된다. 외부에서 삭제한 파일은 다시 열 때 네이티브 파일 없음 응답을 확인해 목록·출력 참조를 정리한다. 다음 목록 조회에 반영되며 라이브러리 영상은 삭제하지 않는다. 권한·네트워크·리비전 오류는 목록에서 지우지 않는다.

프로젝트 원문은 공유 파일함에만 두고, 플러그인 SQLite에는 검색용 제목·상태·파일 ID·리비전·시각과 출력 참조만 저장한다. 목록 조회도 기존 `files.view` 권한을 검사한다. 프로젝트 파일은 공용이며 임시 초안과 출력 작업 이력은 계정별이다. 목록·초안·출력 이력에는 미디어 원본이나 재생 URL을 복제하지 않는다. 계정당 복구 슬롯 하나와 프로젝트·계정당 출력 이력 20개로 보관량을 제한한다.

페이지 어시스턴트는 `hyperframes.projects/details/new/copy/restore_draft/history`와 기존 열기·저장 작업을 사용한다. 화면 없는 작업은 `p_hyperframes_list_projects`, `read_project`, `save_project`, `project_history`를 사용한다. 제목·상태 변경은 문서를 읽고 현재 리비전으로 저장하며, 복제는 새로운 요청 ID와 `fileId` 없는 저장을 사용한다. AI 저장 요청은 기존 호스트 검토 경계를 유지한다.

## 실행 범위

- 프로젝트 64KB, HTML 50,000자, 소재 24개, 개별 512MiB·전체 1.5GiB.
- 최대 1920×1080 상당 픽셀, 가로/세로/정사각, 24/30fps, 120초.
- 패키지당 렌더 1개, 실행 570초 상한(넘으면 프로세스 트리를 종료). CPU·메모리 상한은 없다. 복잡한 120초 영상의 완료 시간은 보장하지 않는다.
- 작업 폴더(`renders/<작업 ID>`)에 선택된 소재 복사본과 출력 폴더를 두고, 렌더러 임시 파일은 시스템 임시 폴더의 `hf-…`에 둔다(Chromium 소켓 경로 길이 제한 때문). 둘 다 작업이 끝나면 지운다. CoNAI DB·인증정보·환경 변수·전체 라이브러리는 전달하지 않는다.
- 정상·실패·취소 시 렌더러 프로세스 트리를 끝내고 작업 폴더를 정리한다. 플러그인이 꺼지면 렌더러는 닫힌 stdin을 보고 스스로 종료한다. 프로세스 강제 종료 시 남은 데이터는 다음 플러그인 활성화에서 정리한다. 원본 미디어는 변경하지 않는다.
- 완료한 작업의 재조회·동일 요청 ID 재시도는 다시 렌더하지 않는다. 재시작으로 중단된 작업은 자동 재실행하지 않는다.

## 검증

공용 호스트 경계: `npx tsx --test backend/test/plugin-server.test.ts backend/test/plugins.test.ts`.

플러그인 회귀: `npx tsx --test backend/test/plugin-hyperframes.test.ts backend/test/plugin-hyperframes-draft.test.mjs frontend/test/plugin-hyperframes-page.test.mjs`. 저장 충돌, 복제·보관, 페이지 조회·권한, 레거시 등록, 동시 탭 복구 슬롯 충돌, 저장 중 추가 편집 보존과 전환 취소를 검증한다.

PowerShell에서 `$env:HYPERFRAMES_RENDER_TEST='1'`로 실행하면 통합 테스트가 렌더러 설치·실제 렌더·라이브러리 저장·출력 이력의 계정 격리 및 플러그인 재시작 후 유지까지 검사한다. 렌더러 자체 회귀는 같은 환경에서 `node --test backend/test/plugin-hyperframes-render.test.mjs`로 실행한다(npm 설치, 소재 반영, 변경된 소재 거절, 진행 중 취소 후 작업 폴더 정리). 둘 다 네트워크, PATH의 `ffmpeg`·`ffprobe`, Chromium 계열 브라우저가 필요하다. 테스트는 별도 임시 DB/소재를 쓰며 실제 사용자 라이브러리나 외부 LLM을 호출하지 않는다. 1.4.0은 렌더러 회귀를 Windows(Chrome, Node 26)와 Linux 컨테이너(`node:24-bookworm-slim`에 Debian `chromium`·`ffmpeg`, root, init 사용)에서 실제 렌더 포함으로 수행했고, Linux에서는 취소 뒤 남은 Chromium 프로세스와 임시 폴더가 없음을 확인했다. 새로 빌드한 CoNAI Docker 이미지 자체에서의 설치·렌더, 실제 렌더 포함 통합 테스트, 플러그인 중지 시 렌더러 종료는 확인하지 않았다. 화면은 가짜 호스트 하네스에서 1440·1024·690·360px로 확인했으며 운영 브라우저 설치는 검증하지 않았다. 1.3.0 실시간 미리보기는 실제 백엔드 플러그인 라우트·CSP 아래(가짜 호스트 브리지)에서 Chromium으로 재생·탐색·장면 이동·편집 후 위치 유지·출력 전환·렌더러 없음·구형 호스트·412px를 확인했다. 소리 재생은 확인하지 않았다.

`vendor/hyperframe.runtime.iife.js`는 HyperFrames 0.8.163 런타임(Apache-2.0, 전문은 `vendor/HYPERFRAMES-LICENSE.txt`), `vendor/gsap.min.js`는 GSAP 3.15.0(GreenSock Standard License)이며 출력에도 이 파일을 그대로 쓴다. 렌더러 버전을 올리면 런타임 파일도 같은 버전의 `@hyperframes/producer` 패키지에서 다시 복사한다.

렌더 스크립트는 `renderer/render.mjs`에 있고 ZIP에 함께 들어간다.
