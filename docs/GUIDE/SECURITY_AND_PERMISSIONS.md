# 보안과 권한

CoNAI는 로컬 계정과 권한 그룹으로 페이지 접근과 주요 작업을 제한할 수 있습니다. 외부 접속이나 다중 사용자를 고려한다면 보안 탭을 먼저 정리하세요.

## 관련 페이지

| 목적 | 경로 |
| --- | --- |
| 로그인 | `/login` |
| 접근 가능한 페이지 확인 | `/access` |
| 보안 설정 | `/settings` → 보안 |
| 설정 전체 | `/settings` |

## 기본 개념

| 용어 | 설명 |
| --- | --- |
| 계정 | 로그인에 사용하는 로컬 사용자입니다. |
| 권한 그룹 | 페이지 접근과 작업 권한을 묶는 단위입니다. |
| 관리자 | 설정과 보안 관리 권한을 가진 계정입니다. |
| 게스트 | 제한된 권한으로 사용하는 계정입니다. |
| anonymous | 로그인하지 않은 공개 접근 상태입니다. |

## 로그인 흐름

1. `/login`으로 이동합니다.
2. 로컬 계정으로 로그인합니다.
3. 아직 계정이 없으면 초기 계정 설정 흐름 또는 설정 → 보안에서 첫 계정을 만듭니다.
4. 게스트 생성이 허용된 경우 게스트 계정을 만들 수 있습니다.
5. 로그인 후 `/access`에서 현재 계정이 열 수 있는 페이지를 확인합니다.

## 접근 페이지

`/access`는 현재 계정이 열 수 있는 페이지와 기능 범위를 보여줍니다.

표시 항목:

- 기본 페이지
- 파생 페이지
- 공개 워크플로우
- 계정 유형
- 항목 수

페이지가 보이지 않거나 메뉴가 사라진 경우 `/access`를 먼저 확인하면 권한 문제인지 빠르게 판단할 수 있습니다.

## 보안 탭에서 할 수 있는 일

| 영역 | 작업 |
| --- | --- |
| 인증 상태 | 현재 인증 사용 여부와 로그인 상태 확인 |
| 계정 폼 | 첫 계정 설정, 현재 계정명/비밀번호 변경 |
| 계정 목록 | 계정별 권한 그룹 지정, 비밀번호 변경, 계정 삭제 |
| 권한 그룹 | 그룹 생성/수정, 페이지 권한 설정, 멤버 관리 |
| 색상 | 권한 그룹 표시 색상 설정 |
| 복구 | auth DB 경로와 로컬 복구 정보 확인 |

## 권한 그룹 운영

권한 그룹은 페이지 접근과 주요 작업 권한을 묶습니다.

설정의 **페이지 접근**과 **기능 사용**은 독립적입니다. 홈 페이지를 꺼도 **이미지 조회 (`images.view`)**가 있으면 채팅, 그룹, 생성 결과, 월페이퍼에서 이미지 목록·썸네일·원본·뷰어 상세를 볼 수 있습니다. 반대로 이미지 페이지를 열 권한만으로 이미지를 조회하거나 편집·삭제할 수는 없습니다. 페이지 권한을 바꿔도 기능 권한은 바뀌지 않습니다.

페이지 접근은 한 목록으로 표시하고, 기능 사용은 이미지·생성·채팅·파일 등 필요한 묶음만 펼쳐 설정합니다. 관리자는 기본적으로 전체 권한을 갖습니다. 프로필에 연결한 생성 프리셋은 사용할 생성 경로를 지정하는 설정이며, 페이지 연결이나 일반 도구 목록에서 다시 허용할 필요가 없습니다.

| 기능 | 필요한 권한 |
| --- | --- |
| 앱 이미지·영상·GIF 등 애니메이션 이미지 조회·다운로드 | `images.view` |
| 이미지 편집·처리 | `images.view` + `images.update` |
| 이미지 메타데이터 수정 | `images.view` + `images.metadata.edit` |
| 라이브러리 이미지 삭제 | `images.view` + `images.delete` (기본은 관리자만 부여) |
| 그룹 생성 / 수정·배치 / 삭제 | `groups.create` / `groups.update` / `groups.delete` |
| 허용된 개인 파일 조회 | `files.view` (이미지·영상 미리보기에는 `images.view`도 필요) |
| 프롬프트·그룹·프리셋 조회 / 생성 / 수정 / 삭제 | `prompts.view` / `prompts.create` / `prompts.update` / `prompts.delete` |
| 와일드카드 조회·확장 / 편집 / 삭제 / LoRA 스캔 | `wildcards.view` / `wildcards.edit` / `wildcards.delete` / `wildcards.lora.scan` |
| 워크플로·그래프·모듈·드롭다운 조회 / 정의 편집 | `workflows.view` / `workflows.update` |
| 생성 큐 등록·재시도, NAI 생성, 워크플로·그래프 실행 | `generation.execute` |
| 전체 채팅 페이지 / 채팅 도크 엔진 사용 | `page.chat.view` / `chat.codex.use` 또는 `chat.llm.use` |
| 전역 설정·외부 연결·자격증명·호스트 코드/패키지 관리 | 관리자 계정 |

`page.*`는 페이지·메뉴 이동만 허용합니다. 기능 API는 페이지가 열려 있는지 확인하지 않습니다. 조회 권한은 편집·삭제·실행을 허용하지 않으며, POST 검색·파싱·경로 조회도 조회 작업입니다. 프롬프트 그룹 가져오기는 기존 그룹을 대체하므로 생성·수정·삭제 권한이 모두 필요합니다. 그래프 자동 실행 예약의 생성·수정은 정의 편집과 실행 권한이 모두 필요합니다.

`GET/PUT /api/settings`와 외부 연결 관리는 관리자 전용입니다. `page.settings.view`만으로 서버 설정을 읽거나 변경할 수 없습니다. 다른 화면은 언어·이미지 저장 옵션·워크플로 기능 활성 여부·뷰어·월페이퍼 등의 작은 읽기 전용 런타임 응답을 사용하며, 전체 비밀 설정을 받지 않습니다.

생성 실행과 이미지 조회는 독립적입니다. 생성 권한만으로 작업을 등록할 수 있고 결과 읽기에는 `images.view`가 필요합니다. 기존 NAI 업스케일 API는 실행과 즉시 이미지 다운로드를 한 응답으로 제공하므로 두 권한을 모두 요구합니다. 로그인한 본인의 큐 목록·상태 조회와 기존 본인 취소는 생성 권한 회수 후에도 유지됩니다. 공개 워크플로는 공개 설정·입력·등급별 큐 제한을 계속 적용하며, 실행 권한이 공개 범위나 소유권을 확대하지 않습니다.

영상과 GIF 등 애니메이션 이미지도 같은 `images.view`를 사용합니다. 저장된 워크플로 입력 미디어를 읽는 `GET/HEAD /api/workflow-input-assets/:assetId`는 기존 로그인 조건과 `images.view`를 요구하며, 이미지·영상·오디오 모두 `mime` 쿼리의 유무나 값과 관계없이 같은 권한을 확인합니다. MIME은 응답 형식에만 사용하며 페이지·생성 실행 권한으로 읽기 권한을 대신할 수 없습니다. 입력 업로드·삭제는 기존 `generation.execute`를 유지하고, 서버 내부 자산 경로 해석에는 이 HTTP 읽기 검사를 적용하지 않습니다.

런타임 이벤트는 같은 REST 기능 권한을 사용합니다. 생성 기록은 `images.view`, 그래프 실행·예약 정보는 `workflows.view`, 본인 큐·런타임 잡은 로그인 세션과 기존 계정 필터를 사용합니다. 현재 계정·권한을 재검증하고, 계정 없는 초기 설정 세션은 인증 구성이 생긴 뒤 거부합니다. 스트림은 세션 내용을 변경하지 않습니다.

페이지로 이동하는 버튼은 해당 페이지 권한도 확인합니다. 익명 사용자는 `images.view`를 부여받으면 공개 라이브러리 조회·다운로드를 할 수 있지만, 변경 작업과 개인 파일·생성 기록은 기존 로그인·소유권 조건도 충족해야 합니다. `images.view`는 다른 계정의 개인 파일이나 대화·생성 기록을 공개하지 않습니다. 라이브러리와 본인 생성 기록의 기존 등급별 미디어 정책도 유지됩니다.

업그레이드 때 `auth_seed_state`의 **`images_view_v1`**을 한 번만 적용합니다. 직접 허용된 기존 `page.home.view`, `page.image-detail.view`, `page.groups.view`, `page.generation.view`, `page.wallpaper.view`, `page.wallpaper.runtime.view`, `page.metadata-editor.view`, `chat.codex.use`, `chat.llm.use` 중 하나가 있는 그룹에만 `images.view`를 추가합니다. `page.files.view`만 있는 그룹과 그 외 그룹에는 추가하지 않습니다. 기존 명시적 `images.view` 값은 덮어쓰지 않으며, 이후 관리자가 회수한 권한도 재시작 때 복구하지 않습니다. 그룹 상속과 멤버십은 유지하고, 관리자와 로컬 초기 설정은 기존 전체 권한을 유지합니다.

별도의 일회성 **`files_view_v1`**은 `page.files.view`를 `files.view`로, **`workflows_view_v1`**은 `page.generation.view`를 `workflows.view`로 전환해 페이지와 데이터 접근을 분리합니다. `/uploads`, `/temp`, `/save`는 기존 로그인 조건에 `images.view`를 추가하며 익명에게 열지 않습니다. 이 공용 런타임 폴더에는 새 소유권 모델을 추가하지 않습니다. 외부 MCP 키와 기존 서명된 산출물 링크는 별도 인증 계약을 유지하고, 계정에 연결된 채팅/MCP 이미지 도구는 호출할 때 현재 `images.view`를 다시 확인합니다.

**`independent_features_v1`**도 하나의 트랜잭션으로 한 번만 적용합니다. 직접 허용된 `page.prompts.view` → `prompts.view`, `page.wildcards.view` → `wildcards.view`, `page.generation.view` → `generation.execute`, `chat.codex.use` 또는 `chat.llm.use` → `page.chat.view`만 변환합니다. `workflows.view`는 앞의 별도 마이그레이션이 처리합니다. 기존 새 권한 행(명시적 거부 포함)을 덮어쓰지 않고, 이후 회수·페이지 변경·재시작으로 기능 권한을 다시 추가하지 않습니다. 모든 로그인 사용자에게 실행 권한을 주거나 페이지 접근만으로 파괴적 작업 권한을 주지 않습니다.

**전환 시 관리자 확인:** 기존 공개 워크플로·채팅/생성 프리셋만으로 실행하던 계정은 `generation.execute`를 자동으로 받지 않습니다. 이 전역 권한을 새로 부여할지는 관리자가 명시적으로 결정해야 합니다. 계정에 연결된 채팅/MCP는 기존 엔진·프로필·도구 범위와 해당 기능 권한을 모두 확인하므로, 프롬프트/와일드카드/워크플로 조회·생성·편집도 필요한 도메인 권한을 별도로 부여해야 합니다. 외부의 계정 없는 API 키와 기존 서명된 산출물 계약은 이 전환에 포함되지 않습니다.

채팅은 별도의 높은 권한 계정으로 실행하지 않습니다. 실행 시점의 현재 계정 기능 권한과 채팅 엔진·도구 범위, 활성 프로필/도구 프리셋의 허용 목록, 소유권/공개 범위를 모두 충족해야 합니다. 알 수 없는 미분류 도구는 차단하고, 설정 제안 도구는 현재 관리자 계정만 사용합니다. 프로필·권한·역할 변경과 계정 정지는 열린 답변, 재사용 MCP 세션과 대기열 실행 전에도 재검사합니다. 본인 방·로어 작업은 기존 소유권 계약을 유지하며 호스트 임의 파일 경로와 저장소 내부 참조를 받을 수 없습니다.

Codex 채팅은 공개 폴더 밖의 계정별 전용 홈을 사용하고, 호스트 설정·MCP·플러그인·훅·스킬·환경 자격 증명 상속을 차단합니다. 설치 CLI의 지원 기능과 실제 설정/MCP 목록을 확인하지 못하면 실행하지 않습니다. 채팅에서 Codex 이미지 생성·단독 실행 추천·그래프 실행·실행 정의 가져오기는 제공하지 않습니다. 정적 HTML 미리보기는 스크립트와 네트워크 요청을 차단합니다. 이는 신뢰된 CLI/백엔드와 등록된 생성 제공자를 전제로 한 애플리케이션 경계이며 OS 전체 읽기 격리 보장은 아닙니다.

계정에 연결된 채팅/MCP가 내보내는 생성 파일 링크는 기존 인증된 생성 이력 다운로드 라우트를 사용해 다운로드 시에도 현재 권한과 소유권을 확인합니다. 그래프 익명 다운로드 링크는 계정에 연결된 도구에 제공하지 않습니다. 계정 없는 외부 키의 서명 링크 계약은 유지합니다. 이 변경 전에 이미 발급된 익명 서명 링크는 기존 만료 시간(기본 15분)까지 유효할 수 있으며, 이를 위해 전역 서명 비밀을 교체하지 않습니다.

예시 권한:

- 홈 보기
- 업로드 보기
- 그룹 보기
- 프롬프트 보기
- 이미지 생성 보기
- 설정 보기
- 삭제 권한
- 워크플로우 접근

권장 방식:

1. 관리자 그룹은 최소 인원만 유지합니다.
2. 일반 사용자 그룹은 보기/생성/업로드를 필요 범위만 부여합니다.
3. 게스트 그룹은 공개 확인용으로 제한합니다.
4. 삭제 권한은 신뢰된 계정에만 부여합니다.
5. 외부 접속 전 anonymous 권한을 확인합니다.

## 계정 관리 팁

- 비밀번호 변경 후 즉시 재로그인 테스트를 합니다.
- 계정 삭제 전 해당 계정이 유일한 관리자 계정이 아닌지 확인합니다.
- 게스트 계정은 생성 가능 여부와 권한 범위를 함께 관리합니다.
- 그룹 색상은 UI 구분용이며 권한 자체를 바꾸지 않습니다.

## 복구 정보

로그인 문제가 생기면 보안 복구 카드 또는 로그인 화면의 복구 가이드를 확인합니다.

복구 정보에는 다음이 포함됩니다.

- auth DB 경로
- 로컬 복구 지침
- 인증 상태 확인 단서

복구 작업은 실제 인증 DB에 영향을 줄 수 있으므로, 먼저 `database` 백업을 확보하세요.

## 외부 접속 전 체크리스트

- 관리자 계정 비밀번호가 충분히 강한지
- 게스트/anonymous 권한이 과하지 않은지
- 삭제 권한이 제한되어 있는지
- `/settings` 접근 권한이 관리자에게만 있는지
- HTTP MCP가 필요할 때만 활성이고 API 키가 안전하게 관리되는지
- `BIND_ADDRESS`, `TRUST_PROXY`, 공개 URL 설정이 의도와 맞는지
- 리버스 프록시/HTTPS 구성에서 실제 접속 IP가 올바르게 처리되는지
- 백업 정책이 있는지

## 권한 문제 해결

1. `/access`에서 현재 계정의 접근 목록을 확인합니다.
2. 관리자 계정으로 로그인합니다.
3. `/settings` → 보안에서 계정이 어떤 권한 그룹에 속했는지 확인합니다.
4. 권한 그룹의 페이지 접근과 필요한 기능 사용 권한을 각각 확인합니다.
5. 저장 후 다시 로그인하거나 페이지를 새로고침합니다.
