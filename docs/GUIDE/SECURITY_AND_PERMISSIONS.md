# 보안과 권한

파일함과 프로젝트 작업 공간은 인스턴스 공용입니다. 계정별 파일·폴더 소유권으로 접근을 제한하지 않으며 로그인·API 인증과 `files.view`·`files.edit`·`files.delete`는 유지합니다. 게스트 가입만으로 파일 권한이 생기지는 않지만, 권한이 부여된 게스트는 다른 계정이 만든 공용 자료도 볼 수 있습니다. 가입 설정은 이 변경으로 바뀌지 않습니다. 프로젝트를 연결한 각 채팅의 쓰기 허용, 개인 채팅·채팅 로어북·엔진 세션의 계정 경계(계정 로어북은 보관함처럼 공용), 경로·충돌·비용 검사는 그대로 적용합니다.


CoNAI는 로컬 계정과 권한 그룹으로 페이지 접근과 주요 작업을 제한할 수 있습니다. 외부 접속이나 다중 사용자를 고려한다면 계정·권한 섹션을 먼저 정리하세요.

## 관련 페이지

| 목적 | 경로 |
| --- | --- |
| 로그인 | `/login` |
| 접근 가능한 페이지 확인 | `/access` |
| 계정·권한 설정 | `/settings?section=accounts` |
| 설정 전체 | `/settings` |

## 기본 개념

관리자가 설치·활성화한 플러그인은 신뢰된 앱 코드입니다. 화면은 같은 origin에서 현재 계정의 앱 데이터와 모든 API를 사용할 수 있고 서버 모듈은 Node의 파일·네트워크·프로세스 기능을 사용할 수 있습니다. 플러그인별 기능 허용 목록과 중복 승인은 두지 않습니다. 설치한 코드 자체를 신뢰해야 하며, 외부 HTTP/MCP 인증·계정 경계·저장 충돌·명시적 검토와 생성된 HTML preview의 격리는 유지합니다.

| 용어 | 설명 |
| --- | --- |
| 계정 | 로그인에 사용하는 로컬 사용자입니다. |
| 권한 그룹 | 페이지 접근과 작업 권한을 묶는 단위입니다. |
| 관리자 | 설정과 보안 관리 권한을 가진 계정입니다. |
| 게스트 | 제한된 권한으로 사용하는 계정입니다. |
| anonymous | 로그인하지 않은 공개 접근 상태입니다. |

## 로그인 흐름

1. `/login`으로 이동합니다.
2. 로컬 계정으로 로그인합니다.
3. 아직 계정이 없으면 초기 계정 설정 흐름 또는 설정 → 계정·권한에서 첫 계정을 만듭니다.
4. 게스트 생성이 허용된 경우 게스트 계정을 만들 수 있습니다.
5. 로그인 후 `/access`에서 현재 계정이 열 수 있는 페이지를 확인합니다.

## 접근 페이지

`/access`는 현재 계정이 열 수 있는 페이지와 기능 범위를 보여줍니다.

표시 항목:

- 기본 페이지
- 파생 페이지
- 공개 워크플로우
- 계정 유형
- 항목 수

페이지가 보이지 않거나 메뉴가 사라진 경우 `/access`를 먼저 확인하면 권한 문제인지 빠르게 판단할 수 있습니다.

## 권한 그룹 운영

기능 권한은 영역별 보기·편집과 필요한 별도 작업 권한으로 구성됩니다. 실제 파일이 사라지는 이미지와 파일은 삭제 권한도 구분합니다. 설정의 **앱 관리**, 계정·서버 연결, 채팅의 **프로필·자원·루틴·판단 기록**(`/chat/profiles`·`/chat/resources`·`/chat/routines`·`/chat/judge`)은 관리자 전용(`page.settings.view`)입니다. 채팅 작업 공간 자체는 `page.chat.view`를 요구합니다. **대화**(`/chat`)와 **내 설정**(`/chat/mine` 또는 `/settings?section=mine`)은 채팅 권한과 기존 계정 소유권을 따릅니다. 내 설정의 사용자 프로필·페르소나·플래그는 두 위치에서 같은 화면을 사용합니다. 공용 설정 검색·시트는 관리자에게만 표시하며 기존 페이지 설정 API의 위임 권한은 유지합니다.

### 페이지 설정 위임

**설정 → 계정·권한**의 권한 그룹 편집에서 **공용 페이지 설정** API 권한을 부여합니다. `settings.appearance.manage`(공용 화면), `settings.library.manage`(라이브러리), `settings.media.manage`(미디어 저장), `settings.generation.manage`(생성 실행), `settings.analysis.manage`(자동 분석·의미 검색), `settings.posts.manage`(게시판·지식), `settings.chat.manage`(채팅 공통)를 각각 선택할 수 있습니다.

설정 위임은 모든 사용자에게 적용되는 기본값을 바꾸는 API 권한입니다. 기존 콘텐츠 편집 권한에서 자동으로 부여하지 않으며 익명 계정에는 부여할 수 없습니다. 설정 권한을 주어도 앱 관리 화면·인증 정보·서버 경로·계정 관리·설치·유지보수 권한은 생기지 않습니다. 서버는 조회·저장 직전에 권한과 리비전을 다시 확인합니다.

| 권한 | 할 수 있는 일 |
| --- | --- |
| `images.view` | 이미지·영상·움짤 보기 (홈·그룹·상세·월페이퍼, 채팅 속 이미지 포함). 채팅 프로필의 아바타 썸네일은 채팅 접근 권한만으로 볼 수 있으며, 원본·배경·참조 이미지에는 적용되지 않습니다. |
| `images.edit` | 태그·메타데이터 수정, 이미지 처리, 그룹 만들기·수정·이미지 배치 |
| `images.delete` | 라이브러리 이미지와 그룹 삭제 |
| `images.upload` | 라이브러리에 이미지·영상 업로드 |
| `prompts.view` / `prompts.edit` | 프롬프트·그룹·프리셋 보기 / 추가·수정·삭제·가져오기 |
| `characters.view` / `characters.edit` | 캐릭터 라이브러리 탐색·외형 설정 불러오기 / 폴더·설정 추가·수정·이동·삭제 |
| `wildcards.view` / `wildcards.edit` | 와일드카드 보기·확장 / 추가·수정·삭제, LoRA 폴더 스캔 |
| `generation.execute` | NAI·ComfyUI·워크플로 생성 실행. 공개 워크플로우 페이지의 큐 등록·결과 보기에는 `images.view`와 함께 필요하지 않습니다(공개 설정 자체가 허용이며, 워크플로우의 등급별 대기열 한도로 제한합니다). |
| `workflows.view` / `workflows.edit` | 워크플로·그래프 보기 / 편집·예약 |
| `files.view` / `files.edit` / `files.delete` | 공용 파일 보관함 보기 / 올리기·정리 / 삭제 |
| `posts.view` / `posts.comment` / `posts.write` | 게시판 보기 / 댓글 / 글 쓰기 (자기 글·댓글 고치기·지우기 포함) |
| `posts.summon` | 댓글에서 `@`로 봇 부르기 (부른 계정으로 실행·사용량) |
| `chat.use` | API 모델 프로필로 채팅 |
| `chat.agent.use` | 서버 계정을 쓰는 Codex·Claude Code 프로필로 채팅 (서버 사용량 공유) |
| `chat.diagnostics.view` | 내 답변이 어떻게 구성됐는지 진단 보기 (관리자 프롬프트 원문은 관리자만) |
| `auth.guest.create` | 로그인 화면에서 게스트 가입 (익명 그룹 전용) |

관리자 전용: 설정의 앱 관리, 계정·권한 그룹, 게시판 카테고리·글 숨김·댓글 숨김, 외부 연결·자격 증명, ComfyUI 서버·커스텀 노드, 채팅 프로필·자원·루틴·판단 기록 관리, 채팅 설정 제안 도구, 실행 파일 같은 제한 형식 업로드, Civitai·파일 검증·캐시 관리.

### 페이지는 권한을 따로 주지 않습니다

메뉴와 페이지는 보여 주는 기능의 권한을 따라 열립니다. 예를 들어 `prompts.view`가 있으면 프롬프트 페이지가, `characters.view`가 있으면 캐릭터 라이브러리가, `images.view`가 있으면 홈·그룹·이미지 상세가 열립니다. 게시판은 `posts.view`, 생성 페이지는 `generation.execute`나 `workflows.view` 중 하나, 채팅 페이지는 `chat.use`나 `chat.agent.use` 중 하나를 따릅니다. 설정의 앱 관리는 관리자, 내 설정은 채팅 권한이 있는 계정에게 열립니다. 페이지를 숨기려면 그 기능 권한을 빼면 됩니다. 상단에 이름과 함께 고정할 페이지는 설정의 **상단 고정 페이지**에서 고르고, 고정하지 않은 페이지는 상단의 **라이브러리**·**만들기**·**확장** 메뉴와 이용 가능 페이지에 보입니다.

### 캐릭터 라이브러리의 권한 경계

[캐릭터 라이브러리](CHARACTER_LIBRARY.md)의 페이지 접근 식별자는 `page.characters.view`, 상단 고정 페이지 항목은 `characters`입니다. 라이브러리 권한이 이미지 조회를 허용하지는 않으며 기준 이미지·아바타·표정과 생성 화면의 참조 이미지 옵션에는 `images.view`도 필요합니다.

폴더·외형 설정 편집은 `characters.edit`, 후보 생성은 **관리자 + `characters.edit`**입니다. 캐릭터 페이지에는 외형 라이브러리와 `prompts.view`가 필요한 캐릭터 카탈로그가 있습니다. 채팅 프로필 관리는 별도 기능으로 관리자 전용이며, 라이브러리 연결은 선택입니다. 삭제 미리보기 API는 연결 프로필 수를 반환하지만 이름 목록은 관리자에게만 공개합니다. 삭제하면 동기화 프로필에 현재 외형을 복사하고 연결을 해제합니다.

화면·MCP·플러그인은 같은 계정 권한과 저장 리비전 검사를 사용합니다. `propose_character_library`는 채팅의 검토 카드로만 적용하며 플러그인 앱 도구로는 제공하지 않습니다. 프로필을 사용할 수 있다는 이유만으로 연결 설정의 이름·폴더까지 볼 수 있는 것은 아닙니다.

### 익명·게스트

- **익명**(로그인 안 함)은 `images.view`와 `auth.guest.create`만 줄 수 있습니다. 나머지 기능은 로그인이 필요합니다.
- **게스트** 그룹은 모든 로그인 계정이 이어받습니다. 모든 계정에 주고 싶은 기능은 게스트 그룹에 줍니다.
- 관리자 그룹은 항상 모든 권한을 가지며 편집할 수 없습니다.

### 채팅 봇의 권한

봇은 **사용자 권한과 관리자가 해당 프로필에 위임한 기능 권한 안에서, 프로필이 허락한 도구만** 씁니다. 기본값은 위임 없음입니다.

1. 기능: 웹에서 같은 작업에 필요한 권한을 확인하되, 해당 프로필에 관리자가 위임한 권한도 인정합니다. 사용자 자신의 페이지·일반 API 권한은 바뀌지 않습니다.
2. 프로필: 프로필 도구 섹션에서 켠 범위(조회·생성·정리·설정)와 도구 목록, 연결한 생성 프리셋입니다. 설정 범위는 관리자 계정에서만 동작합니다.
3. 대화 도구(답장, 방 기록, 로어북)는 채팅이면 항상 제공됩니다.

**채팅 → 프로필 → 도구 → 프로필 위임 권한**에서 설정합니다. 생성 페이지나 라이브러리를 열어 주지 않고 이미지 검색·확인·생성을 제공하려면 프로필에 `images.view`와 `generation.execute`를 위임하고 필요한 도구·생성 프리셋을 연결합니다. ComfyUI에는 `workflows.view`도 필요하며 그룹에 저장·정리하려면 해당 편집 권한을 별도로 선택합니다. 위임은 도구 사용 설정을 대신 켜지 않습니다.

위임은 해당 프로필을 사용할 수 있는 사용자의 그 프로필 실행에만 적용됩니다. 계정 관리·채팅 진입·서버 설정·관리자 자격은 위임할 수 없습니다. 다른 프로필이나 외부 MCP 키에는 전파되지 않으며 공개 페이지의 제한은 유지합니다. 채팅 결과 이미지는 소유한 대화의 실제 도구·생성 결과만 표시하고 라이브러리 전체 조회는 열지 않습니다. 위임 회수·프로필 비활성화·대화 접근 회수는 도구 호출·대기 작업 실행·이미지 요청 때 다시 확인합니다.

기존 검색 기록이나 가져온 대화는 그 기록만으로 이미지 접근 권한을 얻지 않습니다. 실제 서버 실행 증거가 없는 검색 결과는 해당 프로필로 다시 검색해야 합니다. 서버 생성 작업과 연결된 결과는 그 연결을 검증하며, 이미 `images.view`가 있던 사용자의 조회 방식은 그대로입니다.

봇에게는 실제로 쓸 수 있는 도구만 보입니다. 답변이 시작될 때 목록이 정해지고, 호출할 때마다 권한을 다시 확인합니다. 권한을 회수하면 열린 답변에도 바로 반영되고, 새로 준 권한은 다음 답변부터 보입니다. 일반 페이지를 연결해도 계정·프로필이 이미 허용한 도구와 연결 파일은 유지됩니다. 페이지 내용 자체는 작업 승인이나 권한 부여가 아닙니다. 공개 페이지와 게시판 봇 호출은 별도 제한을 유지합니다. 이미 명시적으로 요청한 범위는 다시 승인받지 않으며, 대상·영향이 불명확하거나 범위를 넘는 작업만 추가 확인합니다. 페이지의 파일 이름 변경·이동·실행 중단은 현재 화면 리비전을 확인해 바로 실행하고, 나머지 확정 작업은 검토 카드를 유지합니다.

외부 MCP API 키는 계정에 묶이지 않은 별도 키지만, 권한은 계정과 같이 키에 지정한 권한 그룹에서만 나옵니다. 키별 권한은 없습니다.

### 권한 구조 변경 (permissions_v2)

예전의 세분화된 키는 서버를 처음 다시 시작할 때 한 번만 새 키로 합쳐집니다. 그룹이 예전 키 중 하나라도 가졌으면 합쳐진 새 키를 받습니다 (예: `groups.update` → `images.edit`, `prompts.create` → `prompts.edit`, `chat.codex.use` → `chat.agent.use`). 페이지 키와 봇 도구 키(`chat.tools.*`)는 사라집니다. 익명 그룹에 있던 로그인 전용 권한은 게스트 그룹으로 옮겨져 로그인 계정은 그대로 쓸 수 있습니다. 이전에 `chat.tools.*` 없이 기능 권한만 있던 그룹은 이제 그 계정의 봇도 같은 기능을 쓸 수 있으니, 프로필 도구 설정을 확인하세요.

## 계정 관리 팁

- 비밀번호 변경 후 즉시 재로그인 테스트를 합니다.
- 계정 삭제 전 해당 계정이 유일한 관리자 계정이 아닌지 확인합니다.
- 게스트 계정은 생성 가능 여부와 권한 범위를 함께 관리합니다.
- 그룹 색상은 UI 구분용이며 권한 자체를 바꾸지 않습니다.

## 복구 정보

로그인 문제가 생기면 보안 복구 카드 또는 로그인 화면의 복구 가이드를 확인합니다.

복구 정보에는 다음이 포함됩니다.

- auth DB 경로
- 로컬 복구 지침
- 인증 상태 확인 단서

복구 작업은 실제 인증 DB에 영향을 줄 수 있으므로, 먼저 `database` 백업을 확보하세요.

## 외부 접속 전 체크리스트

- 관리자 계정 비밀번호가 충분히 강한지
- 게스트/anonymous 권한이 과하지 않은지
- 삭제 권한이 제한되어 있는지
- HTTP MCP가 필요할 때만 활성이고 API 키가 안전하게 관리되는지
- `BIND_ADDRESS`, `TRUST_PROXY`, 공개 URL 설정이 의도와 맞는지
- 리버스 프록시/HTTPS 구성에서 실제 접속 IP가 올바르게 처리되는지
- 백업 정책이 있는지

## 권한 문제 해결

1. `/access`에서 현재 계정의 접근 목록을 확인합니다.
2. 관리자 계정으로 로그인합니다.
3. `/settings` → 보안에서 계정이 어떤 권한 그룹에 속했는지 확인합니다.
4. 권한 그룹에 필요한 기능 권한이 있는지 확인합니다. 페이지는 기능 권한을 따라 열립니다.
5. 저장 후 다시 로그인하거나 페이지를 새로고침합니다.
