# 보안과 권한

CoNAI의 권한은 두 가지뿐입니다. 관리자는 권한 그룹마다 **열 수 있는 페이지**와 **읽기·수정·삭제** 세 가지 기본 권한을 정합니다. 그 밖의 앱 기능(생성, 채팅, 게시판 글쓰기 등)은 로그인한 계정이면 누구나 씁니다. 채팅 봇은 계정 권한 안에서 **프로필 도구 설정이 허락한 것만** 합니다. 외부 접속이나 다중 사용자를 고려한다면 계정·권한 섹션을 먼저 정리하세요.

## 관련 페이지

| 목적 | 경로 |
| --- | --- |
| 로그인 | `/login` |
| 접근 가능한 페이지 확인 | `/access` |
| 계정·권한 설정 | `/settings?section=accounts` |
| 설정 전체 | `/settings` |

## 기본 개념

| 용어 | 설명 |
| --- | --- |
| 계정 | 로그인에 사용하는 로컬 사용자입니다. |
| 권한 그룹 | 페이지 접근과 기본 권한을 묶는 단위입니다. |
| 관리자 | 모든 권한과 설정·보안 관리를 가진 계정입니다. |
| 게스트 | 관리자가 아닌 일반 계정입니다. 모든 로그인 계정은 게스트 그룹을 이어받습니다. |
| 익명 | 로그인하지 않은 방문자입니다. |

## 권한 구조

### 페이지 접근

그룹마다 메뉴에 보이는 페이지 15개를 체크합니다: 갤러리, 그룹, 업로드, 파일 보관함, 프롬프트, 와일드카드, 캐릭터, 생성, 오디오, 스프라이트, 채팅, 게시판, 월페이퍼, 월페이퍼 런타임, 플러그인.

- 이미지 상세는 갤러리나 그룹을 열 수 있으면 열립니다. 메타데이터 편집은 이미지 상세가 열리고 수정 권한이 있으면 열립니다.
- 설정의 앱 관리는 관리자에게만 열립니다. 내 설정(`/chat/mine`, `/settings?section=mine`)은 채팅 페이지와 같이 열립니다. 채팅 페이지가 없으면 헤더의 채팅 키와 옆 패널도 보이지 않습니다.
- 페이지 접근은 **화면**을 정합니다. 데이터를 읽고 고치는 것은 아래 기본 권한이 정하므로, 페이지가 없어도 읽기 권한이 있으면 채팅·플러그인을 통해 그 데이터를 볼 수 있습니다.

### 기본 권한

| 권한 | 할 수 있는 일 |
| --- | --- |
| 읽기 | 이미지·영상, 프롬프트·와일드카드, 캐릭터·화풍·RefMod, 워크플로, 공용 파일 보관함, 오디오, 게시판의 모든 데이터 보기 |
| 수정 | 공용 데이터 만들기·올리기·고치기·정리 (업로드, 태그·메타데이터, 그룹 만들기·배치, 프롬프트·워크플로·캐릭터 편집, 파일 올리기·이동 등) |
| 삭제 | 공용 데이터 지우기 (이미지·그룹·휴지통 복원, 파일, 프롬프트, 와일드카드, 워크플로, 캐릭터·화풍, RefMod 삭제·미등록 이동, 오디오 등) |

수정이나 삭제가 있으면 읽기도 있는 것으로 봅니다. 영역별로 따로 나누지 않습니다.

### 로그인만 필요한 것

- 생성: NovelAI·ComfyUI·Codex·워크플로 실행, 오디오 주문. 이미 있는 그룹에 결과를 넣는 것도 생성에 포함됩니다. 그룹 경로를 새로 만드는 것은 수정입니다.
- 미디어 처리로 **새 사본**을 만드는 것(크기 바꾸기, 자르기, 변환, 스프라이트, 영상 자르기·잇기, 프레임 저장). 원본으로 쓰는 라이브러리 미디어는 읽기 권한이 필요합니다.
- 채팅(서버 에이전트 프로필은 프로필 사용 대상이 정합니다), 내 답변의 진단 보기(관리자 프롬프트 원문은 관리자만).
- 게시판 글·댓글·평가·봇 부르기. 게시판을 읽으려면 읽기 권한이 필요합니다.

### 내 것

게시글·댓글, 생성 기록(파일까지 삭제 포함), 생성 큐 작업, 예약, 런타임 작업은 만든 계정이 수정·삭제 권한 없이도 고치고 지울 수 있습니다. 생성 기록의 파일을 지우면 같은 파일 해시로 묶인 라이브러리 항목이 함께 지워질 수 있습니다.

### 관리자 전용

설정의 앱 관리, 계정·권한 그룹, 모든 사용자에게 적용되는 공용 설정, 게시판 카테고리·글 숨김·댓글 숨김, 외부 연결·자격 증명, ComfyUI 서버·커스텀 노드, 채팅 프로필·자원·루틴·판단 기록 관리, 채팅 설정 제안 도구, 실행 파일 같은 제한 형식 업로드, Civitai·파일 검증·캐시 관리, 플러그인 작성·설치.

### 익명·게스트

- **익명**(로그인 안 함) 그룹에는 읽기, 게스트 가입, 이미지 페이지(갤러리·그룹·월페이퍼·월페이퍼 런타임)만 줄 수 있습니다. 나머지는 로그인이 필요합니다.
- **게스트** 그룹은 모든 로그인 계정이 이어받습니다. 모든 계정에 주고 싶은 페이지와 권한은 게스트 그룹에 줍니다.
- 관리자 그룹은 항상 모든 권한을 가지며 편집할 수 없습니다.

## 채팅 봇의 권한

봇이 할 수 있는 일 = **대화하는 계정의 권한** ∩ **프로필 도구 설정**(범위, 도구 목록, 생성 프리셋, 페이지 어시스턴트). 프로필에 주지 않은 기능은 그 채팅의 어떤 경로로도 쓸 수 없습니다.

| 프로필 범위 | 계정에 필요한 것 |
| --- | --- |
| 조회 | 읽기 |
| 생성 | 로그인 |
| 정리 | 수정 |
| 삭제 | 삭제 |
| 설정 | 관리자 |

- 페이지를 연결해도 그 페이지의 도구는 프로필의 범위와 도구 목록을 따릅니다. 페이지 자체를 읽고 입력을 채우는 페이지 도구는 페이지 어시스턴트 설정을 따릅니다.
- 화면 조작(버튼 누르기 등)도 동작마다 범위가 있어서 프로필 범위 밖의 동작은 거절합니다. 예를 들어 삭제 범위가 없는 프로필은 화면의 삭제 버튼도 누를 수 없습니다.
- 플러그인 실행은 그 플러그인이 선언한 도구·기능의 범위가 모두 프로필 범위 안일 때만 됩니다.
- 웹 검색은 프로필의 웹 설정과 도구 목록을 따릅니다. Codex 자체 이미지 생성은 쓰지 않고, 생성은 앱의 생성 도구로만 합니다.
- 다른 봇을 부르면(`call_agent`) 불려온 봇은 자기 프로필 설정대로 동작합니다.
- 서버 계정 사용량을 쓰는 Codex·Claude Code 프로필은 **프로필 사용 대상** 그룹으로 누가 쓸지 정합니다. 대상이 비어 있으면 채팅 페이지가 있는 모든 계정이 씁니다.
- 대화 도구(답장, 방 기록, 로어북)는 채팅이면 항상 제공됩니다. 답변이 시작될 때 목록이 정해지고 호출할 때마다 권한을 다시 확인하므로, 권한을 회수하면 열린 답변에도 바로 반영됩니다.

## 채팅 첨부

채팅에서 새로 업로드한 첨부는 업로드한 계정의 채팅 전용 범위에 있습니다. 업로드에는 로그인만 필요하고, 다른 계정(관리자 포함), 공용 파일 API·검색, 외부 MCP 키는 열거나 나열할 수 없습니다. 내 그룹 방의 봇은 내 계정으로 실행되므로 그 방의 첨부를 읽지만 다른 계정의 채팅으로 파일 접근권을 전달하지 않습니다. 채팅 전용 읽기 도구는 활성 답변·실제 첨부·소유 계정을 확인하며 게시판 @호출과 공개 페이지에서는 사용할 수 없습니다.

공용 파일 고르기와 기존 공용 첨부의 JSON 가져오기, 앱 미디어 첨부에는 읽기 권한이 필요합니다. 그 대화의 답변이 실제로 가져온 결과 이미지는 읽기 권한 없이도 같은 대화의 다음 메시지에 **참조**로 첨부할 수 있습니다(해시만 알거나 다른 대화의 결과인 경우는 거부). 개인 첨부는 마지막 대화 참조 삭제 시 사용할 수 없고, 보내지 않은 업로드는 24시간 뒤 만료됩니다. 개인 첨부를 사용한 방은 요약·도구 결과·진단 캡처·엔진 기억에도 내용이 남을 수 있어 공용 백업/진단 저장과 게시판·공개 페이지 실행을 거부합니다. 상세 보존 규칙은 [채팅 첨부](CHAT.md#파일-첨부와-개인정보)를 참고하세요.

파일 보관함과 프로젝트 작업 공간은 인스턴스 공용입니다. 계정별 파일 소유권으로 나누지 않고 읽기·수정·삭제 권한으로만 제한합니다. 서버 디스크를 관리하는 운영자의 접근은 웹 계정 권한과 별개입니다.

## 플러그인

관리자가 설치·활성화한 플러그인은 신뢰된 앱 코드입니다. 화면은 같은 origin에서 현재 계정의 권한으로 앱 데이터와 API를 사용하고, 서버 모듈은 Node의 파일·네트워크·프로세스 기능을 사용할 수 있습니다. 플러그인 목록과 페이지는 플러그인 페이지 접근을 따릅니다.

관리자가 공용으로 공개한 플러그인 페이지는 그 패키지가 선언한 도구·서버 작업·호스트 기능·코어 경로(`appRoutes`)에 한해 보는 계정에게 **읽기·수정**을 빌려줍니다. 삭제·관리자 전용·LLM은 빌려주지 않습니다. 공개한 뒤 선언이 바뀌면 다시 공개할 때까지 빌려주기를 멈춥니다.

## 외부 MCP 키

외부 MCP API 키는 계정에 묶이지 않은 별도 키지만, 권한은 키에 지정한 권한 그룹의 기본 권한에서만 나옵니다. 키별 권한은 없습니다.

## 권한 구조 변경 (permissions_v3)

예전의 기능 권한(37개)은 서버를 처음 다시 시작할 때 한 번만 새 구조로 바뀝니다.

- 페이지: 그룹이 예전 권한으로 열 수 있던 페이지를 그대로 저장합니다. 메뉴는 바뀌지 않습니다.
- 기본 권한: 보기 권한이 하나라도 있으면 읽기, 편집·업로드 권한이 하나라도 있으면 수정, 삭제 권한이 하나라도 있으면 삭제를 받습니다.
- 공용 설정 위임(`settings.*.manage`)은 관리자 전용이 됩니다.
- 서버 에이전트 채팅 권한은 사라지고, 사용 대상이 비어 있던 Codex·Claude Code 프로필은 그 권한을 가졌던 그룹(과 관리자)만 쓰도록 대상이 채워집니다. 게스트 그룹이 가졌던 경우에는 그대로 둡니다.
- 프로필과 도구 프리셋의 범위에 정리가 있으면 삭제가 추가되어 동작이 그대로입니다. 프로필 위임 권한은 더 쓰지 않습니다.
- 서버 로그에 그룹·프로필마다 바뀌기 전과 후가 한 줄씩 남습니다.

바뀌는 점:

- 로그인 계정은 누구나 생성·미디어 처리(새 사본)·채팅·게시판 쓰기를 할 수 있습니다.
- 한 영역에만 편집 권한이 있던 그룹은 모든 영역을 수정할 수 있게 됩니다.
- 편집 권한만 있고 삭제 권한이 없던 그룹은 프롬프트·워크플로·오디오 같은 항목을 더 이상 지울 수 없습니다.
- 내 생성 기록은 파일까지 직접 지울 수 있습니다(예전에는 관리자만).

## 계정 관리 팁

- 비밀번호 변경 후 즉시 재로그인 테스트를 합니다.
- 계정 삭제 전 해당 계정이 유일한 관리자 계정이 아닌지 확인합니다.
- 게스트 가입은 익명 그룹의 게스트 가입 스위치로 켜고 끕니다.
- 그룹 색상은 UI 구분용이며 권한 자체를 바꾸지 않습니다.

## 복구 정보

로그인 문제가 생기면 보안 복구 카드 또는 로그인 화면의 복구 가이드를 확인합니다. 복구 정보에는 auth DB 경로, 로컬 복구 지침, 인증 상태 확인 단서가 있습니다. 복구 작업은 실제 인증 DB에 영향을 줄 수 있으므로 먼저 `database` 백업을 확보하세요.

## 외부 접속 전 체크리스트

- 관리자 계정 비밀번호가 충분히 강한지
- 게스트 그룹의 페이지와 기본 권한이 과하지 않은지 (특히 수정·삭제)
- 게스트 가입을 열어둘지, 서버 에이전트 프로필의 사용 대상이 맞는지
- HTTP MCP가 필요할 때만 활성이고 API 키가 안전하게 관리되는지
- `BIND_ADDRESS`, `TRUST_PROXY`, 공개 URL 설정이 의도와 맞는지
- 리버스 프록시/HTTPS 구성에서 실제 접속 IP가 올바르게 처리되는지
- 백업 정책이 있는지

## 권한 문제 해결

1. `/access`에서 현재 계정이 열 수 있는 페이지를 확인합니다.
2. 관리자 계정으로 로그인합니다.
3. 설정 → 계정·권한에서 계정이 어떤 권한 그룹에 속했는지 확인합니다.
4. 화면이 안 보이면 페이지 접근을, 화면은 보이는데 저장·삭제가 거절되면 수정·삭제 권한을 확인합니다. 채팅 봇이 거절하면 프로필의 도구 범위를 확인합니다.
5. 저장 후 다시 로그인하거나 페이지를 새로고침합니다.
