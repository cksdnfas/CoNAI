# 플러그인 관리

플러그인은 앱 전체에 필요한 페이지와 기능을 ZIP으로 추가합니다. 선언한 공통 앱 도구와 어시스턴트·MCP를 연결하고, 필요한 경우 파일이나 프로젝트도 연결합니다. 기본 앱에는 개별 플러그인을 자동 설치하지 않습니다.

## 설치와 사용

1. **설정 → 관리 → 플러그인 관리**를 엽니다. 주소는 `/#/settings?section=plugins`입니다. 별도 실행·작업 화면 `/#/extensions`도 유지됩니다.
2. 관리자가 **패키지 설치**로 ZIP을 올립니다. 새 패키지는 비활성 상태입니다.
3. **활성화**에서 요구하는 앱 기능과 파일·프로젝트 접근 범위를 확인합니다.
4. 설치한 플러그인의 페이지 버튼으로 실행합니다. 파일을 사용하는 플러그인은 파일 보관함에서 선택 후 **플러그인으로 열기**로 연결할 수도 있습니다. 플러그인 화면의 **파일 선택**으로 한 번에 20개까지 연결합니다.
5. 도구에서 초안을 만든 뒤 저장 검토를 요청합니다. 앱이 표시한 원본과 변경 내용을 확인하고 **적용**을 눌러야 저장됩니다.

다른 화면에서 파일이 바뀌었다면 저장이 거절됩니다. 문서 편집의 **최신 원본과 비교**를 누르면 초안을 유지하면서 최신 저장 내용과 리비전을 불러옵니다. 비교 후 초안을 수정하고 저장 검토를 다시 요청하세요. 이전 검토 카드는 취소할 수 있습니다. **초안 버리기**는 마지막으로 불러온 원본으로 되돌립니다.

검토 카드는 5분 동안 유효합니다. 화면 연결은 1분마다 갱신하며, 갱신 없이 5분이 지나면 만료됩니다. 새로고침·화면 종료 때 연결을 정리하고 강제 종료로 남은 연결은 만료 후 연결 개수에 포함하지 않습니다. 일시적인 통신 오류에는 화면과 초안을 유지하고 **연결 다시 확인**으로 재시도합니다. 연결이 만료되거나 권한이 회수되면 API 접근을 중단하되 열린 편집 화면은 남겨 초안을 복사할 수 있게 합니다. 장시간 절전 후에는 초안을 복사한 뒤 확장을 다시 여세요.

미저장 초안과 검토 카드가 남아 있으면 페이지 이동 전에 확인합니다. 브라우저 새로고침·탭 종료 후 초안을 자동 복원하는 기능은 없습니다.

비활성화·제거는 관리자가 수행합니다. 비활성화하면 기존 연결과 저장 승인이 무효화됩니다. 제거해도 파일함의 자료는 유지됩니다. 현재 업데이트는 기존 패키지 제거 후 새 ZIP 설치 방식입니다. 패키지 파일 일부나 폴더가 없어져도 등록 정보를 제거하고 재설치할 수 있습니다. 설치 경로가 외부 폴더로 연결된 링크라면 안전을 위해 제거를 거절합니다.

## 개발 예제

공개 소스에는 `text-editor`(문서 편집), `app-workbench`(앱 작업 도구), `chat-instructions`(채팅 지시문) 세 가지 개발 예제를 제공합니다. 기본 제공 기능이 아니라 SDK 연결 방식을 보여주는 선택 설치 패키지입니다.

`plugins/text-editor`는 파일 읽기·초안 수정·AI 작업·저장 검토를 보여줍니다. 일반적인 문서 작성과 편집에는 파일함의 기본 편집기를 사용하면 됩니다. 저장소 루트에서 다음 명령으로 패키지를 만듭니다.

```sh
node scripts/build-plugin.mjs text-editor
```

생성한 `build-output/plugins/text-editor.zip`을 설치합니다. 텍스트 편집, JSON 정렬, 변경 검토와 저장을 제공합니다. 텍스트는 UTF-8 기준 2MB까지 지원합니다. 페이지 어시스턴트는 연결된 파일 선택, 최신 원본과 비교, 정확히 일치하는 문구 교체, JSON 정렬, 저장 검토 요청을 사용할 수 있습니다. 어시스턴트의 요청 자체는 저장 승인으로 취급하지 않습니다.

AI에게 맡기려면 프로필의 **페이지 어시스턴트**를 켜고, 확장 화면에서 해당 1:1 채팅의 **현재 페이지 연결**을 누릅니다. 예를 들어 “이 문서의 초안을 검토완료로 바꾸고 저장 검토를 요청해줘”라고 지시한 뒤 호스트 검토 카드에서 적용합니다. 작업 공간 연결만으로는 확장 화면이 연결되지 않습니다. 새로운 커스텀 기능은 [확장 개발 계약과 SDK](../../plugins/README.md)에 맞춰 패키지로 만들며, AI가 사용할 동작도 manifest에 함께 등록합니다.

개인 전용 플러그인의 소스·문서·테스트는 Git과 Docker 빌드에서 제외하는 `local-plugins/`에 둡니다. `node scripts/build-plugin.mjs --local <플러그인명>`으로 `build-output/local-plugins/`에 ZIP을 만듭니다. 설치는 예제와 같은 패키지 설치 경로를 사용합니다.

## 권한과 범위

설치·활성화는 관리자만 할 수 있습니다. 사용자는 파일 보관함 조회 권한이 필요하고, 저장에는 파일 편집 권한도 필요합니다. 파일함은 인스턴스의 공용 자료입니다. 플러그인이 선언한 기능과 사용자의 현재 권한, 명시적으로 선택한 파일 범위를 모두 검사합니다. 다른 사용자의 플러그인 연결이나 저장 승인은 재사용할 수 없습니다. 공용 파일함이 개인 채팅·인증정보의 공개를 뜻하지는 않습니다.

화면은 격리된 iframe에서 실행됩니다. 앱 API는 호스트가 중계하며 플러그인에 세션 쿠키나 저장 승인 토큰을 전달하지 않습니다. 외부 네트워크 요청, 팝업, 폼 제출 등을 제한합니다. 관리자는 출처와 코드를 확인한 패키지를 설치해야 합니다. 무한 반복 등 브라우저 CPU·메모리 고갈까지 격리하는 실행 환경은 아닙니다.

현재 지원하는 자료는 파일함의 텍스트·미디어와 명시적으로 연결한 프로젝트 문서·미디어 참조입니다. 관리자가 신뢰하여 활성화한 서버 플러그인은 Node worker와 전용 SQLite 저장소를 사용할 수 있습니다. 서버 코드는 앱과 같은 수준으로 신뢰해야 하며 브라우저 iframe과 같은 보안 격리가 아닙니다. 등록된 앱 도구와 플러그인 서버 작업은 화면 없이도 실행할 수 있습니다. 데스크톱 프로그램의 창을 그대로 붙이는 방식은 지원하지 않습니다.

## 플러그인에서 캐릭터 답변 사용

서버 플러그인은 기존 채팅 프로필로 한 번의 답변을 생성할 수 있습니다. 별도 워크플로 등록 없이, 사용 가능한 프로필 선택 → 답변 시작 → 상태·본문 확인 → 취소 흐름을 제공합니다. 일반 사용자도 자신의 채팅 권한과 프로필 사용 대상에 맞는 캐릭터를 사용할 수 있습니다.

프로필의 성격·모델·로어를 재사용하며, 개인 채팅 기록을 가져오거나 기존 채팅방에 메시지를 저장하지 않습니다. 이전 대화와 생활 상태는 플러그인이 관리합니다. 사용량은 LLM 계기판의 **플러그인** 항목에 기록됩니다.

인스턴스 전체에서 최대 4개 답변 작업을 동시에 처리하고 모델 연결의 동시 실행 제한도 적용합니다. 작업은 즉시 ID를 반환하며 결과와 중복 방지 정보의 보관 범위는 24시간입니다. 같은 요청 ID를 재전송하면 기존 작업을 돌려주며, 실패·취소·서버 재시작 뒤에 자동으로 다시 과금하는 실행을 시작하지 않습니다. 만료된 요청은 자동 재전송하지 않아야 합니다.

플러그인 비활성화·업데이트·제거는 실행 중 답변에 취소를 요청합니다. 페이지를 닫는 것만으로는 중단되지 않으므로 플러그인의 중지 기능을 사용하세요. 이미 발생한 모델 사용량은 취소로 되돌릴 수 없습니다. 입력·출력·시간 제한과 제작 API는 [SDK의 Profile replies](../../plugins/README.md#profile-replies)를 참고하세요.

## 프로젝트 연결

파일함의 프로젝트에서 **확장으로 열기**를 누르거나 확장 페이지의 **프로젝트 연결**에서 작업 공간을 선택합니다. 처음에는 읽기 전용입니다. **저장 제안 허용**을 켜서 연결하면 검토 카드를 만들 수 있고, 실제 문서 저장은 사람이 적용합니다. 새로고침하면 읽기 전용으로 돌아갑니다. 연결 변경 시 기존 초안과 검토는 닫히므로 저장 여부를 확인하세요. AI 채팅의 프로젝트 연결과 확장의 연결은 각각 지정합니다.

## 데이터와 배포

패키지는 `RUNTIME_BASE_PATH/plugins/packages/<id>/<version>`에 저장하고 등록 정보는 user settings DB에 저장합니다. Docker에서도 해당 데이터 경로가 영구 볼륨에 포함되어야 합니다. 패키지 폴더와 DB를 같은 시점에 백업하고 복원하세요. 별도로 지정한 DB·파일함 경로도 함께 보존해야 합니다. 자세한 경로는 [데이터와 백업](./DATA_PATHS_AND_BACKUP.md)을 참고하세요.

앱과 `/api/plugin-assets`, `/api/plugin-media`는 같은 브라우저 출처에서 제공해야 합니다. 프록시가 자산의 CSP·CORS·CORP 헤더를 제거하거나 바꾸면 확장이 동작하지 않을 수 있습니다. 활성 패키지의 정적 코드는 인증 없이 제공되므로 ZIP에 비밀값이나 개인 자료를 넣지 마세요. 사용자 파일은 별도의 권한 검사와 만료되는 미디어 링크로 제공됩니다.

MCP의 `list_plugin_pages`로 활성 확장과 페이지별 작업 스키마를 찾을 수 있습니다. 앱 안에서는 현재 페이지를 연결한 뒤 `page_act`로 해당 플러그인이 등록한 작업을 실행합니다. 브라우저 전용 동작은 페이지 연결이 필요하고, 아래의 서버 작업은 화면 없이도 실행할 수 있습니다.


## 앱 기능을 연결하는 커스텀 플러그인

플러그인의 `appTools`에 사용할 앱 기능을 선언하고 `serverActions`에 작업 입력과 연결할 도구를 정의합니다. `pages[].serverActions`에 작업을 참조하면 화면 어시스턴트도 같은 작업을 사용합니다. 기본 앱에 커스텀 화면이나 업무 규칙을 추가할 필요가 없습니다. 지원 도구의 조회·권한·검증·저장은 기존 앱 기능을 재사용합니다. 사용 가능한 범위와 제작 예제는 [SDK 문서](../../plugins/README.md#native-app-bridge-and-headless-actions)를 참고하세요.

선택 설치 예제 `app-workbench`는 라이브러리 그룹, 게시판 초안, 워크플로·오디오 조회, 연결한 프로젝트 문서 작성을 제공합니다. `node scripts/build-plugin.mjs app-workbench`로 ZIP을 만든 뒤 설치합니다. 활성화할 때 요청한 앱 기능 목록을 확인하세요.

외부 MCP는 `list_plugin_pages` → `run_plugin_action` → `get_plugin_action`으로 등록된 서버 작업을 사용합니다. 조회는 바로 실행되고 변경은 **확장 → 확장 앱 작업 · MCP 승인과 결과**에 검토 카드로 표시됩니다. 사람이 **앱 작업 적용**을 누르면 실행합니다. 플러그인 페이지를 닫아도 승인된 작업과 결과는 유지됩니다. 브라우저 UI만으로 구현한 동작은 계속 페이지 연결이 필요합니다.

동일한 요청 ID를 재사용하면 중복 실행을 막으며, 취소·실패·서버 재시작 후 상태를 확인할 수 있습니다. 이미 앱 서비스에 전달된 작업은 취소 요청 뒤에도 완료될 수 있으므로 실제 결과와 개별 생성 작업 상태를 확인하세요. 조회 범위·입력·결과는 제한된 크기로 제공하고 도구 스키마는 필요한 기능만 조회합니다.
