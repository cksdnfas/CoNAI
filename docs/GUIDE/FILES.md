# 파일 보관함

상단 **파일 보관함**에서 내 파일을 업로드하고 폴더별로 정리합니다. 파일은 계정별로 분리되며 채팅에 첨부한 원본은 참조가 남아 있는 동안 삭제되지 않습니다.

파일을 누르면 미리보기가 열립니다. 위쪽 화살표 또는 키보드 **← →**로 같은 폴더의 파일을 이름순으로 넘깁니다. 목록의 100개 페이지 경계를 넘어도 이어집니다. 다운로드 아이콘은 원본을 저장합니다.

검색은 텍스트 파일뿐 아니라 **텍스트가 포함된 PDF**와 **XLSX 엑셀**의 본문도 찾습니다. PDF는 페이지 번호, 엑셀은 시트·행·셀 위치를 남깁니다. 엑셀의 각 셀에는 같은 열의 상단 텍스트 셀을 최대 3개까지 함께 남겨 제목·단위 문맥을 보존합니다. 엑셀 수식은 파일에 저장된 계산 결과를 읽으며 수식·매크로를 실행하거나 외부 링크를 가져오지 않습니다. 구형 XLS는 XLSX로 변환해 올려 주세요. 스캔 PDF의 OCR과 파일함 이미지·영상의 내용 색인은 지원하지 않습니다.

임베딩의 파일 검색을 켜면 키워드 결과와 의미 검색 결과를 함께 보여줍니다. 검색 화면과 봇 도구에는 의미 검색 꺼짐·응답 실패, 본문 추출 대기, 색인 미완료, 추출이 불완전한 파일 수가 표시됩니다. 이런 상태의 빈 결과는 파일 전체에 해당 내용이 없다는 뜻이 아닙니다. 첫 검색에서 문서 추출이 오래 걸리면 먼저 처리된 결과를 반환하므로 잠시 뒤 다시 검색하세요.

의미 검색 결과의 미리보기도 필요한 본문 일부만 읽습니다. 긴 문서의 검색 위치와 읽기 리비전은 유지하며, 검색 요청을 중단하면 의미 검색의 대기도 중단됩니다.

본문 추출은 파일이 바뀌거나 재시도를 요청할 때 실행하고 결과를 재사용합니다. 추출 작업과 임베딩 작업은 작은 배치로 나누어 처리합니다. 긴 문서는 작은 조각으로 나누어 백그라운드에서 이어서 색인하며 서버를 재시작해도 진행 위치가 유지됩니다. PDF·XLSX는 파일당 64MB, 추출 본문은 800만 글자까지 처리합니다. 일반 텍스트는 앞부분 32MB와 800만 글자 제한을 적용하며 제한에 걸리면 부분 처리로 표시합니다. 손상·암호화된 문서나 처리 시간·메모리 한도를 넘긴 문서는 추출 실패로 표시됩니다. 일시적 읽기·워커 실패는 30초·2분·10분 간격으로 최대 3회 자동 재시도하며 재시작 후에도 예약이 유지됩니다. 손상·암호화 오류는 자동 반복하지 않습니다. 검색 결과의 **다시 추출** 버튼이나 봇 읽기 도구의 `retry_extraction`으로 수동 재시도할 수 있습니다(파일당 5초 간격). 손상되었거나 암호화된 원본은 수정 후 다시 업로드하세요.

채팅에 PDF·XLSX 파일이나 그 파일이 든 폴더를 연결할 수 있습니다. 봇은 `search_files`·`linked_search`로 찾고 `read_file_text`·`linked_read`로 추출 본문을 나누어 읽습니다. 이때 읽기 위치와 크기는 원본 바이너리 파일이 아니라 추출된 UTF-8 본문의 바이트 기준입니다. 검색 결과의 `read`에는 `source: extracted`, 바이트 `offset`·`limit`, 본문 `revision`이 함께 제공됩니다. 봇은 이 값을 읽기 도구에 그대로 전달해 해당 구간을 읽으며, 파일이 바뀌면 다시 검색해야 합니다. 추출 본문은 작은 바이트 조각으로도 저장해 부분 읽기마다 전체 문서를 로드하지 않습니다. PDF·XLSX 본문은 이 도구로 편집하지 않습니다.

| 형식 | 미리보기 |
| --- | --- |
| 이미지 | 원본 비율로 표시 |
| 동영상·음성 | 재생·탐색 컨트롤, byte Range 지원 |
| PDF | 페이지별 보기와 이전·다음 페이지 |
| UTF-8 텍스트·코드 | 줄 번호, 자동 줄바꿈, 다음 부분 읽기. JS·TS·Python·JSON·YAML·SQL·CSS·XML·셸 코드 강조 |
| Markdown | 채팅과 같은 Markdown 표시, 원문 전환 |
| JSON | 한 부분에 들어오는 문서는 들여쓰기 정렬, 원문 전환 |
| CSV·TSV | 앞부분 최대 200행·50열을 표로 표시. 따옴표 안 쉼표·줄바꿈 지원, 원문 전환 |
| HTML·SVG | 실행하지 않고 소스 텍스트로 표시 |

## 채팅에서 다루기

텍스트 편집기는 열었을 때의 파일 버전을 확인하고 저장합니다. 다른 창이나 봇이 먼저 바꿨으면 덮어쓰지 않고 초안을 유지합니다. 필요한 초안을 복사해 둔 뒤 최신 파일을 다시 열어 반영하세요. 페이지 어시스턴트의 문서 저장에도 같은 검사가 적용됩니다. 페이지 없이 쓰는 `write_text_file`·`update_file_text`는 `read_file_text`가 반환한 `revision`을 `expected_revision`으로 전달하면 읽은 버전만 수정합니다.

프로필의 **페이지 어시스턴트**를 켠 1:1 채팅에서 보관함 페이지를 연결하면, 봇이 지금 폴더의 목록과 선택을 보고 다룹니다.

- **바로 하는 일**: 폴더 열기, 파일 미리보기, 항목 선택, 새 폴더·이름 변경·이동 창 열기와 이름·대상 폴더 채우기, 새 문서·텍스트 문서 편집기 열기.
- **카드로 하는 일**: 폴더 만들기·이름 바꾸기, 이동, 삭제, 이전 버전 되돌리기, 문서 저장은 검토 카드로 나오고 사람이 저장을 눌러야 됩니다. 지우는 일은 이 카드로만 됩니다.
- **파일 내용**: 페이지를 연결하는 것만으로는 파일 내용이 봇에게 가지 않습니다(연결 중에는 파일을 읽는 도구도 빠짐). 사람이 편집기로 연 문서만 함께 보이고, 닫으면 빠집니다. 2000자까지는 입력칸으로, 더 긴 문서는 2000자씩 이어 읽고 부분 고치기·이어 쓰기로 바꿉니다.
- 미리보기 중인 텍스트 파일은 이전 버전 목록(언제·누가 바꿨는지)만 보이고, 버전 내용은 보이지 않습니다.
- 페이지 없이 채팅하면 `list_file_versions`·`read_file_version`·`restore_file_version` 도구로 이전 버전을 보고 되돌립니다.

## 검색

툴바의 돋보기를 누르면 경로 자리에 검색창이 열립니다. 내 보관함 전체에서 이름이나 내용에 검색어가 들어간 파일·폴더를 찾고, 결과는 파일명·폴더 경로·찾은 문장 일부로 표시됩니다. 결과를 누르면 미리보기가 열리고, **Esc**나 ✕로 검색을 닫습니다.

- 키워드 검색은 띄어 쓴 단어가 모두 들어 있어야 찾습니다. `"캐릭터 설정"`처럼 따옴표로 묶으면 그 문장 그대로 찾습니다.
- 영문은 대소문자를 구분하지 않습니다. 한 글자·두 글자 검색어도 됩니다.
- 내용 검색 대상은 UTF-8 텍스트 형식(Markdown, txt, JSON, CSV 등)입니다. HTML은 태그·스크립트·스타일을 뺀 보이는 글자만 찾습니다. 텍스트 PDF와 XLSX도 본문을 찾으며 다른 Office 형식은 이름만 찾습니다.
- 추출 범위는 위의 파일 크기·본문 길이 제한을 따릅니다. 결과는 최대 50개입니다. 키워드 검색은 이름 일치를 우선하며 의미 검색을 켜면 두 결과의 순위를 합칩니다.
- 자연어 검색은 최대 2000자이며 의미 검색에 전체 문장을 전달합니다. 키워드 검색에는 앞의 서로 다른 검색어 8개를 사용하고, 그 이상은 화면과 봇 응답에 제한 적용을 표시합니다.
- 채팅은 `search_files` 도구로 같은 검색을 하고, 보관함 페이지를 연결했을 때는 검색어를 채워 검색 화면을 엽니다.

내용은 검색할 때 바뀐 파일만 다시 읽어 `search.db`에 저장해 둡니다(크기·수정 시각 기준). 그래서 처음 검색할 때는 파일이 많으면 조금 걸립니다. 삭제한 파일의 내용은 삭제와 함께 지워집니다. `search.db`는 원본에서 다시 만들 수 있는 사본이라 DB 백업에 들어가지 않고, 지우거나 깨져도 다음 검색 때 다시 만들어집니다.

큰 텍스트는 한 번에 약 16KB씩 읽습니다. 한글 UTF-8 문자가 중간에 잘리지 않으며 **처음**으로 돌아갈 수 있습니다. 이어 읽는 동안 다른 창이나 봇이 파일을 바꾸면 변경 안내가 나오며 **처음부터 다시 읽기**로 최신 내용을 엽니다. 지원되지 않는 형식·코덱·암호화 PDF는 원본을 다운로드해서 엽니다.

아이콘 보기에서 이미지와 동영상은 썸네일이 나옵니다. 동영상은 1초 지점(짧은 영상은 첫 프레임)을 사용하고 `.thumbs`에 캐시합니다. 파일 삭제 때 캐시도 정리됩니다. FFmpeg가 없거나 디코딩이 실패하면 형식 아이콘을 표시합니다.

## 구현·검증 기록 (2026-10-04)

보기 경로 `GET /api/files/:id/view`는 파일 소유권을 확인하고, 업로드 MIME 대신 파일 헤더로 허용 형식을 판별합니다. HTML·SVG와 텍스트 확장자는 `text/plain; charset=utf-8`로 강제합니다. `nosniff`와 `Content-Security-Policy: sandbox`를 적용하고, 기존 다운로드는 `application/octet-stream` + attachment를 유지합니다.

PDF는 [PDF.js의 페이지 렌더링](https://mozilla.github.io/pdf.js/examples/)으로 만든 이미지를 스크립트 없는 sandbox iframe에 표시합니다. 문서 스크립트·폼·링크는 실행하지 않습니다. 폰트·CMap·워커는 앱에서 제공하며 외부 CDN에 파일을 보내지 않습니다. PDF.js는 6.4.299이며 실행 환경은 Node 22.13 이상입니다. PDF 뷰어는 필요할 때만 로드됩니다(현재 JS 약 542KB, gzip 172KB, 별도 워커 약 1.2MB). 코드 강조도 [필요한 언어만 등록한 highlight.js](https://highlightjs.org/#usage)를 지연 로딩합니다(약 64KB, gzip 22KB).

격리 백엔드와 Vite preview에서 이미지·동영상·음성·PDF·텍스트·TS·MD·JSON·CSV·HTML·SVG 표시를 확인했습니다. HTML 실행 차단, 다른 계정 파일의 보기·텍스트·썸네일·이웃 조회 404, Range 206/416, 동시 썸네일 요청, 큰 한글 텍스트 분할 읽기와 원본 다운로드를 확인했습니다.
