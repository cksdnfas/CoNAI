# 채팅 (Codex · Claude Code · API LLM)

채팅 프로필과 대화하면서 CoNAI를 조작합니다. 프로필마다 엔진을 고릅니다.

- **Codex**: 서버에 연결된 Codex CLI. 대화 기억은 Codex가 직접 관리합니다.
- **Claude Code**: 서버에 설치된 Claude CLI를 사용합니다. 대화 기록·최근 턴·요약은 CoNAI가 관리하며, 요청마다 전용 홈에서 실행합니다. 프로필의 모델에는 `sonnet`, `opus`, `haiku` 또는 사용 가능한 모델 ID를 입력합니다.
- **API LLM**: 설정의 LLM 연결(OpenAI 호환, Ollama). 로컬 엔진(예: Strata, LM Studio)이나 외부 API를 쓸 수 있고, 대화 기억(최근 턴·토큰 한도·요약)은 프로필에서 정합니다.

모든 엔진은 현재 계정과 프로필이 허용한 CoNAI 도구만 사용합니다. 이미지 검색·메타데이터 조회·NAI/등록된 ComfyUI 생성·그룹 정리를 요청할 수 있습니다. 채팅에서 Codex 이미지 생성, 그래프 실행, 실행 가능한 워크플로 가져오기는 차단됩니다. 해당 작업은 웹사이트의 기존 화면에서 직접 실행합니다.

## 위치

- **패널**: 상단 헤더의 채팅 아이콘을 누르면 어느 페이지에서든 오른쪽 패널로 열립니다. 패널은 [채팅 목록](#채팅-목록)과 채팅 화면을 오가며, 채팅 화면 왼쪽 위 ←로 목록에 돌아갑니다. 다시 열면 닫을 때 보던 화면이 나옵니다. 휴대폰 폭에서는 전체 화면으로 열리고, 뒤로가기는 이미지 모아보기·컨텍스트 → 채팅 → 목록 순으로 한 단계씩 나가다가 목록에서 닫힙니다.
- **전체 페이지**: `/#/chat`. 패널 목록의 "전체 페이지로 열기"로 넘어가고, "패널로 접기"로 돌아옵니다. 왼쪽에 채팅 목록이 나옵니다(휴대폰 폭에서는 패널처럼 목록과 채팅을 오갑니다).

채팅이 켜져 있고 계정에 채팅 권한이 있을 때만 헤더에 채팅 아이콘이 보입니다. 예전 주소 `/#/generation?tab=chat`은 `/#/chat`으로 넘어갑니다. 페이지를 옮기거나 패널과 전체 페이지를 바꿔도 진행 중인 답변은 끊기지 않습니다.

## 설정

설정 → **채팅**. 바꾼 값은 바로 적용됩니다. 위쪽 글자 탭 세 개로 화면이 나뉩니다(주소는 `?section=chat&view=resources`처럼 `view`로 열 수 있습니다).

| 탭 | 들어 있는 것 |
| --- | --- |
| **프로필** | **채팅 사용**(모든 프로필의 전체 스위치)과 채팅 프로필 목록. 목록에서 켜고 끄고, 연필 아이콘으로 편집합니다. 한 줄에 아바타, 이름, 쓰는 대화 모델(`★ 모델`, 마우스를 올리면 `연결 · 모델`)과 도구 표시가 보입니다. |
| **자원** | 프로필들이 가져다 쓰는 도구 프리셋, 생성 프리셋, 표시 블록, 로어북. 도구 프리셋은 프로필 도구 탭에서 불러와 복사하는 틀이라 고치거나 지워도 프로필은 그대로입니다. 줄에는 이름과 요약, 어느 프로필에 연결됐는지만 보이고, 편집·삭제·**내보내기**·**복제**는 줄을 열면 나오는 편집 창 아래쪽 버튼으로 합니다. |
| **내 설정** | 내 계정의 사용자 프로필과 플래그. |

설정 → **LLM** 탭은 모델과 접속 정보를 정합니다.

- **CLI 인증과 업데이트**(관리자): Codex와 Claude Code의 설치·인증 상태, 현재/최신 버전을 확인하고 로그인·설치·업데이트합니다. Codex 이미지 생성 탭의 기존 로그인·업데이트 기능과 같은 서버 상태를 사용합니다. Claude Code는 인증 링크에서 로그인한 뒤 코드가 표시되면 로그인 창에 붙여넣습니다. 서버 계정의 사용량을 공유하며 `chat.agent.use` 권한이 필요합니다.

- **LLM 연결**: 연결 하나가 서버 하나이고, 그 서버에서 쓰는 모델이 연결 아래 줄로 붙습니다(서버 ▸ 모델).
  - **연결 줄**: 이름, 종류(OpenAI 호환·Ollama·TypeSafe 판단 모델), 주소, API 키, 요청 제한 시간, 동시 요청 수, 생각 끄는 방법, **프롬프트 캐시 표시**. 연필 아이콘으로 편집합니다. OpenAI 호환 연결의 **연결 테스트**(플라스크 아이콘)는 첫 모델에 짧은 요청을 보내 저장된 생각 끄는 방법이 실제로 생각을 끄는지 보고, 안 꺼지면 되는 방법(`reasoning_effort: none` → `enable_thinking: false` → 보내지 않음 순)으로 바꿔 둡니다. 바뀐 칸에는 점과 테두리가 붙고, **저장**해야 적용됩니다. 연결 자체에는 모델이 없습니다.
  - **모델 고르기**: 연결 편집 창 아래쪽에 서버가 알려 주는 모델 목록이 체크 박스로 나오고, 체크한 모델이 연결 아래 줄이 됩니다. 새 연결은 주소를 넣으면 첫 모델이 미리 체크되어 저장 한 번으로 끝납니다. 목록을 알려 주지 않는 서버는 아래 칸에 모델 ID를 적어 추가합니다. 쓰는 곳이 있는 모델은 자물쇠와 사용처 수가 표시되고 체크를 풀 수 없습니다.
  - **모델 줄**: 모델 ID와 사용처 수(마우스를 올리면 프로필과 역할, 판단 프리셋, 사용자 프로필, 채팅 반응, 워크플로우 노드)가 보이고, 쓰는 곳이 없으면 **사용처 없음**이 붙습니다. 줄을 누르면 모델 ID를 바꾸거나 지웁니다. 모델 ID를 바꾸면 그 줄을 쓰는 프로필·판단·워크플로우 노드가 모두 따라 바뀝니다. 쓰는 곳이 있는 줄은 지울 수 없습니다.
  - **기본 모델**(★): 모델 줄 하나(LLM 연결의 모델만)가 기본입니다. 새 프로필의 대화 모델이 되고, 대화 모델이 없는 프로필도 이 모델을 씁니다. 기본 줄이 지워지면 남은 첫 LLM 모델이 기본이 됩니다.
  - 쓰는 모델이 있는 연결은 지울 수 없고, 어디서 쓰는지 알려 줍니다. 쓰지 않는 모델만 있으면 연결과 함께 지워집니다.
  - 이전 버전의 연결 기본 모델, 프로필의 **직접 지정**(연결 + 모델), 판단 연결, 모델 슬롯은 처음 시작할 때 각 연결 아래 모델 줄로 옮겨지고, 원래 쓰던 서버와 모델을 그대로 씁니다. 같은 연결·모델의 슬롯이 여럿이면 하나로 합쳐지고, 슬롯 이름은 쓰지 않습니다.
- 캐시 표시는 LiteLLM·OpenRouter 같은 경로로 Anthropic 모델을 쓸 때 필요합니다. 모델 ID에 `claude`가 들어가면 스위치를 켜지 않아도 붙습니다. 요청의 고정 부분(캐릭터 설정, 그 뒤의 로어 목차·요약, 참고 설정 블록 앞까지, 마지막 메시지 앞까지)에 `cache_control` 표시를 붙여 Anthropic이 그 앞부분을 캐시에서 읽게 합니다. 캐릭터 설정과 요약을 따로 표시하므로 요약이 바뀌어도 캐릭터 설정은 캐시에서 읽힙니다. 표시를 모르는 서버가 거절하면 표시 없이 다시 보내고, 그 연결·모델에는 한 시간 동안 표시를 붙이지 않습니다. OpenAI와 로컬 엔진은 표시 없이도 같은 앞부분을 알아서 캐시합니다.
- **로컬 서버를 빠르게 쓰는 법**: 로컬 엔진(llama.cpp·Strata·LM Studio·Ollama)은 직전 요청과 앞부분이 같을 때만 프롬프트를 다시 읽지 않습니다. 채팅은 요청 앞부분(도구 목록·캐릭터 설정)을 턴마다 같게 유지합니다. 그래도 판단·번역·요약 모델이 대화 모델과 같은 서버의 슬롯 하나를 나눠 쓰면, 답변 직전의 판단 요청이 대화의 캐시를 밀어내서 매 답변이 프롬프트 전체를 다시 읽습니다. 판단·요약을 쓰는 프로필은 서버를 슬롯 2개 이상으로 띄우거나(llama.cpp `-np 2`, 이때 슬롯마다 컨텍스트가 나뉩니다), 판단·요약용 작은 모델을 다른 연결로 두면 빨라집니다. llama.cpp는 `--cache-ram`으로 밀려난 캐시를 일부 되살립니다. 판단·번역이 대화와 같은 연결을 쓰는데 그 연결의 **동시 요청**이 1이면, 연결 편집 창의 동시 요청 옆에 ⚠가 뜨고 마우스를 올리면 해당 프로필이 보입니다. 같은 연결에서는 답변에 필요한 요청(번역·판단·답변)이 답변 뒤의 정리 작업(상태 판단·후속 판단·미리 요약·생성 반응)보다 먼저 서버를 씁니다.
- **컨텍스트 길이**: 프로필에 컨텍스트 길이가 없으면, 서버가 알려 주는 크기(llama.cpp `/props`, `/v1/models`, LM Studio)가 64k 이하일 때 그 값을 프로필에 넣은 것처럼 씁니다. 조회는 답변을 기다리게 하지 않고 뒤에서 하며, 다음 답변부터 쓰입니다. 서버가 "컨텍스트 크기를 넘었다"며 크기를 알려 주면 그 값도 바로 씁니다.
- **도구를 못 받는 모델**: 서버가 도구 정의 때문에 요청을 거절하면(Ollama "does not support tools", `--jinja` 없는 llama-server) 도구 없이 다시 보내고, 그 연결·모델에는 10분 동안 도구를 보내지 않습니다. 할 일이 없는 롤플레이 프로필(도구 범위·페이지·생성 프리셋 없음)에는 작업 도구가 처음부터 붙지 않습니다.
- 온도·출력 길이·추론 같은 생성 옵션은 연결이나 모델 줄이 아니라 **프로필**에서 정합니다. 워크플로우의 LLM 호출 노드도 프로필을 골라 같은 옵션으로 실행합니다.

### 채팅 프로필 항목

편집 창은 **캐릭터**(이름·아바타·프롬프트·로어북 연결), **모델**(대화 모델·생성 옵션·보조 모델·컨텍스트), **꾸미기**, **도구** 네 탭입니다. 설명이 필요한 항목은 라벨 옆 ⓘ에 마우스를 올리면(휴대폰은 누르면) 툴팁으로 나오며, 아래 표에는 그 내용을 함께 적었습니다. 내보내기·복제·삭제는 목록 줄이 아니라 편집 창 아래쪽 버튼입니다. 저장에 꼭 필요한 값(이름, 대화 모델)이 비어 있으면 그 탭 이름 옆에 점이 표시됩니다. 꾸미기의 이모티콘 그룹·등장인물·표시 블록은 접혀 있고, 내용이 있으면 펼쳐진 채로 열립니다.

| 항목 | 설명 |
| --- | --- |
| 이름·아바타 | 채팅에 표시되는 이름과 그림. 아바타는 정사각형으로 잘라 작게 저장합니다. |
| 짧은 소개 | 새 채팅 프로필 카드에 표시할 한 줄 소개(최대 200자). |
| 엔진 | **모델** 탭 맨 위. API LLM, Codex 또는 Claude Code. |
| 사용 대상 | 엔진 바로 아래. **모두**(엔진 권한이 있는 모든 계정) 또는 고른 권한 그룹의 계정만 이 프로필로 채팅합니다. 관리자는 항상 쓸 수 있으니 **관리자**만 고르면 관리자 전용이 됩니다. |
| 대화 모델 | API LLM. 한 칸에서 고릅니다. 연결별로 묶인 모델(`★`는 기본 모델) 중 하나를 고르며, 그 모델 줄이 바뀌면 프로필도 따라 바뀝니다. 목록에 없는 모델은 설정 → LLM에서 연결 아래에 먼저 추가합니다. 새 프로필은 기본(★) 모델로 시작합니다. |
| 온도·최대 출력 토큰 | API LLM. 비우면 요청에 넣지 않아 서버 기본값을 씁니다. 최대 출력 토큰은 추론과 답변을 합친 한도이며, 채팅마다 **⋯ → 컨텍스트**에서 따로 정하면 그쪽이 우선입니다. |
| 추론 강도·추론 토큰 예산 | API LLM. `reasoning_effort`(none·low·medium·high)와 `reasoning_budget_tokens`로 보냅니다(LiteLLM·OpenAI 호환 형식, Ollama는 `think`). 비우면 보내지 않습니다. 대화 요약은 추론을 끄고(none) 보냅니다. |
| 고급: 추가 파라미터 (JSON) | API LLM. 서버마다 다른 옵션을 요청 본문에 그대로 붙입니다(예: `{"chat_template_kwargs": {"enable_thinking": true}}`). `model`, `messages`, `stream`, `tools`는 덮어쓸 수 없습니다. |
| 이미지를 볼 수 있는 모델 | API LLM. 켜면 `view_images`·`view_media_frames` 도구로 받은 이미지를 모델에게 그대로 보여 줍니다. 비전을 지원하지 않는 모델에서 켜면 요청이 실패할 수 있습니다. |
| 허용 등급 | 이미지를 보는 모델에만 표시. 이 등급(설정 → 자동화 및 분석의 평가 등급)을 넘는 이미지·영상·움짤은 모델에 보내지 않습니다. API LLM은 **모델 설정 따름**(설정 → LLM에서 모델 줄을 눌러 정한 값)이 기본이고, 프로필에서 직접 고르면 그쪽이 우선입니다. Codex·Claude Code는 프로필에서만 정합니다. 아래 [허용 등급](#허용-등급) 참고. |
| Codex 모델·추론 강도 | Codex. 비우면 채팅 전용 런타임의 기본값을 씁니다. 호스트 사용자 설정은 가져오지 않습니다. 모델이 지원하지 않는 추론 강도는 저장되지 않습니다. |
| 시스템 프롬프트 | 대화마다 지시문으로 들어갑니다. `{{char}}`는 프로필 이름으로 바뀝니다. |
| 섹션 | **섹션 추가**로 제목과 내용을 직접 만듭니다(예: 캐릭터, 세계관, 내 페르소나). 접고 펼칠 수 있고, 스위치로 잠시 빼 둘 수 있습니다. 일반 텍스트 섹션은 시스템 프롬프트 뒤에 `## 제목`으로 붙습니다. |
| 섹션 형식: 대화 예시 | `사용자:` / `{{user}}:` 와 `{{char}}:` / 프로필 이름으로 시작하는 줄이 있으면, API LLM에는 지시문 대신 **실제 user/assistant 대화**로 넘겨 말투를 더 잘 따라 하게 합니다(예시라는 안내가 지시문에 붙습니다). 화자 표시가 없거나 Codex 프로필이면 텍스트로 붙습니다. |
| 첫 인사말 | 새 채팅을 시작하거나 채팅을 초기화할 때 추가 인사말과 함께 후보가 되어, 무작위로 고른 하나가 첫 메시지로 저장됩니다(지시문에는 들어가지 않습니다). |
| 추가 인사말 | 첫 인사말 줄을 펼쳐 추가 인사말을 두고 고칩니다. 캐릭터 카드의 추가 인사말이 여기로 들어옵니다. API LLM·Codex 모두 비어 있지 않은 기본·추가 인사말 중 하나를 같은 확률로 고릅니다. 같은 인사말이 연속으로 나올 수도 있으며, 기존 대화는 유지됩니다. |
| 프리셋 불러오기 | 책 아이콘. 설정 → **LLM** 탭의 프리셋을 불러옵니다. 시스템 프롬프트 프리셋은 시스템 프롬프트를 바꾸고(내용이 있으면 확인 후), 프롬프트 프리셋은 같은 이름의 섹션으로 추가됩니다. 처음 실행하면 캐릭터 롤플레이 기본, CoNAI 도우미, 이미지 프롬프트 작가, 롤플레이 출력 형식 같은 기본 프리셋이 한 번 들어가며, 이후에는 자유롭게 고치거나 지울 수 있습니다. |
| 프롬프트 미리보기 | 눈 아이콘. 모델이 받는 지시문·예시 대화·도구 목록과 토큰 추정치(프롬프트, 도구 설명, 합계)를 보여 주고, 컨텍스트 길이를 넘으면 표시합니다. |
| 꾸미기: 글꼴 | 이 프로필 채팅의 글꼴(기본·명조·고정폭). |
| 꾸미기: 배경 이미지 | 채팅 뒤에 깔리는 그림. 긴 변 1600px로 줄여 저장하고, 어둡게·흐리게 정도로 글이 잘 읽히게 맞춥니다. |
| 꾸미기: 롤플레이 글자색 | 켜면 `"대사"`, `*묘사*`, `'속마음'`을 각각 다른 색으로 보여 주고(대사를 비우면 기본 글자색), 모델에게 이 표기법을 쓰라고 지시문으로 알려 줍니다. 아래 예시 줄에서 바로 확인할 수 있습니다. |
| 꾸미기: 등장인물 | 프로필 말고도 답변에 함께 나오는 캐릭터(최대 8명). 이름·아바타·이름 색을 정합니다. 모델은 다른 캐릭터가 말할 때 `[이름]` 줄로 화자를 바꾸라고 안내받고, 채팅은 그 줄에서 답변을 나눠 캐릭터마다 아바타와 이름을 따로 보여 줍니다. 등록되지 않은 이름의 `[…]` 줄은 그대로 글로 둡니다. |
| 꾸미기: 이모티콘 그룹 | 연결할 [LLM 이모티콘 그룹](GROUPS_GUIDE.md#llm-이모티콘-그룹)을 고릅니다. 고른 순서가 우선순위라서, 두 그룹에 같은 키워드가 있으면 먼저 고른 그룹의 이미지가 쓰입니다. 모델은 지시문으로 키워드 목록(최대 150개)과 `&*키워드*&` 표기법을 안내받습니다. |
| 꾸미기: 표시 블록 | 상태창(호감도·HP·소지품 같은 값)으로 쓰는 블록. 아래 [표시 블록](#표시-블록) 참고. |
| CoNAI 도구(MCP) 사용·권한 | 조회·생성·정리·설정 중에서 고릅니다. 각 도구는 채팅하는 계정의 기능 권한도 확인하며, 설정은 관리자 계정에서만 동작합니다. |
| 생성 프리셋 | 연결한 NAI·ComfyUI 프리셋은 생성 도구가 되고 생성 범위가 함께 켜집니다. 대신 자유 생성과 워크플로 조회 도구는 빠집니다. 실행에는 계정의 `generation.execute`가 필요합니다. 연결을 해제하면 해당 도구도 해제됩니다. |
| 도구 탭의 고급 | 펼쳐서 **도구를 하나씩** 고를 수 있습니다. 도구 설명이 프롬프트를 크게 차지하므로(전체 약 5천~1만 토큰), 컨텍스트가 짧은 모델은 필요한 도구만 고르면 가벼워집니다. API LLM은 도구 호출 반복 한도(한도에 닿으면 도구 없이 답함)와 도구 결과 최대 길이도 정합니다. |
| 최근 턴 수 | API LLM. 요청마다 보내는 최근 대화(사용자 메시지 하나와 그 답변이 한 턴). 창이 꽉 차면 가장 오래된 턴을 한 턴씩이 아니라 상한의 1/4만큼 묶어서 빼서, 요청 앞부분이 여러 턴 동안 그대로 유지됩니다(서버 프롬프트 캐시가 맞습니다). |
| 기본 작가 노트 | 이 프로필의 모든 채팅에 매 요청 들어가는 장면 지시(예: "대사는 짧게"). 캐릭터 설정과 달리 대화 끝 쪽(로어북 삽입 위치)에 들어가서 작은 모델도 잊지 않습니다. 채팅마다 **⋯ → 컨텍스트**에서 따로 쓰면 그쪽이 우선입니다. |
| 컨텍스트 길이 | API LLM. 비우면 제한이 없습니다. 지정하면 시스템 프롬프트·요약·도구 설명·답변 몫을 뺀 만큼만 최근 턴을 보냅니다. 토큰 수는 서버가 알려 주는 실제 사용량으로 프로필마다 보정합니다. 컨텍스트가 짧은 모델에 맞춰 줄입니다. |
| 요약·한 번에 요약할 턴 수 | API LLM. 켜면 요약 이후의 턴만 원문으로 보내고, 그 턴들이 턴 수나 토큰 한도를 채우면 창 밖으로 밀려나기 전에 가장 오래된 턴을 이 수만큼 요약에 합칩니다. 원문과 요약 사이에 빠지는 턴이 없습니다. 답변 직후에 미리 요약하고, 요청 때 아직 넘치면 요약이 끝날 때까지 기다렸다 보냅니다. |
| 보조 모델 | **요약**(API LLM만)·**번역**·**답장 추천**마다 한 줄씩 고릅니다. 선택지는 **끔**(번역은 **안 함**), **대화 모델 그대로**(요약·답장 추천만), 연결별로 묶인 모델입니다. 가볍고 빠른 모델로 맡길 수 있습니다. 요약은 켜면 기본 요약 프롬프트(또는 아래 **요약 프롬프트**)로 요약합니다. 번역을 고르면 내 메시지는 영어로 번역해서 대화 모델에 보내고, 답변은 한국어로 번역해서 보여 줍니다(아래 [번역](#번역) 참고). 답장 추천은 입력창 옆 반짝이 버튼을 누를 때만 내가 다음에 할 말 3개를 제안합니다. Codex 프로필에는 번역과 답장 추천만 있고, 답장 추천을 켜려면 모델을 골라야 합니다(**대화 모델 그대로**는 없습니다). |
| 로어북 최근 메시지·토큰 상한·삽입 위치 | 컨텍스트 묶음의 로어북 값. 얼마나 최근 메시지까지 훑을지, 한 번에 넣을 토큰 상한, 대화 끝에서 몇 턴 앞에 넣을지입니다([로어북](#로어북) 참고). |
| 압축 기준 | Codex. 토큰. Codex가 대화를 압축하는 기준입니다(기본 64,000, 최소 48,000). |

이전 버전의 Codex 채팅 설정(사용 여부, MCP 권한, 실행 모델, 추론 강도)은 처음 채팅을 열 때 **Codex** 프로필로 옮겨지고, 기존 Codex 채팅도 그 프로필에 연결됩니다.

### 표시 블록

채팅마다 블록별 **상태**(JSON 값)를 서버가 들고 있고, 모델은 매 답변에 **바뀐 값만** 씁니다. 모양은 프로필에 미리 만든 템플릿이 정하므로 작은 모델도 꾸민 상태창을 낼 수 있고, 모델이 쓴 내용이 코드로 실행되지 않습니다. 현재 값은 매 요청 대화 끝쪽 `[참고 설정]`에 작가 노트와 함께 들어가서, 캐릭터가 호감도·소지품 같은 값을 사실로 알고 행동합니다.

1. **표시 블록 추가**를 누르면 상태창 예시가 채워진 블록이 생깁니다.
2. **이름**은 모델이 쓰는 코드 블록 이름입니다. 이름이 `status`면 모델은 ` ```status ` 블록 안에 바뀐 필드만 JSON으로 씁니다. `null`로 쓴 필드는 지워지고, 목록은 통째로 바뀝니다.
3. **시작 값(JSON)**은 새 채팅의 첫 상태이자 모델에게 보여 주는 형식입니다. 아래 미리보기에도 쓰입니다. `{{char}}`는 캐릭터 이름으로 바뀝니다.
4. **언제 쓰는지**와 **갱신 규칙**(예: "items는 실제로 얻거나 잃은 것만 바꿔")은 지시문과 현재 값 옆에 들어갑니다. 모델이 지키는 걸 전제로 하는 말 규칙입니다.
5. **필드 규칙**은 서버가 강제합니다. 필드마다 최소·최대, 한 답변에 움직일 수 있는 폭(턴당), 허용 값 목록, 고정(모델이 못 바꿈)을 정하면 모델이 어겨도 그 범위로 잘라서 반영합니다. 허용 값 밖의 값과 고정 필드의 변경은 버립니다. 같은 내용이 지시문에도 자동으로 들어가고, 상태창에서 직접 고친 값에는 적용되지 않습니다.
6. **한 줄 요약**은 접힌 상태창에 보일 한 줄 템플릿입니다(예: `{{place}} · HP {{hp}}`). 비우면 앞쪽 값 몇 개를 자동으로 보여 줍니다.
7. **HTML 템플릿**에 값이 들어갈 자리를 표시하고, **CSS**로 꾸밉니다.

| 템플릿 문법 | 뜻 |
| --- | --- |
| `{{name}}`, `{{a.b}}` | 값. 목록은 쉼표로 이어 붙입니다. |
| `{{hp / maxhp * 100}}`, `{{"Lv." + level}}` | 계산식. `+ - * / %`, 괄호, 숫자·문자열(따옴표)·`true`/`false`를 씁니다. 소수는 둘째 자리까지 보입니다. |
| `{{round(x, 1)}}` 등 | 함수: `round` `floor` `ceil` `abs` `min` `max` `clamp(x, 최소, 최대)` `pct(x, 최대)`(0~100%) `len(목록)` `join(목록, "·")`. |
| `{{#each items}}…{{/each}}` | 목록을 반복합니다. 안에서 `{{.}}`은 항목 자체, `{{field}}`는 항목의 필드입니다. |
| `{{#if field}}…{{else}}…{{/if}}` | 값이 있을 때(빈 값·0·false가 아닐 때)만 보여 줍니다. |
| `{{#if affinity >= 50 && mood == "들뜸"}}` | 비교 조건: `== != < <= > >=`와 `&& \|\| !`. 호감도 구간별 표정·칭호 같은 걸 모델 도움 없이 바꿀 수 있습니다. |
| `data-pick="캔커피 사용"` | 누를 수 있는 요소. 누르면 그 글이 **선택**으로 입력창 위에 쌓이고, 다음 메시지와 함께 `[사용자 선택]`으로 모델에게 갑니다. 글 없이 보내면 선택 글이 메시지가 됩니다. 값을 비우면 요소의 글자가 쓰이고, 선택된 요소에는 `picked` 클래스가 붙어 CSS로 표시할 수 있습니다. 인벤토리·스킬 슬롯에 씁니다. |
| `data-set="focus=true"` | 누르면 그 필드를 바로 그 값으로 바꿉니다(직접 고치기와 같음). 값은 JSON으로 읽히면 숫자·참거짓·목록, 아니면 글자입니다. 토글·장비 슬롯에 씁니다. |

- 값은 글자로만 들어갑니다. 모델이 값에 HTML을 써도 태그가 아니라 글자로 보입니다.
- 스크립트, 이벤트 속성(`onclick` 등), 프레임, 폼, `javascript:` 주소는 템플릿에 있어도 지워집니다.
- CSS는 그 블록 안에만 적용돼서 앱 화면에 영향을 주지 않습니다.
- 값이 JSON으로 읽히지 않으면(답변이 아직 오는 중일 때 포함) 평범한 코드 블록으로 보입니다.
- 상태는 저장되지 않고 대화에서 그때그때 접어서 계산합니다. 답변을 다시 생성하거나 다른 답변으로 바꾸거나 메시지를 지우면 상태도 그에 맞게 돌아갑니다. 상태창에서 직접 고친 값은 채팅에 남아 그 시점부터 적용되고, **대화 비우기**로 함께 지워집니다.
- 그룹 방에서는 참가자마다 자기 블록의 상태를 따로 가집니다. 참가자의 답변만 그 참가자의 상태를 바꾸고, 각 참가자는 자기 상태만 받아 봅니다. 상태창 탭은 "이름 · 블록" 꼴로 참가자별로 놓입니다.

### 번역

영어가 더 능숙한 모델을 한국어로 쓰고 싶을 때 프로필의 보조 모델에서 **번역** 모델(LLM 연결의 모델 중 하나)을 고릅니다. 가볍고 빠른 모델이면 충분합니다.

- **보내는 쪽**: 내 메시지는 영어로 번역한 뒤 대화 모델에 보냅니다. 저장도 영어 본문이 모델용 기록(컨텍스트·요약·검색)이 되고, 내가 쓴 원문은 화면용으로 따로 보관합니다. 한글이 없는 메시지는 번역하지 않습니다.
- **받는 쪽**: 답변은 영어로 실시간 스트리밍되고, 다 쓰이면 **번역 중…**이 표시된 뒤 한국어로 바뀌어 저장됩니다. 모델이 이미 한국어로 답하면 번역하지 않습니다.
- **번역 지시**: 프로필 편집 → 모델 › 보조 모델에서 번역 모델을 고르면 그 아래에 **번역 지시** 칸이 나옵니다. 답변을 한국어로 옮길 때 번역 모델이 따르는 메모로, 캐릭터의 말투·호칭·말버릇이나 고유명사 번역표를 적습니다(예: `{{char}}는 무뚝뚝한 반말, 문장 끝을 "…"로 자주 끊음. {{user}}를 "선배"라고 부름.`). `{{char}}`·`{{user}}`는 이름으로 바뀌고, 칸을 비워도 번역 모델은 누구의 대사인지(캐릭터 이름)는 받습니다. 내 메시지를 영어로 옮길 때는 쓰지 않습니다. 그룹 방은 참가자마다 자기 프로필의 지시를 따릅니다.
- **원문 전환**: 번역된 메시지(내 메시지, 답변 모두)에는 마우스를 올리면(휴대폰은 누르면) 답장 옆에 번역 아이콘이 나옵니다. 누르면 모델이 실제로 보낸·받은 영어 원문을, 다시 누르면 번역을 보여 줍니다. 답장 인용과 메시지 수정은 화면용 본문(한국어)을 씁니다.
- **지켜지는 것**: 코드 블록, 표시 블록 펜스, `@멘션`, `{{user}}` 같은 자리표시자, `&*키워드*&` 이모티콘 토큰, `[이름]` 캐스트 줄은 그대로 두라고 번역 모델에 지시하고, 번역 결과에서 이들의 개수가 달라지면 그 번역은 버리고 원문을 보여 줍니다.
- **실패하면**: 번역 연결이 없어졌거나 요청이 실패·시간 초과하면 메시지는 번역 없이 그대로 보내고 보여 줍니다. 채팅이 멈추지는 않습니다.
- **그룹 방**: 답변은 참가자마다 자기 프로필의 번역 모델로 번역하고, 내 메시지는 대표부터 순서대로 번역 모델이 있는 첫 참가자의 설정으로 번역합니다.

Markdown 내보내기는 번역 본문 아래에 원문을 접어서 넣고, JSON 내보내기에는 둘 다(`content`·`display_content`) 들어갑니다.

### 권한

설정 → 계정·권한의 권한 그룹에서 **채팅** 묶음으로 부여합니다. 관리자는 모두 가집니다.

| 권한 | 설명 |
| --- | --- |
| 채팅 (`chat.use`) | API 모델 프로필로 채팅합니다. |
| 서버 에이전트 채팅 (`chat.agent.use`) | Codex·Claude Code 프로필로 채팅합니다. 서버에 로그인된 계정 사용량을 함께 씁니다. |
| 채팅 진단 보기 (`chat.diagnostics.view`) | 내 답변의 구성을 봅니다. 관리자 프롬프트 원문은 관리자만 봅니다. |

봇 전용 도구 권한은 없습니다. 봇은 채팅하는 계정이 웹에서 가진 기능 권한 안에서, 프로필 도구 탭이 허락한 범위만 씁니다. 설정 범위(설정 제안)는 관리자 계정에서만 동작합니다. 자세한 규칙은 [보안과 권한](./SECURITY_AND_PERMISSIONS.md#채팅-봇의-권한)을 참고하세요.

### 채팅에서 설정 제안

프로필의 도구 권한에 **설정**을 켜면, 에이전트에게 "이런 상태창 만들어 줘"나 "이 프로필 말투를 바꿔 줘"처럼 말로 요청할 수 있습니다. 에이전트는 설정을 직접 바꾸지 않고 제안만 하며, 제안은 답변 아래 카드로 나타납니다.

| 카드 | 내용 |
| --- | --- |
| 표시 블록 제안 | 블록 미리보기와 필드 규칙. **이 프로필에 연결**을 켠 채 저장하면 말하고 있는 프로필에도 바로 연결합니다. |
| 프로필 제안 | 이름·소개·시스템 프롬프트 요약. 저장하면 새 프로필이 만들어집니다. |
| 프로필 수정 제안 | 바뀌는 항목의 이전 값(취소선)과 새 값. 저장하면 그 프로필이 제자리에서 바뀝니다. |

- **저장**: 제안을 그대로 저장합니다. 끝나면 카드가 "저장됨"으로 바뀌고, 다시 열어도 그대로입니다.
- **편집기에서 열기**: 설정 화면의 편집기를 제안 내용으로 채워서 엽니다. 다듬은 뒤 직접 저장합니다.
- 누르기 전에는 아무것도 저장되지 않습니다. 카드의 버튼은 관리자에게만 보이고, 다른 계정에는 제안 내용만 보입니다.

## 사용

1. 헤더의 채팅 아이콘으로 채팅을 엽니다. PC에서는 패널 왼쪽 가장자리를 끌어 폭을 바꿀 수 있습니다(더블클릭하면 기본 폭, 이 브라우저에 저장).
2. 채팅 목록에서 이어갈 채팅을 고르거나, 목록 위의 **+**로 새 채팅 화면을 엽니다. 큰 아바타, 소개, 엔진·모델이 있는 프로필 카드를 고르면 새 대화 화면이 열리고 첫 인사말이 보입니다. 1:1 채팅은 첫 메시지를 보낼 때 그 인사말과 함께 저장되므로, 보내지 않고 나가면 목록에 아무것도 남지 않습니다(저장 전에는 첨부·플래그·채팅 메뉴를 쓸 수 없습니다). 그룹 만들기와 대화 가져오기는 바로 저장됩니다. 카드는 최근에 1:1로 대화한 프로필부터 놓이고, 아직 대화한 적 없는 프로필은 그 뒤에 설정 순서대로 놓입니다. 검색으로 프로필을 좁힐 수 있고, ←로 목록에 돌아갑니다. 패널은 한 열, 넓은 전체 페이지는 두 열입니다.
3. 입력창에 요청을 적고 Enter로 보냅니다. 줄바꿈은 Shift+Enter입니다.
4. 답변이 실시간으로 표시됩니다. 동영상은 썸네일 자리에서 소리 없이 반복 재생되고, 뷰어에서 열면 소리와 함께 재생됩니다. 생각하는 모델은 "생각하는 중…"을 눌러 과정을 볼 수 있습니다(저장되지는 않습니다). 쓴 도구는 이름 옆에 렌치 아이콘과 횟수로 나오고, 마우스를 올리면(휴대폰은 누르면) 도구별 횟수·결과 요약 목록이 열립니다.
   답변은 마크다운으로 표시됩니다(제목, 목록, 표, 링크, 인용, 코드). 코드 블록에는 언어 표시와 복사 버튼이 있고, `html`·`svg` 블록은 눈 아이콘으로 미리 볼 수 있습니다. 미리보기는 스크립트·폼·프레임·네트워크 요청을 차단한 정적 격리 창(sandbox)입니다. 인라인 스타일과 data/blob 미디어만 표시하며, 대화형 JavaScript는 실행하지 않습니다. 원본 코드는 복사할 수 있습니다. 코드 블록 밖의 HTML은 실행하지 않고 글자로 보여 줍니다. 두 엔진 모두 이 표시 방식을 지시문으로 안내받습니다.
5. 생성하거나 찾은 이미지는 답변에 나옵니다. 답변이 **생성한** 이미지(생성 도구 결과)는 크게, 검색·조회로 **찾은** 이미지는 그 아래 정사각 썸네일 그리드로 작게 보입니다. 그리드는 패널에서 3열, 넓은 전체 페이지에서 6열이며 한 번에 6장씩 보여 주고, 더 많으면 아래 ‹ › 와 쪽수로 넘깁니다(높이는 그대로라 스크롤이 밀리지 않습니다). 같은 이미지가 둘 다에 걸리면 생성 쪽에만 나옵니다. 생성 직후 파일 후처리가 끝나기 전이면 잠시 대기 표시가 나왔다가 자동으로 다시 불러옵니다(약 1분까지). PC에서는 마우스를 올리면 크게 미리 보이고, 누르면 페이지를 떠나지 않는 이미지 뷰어가 열립니다. 썸네일에 마우스를 올리면 모서리에 **참조** 버튼이 나타나고(뷰어 도구 모음에도 같은 버튼), 누르면 그 이미지가 다음 메시지의 앱 미디어 첨부로 들어갑니다. 한 번 더 누르면 빠집니다. 뷰어에서 같은 답변의 이미지를 ← →(휴대폰은 좌우로 밀기)로 넘기고, 더블클릭으로 원본 크기를 보고, 상세 보기·다운로드를 할 수 있습니다. ESC·뒤로가기·바깥 클릭으로 닫으면 채팅으로 돌아옵니다.
6. 답변 도중 중단 버튼으로 멈출 수 있습니다. 답변이 오는 동안에도 목록으로 나가거나 다른 채팅을 열어 볼 수 있고, 답변은 끝까지 저장됩니다. 답변은 한 번에 하나만 받기 때문에, 그동안 다른 채팅에서는 보내기와 다시 답하기가 잠깁니다.
7. 프로필에서 **답장 추천**을 켰다면 입력창 옆 반짝이 버튼을 눌러 내가 다음에 할 말 3개를 받아 봅니다. 누를 때만 만들고, 하나를 누르면 입력창에 채워집니다(바로 보내지는 않습니다). 대화가 이어지면 추천은 닫히고, 다시 뽑기 버튼으로 새로 받을 수 있습니다.

### 채팅 목록

- 줄마다 상대 아바타, 채팅 이름, 마지막으로 움직인 시각이 있고, 패널과 휴대폰 화면에서는 그 아래에 마지막 메시지가 한 줄로 보입니다(첨부만 있으면 "이미지"·"파일"). 보내지 않은 글이 있으면 그 자리에 **초안**으로 보입니다. 답변이 오는 중인 채팅에는 초록 점이 붙습니다.
- 입력하던 글은 채팅마다 따로 남고, 이 브라우저에 계정별로 저장되어 새로고침해도 남습니다(글만, 첨부 파일은 제외). 첨부·답장 대상·상태창 선택은 다른 채팅에 다녀와도 그 채팅에 남지만 새로고침하면 사라집니다. 위로 올려 읽던 채팅은 돌아오면 그 위치에서 이어집니다.
- 줄에 마우스를 올리면(휴대폰은 늘) 나오는 **⋯**에서 **고정**, **이름 바꾸기**, **보관**을 합니다. 고정한 채팅은 목록 맨 위에 핀 표시와 함께 놓입니다. 보관한 채팅은 목록 맨 아래 **보관함**으로 옮겨질 뿐 메시지·로어북·이미지는 그대로이며, 같은 메뉴의 **보관 해제**로 돌아옵니다.
- 게시판 호출·루틴·워크플로가 스스로 만든 방은 목록 위의 **대화 / 자동화** 탭 중 **자동화**에 모입니다(그런 방이 있을 때만 탭이 보입니다). 채팅을 처음 열 때는 자동화 방을 건너뛴 최근 채팅이 열리고, 링크로 자동화 방을 열면 그 탭으로 바뀝니다.
- 지난 메시지를 고치면서 남긴 분기는 원래 채팅 아래 **수정 전 분기**로 접혀 있습니다. 메시지의 분기 버튼으로 직접 만든 분기는 일반 채팅처럼 놓입니다. 이 기능 이전에 만든 분기는 원래 채팅을 알 수 없어 따로 놓입니다.
- **대화 가져오기**(JSON 내보내기 파일이나 백업): 메시지(다른 답변 후보·답장 인용·번역문 포함), 요약, 작가 노트와 채팅별 설정, 상태창 수정 내역, 채팅 로어북 항목이 돌아옵니다. 그 채팅에서 켜 둔 플래그·사용자 프로필·연결한 계정 로어북은 지금 계정에 같은 것(다른 계정이면 같은 이름)이 있으면 다시 연결되고, 없으면 알려 줍니다. 이미지·영상과 첨부는 파일이 아니라 참조로 들어 있어서, 라이브러리나 내 파일 보관함에 아직 있으면 보이고 없으면 빠지며 몇 개 빠졌는지 알려 줍니다. 도구 결과는 짧은 요약만 남고, 채팅 모양·고정·보관·분기 관계는 새로 시작합니다.
- **여러 개 정리**: 줄에 마우스를 올리면 아바타 자리에 체크 상자가 나옵니다(휴대폰은 **⋯ → 선택**). 하나라도 체크하면 선택 모드가 되어 줄을 누르면 열리지 않고 체크되며, 아래에 뜨는 바에서 전체 선택·보관(모두 보관된 채팅이면 보관 해제)·삭제·선택 해제를 합니다. Esc로도 선택을 풉니다.
- **삭제와 백업**: 여러 개를 지우든 채팅 안 **⋯ → 삭제**로 하나를 지우든, 확인 창에서 **백업하고 지우기**(기본)와 **그냥 지우기**를 고릅니다. 백업은 내 **파일 보관함 › 채팅 백업 › 날짜**(지운 날, 내 기기 기준) 폴더에 채팅마다 `제목 (#번호).json`으로 남고, 채팅 로어북 항목도 함께 들어갑니다(로어북에 연결한 파일은 제외). 되살리려면 새 채팅 화면의 **가져오기 → 파일 보관함에서**를 누릅니다. 채팅 백업 폴더에서 열리고, JSON 파일을 여러 개 골라 한 번에 가져올 수 있습니다(**내 기기에서**는 내려받은 파일용). 백업에 실패한 채팅은 지우지 않으며, 답변 중인 채팅은 건너뜁니다. 여러 개를 지울 때 채팅 로어북은 채팅과 함께 지워집니다(계정 로어북으로 보관·병합하려면 하나씩 지우세요).
- 위쪽 검색은 메시지 내용을 찾습니다.

답변 속 `&*키워드*&`는 연결된 이모티콘 이미지로 바뀝니다. 한 줄에 그것만 있으면 큰 스티커로, 문장 중간에 있으면 글자 크기만 한 이모티콘으로 보입니다. 등록되지 않은 키워드는 글자 그대로 남습니다. 이모티콘과 채팅 이미지에도 앱 공통 이미지 조회 권한 `images.view`가 필요합니다. 홈 갤러리 페이지를 꺼도 이 기능 권한이 있으면 볼 수 있습니다.

글꼴·글자색·배경은 프로필이 정하고, 읽는 사람은 헤더의 **⋯ → 채팅 모양**에서 자기 쪽 보기 방식을 바꿉니다. 창 위의 한 줄 미리보기 아래에 탭 다섯 개가 있습니다. **글**: 글꼴(프로필 그대로 / 고딕 / 명조 / 고정폭), 글자 크기 12~22px, 줄·문단 간격, 자간. **배치**: 답변을 평문 또는 말풍선으로, 내 메시지를 오른쪽·왼쪽 말풍선 또는 평문으로, 본문 폭(전체 페이지에서만), 메시지 간격, 이름 표시, 보낸 시각(끔 / 마우스를 올리면 / 항상), 도구 호출 칩과 추론 블록 표시. **그림**: 프로필 사진(숨김 포함), 문장 속 이모티콘과 스티커 크기, 생성 이미지 크기와 여러 장일 때 격자·세로 배열. **배경**: 배경 표시, 어둡게·흐리게(프로필 값이 기본이고 바꾸면 이 채팅에서만 덮어씀, ↺로 프로필 값으로), 채움·맞춤·타일. **입력창**: 플래그 모양. 생성 이미지는 기본으로 **채팅 너비**에 맞춰(높이는 원래 비율대로, 원본 파일로) 보이고, **작게**·**보통**은 썸네일로 보입니다. 검색·조회로 찾은 이미지의 그리드는 이 설정과 상관없이 늘 작게 보입니다. 채팅 모양 창은 ⋯ 버튼 아래에 열리며 바깥을 누르거나 Esc로 닫습니다. 문장 속 이모티콘을 크게 하면 그 줄의 간격이 그만큼 벌어집니다. 이 설정은 **채팅마다** 따로 저장되고(계정별 파일, 어느 기기에서 열어도 같음) 패널과 채팅 페이지에 함께 적용됩니다. 창 머리의 **↺**를 누르면 설정 위로 **기본값**과 저장 슬롯 칩이 튀어나오고, 칩을 누르면 그 모양이 이 채팅에 바로 적용됩니다. 항목을 바꾸면 **저장**이 켜지고, 누르면 지금 슬롯에 덮어쓰거나(기본값 위에서 바꿨으면) 새 슬롯을 만듭니다. 슬롯은 12개까지이며, 지금 적용된 슬롯은 칩 아래에서 ★(새 채팅 기본)·이름 바꾸기·지우기를 할 수 있습니다. ★ 슬롯은 새 채팅을 만들 때 복사되어 들어가므로, 나중에 슬롯을 고쳐도 이미 만든 채팅은 그대로입니다.

프로필에 표시 블록이 있으면 답변 본문에는 카드 대신 "hp +5", "+ 캔커피" 같은 **변경 칩**만 남고, 전체 값은 **상태창**에서 봅니다. 칩을 누르면 상태창이 열립니다. 전체 페이지(넓은 화면)에서는 헤더의 상태창 아이콘으로 열고 닫으며, 머리의 아이콘으로 **오른쪽 열에 붙이거나** 대화 위에 **떠 있는 카드**로 뗄 수 있습니다. 떠 있는 카드는 왼쪽 그립으로 끌어 옮기고 오른쪽 아래 모서리로 크기를 바꾸며, 위치는 이 브라우저에 저장됩니다. 사이드 패널과 휴대폰에서는 헤더 아래 한 줄 띠에 요약이 보이고, 누르면 시트로 펼쳐집니다. 블록이 여럿이면 글자 탭으로 고릅니다. 연필 아이콘으로 값을 JSON으로 직접 고치고(Ctrl+Enter로 저장), ↺로 시작 값으로 되돌립니다. 카드 아래에는 최근에 값을 바꾼 답변이 시각과 함께 몇 줄 보입니다.

헤더의 **⋯ → 이미지 모아보기**는 이 채팅에 나온 이미지를 날짜별로 모아 보여 줍니다. **생성**(채팅에서 만든 이미지)과 **찾아본**(검색·조회로 본 이미지)으로 나눠 볼 수 있고, 뷰어의 "메시지로 이동"으로 그 이미지가 나온 답변으로 돌아가고, 타일에 마우스를 올리거나 뷰어에서 **참조**를 누르면 다음 메시지에 첨부됩니다. 목록은 저장된 대화에서 그때그때 만들기 때문에, 채팅을 지우면 함께 사라지고 이미지 자체는 라이브러리에 남습니다.

헤더 **⋯ → 컨텍스트**의 맨 위에는 **작가 노트**가 있습니다. 이 채팅에서만 쓸 장면 지시를 적으면 매 요청 대화 끝에서 N턴 앞에 `[참고 설정]`으로 들어가고, 타이핑을 멈추면 저장됩니다. 비우면 프로필의 기본 작가 노트가 쓰이며(입력칸에 흐리게 보입니다), 오른쪽 숫자는 끝에서 몇 턴 앞에 넣을지로 비우면 프로필의 로어북 삽입 위치를 따릅니다. Codex 채팅은 노트를 한 번 넣고 내용이 바뀐 턴과 압축 뒤에만 다시 넣습니다. `/note 내용`으로도 바꿀 수 있고 `/note`만 보내면 지웁니다.

API LLM 채팅의 컨텍스트 화면에서는 이어서 이 채팅만의 참고 턴 수, **최대 출력 토큰**, 요약 사용 여부를 바꾸고(비우거나 "프로필"을 고르면 프로필 값을 따릅니다), 지금까지의 요약을 보고 고치거나 **지금 요약**으로 바로 요약할 수 있습니다. 최대 출력 토큰은 이 채팅의 답변 길이 상한이자 컨텍스트 예산에서 답변 몫으로, 추론 토큰 예산보다 작게 잡으면 경고 아이콘이 붙습니다(추론만 하다 답변 없이 끊길 수 있음). 답변이 이 한도에 닿아 끊기면 답변 아래에 **길이 제한에서 잘림**이 표시됩니다. 짧게 답하라는 식의 문장 수준 제한은 작가 노트나 플래그로 하고, 이 값은 그래도 넘칠 때 자르는 하드 컷입니다. 그룹 방의 컨텍스트 화면에는 **방 전체** 최대 출력 토큰과 그 아래 API LLM 참가자마다 `@이름` 행이 있어, 참가자 값 → 방 값 → 그 프로필 값 순서로 적용됩니다. Codex 참가자는 하드 컷을 걸 수 없어 목록에 나오지 않습니다.

대화는 채팅별로 저장됩니다. 페이지를 닫아도 진행 중인 답변은 서버에서 끝까지 진행되고 저장됩니다.

긴 대화는 최근 80개 메시지부터 표시합니다. 위로 스크롤하거나 **이전 메시지**를 누르면 80개씩 더 펼쳐집니다. 이전 대화를 읽는 동안에는 새 답변이 와도 맨 아래로 강제로 이동하지 않으며, 이미지 모아보기의 **메시지로 이동**은 접힌 메시지도 펼쳐서 찾아갑니다.

API LLM 채팅에서 마지막 답변에 마우스를 올리면 **다시 생성**, 내 메시지에는 **수정** 버튼이 나옵니다. 휴대폰에서는 메시지를 탭합니다. 수정은 Enter로 저장하고 다시 답변하며, Shift+Enter로 줄바꿈, Esc로 취소합니다. 이전 턴을 수정할 때는 이후 대화를 지울지 확인합니다. 여러 답변이 있으면 **‹ 1/2 ›** 버튼으로 전환합니다.

메시지를 수정하면 그 뒤의 대화와 첨부 연결이 지워집니다. 영향을 받는 요약은 초기화되고, 다시 생성이 응답 없이 실패하면 기존 답변이 유지됩니다. 답변 전환 후 다음 요청은 선택한 답변을 사용합니다. 답변이 진행 중이면 기록 변경과 수동 요약은 409로 거절됩니다.

대화 비우기는 채팅 자체를 유지하면서 메시지·첨부 연결·요약을 초기화하고 프로필의 기본·추가 인사말 중 하나를 무작위로 다시 넣습니다. 파일 보관함의 원본과 생성 이미지는 남습니다. Codex 채팅은 대화 비우기 후 새 Codex 스레드로 시작하며, 메시지 수정·다시 생성·답변 전환은 API LLM 채팅에서만 지원합니다.

### 사용자 프로필

채팅에서 **내가 누구인지**를 정하는 프로필입니다. 이름·설명·아바타로 이루어지며 계정마다 자기 것을 여러 개 만들 수 있습니다(최대 20개). 채팅 헤더의 **⋯ → 사용자 프로필**과 설정 → 채팅의 **사용자 프로필** 묶음에서 추가·편집·삭제하고, ★로 **새 채팅 기본**을 지정합니다.

- **채팅에 적용되는 것**: 기록과 요약·내보내기·방 기록 도구에서 내 메시지의 화자 표기가 `사용자` 대신 그 이름으로 나가고, 프롬프트·작가 노트·플래그의 `{{user}}`도 그 이름으로 바뀝니다. 설명은 캐릭터 프로필의 지시문 끝에 `## 사용자` 섹션(이름 + 설명)으로 들어가며, 옛 프로필에 남아 있는 사용자 페르소나 섹션이 있으면 그 자리를 대신합니다. Codex 채팅은 지시문이 스레드 시작 때 고정되므로 참고 설정 블록으로 한 번 보내고, 프로필이 바뀌거나 압축된 뒤에 다시 보냅니다. 내 메시지 옆에는 프로필 아바타와 이름이 표시됩니다(채팅 모양의 프로필 사진·이름 표시 설정을 따릅니다).
- **새 채팅에서 고르기**: 사용자 프로필이 없거나 하나뿐이거나 ★ 기본이 있으면 바로 새 대화 화면이 열립니다. 둘 이상인데 기본이 없을 때만 캐릭터를 고른 뒤 "누구로 참여할까?"가 뜨고, 고르면 새 대화 화면이 열립니다(`/new`도 같습니다). 인사말의 `{{user}}`는 그 프로필 이름으로 보입니다. 그룹 만들기 창은 둘 이상일 때 맨 아래에 사용자 프로필 선택이 있으며 기본값이 미리 골라져 있습니다.
- **중간에 바꾸기**: **⋯ → 컨텍스트** 맨 위의 **사용자 프로필** 행에서 바꾸면 다음 요청부터 적용됩니다. 지난 메시지는 바뀌지 않고, Codex 참가자의 기억도 초기화하지 않습니다.
- **그룹 방**: 방 안내의 참가자 목록 첫 줄이 그 이름으로 나가고, 멘션은 걸 수 없다고 안내합니다. 이름이 참가자 이름(또는 첫 단어 별칭)과 겹치면 방을 만들거나 바꿀 때 거절됩니다. 이름에 `@`나 대괄호는 쓸 수 없습니다.
- 프로필을 지우면 그 프로필을 쓰던 채팅은 기본 `사용자`로 돌아갑니다.

### 앱 미디어 첨부

입력창의 클립 → **앱 미디어에서 고르기**에서 앱에 등록된 미디어를 선택합니다. 프롬프트·자동 태그를 전체 미디어에서 검색하고, 생성 도구(NAI·ComfyUI·기타)로 필터링하거나 최신순·오래된순으로 정렬할 수 있습니다. **더 보기**로 다음 항목을 불러오며, 검색·필터를 바꿔도 선택은 유지됩니다. **선택 해제**는 전체 선택을 비우고, **첨부 적용**으로 입력창에 반영합니다.

보관함 파일과 앱 미디어를 합쳐 최대 20개까지 첨부할 수 있습니다. 앱 미디어는 재업로드 없이 원본을 참조하며, 입력창에는 썸네일이, 보낸 메시지에는 **참조 이미지** 라벨만 표시됩니다(그림은 이미 대화에 있으니까). 라벨을 누르면 그 이미지가 처음 나온 답변으로 이동하고, 이 채팅에 나온 적 없는 이미지(라이브러리에서 고른 것)는 뷰어가 열립니다. PC에서 라벨에 마우스를 올리면 미리보기가 뜹니다. 답변 썸네일의 **참조** 버튼으로 넣은 이미지도 같은 앱 미디어 첨부입니다. 텍스트 없이 미디어만 보내도 되고, 메시지 수정·재생성에서도 첨부 참조가 유지됩니다. 전송 시 미디어 접근 권한과 원본의 삭제·숨김 여부를 다시 확인합니다.

이미지 내용을 이해하려면 프로필에서 이미지 보기 도구(`view_images`)와 비전 모델을 사용할 수 있어야 합니다. 영상과 움직이는 GIF·WebP는 프레임 보기 도구(`view_media_frames`)로 시간대별 프레임을 뽑아 봅니다(소리는 듣지 못함). 이 도구는 이미지를 볼 수 있는 모델이면 프로필 도구 설정과 상관없이 항상 쓸 수 있습니다. 오디오는 참조 첨부만 지원하며 내용 분석은 지원하지 않습니다. 원본이 삭제되거나 숨겨지면 첨부의 미리보기·원본 접근도 제한됩니다.

### 허용 등급

검열이 있는 모델에 민감한 미디어를 보내면 거절하거나 오류가 납니다. 모델 줄(설정 → LLM → 연결 아래 모델)과 채팅 프로필에서 **허용 등급**을 정하면, 그 등급 구간을 넘는 미디어는 그 모델에 보내지 않습니다.

- 적용 범위: 첨부 이미지, `view_images`·`view_media_frames`, 생성 결과 반응, 프로필 에셋 비전 검수, 외형 초안, 워크플로 LLM 노드의 이미지. 막힌 첨부는 참조로만 남고, 도구는 해당 항목에 등급 제한이라고 답합니다.
- 기준: 미디어의 등급 점수가 속한 등급 구간(설정 → 자동화 및 분석의 평가 등급, 피드 숨김·흐림과 같은 구간)이 허용 등급 이하면 보냅니다.
- 등급이 아직 없는 미디어(자동 태깅 전, 보관함 파일, 워크플로 입력)는 보낼 때 태거로 바로 매기고 점수를 저장합니다. 보관함 이미지·영상은 올릴 때 미리 매깁니다. 태거가 꺼져 있거나 실패해서 등급을 알 수 없으면 허용 등급이 있는 모델에는 보내지 않습니다.
- 프롬프트 같은 텍스트 정보는 아직 거르지 않습니다.

### Codex 기억 관리

Codex는 채팅의 전체 기억을 직접 들고 있다가 모델 요청마다 다시 읽습니다. 그래서 대화가 길수록 요청 하나가 커지며, 고정 지시문과 CoNAI 도구 설명만으로도 약 2만 5천 토큰이 들어갑니다.

- **자동 압축**: 요청 입력이 프로필의 **압축 기준**(프로필 편집 → 모델 › 컨텍스트, 기본 64,000 토큰, 최소 48,000)에 닿으면 Codex가 다음 턴 시작 전에 기억을 요약해 접습니다. 압축에는 10초 정도 걸리며, 대화에 요약 경계가 표시됩니다. 압축 기준을 바꾸면 열려 있는 채팅에도 다음 메시지부터 적용됩니다.
- **수동 압축**: `/compact` 또는 헤더 메뉴의 **압축**, 컨텍스트 화면의 **지금 압축**.
- **컨텍스트 화면**: 현재 컨텍스트(마지막 요청의 입력 토큰) / 압축 기준, 모델 한도, 누적 입력(캐시 비율)과 출력을 Codex가 보고한 값으로 보여 줍니다. 압축 직후에는 다음 답변 전까지 현재 컨텍스트가 `—`로 표시됩니다.
- **기록 정리**: 채팅을 지우거나 비우면 서버의 Codex 대화 기록(rollout)도 함께 삭제합니다.
- 프로필의 지시문(시스템 프롬프트·섹션·꾸미기)은 Codex 스레드를 만들 때 고정됩니다. 바꾼 지시문을 기존 Codex 채팅에 반영하려면 대화를 비웁니다. 로어북은 매 턴 새로 읽으므로 바로 반영됩니다.

예:

```text
"풍경" 그룹에 있는 이미지 중 최근 것 5장 보여줘.
NAI로 비 오는 골목 일러스트 한 장 만들어서 "채팅 테스트" 그룹에 넣어줘.
```

## 메시지에 답장하기

1:1과 그룹 모두 메시지 아래 **답장** 버튼을 누르면 입력창 위에 원문 미리보기가 생깁니다. PC에서는 메시지에 마우스를 올리면, 휴대폰에서는 메시지를 누르면 버튼이 보입니다. **×**로 답장을 취소할 수 있고, 전송에 실패하면 작성 내용과 답장 선택이 복원됩니다.

보낸 말풍선에도 원문 작성자·인용문과 가능한 경우 이미지 썸네일이 표시됩니다. 인용 부분을 누르면 오래된 메시지라도 원문 위치로 이동합니다. 이미지·파일만 있는 메시지에도 답장할 수 있습니다. 이미지의 내용을 이해하려면 비전 모델과 이미지 조회 도구가 필요합니다.

그룹에서 **B의 메시지에 답장하면 `@B` 없이 B가 응답**합니다. 본문에 `@C`를 명시하면 원문 인용은 유지하면서 C에게 전달하고, 입력창에도 받는 사람을 표시합니다. 자기 메시지를 인용하면 원래 수신자에게, 수신자 정보가 없으면 대표에게 전달합니다. 방을 나갔거나 비활성화된 참가자에게는 전달하지 않고 이유를 알려줍니다.

오래된 원문에 답장할 때 API LLM과 Codex 모두 원문과 주변 대화를 참고자료로 받습니다. 1:1은 원문이 속한 턴과 앞뒤 한 턴, 그룹은 앞뒤 두 메시지를 기준으로 하고, 이전 답장 연결은 두 단계까지 보충합니다. 최근 컨텍스트와 겹치는 원문은 중복 전송하지 않고, 길이는 컨텍스트 예산에 맞춰 제한합니다. 답장 당시 인용문과 답변 버전을 보관하므로 원문의 다른 답변을 선택해도 인용 내용은 유지됩니다. 원문이 삭제되면 삭제된 메시지로 표시합니다.

캐릭터도 답장 관계와 받는 사람을 사용합니다. B가 A의 요청에 답장하면 A가 멘션 없이 이어서 반응하며, 사용자에게 답하거나 방 전체에 마무리 발언을 하면 자동 호출이 끝납니다. 이어 말하기 한도에 도달한 호출은 실패 이유를 반환합니다. 생성 이미지는 실제 생성한 캐릭터의 답변에 연결되고, 다른 캐릭터가 진행 상황을 조회해도 생성자 위치가 바뀌지 않습니다.

## 그룹 방

여러 프로필이 한 방에서 함께 대화합니다. 1:1 채팅과는 별개의 방이며, 1:1 채팅은 그대로 남습니다.

- **만들기**: 1:1 채팅 헤더의 **참가자 초대**(사람+ 아이콘)에서 함께할 프로필을 고르고 **그룹 만들기**를 누릅니다. 원래 1:1 상대는 대표로 고정되고, 그룹 방은 빈 대화로 시작합니다. 참가자는 최대 6명이고, 이름이 같은 프로필은 함께 넣을 수 없습니다(멘션이 이름으로 동작하기 때문입니다). [사용자 프로필](#사용자-프로필)이 둘 이상이면 창 아래에서 누구로 참여할지 고릅니다.
- **누가 답하나**: `@이름`으로 부르면 부른 순서대로 답하고, `@모두`는 참가자 순서대로 전원이 답합니다. 멘션 없이 참가자의 메시지에 **답장**하면 그 참가자가 답하고, 답장 대상도 없으면 **대표**가 답합니다. 입력창에 `@`를 치면 참가자 목록이 나오며 ↑·↓와 Enter(또는 Tab)로 고릅니다. 이름 뒤에 바로 조사가 붙어도(`@카이야`) 인식하고, 코드·인용 안의 `@`와 이메일 주소는 무시합니다.
- **봇끼리 이어지기**: 답변에 다른 참가자의 `@이름`이 있거나, 참가자가 `room_call_member` 도구로 다른 참가자를 부르면 그 참가자가 이어서 답합니다. 모델이 이름을 번역해 쓰는 경우(`@스타킹`)가 있어서, 모든 참가자의 요청에 참가자별 멘션 이름 목록(`- Ochako Uraraka: mention as @Ochako Uraraka or @Ochako`)과 "표기 그대로, 번역·음차 금지" 규칙을 영문 안내로 시스템 프롬프트에 넣고, 요청 끝에도 한 줄로 다시 적어 줍니다. 도구로도 부를 수 있습니다. 여러 단어 이름은 첫 단어만 써도 됩니다(`@Ochako`, 다른 참가자와 겹치지 않을 때). 사용자 메시지 1개당 이어지는 횟수는 기본 3회이고, 다 쓰면 사용자 차례로 돌아옵니다.
- **부르기 전에는 쉼**: 부르지 않은 참가자는 실행되지 않습니다. 깨울 때 API LLM 참가자는 방의 최근 대화를, Codex 참가자는 자기가 마지막으로 말한 뒤에 놓친 대화를 받습니다. 둘 다 **넘길 대화**(기본 30개) 안에서만 받고, 그보다 앞의 대화는 참가자가 방 대화 검색 도구(`room_history_search`·`room_history_read`, 읽기 전용, 이 방 한정)로 찾아봅니다. 답장 원문이 최근 대화 밖에 있을 때도 같은 방의 기록만 조회할 수 있습니다.
- **끼어들기**: 참가자들이 답하는 중에도 메시지를 보낼 수 있습니다. 답하던 참가자는 거기서 멈춰 "중단됨"으로 저장되고, 남은 차례는 취소되며 새 메시지부터 다시 진행합니다. 입력창이 비어 있으면 같은 자리에 중단 버튼이 나옵니다.
- **참가자 팝오버**: 헤더의 겹친 아바타를 누르면 참가자 목록이 열립니다. 대표에는 왕관이 표시되고, 마우스를 올리면 **대표로 지정**·**방에서 내보내기**가 나옵니다. 대표가 나가면 가장 먼저 들어온 참가자가 대표가 됩니다. 아래에서 **봇끼리 이어지기**(0~10)와 **넘길 대화**(5~200)를 방마다 바꿉니다.
- **표시**: 답변마다 쓴 참가자의 아바타·이름·이모티콘·디스플레이 블록이 나오고, 배경·글꼴·역할극 색은 대표 프로필을 따릅니다. 입력창 위에 "○○ 답하는 중 · 다음 [아바타]"가 표시됩니다.
- **기록 변경**: 마지막 답변 다시 생성은 API LLM 참가자의 답변만 가능하며 이어지기는 하지 않습니다. 내 메시지를 수정하면 그 뒤가 지워지고 다시 판정해 답합니다. 수정·비우기를 하면 Codex 참가자들의 기억도 초기화됩니다. 그룹 방에는 요약·압축이 없고, **⋯ → 컨텍스트**에는 방의 **작가 노트**만 있습니다. 방 노트는 모든 참가자의 요청에 들어가고, 비어 있으면 참가자마다 자기 프로필의 기본 노트를 씁니다.
- **Codex 참가자**: 참가자마다 자기 Codex 스레드(기억)를 따로 둡니다. 고정 지시문에는 페르소나만 들어가고, 방 정보와 참가자 목록은 깨울 때마다 입력 앞에 붙습니다. 방을 비우거나 지우거나 참가자를 내보내면 그 Codex 기록도 삭제합니다.
- **답변 정리**: 작은 모델이 다른 참가자의 대사를 이어 쓰면, 다른 참가자 이름(`카이:`·`[카이]`)으로 시작하는 줄부터 잘라서 저장합니다. 자기 캐스트 인물의 줄은 유지합니다. 잘라서 아무것도 남지 않으면 원문을 그대로 두고, 모델이 빈 답을 보내면 실패로 저장해 오류 표시와 다시 생성이 나오게 합니다.

## 캐릭터 카드 가져오기

설정 → 채팅에서 **+ 옆 가져오기 아이콘**으로 PNG 또는 JSON 캐릭터 카드(V1/V2/V3, 최대 8MB)를 엽니다. 이름·소개·프롬프트 섹션·대화 예시·첫 인사말을 채우고 카드의 로어북을 연결한 편집 창이 열리고, **저장**을 누르기 전에는 프로필이 등록되지 않습니다(카드의 로어북은 가져올 때 로어북 목록에 바로 추가됩니다). PNG는 128px WebP 아바타로 바뀝니다.

카드의 인사말·추가 인사말·프롬프트 섹션·시스템 프롬프트에 있는 웹 이미지(Markdown 이미지, `<img>`)는 가져올 때 CoNAI 안에 복사하고 링크를 내부 주소(`chat-asset:`)로 바꿉니다. 이미지 호스트가 이 네트워크의 DNS에서 막혀 있어도(예: catbox.moe) 공용 DNS(1.1.1.1·8.8.8.8)로 다시 찾아 받습니다. https/http만, 공인 IP 주소만, 장당 10MB·한 번에 30장까지 받고, 실제 이미지인지 확인합니다. 받지 못한 링크는 그대로 남습니다. 이미 가져온 프로필은 프로필 편집 › 캐릭터 탭의 프롬프트 옆 **외부 이미지 저장** 아이콘으로 같은 처리를 하며(프로필을 저장해야 반영), 이미 채팅에 올라간 인사말 메시지의 같은 링크도 함께 바뀝니다.

엔진은 API LLM, 대화 모델은 기본(★) 모델로 선택하며 MCP는 꺼진 상태입니다. 다른 첫 인사말들도 보관하지만 새 대화에서 선택하는 기능은 후속 범위입니다. 카드 내용은 문자열로만 다루며 `{{original}}`은 제거합니다. 압축 텍스트의 해제 크기와 이미지 픽셀 수에도 제한을 둡니다.

## 로어북

로어북은 설정 → 채팅의 **로어북** 목록에서 따로 관리하고, 프로필은 로어북을 연결만 합니다. 가져오기 아이콘으로 SillyTavern 월드인포 JSON, NovelAI `.lorebook`, 로어북이 든 캐릭터 카드(PNG/JSON, 최대 8MB)를 새 로어북으로 넣고, **+**로 빈 로어북을 만듭니다. 각 줄에는 항목 수와 연결된 프로필 수가 표시됩니다. **파일로 업데이트** 아이콘은 이름과 연결을 그대로 두고 항목만 새 파일 내용으로 바꿉니다. 편집 창에서는 이름과 항목을 고치거나 로어북을 삭제하며, 삭제하면 연결된 프로필에서도 연결이 풀립니다. 한 로어북의 항목은 최대 500개입니다.

대화 중 모델이 오래 기억할 사실을 `save_lore`로 남기면, 기본으로는 그 채팅의 로어북에 바로 저장되고 답 아래 카드에 **로어북에 남겼어**와 **저장 되돌리기** 버튼이 보입니다. 되돌리면 새 항목은 로어북에서 빠지고(같이 만든 자료 파일도), 같은 제목을 고친 경우는 이전 내용으로 돌아가며, 그 제목은 다시 제안되지 않습니다. 바로 저장은 설정 → LLM → 연결의 **기억 › 로어 자동 저장**에서 끄고 켜며, 채팅마다 **⋯ → 컨텍스트**의 로어북 칸에서 **설정 따름 / 켬 / 끔**으로 따로 정합니다. 끄면 카드의 **저장**을 눌러야 들어갑니다.

프로필 편집 › 캐릭터 탭의 **로어북**에서 칩을 눌러 로어북을 연결하거나 해제합니다(최대 20개). 로어북 내용은 보낼 때마다 새로 읽으므로, 로어북을 고치거나 업데이트하면 연결된 모든 프로필에 바로 반영됩니다. 캐릭터 카드를 가져올 때 카드에 로어북이 있으면 공유 로어북으로 추가되고 새 프로필에 연결됩니다.

기본으로 최근 메시지 4개에서 키워드를 부분 일치로 찾으며, 대소문자 구분과 항상 넣기를 항목별로 설정할 수 있습니다. 연결된 모든 로어북의 항목을 합쳐 낮은 순서부터 토큰 상한(기본 1024) 안에 들어가는 항목을 반영합니다. 검색 범위(최근 메시지 수), 토큰 상한, 삽입 위치는 프로필의 모델 › 컨텍스트에서 정합니다. 키워드는 Enter·쉼표 또는 입력칸을 벗어날 때 칩으로 추가됩니다.

API LLM은 **항상 넣기** 항목을 시스템 프롬프트 끝의 `## 설정`으로 받고, **키워드로 걸린** 항목은 대화 끝에서 **삽입 위치**(기본 4턴) 앞의 사용자 메시지 앞에 `[참고 설정]`으로 받습니다. 항상 넣기 항목은 바뀌지 않아 요청 앞부분과 함께 서버의 프롬프트 캐시에 남고, 매 턴 바뀌는 키워드 항목은 뒤쪽에 있어 그 뒤 몇 턴만 다시 읽히며 작은 모델도 잊지 않습니다. 삽입 위치 0은 마지막 메시지 바로 앞입니다. Codex는 해당 턴 사용자 입력 앞의 `참고 설정`으로 받습니다. Codex는 넣은 입력을 계속 기억하므로, 이미 넣은 항목(같은 내용)은 다음 압축 전까지 다시 넣지 않고, 내용을 고친 항목과 압축 뒤의 항목만 다시 넣습니다. 프롬프트 미리보기에는 항상 넣기 항목만 표시됩니다. 격리 환경에서 한글·영문 부분 일치, 대소문자, 검색 범위, 순서·상한과 미리보기 동작을 확인했습니다.

## 커맨드·검색·내보내기

입력창에 `/`를 쓰면 커맨드가 나옵니다. ↑·↓로 고르고 Enter로 실행하거나 Tab으로 입력합니다. Esc로 목록을 닫습니다. `//help`처럼 슬래시를 두 번 쓰면 `/help`라는 일반 메시지로 보냅니다. 커맨드 자체는 대화 기록에 저장하지 않습니다.

| 커맨드 | 동작 |
| --- | --- |
| `/new [프로필 이름]` | 지정한 프로필로 새 채팅. 이름을 비우면 현재 프로필. |
| `/clear` | 확인 후 대화를 비우고 첫 인사말 복원. Codex 기억도 초기화. |
| `/compact` | 대화를 강제로 요약하고 이 채팅의 요약 사용을 켬. Codex 채팅은 Codex 기억을 압축. 대화에 요약 경계 표시. 그룹 방에서는 쓸 수 없음. |
| `/note [내용]` | 이 채팅의 작가 노트를 바꿈. 내용을 비우면 지워서 프로필 기본 노트로 돌아감. |
| `/retry` | 마지막 답변 다시 생성(API LLM). |
| `/edit` | 마지막 내 메시지 수정(API LLM). |
| `/export` | Markdown 또는 JSON 다운로드. |
| `/search 단어` | 내 대화 전체에서 메시지 검색. |
| `/help` | 커맨드 목록. |

헤더의 **⋯** 메뉴에는 아이콘과 함께 컨텍스트, 이미지 모아보기, 채팅 모양, 대화 비우기, 압축, 내보내기, 삭제가 있습니다. 패널과 전체 페이지에서 같은 메뉴를 사용합니다.

전체 페이지 왼쪽 검색칸 또는 `/search`로 본인 대화만 검색합니다(최대 50개). 결과를 누르면 해당 채팅과 메시지를 펼쳐서 이동·강조합니다. Markdown에는 화자·시각·첨부와 이미지 링크가, JSON에는 메시지·답변 변형·도구 호출·요약이 들어갑니다. 링크를 열 때도 원래 파일·이미지 접근 권한이 필요합니다.

## 현재 페이지 읽기와 입력 보조

1:1 채팅에서 입력창 옆 **현재 페이지 연결**을 누르면 현재 CoNAI 페이지와 등록된 입력·작업을 모델에게 전달합니다. 기본은 꺼져 있고 다른 채팅이나 새 프로필을 선택하면 해제됩니다. 채팅을 사용할 수 있는 계정이 해당 페이지를 열 수 있으면 연결할 수 있습니다. 프로필 도구 설정은 필요하지 않습니다.

페이지 도구는 연결한 요청에 자동으로 제공되며 프로필의 일반 도구 목록에서 다시 고르지 않습니다. 연결 중에도 프로필이 가진 조회 도구와 채팅 설정 제안(프로필·표시 블록 카드)은 그대로 쓸 수 있습니다. 개인 파일 읽기와 무언가를 바꾸는 도구는 연결 중에 빠지고, 남이 만든 공유 워크플로 페이지에서는 페이지 도구만 남습니다. 현재 페이지의 입력을 읽는 권한은 페이지 접근 권한으로 판단합니다. 워크플로 상세·추가 데이터 조회와 생성·저장·삭제 같은 실제 작업은 해당 기능 권한을 별도로 확인합니다. 별도로 연결한 생성 프리셋은 페이지 연결 여부와 무관하게 사용할 수 있으며, 생성 요청에는 페이지 연결이 필요하지 않습니다. 페이지 내용만으로 생성이나 다른 비공개 데이터 조회를 지시할 수는 없습니다.

- **프롬프트**: 목록 검색·정렬·선택, 본문·동의어·그룹 생성/수정과 프리셋 생성/수정/항목 편집을 지원합니다. 자동 관리 LoRA·Danbooru 그룹의 보호는 유지합니다.
- **와일드카드**: 일반/NAI/ComfyUI 항목·가중치·상위 항목·하위 포함·체인 설정을 생성/수정할 수 있습니다. 자동 수집 탭은 읽기 전용입니다.
- **NAI·Codex 생성**: 일반 입력, 프롬프트 프리셋 추가/교체, 권한 있는 라이브러리 이미지나 내 파일을 참조/마스크 등에 등록할 수 있습니다. Codex의 프롬프트·부정 프롬프트·모델·반복 개수·비율·해상도·이미지 모드도 지원합니다.
- **ComfyUI·공유 페이지**: 일반 marked field, 이미지 등록/해제, H3 모드·프롬프트 빌더·해상도·후처리·타임라인과 LoRA 사용/가중치를 지원합니다. 일반 페이지는 워크플로 선택도 가능합니다. 공유 페이지는 게시된 해당 워크플로를 사용합니다.
- **Comfy 등록·수정**: 관리 권한이 있으면 채팅으로 편집기를 열어 API 형식 JSON·marked field 등록/해제·기본값·옵션·숫자 범위·필수/표시/접기·H3 설정·순서를 편집하고 등록/수정 저장을 제안할 수 있습니다. 편집 모달이 열리면 그 모달을 우선 연결합니다.
- **노드 워크플로**: 노드 추가/삭제·배치·입력·연결 편집을 열린 편집기에 바로 반영하고(되돌리기 가능), 저장된 워크플로 선택/편집기 열기와 Runner의 일반 실행 입력을 지원합니다. 자세한 예시는 [워크플로우 편집](./WORKFLOW_EDITOR.md#채팅으로-워크플로-구성하기)을 참고합니다.
- **다른 페이지**: 라이브러리 정렬·열 수, 상세 이미지 정보/표시 탭, 그룹 표시, 내 파일의 검색어·현재 이름/이동 초안, 업로드 메타데이터를 지원합니다. 해당 페이지의 실제 업로드·이동·삭제는 기존 버튼으로 진행합니다.
- **설정**: 열린 탭의 항목을 읽고 초안에 채웁니다. 일반(언어·다운로드·갤러리·상단 메뉴·테마 전체), 라이브러리(유사 검사·메타데이터), 미디어(이미지 저장·썸네일·비디오 최적화), 자동(WD Tagger·Kaloscope·평가 가중치·평가 등급), 생성(예약 작업·NovelAI/Codex 생성 텀), 시스템(안전 및 정리)입니다. 저장은 화면 아래 저장 바로 합니다. 감시 폴더와 백업 소스는 이름과 감시 상태만 읽고(경로는 보내지 않음), 추가·수정은 기존 버튼으로 합니다. 서버가 실행하는 Python 경로, 계정·권한, MCP 키, 테마 파일 가져오기·폰트 업로드, 유지보수 작업은 모델이 바꾸지 않습니다.
- **라이브러리·보관함**: 검색 실행(검색 서랍은 열지 않음), 목록 이미지 선택·열기, 폴더 열기와 파일 미리보기를 바로 실행합니다.
- **오디오·스프라이트**: 오디오는 그룹 열기, 검수 탭(전체·미검수·채택·보류) 바꾸기, 테이크 선택을, 스프라이트는 추출 목록의 영상 고르기를 바로 실행합니다. 검수 결정과 생성은 기존 도구와 버튼으로 합니다. 오디오·스프라이트 작업 도구(효과음 주문·편집, 스프라이트 추출 등)는 모든 요청에 실리면 도구 정의의 3분의 1을 차지하므로, 그 페이지를 연결했을 때만 모델에게 주어집니다. 다른 곳에서도 쓰려면 프로필의 도구 프리셋에서 그 도구를 직접 고릅니다.
- **월페이퍼**: 이름·캔버스 초안, 위젯 선택, 위젯 추가(되돌리기 가능), 저장된 배경화면 불러오기를 바로 하고, 저장은 카드로 제안합니다.
- **메타데이터 편집기**: 프롬프트 등 초안을 채우고, 파일에 쓰는 저장은 카드로 제안합니다.
- **채팅 페이지(/chat)**: 목록의 다른 채팅 열기와, 프로필을 골라 새 채팅 화면 열기(인사말만 보이고 첫 메시지를 보내야 저장)를 바로 실행합니다.

예: "현재 프리셋에 스타일 watercolor, 조명 soft daylight 두 항목을 넣는 수정안을 만들어 줘", "H3의 FPS를 30으로 바꾸고 첫 라이브러리 이미지를 슬롯 0에 등록하는 작업을 제안해 줘".

모델이 하는 일은 세 단계로 나뉩니다. 등급은 앱이 정하며 페이지가 바꿀 수 없습니다.

| 등급 | 예 | 처리 |
|---|---|---|
| 보기 | 페이지·탭 이동, 항목 선택, 편집기 열기, 새로고침 | 바로 실행하고 바뀐 화면을 모델이 이어서 읽습니다. |
| 초안 | 입력 채우기, 프리셋 넣기, 이미지 등록, 노드 입력 | 바로 반영합니다. 저장하지 않으며 이후 편집이 없으면 되돌릴 수 있습니다. |
| 확정 | 생성·수정 저장, 등록, 자동 수집 | 지금처럼 카드로 보여 주고 **검토한 내용 저장**을 눌러야 진행합니다. |

그래서 "설정 일반 탭에서 다운로드 위치 묻기 켜 줘"처럼 이동과 입력이 이어지는 요청을 한 답변 안에서 끝냅니다. 모델이 바꾼 화면의 저장은 기존 저장 버튼으로 합니다. 저장하지 않은 변경이 있는 화면에서는 다른 곳으로 이동하거나 다른 항목을 여는 보기 작업이 거절됩니다. 바로 실행은 채팅을 연 브라우저 탭에서 일어나므로 탭이 열려 있고 화면에 보여야 합니다. 응답이 없으면 약 20초 뒤 모델에게 실패로 돌아갑니다. 탭이 닫혔거나 1분 넘게 숨겨져 실시간 연결이 끊긴 상태면 기다리지 않고 바로 그 사실을 모델에게 알립니다. 실제 생성은 기존 생성 버튼이나 연결한 생성 프리셋으로 진행합니다.

모델이 실행한 보기·초안 작업은 답변 아래 칩으로 남습니다. 입력을 채운 칩에는 되돌리기 아이콘이 붙고, 같은 탭에서 그 뒤에 입력을 고치지 않았다면 누르는 즉시 이전 값으로 돌아갑니다. 모델이 조작하는 동안에는 화면 맨 위에 얇은 진행 줄이 지나가고 페이지 연결 아이콘이 깜빡입니다. 채운 칸에는 주황 테두리나 점이 붙고, 직접 고치면 사라집니다.

**설정 › 채팅**에 연결하면 모델이 새 프로필 편집기나 목록의 프로필 편집기를 엽니다. 이어서 이름·소개·시스템 프롬프트·섹션·인사말·작가 노트·외형·엔진·대화 모델·로어북·표시 블록을 초안에 채우고, 편집기 항목을 옮겨 다닙니다. 프로필 저장과 캐릭터 이미지 생성(기준 이미지·배경·표정)은 카드로 제안합니다. 도구 권한·사용 대상은 모델이 바꾸지 않습니다. 편집기는 오른쪽 채팅 패널 자리를 비워 두고 열려서, 둘을 함께 쓸 수 있습니다. **설정 › 채팅 › 자원**에서는 로어북·생성 프리셋·판단 프리셋·표시 블록·도구 프리셋 편집기를 엽니다. 로어북은 이름과 항목(키워드·내용·항상 넣기)을, 생성 프리셋은 이름·용도·NAI 모델·샘플러·스텝·CFG·고정 프롬프트나 ComfyUI 워크플로를, 판단 프리셋은 이름을 채우고, 저장은 카드로 제안합니다. 도구 프리셋의 도구 권한은 모델이 바꾸지 않습니다.

모델은 다음 요청에서 최근 카드가 어떻게 됐는지(저장됨과 새 id, 무시됨, 대기)를 함께 받고, 필요하면 `get_proposal_status`로 다시 확인합니다. 그래서 "저장했어"라고 따로 말하지 않아도 다음 단계로 이어갑니다. 캐릭터 이미지 생성 뒤에는 `get_asset_batch`로 진행과 후보·검토 결과를 읽고, 고른 후보를 적용 카드에 담아 제안할 수 있습니다. 카드를 승인할 때 그 후보가 선택되고 프로필에 연결됩니다.

카드로 남는 확정 작업은 페이지·모달·선택·입력이 바뀌거나 연결을 해제하면 적용할 수 없습니다. 카드는 5분간 유효하고 현재 계정·프로필·기능 권한과 저장 원본 버전을 다시 확인합니다. 다른 작업의 저장과 충돌하면 다시 읽고 새 제안을 받아야 합니다.

## 여러 단계 작업

1:1 채팅에서 "새 캐릭터 프로필을 이미지까지 만들어 줘"처럼 여러 번 오가야 하는 일을 맡기면, 모델이 먼저 **작업 플랜** 카드를 보여 줍니다. 카드에는 목표, 단계(저장처럼 사람이 승인해야 하는 단계는 **승인** 표시), 예산(이어가기 횟수, 이미지 장수)이 있습니다. **승인**을 누르기 전에는 아무것도 진행하지 않습니다.

승인하면 서버가 다음 차례를 알아서 보냅니다. 이어가는 요청은 대화에 "작업 이어가기 · 2/5 · 단계 이름" 한 줄로만 보이고, 진행 중인 단계 목록은 최신 답변 아래에 나옵니다. 다음 경우에 모델의 다음 차례가 시작됩니다.

- 앞 답변이 끝났을 때
- 모델이 기다리던 카드를 저장하거나 무시했을 때
- 기다리던 생성 작업이 모두 끝났을 때

입력창 위 줄에는 지금 단계, 상태(진행 중·승인 대기·생성 대기·멈춤), 진행도와 **일시정지·이어가기·중단** 버튼이 있습니다. 다음 경우에는 자동으로 멈추고, 이유는 상태 표시에 마우스를 올리면 보입니다. 이어가기 버튼으로 다시 시작합니다.

- 예산을 다 썼을 때
- 세 번 연속 단계에 진전이 없을 때
- 승인하거나 이어간 뒤 3시간이 지났을 때
- 서버가 다시 시작됐을 때

모델이 사람의 대답을 기다리면 채팅에 답을 보내는 것으로, 페이지를 기다리면 페이지를 연결한 채 메시지를 보내는 것으로 다시 진행합니다. 이어가기 버튼도 됩니다. 진행 중인 작업이 있는 채팅은 채팅 목록에 진행 링(끝난 단계 비율)이 붙고, 링에 마우스를 올리면 지금 단계와 상태가 보입니다. 채팅 하나에 진행 중인 작업은 하나뿐이며, 그룹 채팅에는 없습니다. 페이지 작업이 필요한 단계는 채팅을 연 탭이 열려 있고 페이지 연결이 켜져 있어야 진행됩니다.

모델에게 DOM 전체, 미디어 바이트·서버 경로·인증 설정을 전달하지 않습니다. 일반 입력에 직접 적은 내용과 제안의 변경 전후는 선택한 LLM 및 대화 기록에 전달될 수 있습니다. 외부 사이트나 임의 브라우저 조작은 지원하지 않습니다. 그룹 채팅, 코드/모듈 정의·보안 설정·예약작업 편집·월페이퍼 위젯 설정/삭제·NAI 참조 세부 수치 등 표 밖의 기능은 연결하지 않았습니다. 자세한 지원 범위와 검증은 [개발 계획](../systems/chat-web-assistant-plan.md#페이지별-확장-완료--2026-10-07)을 참고합니다.

## 할 수 있는 것과 없는 것

| 가능 | 불가능 |
| --- | --- |
| CoNAI MCP 도구 호출 (권한 안에서) | 셸 명령 실행 |
| 연결한 CoNAI 페이지 안의 이동·입력 채우기, 저장 카드 제안 | 서버 파일 읽기·쓰기 |
| 연결한 노드 편집기의 워크플로 구성·수정(바로 반영, 되돌리기 가능) | 채팅의 그래프 실행·실행 정의 가져오기 |
| | 웹 검색·외부 사이트 및 임의 브라우저 조작 |
| | 서버 Codex 설정에 등록된 다른 MCP 서버·플러그인·스킬·훅 사용 |
| 등록된 NovelAI/ComfyUI 생성과 본인 파일·로어 작업 | Codex 이미지 생성·Codex 단독 실행을 통한 답장 추천 |

- 봇에게는 실제로 쓸 수 있는 도구만 보이고, 도구를 호출할 때마다 현재 계정의 기능 권한, 엔진, 활성 프로필의 범위와 도구 목록, 소유권을 다시 검사합니다. 계정 정지·관리자 강등·권한 회수·MCP 끄기·프리셋 수정은 열린 답변과 재사용 세션에도 반영되고, 새로 준 권한은 다음 답변부터 보입니다. 대화 도구(답장·방 기록·로어북)는 도구 목록과 관계없이 채팅이면 제공됩니다.
- 생성 대기열은 실제 실행 직전에 같은 권한을 다시 검사합니다. 권한이 회수되거나 프로필이 꺼진 작업, 새 권한 바인딩이 없는 이전 채팅 작업은 실패하며 다시 요청해야 합니다. 이미 제공자에게 제출한 작업을 소급 취소하는 보장은 아닙니다.
- 생성한 결과는 채팅한 계정의 생성 이력으로 기록됩니다. 계정에 연결된 생성 파일 링크는 웹사이트의 로그인·현재 이미지 조회 권한·소유권 검사를 통과해야 합니다. 그래프 산출물의 익명 서명 다운로드 링크는 채팅에 제공하지 않습니다.
- Codex는 공개 미디어 폴더 밖의 계정별 전용 홈·작업 폴더에서 실행합니다. 기존 파일 기반 로그인만 복사하고 호스트 설정·환경 자격 증명·프로젝트 지시·외부 MCP는 상속하지 않습니다. CLI 기능 목록과 실제 설정/MCP 목록을 확인하지 못하거나 필수 차단 기능이 없으면 채팅을 시작하지 않습니다. 서버 요청으로 권한을 넓힐 수도 없습니다.
- 이 제한은 신뢰된 백엔드·설치된 Codex CLI·등록된 생성 제공자에 대한 애플리케이션 경계입니다. 설치된 CLI의 `read-only`는 운영체제 전체에 대한 읽기 격리를 보장하지 않습니다. 셸·파일 변경·브라우저·앱·에이전트·코드 실행 도구를 비활성화하고 CoNAI 도구로만 작업합니다.
- NovelAI 생성은 요청 한 번에 1장만 허용합니다. 2장 이상 동시 생성은 Anlas가 차감되므로, 여러 장이 필요하면 에이전트가 요청을 나눠 보냅니다.
- Codex 프로필은 서버에 로그인된 Codex 계정 하나의 사용량을 함께 씁니다.
- 작은 로컬 모델은 도구를 잘못 부르기도 합니다. 도구가 필요 없는 프로필은 MCP를 끄거나, 도구 탭의 고급에서 필요한 도구만 고르면 요청이 가벼워집니다.
- 라이브러리 검색 도구(`search_images`)는 이미지·동영상·움짤(GIF)을 구분해 찾을 수 있습니다("동영상만 찾아줘").

## 문제 해결

| 문제 | 확인 |
| --- | --- |
| 채팅 아이콘이 안 보임 | 설정에서 채팅 사용이 켜져 있는지, 계정에 채팅 권한이 있는지 확인합니다. |
| + 메뉴에 프로필이 없음 | 프로필이 켜져 있는지, 그 엔진의 채팅 권한이 있는지 확인합니다. |
| 보내기 버튼이 비활성화됨 | 입력창 위 경고를 확인합니다. Codex 로그인이 필요하면 생성 페이지의 Codex 탭에서 로그인합니다. 프로필이 지워졌거나 꺼져 있으면 새 채팅을 시작합니다. |
| "LLM 요청 실패" 오류 | LLM 연결의 주소·키, 연결 아래 모델 ID, 엔진이 켜져 있는지 확인합니다. Docker로 실행 중이면 같은 PC의 엔진 주소는 `127.0.0.1` 대신 `host.docker.internal`을 씁니다. |
| Codex 기능·설정·MCP 격리 확인 실패 | 설치된 CLI가 필요한 차단 기능을 지원하는지 확인하고 업데이트합니다. 제한을 풀어서 우회하지 않습니다. |
| Codex 파일 기반 로그인 필요 | 서버 CLI의 파일 기반 로그인이 필요합니다. 키링만 사용하는 로그인이나 호스트 홈으로의 무제한 대체 실행은 지원하지 않습니다. |
| 도구 호출이 실패함 | 프로필 도구 탭의 범위와, 채팅하는 계정에 그 작업의 기능 권한(예: 생성은 `generation.execute`)이 있는지 확인합니다. |

응답이 시작되기 전의 연결 실패, 502·503·504 또는 LiteLLM 연결 오류는 1초·2초 간격으로 최대 두 번 자동 재시도합니다. 같은 연결에 1분 안에 두 번 접속하지 못하면 30초 동안은 그 연결로 가는 요청(답변·판단·번역·요약)을 기다리지 않고 바로 실패시킵니다. 요청이 너무 많다는 응답(429)은 아직 아무것도 표시되지 않았을 때 서버가 알려 준 시간(10초 이내)만큼 기다렸다가 한 번 다시 보냅니다. 답변이나 추론이 표시된 뒤의 오류, 인증·입력 오류(4xx), 취소·요청 제한 시간 초과는 재시도하지 않습니다. 워크플로우 LLM 호출도 같은 규칙을 사용하며, 이미 실행한 도구를 다시 실행하지 않습니다.

프로필의 스위치는 옆 글자를 눌러도 한 번씩 켜고 끌 수 있습니다. 채팅 모양 팝업은 크기·간격을 고른 뒤에도 Esc로 닫을 수 있습니다.
