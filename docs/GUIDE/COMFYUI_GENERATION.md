# ComfyUI 생성

ComfyUI 탭은 등록된 ComfyUI 서버와 워크플로우를 사용해 이미지를 생성합니다. CoNAI에서 서버, 워크플로우, 사용자 입력 필드, 큐 라우팅, 결과 보기 방식을 한 화면에서 관리합니다.

## 위치

`/generation?tab=comfyui`

## 핵심 구조

| 구성 | 역할 |
| --- | --- |
| 서버 | 실제 ComfyUI 또는 Modal ComfyUI 엔드포인트 |
| 워크플로우 | 실행할 ComfyUI API workflow JSON |
| Marked Fields | 사용자가 생성 화면에서 바꿀 입력값 |
| 드롭다운 목록 | 모델/LoRA/스타일 같은 선택지 목록 |
| 큐 | 실행 요청을 저장하고 서버로 분배 |
| 결과 보기 | 생성 이력 또는 artifact explorer |

## 기본 흐름

1. ComfyUI 서버를 등록합니다.
2. 서버 연결을 테스트합니다.
3. 워크플로우를 등록합니다.
4. 그래프 보기나 JSON 검색으로 바꿀 노드를 찾습니다.
5. 사용자가 입력할 값을 Marked Field로 추가합니다. 같은 원본 노드의 필드는 생성 화면에서 한 그룹으로 표시됩니다.
6. 워크플로우를 저장합니다.
7. 워크플로우를 선택합니다.
8. 필수 필드와 이미지 입력을 채웁니다.
9. 실행 대상과 큐 등록 개수를 선택합니다.
10. 생성 버튼으로 큐에 등록합니다.
11. 생성 이력이나 artifact explorer에서 결과를 확인합니다.

다른 작업이 먼저 워크플로를 저장하면 열린 편집기의 저장은 거절되고 초안은 남습니다. 필요한 내용을 보존한 뒤 최신 워크플로를 다시 불러옵니다.

## 서버 등록

이름이 표시된 ComfyUI 탭의 서버 섹션에서 서버를 추가합니다. 관리자는 **설정에서 관리**로 설정 → 생성 엔진 → ComfyUI 서버를 열 수도 있습니다.

워크플로우 실행 화면의 **생성** 줄에서 반복 수와 결과 그룹을 고릅니다. **…** 메뉴에는 모듈 저장, 초기화와 활성화된 플러그인 작업이 있으며, 생성 이력 결과의 동작은 이미지 위 가로 툴바에 있습니다.

| 필드 | 설명 |
| --- | --- |
| Name | 화면에 표시할 서버 이름 |
| Endpoint | 서버 주소. 예: `http://127.0.0.1:8188` |
| Backend | `Local ComfyUI API` 또는 `Modal ComfyUI /generate` |
| Capacity | 동시 실행 슬롯 수 |
| Description | 선택 설명 |
| Routing tags | 자동 분배용 태그. 쉼표로 구분 |

### Local ComfyUI API

일반 ComfyUI 서버입니다. 테스트 버튼은 연결 상태, idle/busy, 실행/대기 개수, 응답 시간을 확인합니다.

권장 확인:

- ComfyUI가 켜져 있는지
- CoNAI 서버에서 Endpoint에 접근 가능한지
- 방화벽/포트가 막혀 있지 않은지
- 필요한 커스텀 노드와 모델이 서버에 있는지

### Modal ComfyUI /generate

Modal로 감싼 ComfyUI 엔드포인트입니다. 테스트 호출이 원격 비용을 만들 수 있어 UI에서 별도로 표시합니다.

Modal 서버는 일반 ComfyUI의 idle 상태 확인과 다르게 동작할 수 있습니다.

## 서버 라우팅

워크플로우 실행 화면에서 실행 대상을 고릅니다.

| 대상 | 동작 |
| --- | --- |
| 자동 분산 | 연결된 일반 ComfyUI 서버 중 사용 가능한 서버로 큐 등록 |
| 특정 서버 | 선택한 서버로 큐 등록 |
| 태그 | 해당 routing tag를 가진 서버로 큐 등록 |

큐 등록 개수는 1~32 범위입니다. 같은 입력으로 여러 작업을 큐에 넣고 싶을 때 사용합니다.

## 워크플로우 등록

워크플로우 섹션에서 등록 버튼을 누릅니다.

### 1. 기본 정보 입력

| 필드 | 설명 |
| --- | --- |
| 이름 | 워크플로우 목록에 표시할 이름 |
| 설명 | 용도, 모델, 입력 규칙 등을 적는 선택 설명 |
| 공용 페이지 사용 | 로그인 없는 공개 실행 페이지를 열지 여부 |
| 공용 slug | 공개 페이지 URL 식별자 |
| 공용 1회 요청 상한 | 공개 페이지에서 한 번에 등록 가능한 큐 상한. 1~32 |
| 결과 표시 방식 | 히스토리 뷰어 또는 탐색형 뷰어 |
| 결과 저장 방식 | 공유 폴더 또는 실행별 폴더 |
| 결과 저장 루트 경로 | artifact explorer를 쓸 때 결과 저장 루트 |

공용 페이지는 외부 사용자가 큐를 만들 수 있는 경로가 될 수 있으니 공개 범위와 권한을 먼저 확인합니다.

### 2. Workflow JSON 넣기

업로드 버튼으로 ComfyUI workflow JSON을 선택하거나, JSON 탭에 직접 붙여 넣습니다.

ComfyUI API workflow JSON(Workflow → Export (API))과 ComfyUI 편집기에서 저장한 일반 workflow JSON을 모두 받습니다. 일반 workflow는 등록된 ComfyUI 서버의 노드 정보로 API 형식으로 바뀌고, 바꾸지 못하면 그 이유가 표시됩니다. 그때는 ComfyUI에서 Export (API)로 내보낸 JSON을 넣습니다.

JSON이 바뀌면 실행할 수 있는 서버와 대조하는 서버 검사가 돕니다. 없는 노드·모델, 범위를 벗어난 값, 출력에 닿지 않는 노드가 그래프에 표시됩니다.

JSON이 유효하면 그래프 보기에서 노드가 표시됩니다.

### 3. 그래프에서 입력 노드 찾기

그래프 보기에서 다음 기준으로 검색할 수 있습니다.

- 노드 title
- `class_type`
- node id

검색 결과 이동 버튼으로 노드를 빠르게 찾습니다.

### 4. Marked Field 추가

그래프의 입력값 중 사용자가 바꿀 값을 Marked Field로 추가합니다.

Marked Field는 생성 화면에 노출되는 입력칸입니다. 너무 많이 열면 사용이 어려워지므로 자주 바꾸는 값만 노출합니다.

좋은 후보:

- positive prompt
- negative prompt
- seed
- steps
- CFG
- sampler / scheduler
- checkpoint
- LoRA
- 입력 이미지
- ControlNet 이미지
- denoise / strength

### 시드

`seed`·`noise_seed` 입력은 실행할 때마다 새 무작위 값으로 바뀌어서, 같은 워크플로를 다시 돌려도 결과가 달라집니다. 시드가 그대로 유지되는 경우는 두 가지입니다.

- Marked Field로 연 시드 칸에 0 이상의 숫자를 넣은 경우 (그 실행에만 적용)
- ComfyUI 편집기에서 그 시드가 "fixed"였던 workflow를 변환한 경우 (노드 `_meta.conai_fixed_seeds`에 남음)

시드 칸을 비우거나 -1을 넣으면 매번 새 시드로 생성합니다. 음수 시드는 항상 새로 뽑습니다.

## Marked Field 설정

각 필드는 펼쳐서 세부 설정을 바꿀 수 있습니다.

| 설정 | 설명 |
| --- | --- |
| Label | 생성 화면에 표시할 이름 |
| Type | text, textarea, number, select, image, node |
| Description | 사용자가 볼 설명 |
| Default | 기본값 |
| required | 비어 있으면 실행을 막음 |
| collapsed by default | 생성 화면에서 기본 접힘 처리 |
| simple upload mode | 이미지 필드에서 간단 업로드 모드 사용 |
| Min / Max / Step | number 필드 입력 범위 |
| Dropdown List | select 필드에 연결할 목록 |
| Manual Options | select 필드 직접 선택지 |

필드 순서는 드래그로 바꿀 수 있습니다. 자주 쓰는 입력을 위로 올립니다. 같은 ComfyUI 노드에서 가져온 필드들은 한 카드 안에 묶이므로 노드 단위로 입력 맥락을 확인할 수 있습니다.

number 필드는 화살표로 단계 조정하거나 직접 입력합니다. 입력 중에는 값을 강제로 보정하지 않지만, 실행 시에는 설정된 Min / Max 범위를 벗어난 값이 서버 경계에서도 차단됩니다.

## 드롭다운 목록

ComfyUI 모델 파일명처럼 사용자가 직접 타이핑하기 어려운 값은 드롭다운 목록으로 관리합니다.

### 커스텀 목록

직접 이름과 항목을 입력합니다. 항목은 줄바꿈 또는 쉼표로 구분합니다.

예:

```text
realistic.safetensors
anime_v5.safetensors
product_photo.safetensors
```

### 자동수집 목록

대표 ComfyUI 서버의 모델 API에서 파일 목록을 읽어 통합 목록과 하위 폴더별 드롭다운 목록을 만듭니다.

기본 API 경로:

- `/models/checkpoints`
- `/models/diffusion_models`
- `/models/unet_gguf`
- `/models/loras`

일부 경로가 없거나 요청에 실패해도 나머지 경로의 수집은 계속됩니다. 완료 알림에 수집 결과와 실패한 경로·오류 원인을 함께 표시합니다.

성공한 경로의 목록만 갱신하며, 실패한 경로·이번에 요청하지 않은 경로의 기존 목록과 직접 만든 목록은 보존합니다. 성공한 경로가 빈 목록을 반환하면 해당 경로의 오래된 자동수집 목록은 제거합니다. 모든 경로가 실패하면 기존 목록을 바꾸지 않고 오류를 알립니다.

구버전 자동 목록도 이름이 `checkpoints`·`checkpoints/SD15`처럼 소속 모델 폴더를 식별할 수 있으면 성공한 폴더와 함께 갱신합니다. `SD15`처럼 소속 모델 폴더를 알 수 없는 목록은 보존합니다.

같은 모델 폴더를 여러 API 경로에서 조회할 때 그중 하나라도 실패하면, 기존 항목을 보존하면서 성공한 경로의 결과를 합칩니다.

## 워크플로우 실행

워크플로우를 선택하면 실행 화면으로 들어갑니다.

1. 실행 대상 선택: 자동, 태그, 특정 서버
2. 큐 등록 개수 입력
3. Marked Field 값 입력
4. 이미지 필드가 있으면 이미지 선택
5. 생성 실행

이미지 입력에는 라이브러리 이미지를 고르거나 파일을 올려. API에서는 이미지 조회 권한이 있는 `composite_hash`, workflow-input-asset·queue-input 참조, data URL이나 base64를 쓸 수 있어. 이미지 객체의 `path`, `file_path`, `filePath`, `storagePath`, `originalPath`, `original_file_path`에 서버 파일 경로를 넣으면 400으로 거부돼. 단독 이미지 문자열은 서버 파일을 읽는 경로가 아니라 base64 입력 데이터로 다뤄.

실행 중에는 대기열과 생성 이력에서 현재 ComfyUI 노드 진행률을 확인할 수 있습니다. WebSocket 연결이 잠시 끊겨도 재연결 백오프와 상태 조회를 사용해 화면을 복구합니다.

### 캐릭터 라이브러리에서 불러오기

폼의 **캐릭터 불러오기**로 [외형 설정](CHARACTER_LIBRARY.md)을 선택합니다. 태그를 넣을 marked text/textarea 필드를 고르고, 필요하면 기준 이미지를 넣을 marked image 필드도 고릅니다. 텍스트 필드가 없는 워크플로우에는 이 버튼이 없습니다.

로그인한 계정에 `characters.view`가 있으면 공개 워크플로우 페이지에서도 사용할 수 있습니다. 이미지 옵션에는 `images.view`도 필요합니다. 값은 불러올 때 복사되며 이후 라이브러리 변경은 이미 채운 폼에 반영되지 않습니다.

## MiniMax H3 Director

DaSiWa 계열 MiniMax H3 Director 노드가 포함된 워크플로우는 전용 입력 UI를 사용합니다.

- I2V, FL2V, FL2VA, REF2V, REF2VA 모드별 이미지·비디오·오디오 타임라인 구성
- 미디어 카드 드래그 정렬, 파일 드롭 교체, 레인별 초기화
- 전용 프롬프트 빌더와 미디어 프롬프트 요약
- 화면 순서는 미디어, 프롬프트, **출력 설정**입니다. 해상도·길이·프레임 레이트·후처리는 출력 설정에 접혀 있고 머리글에 현재 값이 요약됩니다. 해상도 패널이 캔버스를 계산하므로 패널이 보이는 워크플로우에는 너비·높이 직접 입력이 없습니다.
- 참조 카드의 **마커 복사** 버튼으로 `<Picture 1>`·`<Video 1>`·`<Audio 1>` 마커를 복사해 프롬프트에 붙여 넣을 수 있습니다.
- 영상·오디오는 카드의 재생기 하나와 구간 슬라이더로 사용할 구간을 정합니다.
- 이미지·비디오 원본 비율 표시
- 최신 노드 입력 규격과 기존 프롬프트 형식 호환

워크플로우 편집에서 전용 필드 노출 여부를 정한 뒤 생성 화면에서 미디어와 프롬프트를 구성합니다. 서버에는 해당 MiniMax H3 Director 커스텀 노드가 설치되어 있어야 합니다.

### RefMod (REF2VA)

RefMod는 ComfyUI의 `models/refmods/` 폴더에 저장된 MiniMax H3 참조 번들(`.safetensors`)입니다. REF2VA 모드에서는 Director 입력에 **RefMod** 패널이 나타나고, 서버의 RefMod 목록에서 파일을 골라 최대 8개 슬롯에 넣을 수 있습니다.

- 행마다 사용 여부, 강도(0–1), 설명을 정합니다. 설명을 쓰면 파일에 들어 있는 설명 대신 사용됩니다.
- 프롬프트에 `<RefMod N>`(N은 슬롯 번호)을 쓰면 실행 시 DaSiWa 노드가 실제 `<Picture N>`·`<Video N>`·`<Audio N>` 라벨로 바꿉니다.
- 목록은 대표(기본) ComfyUI 서버의 `models/refmods`에서 읽습니다. DaSiWa 팩이 없는 서버에서는 "RefMod를 사용할 수 없어"로 표시됩니다.
- 다른 모드로 바꾸면 패널은 숨겨지고 선택은 그대로 보존됩니다. 워크플로 편집의 숨김 컨트롤에 `refmods`를 넣으면 패널을 끌 수 있습니다.
- 페이지 어시스턴트와 MCP(`list_comfy_refmods`, Director 입력의 `refmods`)도 같은 행을 읽고 수정합니다.

### RefMod 만들기

ComfyUI 탭의 워크플로 목록 머리글에서 **RefMod 생성 워크플로 추가**를 누르면 "MiniMax H3 RefMod 생성" 워크플로가 등록됩니다(워크플로 편집 권한 필요). 구성은 Director(참조 입력용, REF2VA) + 영상/음성 VAE 로더 + DaSiWa **MiniMaxH3 Create RefMod**(`DaSiWaH3RefModExport`) 노드이고, 서버를 지정해 등록하면 VAE 선택지가 그 서버의 목록으로 채워집니다. 직접 만든 워크플로도 같은 노드가 들어 있으면 똑같이 동작합니다.

- 이 워크플로는 RefMod만 만들므로 Director에 모델 연결이 없어도 실행됩니다. 패널에 "RefMod를 만들기만 해" 안내가 뜹니다.
- Director에 이미지·영상·음성을 넣고 각 미디어의 설명(프롬프트)을 쓰면 그 설명이 RefMod 멤버 설명이 됩니다. 이름을 비우면 DaSiWa가 자동 이름을 붙입니다.
- 실행 시 CoNAI가 `request_id`를 새로 채우고 Director 스냅샷(업로드된 활성 미디어만)을 export 노드에 복사합니다. 결과는 ComfyUI의 `models/refmods/`에 저장되고 이미지 출력은 없으며, 기록 탭에는 "RefMod 저장: 이름"으로 표시됩니다.

CoNAI는 이때 넣은 원본을 자체 보관합니다. 라이브러리 이미지는 참조로, 업로드한 파일은 복사본으로 남기고 멤버별 종류·설명·트림 구간·크기·길이를 기록합니다. RefMod 패널에서 CoNAI가 만든 항목을 고르면 **원본 보기**로 이미지·영상·음성을 그대로 볼 수 있고, 패널 머리글의 **CoNAI에서 만든 RefMod**에서 전체 목록을 보고 빈 슬롯에 넣을 수 있습니다. **기록 삭제**는 CoNAI의 레코드와 복사본만 지우며 ComfyUI 서버의 `.safetensors`는 남습니다. ComfyUI 화면에서 직접 만든 RefMod에는 원본 정보가 없어 DaSiWa가 저장한 멤버 설명만 보입니다. 서버 간 RefMod 파일 복사·동기화는 CoNAI 범위 밖이므로 별도 도구를 사용하세요.

실행 전 검증:

- 워크플로우가 선택되어 있어야 합니다.
- required 필드는 비어 있으면 안 됩니다.
- 일반 ComfyUI 서버는 연결 테스트가 성공해야 합니다.
- 태그 실행은 해당 태그의 사용 가능한 서버가 있어야 합니다.

실행을 막는 항목은 입력 폼 맨 위의 **실행 준비 필요** 알림 하나로 모아 보여 줍니다. Director 입력 문제도 이 알림에 함께 나오며 Director 안에 같은 목록을 따로 띄우지 않습니다. 폼을 스크롤하면 알림이 스크롤 영역 상단에 고정되어 따라오고, 위로 올리면 원래 자리에 있습니다. **문제 필드로 이동**을 누르면 알림은 그대로 두고 문제 필드로 스크롤하며 해당 필드를 표시합니다.

## SnapRef

SnapRef(`SnapRefSimple`, 표시 이름 "SnapRef") 노드가 있는 워크플로우는 전용 입력 UI로 캐릭터 참조 사진을 넣습니다. 서버에 SnapRef 커스텀 노드(`custom_nodes/snapref`)와 `models/loras`의 SnapRef 가중치 파일(예: `snapref_v2a.safetensors`)이 있어야 합니다.

- 워크플로우 편집의 그래프에서 SnapRef 노드는 **SnapRef** 입력 하나로 표시됩니다. 이 노드 필드 하나가 노드 입력 전체를 맡으므로 `reference`·`strength` 같은 개별 입력은 따로 고르지 않습니다. `model`·`clip`·`vae` 연결은 워크플로우에 저장된 그대로 유지됩니다.
- 생성 화면에서는 같은 캐릭터의 사진을 1~8장 넣습니다. 첫 사진은 필수라 지울 수 없고 **이미지 교체**로만 바꿉니다. **참조 사진 추가**로 나머지 칸을 채우고, 행 메뉴의 **제거**로 빼면 뒤 사진이 앞으로 당겨집니다. 쓰지 않는 칸은 `none`으로 보냅니다.
- 사진은 일반 이미지 입력과 같은 선택 창에서 라이브러리 이미지를 고르거나 파일을 올립니다. 고른 사진은 CoNAI의 워크플로 입력 자산으로 보관되었다가 실행할 때 ComfyUI 서버의 입력 폴더로 전송되고, 노드에는 그 파일 이름이 들어갑니다. 워크플로우에 저장된 첫 사진처럼 이미 서버 입력 폴더에 있는 파일은 이름으로 표시됩니다.
- 사진마다 **강도**(0–2, 1이 학습 기준)를 정합니다. **모드**는 사진의 캐릭터와 그림체를 함께 가져오는 "캐릭터 + 스타일"(`Character & Style`)과 그림체는 모델·프롬프트에 맡기는 "캐릭터만"(`Character`) 중에서 고릅니다. **충실도**(0–1)는 1이면 사진의 디테일을 그대로 살리고 낮출수록 프롬프트를 더 따릅니다. **어댑터**는 LoRA 자동수집 목록에서 SnapRef 가중치 파일을 고릅니다.
- 입력 초안은 사진·강도·설정을 함께 복원합니다. 생성 기록에서 불러오기는 강도·설정과 다시 쓸 수 있는 사진(CoNAI에 보관된 사진, 라이브러리 이미지, 서버 입력 파일 이름)을 복원합니다. 기록에 이미지 데이터가 남지 않은 사진은 일반 이미지 입력처럼 복원되지 않습니다. 첫 사진이면 현재 사진을 그대로 두고, 나머지는 빈 칸으로 두며, 사진을 다시 넣으라는 안내가 나옵니다. 초기화하면 이 초안에서 올린 사진은 정리 대상으로 표시됩니다.
- 범위를 벗어난 값, 알 수 없는 모드, 비어 있는 첫 사진, 8장을 넘는 입력은 서버가 큐 등록 전에 거절하고 이유를 알려 줍니다.
- 워크플로우를 모듈로 저장하면 노드 워크플로 인스펙터에서 같은 입력 UI로 값을 정합니다.
- 페이지 어시스턴트는 `media.attach`의 `slot`(1–8)로 사진을 넣고 노드 입력 편집으로 모드·충실도·어댑터와 사진별 강도·제거를 바꿉니다. MCP는 `get_workflow_details`의 `value_schema`로 입력 형식을 확인합니다([MCP 가이드](./MCP_GUIDE.md)).

여러 장을 넣을 때 보조 사진(예: 전신)의 강도를 낮추면 첫 사진 위주로 반영됩니다. 고급 노드 `SnapRef`(SnapRef (Advanced))는 사진을 다른 노드의 IMAGE 연결로 받으므로 전용 UI 없이 일반 Marked Field로 입력을 엽니다.

## 결과 보기

워크플로우 설정의 결과 표시 방식에 따라 달라집니다.

| 방식 | 설명 |
| --- | --- |
| 히스토리 뷰어 | 생성 이력 패널에서 결과를 확인 |
| 탐색형 뷰어 | workflow artifact explorer에서 실행 산출물을 탐색 |

artifact explorer를 쓰면 결과 저장 루트와 저장 방식이 중요합니다.

| 저장 방식 | 설명 |
| --- | --- |
| 공유 폴더 | 같은 워크플로우 결과를 한 폴더에 모음 |
| 실행별 폴더 | 실행마다 별도 폴더를 만들어 산출물 분리 |

## 워크플로우를 모듈로 저장

워크플로우 목록의 저장 아이콘으로 ComfyUI 워크플로우를 모듈 그래프용 모듈로 만들 수 있습니다.

사용 흐름:

1. 저장 아이콘을 누릅니다.
2. 모듈 이름과 설명을 정합니다.
3. 외부에서 입력 가능하게 열 필드를 선택합니다.
4. 새 모듈로 저장하거나 기존 모듈을 덮어씁니다.

자주 쓰는 ComfyUI 파이프라인을 모듈 그래프 워크플로우 안에서 재사용할 때 유용합니다.

## 운영 팁

- 처음에는 prompt, negative, seed, 입력 이미지만 Marked Field로 엽니다.
- 모델 파일명은 select + 드롭다운 목록으로 만듭니다.
- seed는 number 필드로 열고 비워 둡니다. 같은 이미지를 다시 뽑을 때만 그 시드 값을 넣습니다.
- 실험용 서버와 운영용 서버는 routing tag를 분리합니다.
- 대형 워크플로우는 큐 등록 개수를 낮게 시작합니다.
- artifact explorer를 쓸 워크플로우는 저장 루트를 명확히 정합니다.
- 공개 페이지는 큐 상한을 낮게 잡고 권한을 확인합니다.

## 채팅으로 편집하기

워크플로 등록·수정 편집기를 채팅에 연결하면 채팅이 다음을 할 수 있습니다. 저장은 항상 카드로 제안되고 사람이 적용합니다.

- API JSON이나 ComfyUI 편집기 workflow를 넣기 (편집기 workflow는 먼저 API 형식으로 바꿈, 변환 경고도 읽음)
- 서버 검사를 바로 돌리고 결과(서버별 문제, 출력에 닿지 않는 노드)를 읽기
- 추천 필드(프롬프트, 입력 이미지, seed·steps·CFG, 크기 등)를 Marked Field로 표시하기
- 시드 입력마다 고정 여부를 보고 고정·해제하기
- Marked Field 등록·수정·해제·순서 바꾸기

페이지 연결 없이도 채팅과 MCP는 `check_comfy_workflow`로 등록된 워크플로나 초안 JSON을 저장 없이 서버 검사할 수 있습니다. 생성 화면을 연결하면 채팅은 어느 칸이 시드인지 알고, 같은 이미지를 다시 뽑을 때는 시드 값을 넣고 새 이미지를 원할 때는 비워 둡니다.

## 실패 시 확인

| 증상 | 확인 |
| --- | --- |
| 서버 테스트 실패 | Endpoint, 포트, 방화벽, ComfyUI 실행 상태 |
| Modal 호출 실패 | `/generate` 엔드포인트, 인증, 원격 로그, 비용 제한 |
| 워크플로우 저장 실패 | JSON 형식, 일반 workflow 변환 실패 이유, 이름 입력 여부 |
| 매번 다른 결과가 나옴 | 시드 칸이 비어 있는지 (비우면 실행마다 새 시드) |
| 실행 버튼 후 실패 | required 필드, 이미지 입력, 선택 서버 연결 상태 |
| 모델을 찾지 못함 | 서버의 모델 폴더와 드롭다운 값이 실제 파일명과 일치하는지 |
| 커스텀 노드 오류 | 해당 서버에 필요한 ComfyUI 커스텀 노드가 설치되어 있는지 |
| 결과가 안 보임 | 결과 표시 방식, 저장 루트, artifact directory 설정 |
| 큐가 밀림 | 서버 capacity, running/pending 수, 예약작업 상태 |
