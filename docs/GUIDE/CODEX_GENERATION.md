# Codex 생성

Codex 탭은 Codex CLI의 이미지 생성 능력을 CoNAI 생성 큐에 연결합니다. 텍스트 생성만 하는 기능이 아니라, Codex를 새 실행 세션으로 띄워 결과 이미지 파일을 만들고 CoNAI가 그 파일을 생성 이력으로 가져오는 방식입니다.

## 위치

`/generation?tab=codex`

## 언제 쓰나

| 상황 | Codex가 맞는 경우 |
| --- | --- |
| 자유로운 이미지 생성 | 자연어 지시로 결과를 만들고 싶을 때 |
| 이미지 편집 | 기존 이미지를 참고해 수정하고 싶을 때 |
| 인페인트 | 참조 이미지와 마스크로 특정 영역만 바꾸고 싶을 때 |
| 실험 | 프롬프트 지시를 길게 주고 결과를 빠르게 비교하고 싶을 때 |

정밀한 노드 기반 파이프라인은 ComfyUI가 더 적합합니다. Codex는 “말로 지시해서 결과를 받는” 쪽에 가깝습니다.

## 사전 조건

서버에서 Codex CLI가 설치되어 있고 로그인되어 있어야 합니다.

CoNAI는 생성 전에 `codex login status`로 상태를 확인합니다.

| 상태 | 의미 | 조치 |
| --- | --- | --- |
| 생성 버튼 활성 | Codex CLI와 로그인 상태 확인됨 | 바로 생성 |
| 상태 확인 중 | 로그인 상태 조회 중 | 잠시 대기 |
| 로그인 확인 후 생성 | CLI는 있으나 로그인이 안 됨 | 관리자는 상태 옆 로그인 버튼, 또는 서버에서 `codex login` 실행 |
| Codex 확인 후 생성 | CLI를 찾지 못했거나 실행 실패 | 서버 설치/경로 확인 |

상태가 애매하면 상단 새로고침 버튼으로 다시 확인합니다.

### 앱에서 로그인

관리자 계정이면 `로그인 필요` 옆에 로그인 버튼이 보입니다. 누르면 서버가 `codex login --device-auth`를 실행하고 일회용 코드와 인증 페이지 링크를 띄웁니다. 아무 기기의 브라우저에서 인증 페이지를 열어 코드를 입력하면 창이 닫히고 상태가 `사용 가능`으로 바뀝니다.

- 코드는 15분 뒤 만료됩니다. 만료되면 다시 시도합니다.
- 창을 닫으면 진행 중인 로그인은 취소됩니다.
- 서버 전체가 로그인한 계정 하나로 Codex를 쓰므로 관리자만 할 수 있습니다.
- Docker 배포는 [Docker로 실행 → Codex 로그인](./DOCKER.md#codex-로그인)을 참고합니다.

### CLI 업데이트

관리자 계정이면 npm에 더 새로운 Codex CLI가 있을 때 상태 옆에 업데이트 버튼이 보입니다. 버튼에 마우스를 올리면 현재 버전과 새 버전이 나옵니다.

- 실행 중인 Codex 생성 작업이 있으면 업데이트를 거절합니다. 작업이 끝난 뒤 다시 누릅니다.
- 업데이트하는 동안 Codex 채팅 세션이 끊깁니다.
- 설치 위치는 `CODEX_NPM_PREFIX`가 있으면 그 폴더, 없으면 npm 전역 설치입니다. Docker 이미지는 볼륨 안(`/app/data/user/codex-cli`)을 써서 컨테이너를 다시 만들어도 업데이트가 유지됩니다.
- 설치본이 여러 개면 버전이 가장 높은 것을 씁니다. 이미지를 다시 빌드해 기본 설치본이 더 새로우면 그쪽을 씁니다.

## 기본 흐름

1. Codex 탭을 엽니다.
2. 상태가 사용 가능인지 확인합니다.
3. Prompt를 입력합니다.
4. 필요하면 Negative Prompt를 입력합니다.
5. 비율과 해상도를 선택합니다.
6. 편집/인페인트가 필요하면 참조 이미지와 마스크 이미지를 넣습니다.
7. 생성 개수를 정합니다.
8. 생성 버튼으로 큐에 등록합니다.
9. 생성 이력에서 결과와 실패 메시지를 확인합니다.

## 작업 모드

`이미지 사용 방식`에서 새 이미지 생성과 원본 편집을 선택합니다. 기본값은 새 이미지 생성입니다.

| 입력 | 작업 | 설명 |
| --- | --- | --- |
| 새 이미지 생성 + Prompt | Generate | 텍스트로 새 이미지 생성 |
| 새 이미지 생성 + Prompt + 참조 이미지 | Generate (참조 t2i) | 첨부 이미지의 스타일·색감·구도를 참고해 새 이미지 생성 |
| 원본 편집 + Prompt + 원본 이미지 | Edit (i2i) | 원본을 유지하면서 요청한 부분 수정 |
| 원본 편집 + Prompt + 원본 이미지 + 마스크 | Infill | 마스크 영역 중심으로 인페인트 |

원본 편집은 이미지 첨부가 필수입니다. 마스크는 원본 편집에서만 선택할 수 있습니다. 원본을 교체·제거하거나 사용 방식을 바꾸면 기존 마스크는 해제됩니다. 마스크는 자연어 편집 지시와 함께 전달되므로 픽셀 단위 보존을 보장하지 않습니다.

### 프롬프트 저장과 재사용

- 생성에 사용한 사용자 프롬프트와 네거티브 프롬프트는 결과 이력과 이미지 메타데이터에 저장됩니다. 와일드카드는 실행 시 확정된 텍스트가 저장됩니다.
- 결과의 `프롬프트 복사` 또는 `이 설정 불러오기`로 재사용합니다. Codex 설정을 불러올 때는 실제 사용한 프롬프트와 생성/편집 모드를 복원하며, 첨부 이미지는 다시 선택해야 합니다.
- 입력 영역의 `프롬프트 프리셋 저장`에서 포지티브 또는 네거티브를 선택하고 이름을 지정해 저장합니다. 기존 프롬프트 프리셋 라이브러리를 사용하며 프리셋 생성 권한이 필요합니다.
- 저장한 프리셋은 프롬프트 행의 프리셋 삽입 버튼으로 불러옵니다. 포지티브와 네거티브는 각각 저장·삽입합니다.
- 저장 대상은 CoNAI가 전달한 사용자 프롬프트입니다. 이미지 도구 내부에서 재작성된 프롬프트는 현재 CLI 연동에서 수집하지 않습니다.

## 프롬프트

### 실행 모델

`Codex 실행 모델`에 모델 ID를 입력하면 해당 작업의 `codex exec --model`로 전달됩니다. 후보는 서버 Codex CLI의 로컬 모델 캐시에서 읽으며, 캐시가 없거나 목록에 없는 모델도 직접 입력할 수 있습니다. 사용 가능 여부는 서버 로그인 계정과 CLI에서 결정됩니다.

- 비워두면 기존처럼 서버 CLI 기본 모델을 사용합니다. 서버 전역 설정은 변경하지 않습니다.
- 선택한 모델은 브라우저 초안, 큐 요청, 결과 메타데이터에 남고 `이 설정 불러오기`에서도 복원됩니다.
- 이 항목은 Codex 에이전트의 실행 모델입니다. 내부 이미지 생성 도구의 이미지 전용 모델을 지정하는 항목이 아닙니다.
- 워크플로우의 `Codex 이미지 생성` 노드에서도 `model`과 `operation`을 지정할 수 있습니다. `operation=generate`는 이미지 참조 생성, `edit`는 원본 편집, `infill`은 마스크 편집이며 `auto`는 기존처럼 첨부 입력에 따라 결정합니다.

### MCP에서 동일한 설정 사용

`get_codex_generation_options`로 모델 후보와 요청 JSON Schema를 조회한 뒤 `submit_generation_job`의 `request_payload`에 UI와 같은 값을 보냅니다. 모델, 프롬프트/네거티브, 생성 방식, 첨부 이미지/마스크, 크기, 개수, 저장 옵션을 지원합니다.

```json
{
  "service_type": "codex",
  "request_payload": {
    "prompt": "Create a blue ceramic teapot",
    "model": "",
    "operation": "generate",
    "size": "1024x1024",
    "count": 1
  }
}
```

`model`에 사용할 Codex 모델 ID를 넣습니다. `image`와 `mask`는 base64 data URL입니다. 참조 t2i는 `operation=generate`와 `image`를 함께 전달합니다.

- `get_generation_history_request`: 이력 ID로 전체 프롬프트와 모델/생성 설정 조회. 이미지 바이트는 반환하지 않습니다.
- `list_prompt_presets`: UI와 공유하는 프리셋 조회.
- `create_prompt_preset`: `name`, `items: [{ description, value }]`로 프리셋 저장. 중복 이름은 덮어쓰지 않습니다.
- 조회는 MCP `read`, 생성은 `generate`, 프리셋 저장은 `organize` 권한이 필요합니다.

### Prompt

Codex에 전달되는 핵심 지시입니다. 결과 파일 생성까지 Codex가 수행하므로, 원하는 결과를 명확히 적습니다.

좋은 형태:

```text
Create a clean product-style illustration of a blue capsule machine, front view, simple background, crisp edges, high contrast.
```

### Negative Prompt

피하고 싶은 요소입니다. 내부적으로 `Avoid:` 지시로 함께 전달됩니다.

예:

```text
blurry, low quality, distorted text, extra limbs, watermark
```

## 출력 설정

| 설정 | 값 | 설명 |
| --- | --- | --- |
| 생성 개수 | 1~4 | 큐 등록 개수. 2개 이상이면 각각 별도 큐 작업으로 분리됩니다. |
| 비율 | Random, 1:1, 4:3, 3:4, 16:9, 9:16 | 출력 비율. Random은 실행 시 지원 비율 중 하나를 선택합니다. |
| 해상도 | 1024px, 1536px, 2048px | 긴 변 기준 해상도입니다. 실제 너비/높이는 64 단위로 반올림됩니다. |

예:

| 비율 | 1024px 선택 시 요청 크기 |
| --- | --- |
| 1:1 | 1024x1024 |
| 4:3 | 1024x768 |
| 3:4 | 768x1024 |
| 16:9 | 1024x576 |
| 9:16 | 576x1024 |

비율과 해상도는 Codex에 전달하는 요청값이며 실제 생성 크기는 달라질 수 있습니다. 저장 포맷, 품질, 리사이즈 정책은 설정 → 미디어 생성/저장의 이미지 저장 설정을 따릅니다.

## 이미지 입력

### 참조 이미지

편집하거나 스타일/구도를 참고할 이미지입니다.

사용 방법:

1. 이미지 섹션에서 참조 이미지 선택을 누릅니다.
2. 라이브러리나 업로드된 이미지에서 선택합니다.
3. 필요하면 교체하거나 제거합니다.

새 이미지 생성 모드에서는 참조로, 원본 편집 모드에서는 수정할 원본으로 큐에 들어갑니다.

### 마스크 이미지

인페인트할 영역을 지정하는 이미지입니다.

사용 조건:

- 참조 이미지가 먼저 있어야 합니다.
- 마스크가 있으면 Infill 모드가 됩니다.
- 흰 영역은 편집 대상, 어두운 영역은 보존 대상으로 전달됩니다.

## 큐 동작

Codex 생성은 바로 실행하지 않고 CoNAI 생성 큐에 등록됩니다.

동작 방식:

1. CoNAI가 요청 payload를 저장합니다.
2. 큐 워커가 Codex CLI 상태를 다시 확인합니다.
3. 임시 작업 폴더를 만듭니다.
4. 참조/마스크 이미지가 있으면 작업 폴더에 저장합니다.
5. Codex를 `exec --ephemeral --sandbox workspace-write` 형태로 실행합니다. sandbox 값은 `CODEX_SANDBOX_MODE`로 바꿀 수 있고, Docker 이미지는 `danger-full-access`를 씁니다.
6. Codex가 요청된 결과 파일을 만들면 CoNAI가 가져옵니다.
7. 생성 이력에 결과, 프롬프트, 크기, 작업 모드, Codex 메시지를 기록합니다.

생성 개수를 4로 넣으면 큐 작업 4개가 등록됩니다. 각 작업은 결과 1장을 만드는 식이라 실패/재시도가 분리됩니다.

## 결과 확인

오른쪽 생성 이력에서 다음을 확인합니다.

- 대기/실행/성공/실패 상태
- 결과 이미지
- 작업 요약
- 실패 메시지
- 재시도/취소 가능 여부

Codex가 이미지를 만들지 못하면 실패 메시지에 Codex 마지막 메시지나 stderr 일부가 표시될 수 있습니다.

## 프롬프트 작성 팁

- 파일명이나 저장 위치를 직접 지시하지 않아도 됩니다. CoNAI가 Codex에 필요한 파일명을 따로 지시합니다.
- 스타일, 피사체, 구도, 배경, 색감, 금지 요소를 분리해서 적으면 안정적입니다.
- 편집 모드에서는 “참조 이미지에서 무엇을 유지하고 무엇을 바꿀지”를 명확히 씁니다.
- 인페인트에서는 “마스크 영역에 무엇을 채울지”를 먼저 씁니다.
- 실패가 반복되면 해상도를 낮추고, 프롬프트를 짧게 줄여 다시 시도합니다.

## 문제 해결

| 문제 | 확인 |
| --- | --- |
| 버튼이 비활성화됨 | Prompt가 비었거나 Codex 상태가 사용 불가입니다. |
| 로그인 필요 메시지 | 관리자가 상태 옆 로그인 버튼으로 로그인하거나, 서버에서 `codex login`을 완료합니다. |
| CLI를 찾지 못함 | Codex CLI 설치 위치와 서버 PATH를 확인합니다. Windows 서버는 npm 전역 설치 경로도 확인합니다. |
| 마스크 선택 불가 | 참조 이미지를 먼저 선택합니다. |
| 결과 없음 | Codex 실행은 끝났지만 이미지 파일을 만들지 못한 상태입니다. 프롬프트를 단순화하고 다시 시도합니다. |
| 품질이 들쭉날쭉함 | Codex는 지시 기반 생성입니다. 같은 결과 재현이 중요한 작업은 ComfyUI 워크플로우가 더 적합합니다. |
