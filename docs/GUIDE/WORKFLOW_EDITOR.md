# 워크플로우 편집

워크플로우 탭은 모듈 그래프로 생성·처리 흐름을 만들고, 저장하고, 실행 결과를 관리하는 화면입니다. ComfyUI, NAI, Codex, LLM, 커스텀 노드 같은 작업을 노드로 이어 붙여 반복 가능한 파이프라인으로 씁니다.

## Codex 역할 참조 입력

`Codex 이미지 생성` 노드는 기존 `image`/`mask` 포트와 `operation:auto` 추론을 유지합니다. `references` JSON 텍스트 영역에 순서 있는 배열을 입력합니다. 예: `[{"role":"style","label":"palette","data_url":{"composite_hash":"라이브러리 해시"}}]`. API에서 이미 파싱한 배열도 받을 수 있고 빈 문자열/null은 첨부 없음입니다. JSON 파싱은 라이브러리 이미지 해석 전에 수행합니다. `role`은 `reference|style|material|scale|item`, `label`은 최대 128자입니다. `data_url`은 PNG/JPEG/WebP base64 data URL 또는 `{ "composite_hash": "…" }`입니다. 라이브러리 입력은 기존 image/mask 포트와 같은 권한/파일 해석 경로를 사용하며 별도 접근 권한을 부여하지 않습니다. 전체 파일을 읽기 전에 파일 종류·크기와 헤더의 크기를 검사하고, 큐 저장 전에 큰 바이트를 별도 입력 저장소로 분리합니다.

`preserve`의 빈 값은 기존 동작, `strict`는 원본과 같은 크기의 불투명 PNG 마스크가 있는 infill 전용입니다. strict에서는 요청 크기를 측정한 원본 크기로 덮어씁니다. 알파 255, 검정 보호 픽셀 1개 이상이 필수이며 흰색은 편집, 회색은 혼합입니다. 원본은 회전 없는 8비트 sRGB/회색조(ICC 없음 또는 Sharp 표준 sRGB)만 지원합니다. 생성 크기 불일치를 거부하고 검정 보호 영역을 유지한 PNG를 감시 폴더 밖에서 검증한 뒤 게시합니다. 원본/마스크/참조 합계 5장, 파일당 10 MiB·합계 32 MiB, 최대 한 변 4096px입니다. MCP·웹·그래프는 같은 검증을 거칩니다. 일반 생성 크기는 요청과 달라질 수 있습니다. 전체 계약은 [Codex 생성](./CODEX_GENERATION.md)을 참고합니다.

## 위치

- 생성 페이지: `/generation?tab=workflows`
- 바로가기: `/graph` → 워크플로우 탭으로 이동

## 화면 구조

워크플로우 탭은 두 모드로 나뉩니다.

생성 화면 상단에서 이름이 표시된 **워크플로** 탭을 선택합니다.

| 모드 | 용도 |
| --- | --- |
| Browse | 저장된 워크플로우 선택, 입력값 채우기, 실행, 결과 확인 |
| Editor | 노드 배치, 연결, 입력값 설정, 검증, 저장 |

왼쪽 목록에서 폴더와 워크플로우를 고르고, 오른쪽에서 실행기 또는 편집기를 사용합니다.

## 새 워크플로우 만들기

1. 워크플로우 탭을 엽니다.
2. 새 워크플로우 또는 편집 진입 버튼을 선택합니다.
3. 캔버스 빈 곳을 우클릭하거나 상단의 모듈 추가 버튼을 누릅니다.
4. `시스템`, `생성`, `커스텀 노드` 탭에서 노드를 고릅니다.
5. 노드 포트를 드래그해 다른 노드와 연결합니다.
6. 필요한 입력값을 노드 Inspector에서 채웁니다.
7. 검증 버튼으로 치명 이슈가 없는지 확인합니다.
8. 저장 버튼을 누르고 이름, 설명, 저장 폴더를 확정합니다.

## 채팅으로 워크플로 구성하기

1:1 채팅으로 빈 초안을 구성하거나 편집 중인 워크플로를 수정할 수 있습니다.

1. 새 워크플로우를 열거나 기존 워크플로를 Editor에서 엽니다.
2. 채팅 입력창의 **현재 페이지 연결**을 켭니다. 페이지 도구(`get_workflow_editor`, `list_workflow_modules`, `workflow_edit`)는 연결한 요청에 자동으로 들어갑니다.
3. 원하는 노드와 처리 흐름을 요청합니다. 모델이 만든 변경은 열린 편집기에 바로 반영되고, 답변 아래에 "노드 편집 N건" 칩이 남습니다.
4. 마음에 들지 않으면 칩의 되돌리기 아이콘으로 그 변경 전체를 되돌립니다. 기존 검증·저장·실행 버튼으로 작업을 마칩니다.

요청 예시:

- “상수 텍스트 hello cat을 텍스트 변환 노드에서 cat → dog로 치환한 뒤 최종 결과에 연결하는 워크플로를 짜줘.”
- “변환 노드와 최종 결과 사이에 접두어를 붙이는 텍스트 변환 노드를 추가하고 연결을 바꿔줘.”
- “이 상수 노드를 실행 입력으로 노출하고 라벨을 원문으로 바꿔줘.”
- “이 노드를 삭제하고 앞뒤 노드를 직접 연결해줘.”
- “이 논리 노드를 OR 변형으로 바꾸고 오른쪽으로 옮겨줘.”

채팅은 대표 노드와 변형 이름으로 모듈을 검색하고, `set_variant`로 같은 그룹의 변형을 변경할 수 있습니다. 화면에서 바꿀 때와 동일하게 기존 입력·연결·실행 입력을 보존할 수 있어야 적용됩니다. 채팅에 공개되지 않은 로컬 입력도 적용 전에 검사하며, 손실되는 값이 있으면 변경 전체를 거절합니다.

캐릭터·채팅방·로어북·생성 프리셋·모델·게시판 카테고리처럼 목록에서 고르는 칸은, 채팅이 노드 편집기의 선택 목록과 같은 현재 목록(내 채팅방·내 로어북 포함)을 받아 그 안의 값만 넣습니다. 목록에 없거나 꺼진 항목은 거절하고 고를 수 있는 값을 알려 줍니다. 채팅방 ID는 `list_chat_rooms`로도 찾습니다. 이미지·마스크 입력은 라이브러리 이미지의 해시(`search_images`로 찾은 composite_hash)로 채우며, 파일 경로나 이미지 데이터는 채팅에 보이지도 않고 넣을 수도 없습니다.

등록된 활성 모듈의 실제 입력과 포트만 사용합니다. 선언된 일반 입력은 설정하거나 지울 수 있고, 이미지·영상 등의 포트 연결도 타입이 맞으면 사용할 수 있습니다. 인증값·코드·파일 경로·영상·오디오 원본 입력과 복합 전용 편집 필드는 직접 편집합니다. 커스텀 모듈 정의나 ComfyUI API JSON의 원본 노드 구조는 이 기능으로 변경하지 않습니다.

변경 작업은 전체 검증 후 한 번에 적용합니다. 없는 포트, 타입 불일치, 중복 연결, 단일 입력의 다중 연결과 순환 연결은 거부합니다. 필수 입력이나 최종 결과가 부족한 초안은 모델에게 확인 항목으로 돌아가고, 기존 저장·실행 검증을 따릅니다.

변경은 모델이 읽은 편집기 상태에 묶여 있어서, 그사이 직접 편집했다면 반영하지 않고 모델이 다시 읽게 합니다. 반영 뒤 편집하지 않았을 때만 칩의 되돌리기로 전체 초안을 복원할 수 있습니다. 저장하지 않은 변경이 있으면 모델이 다른 워크플로를 열거나 페이지를 떠나는 작업은 거절됩니다. 비공개 입력과 실행 입력의 현재 값도 로컬에서 보존합니다. 지원 범위는 노드 128개, 연결 512개, 변경 작업 80개 및 편집 정보 크기 제한 안의 그래프입니다.

### 채팅으로 실행과 자동 실행 관리하기

- **실행 화면**(워크플로를 고른 상태)에 연결하면 채팅이 실행 입력을 채우고(이미지 입력은 라이브러리 이미지 해시), **워크플로 실행** 카드를 제안합니다. 카드를 적용하면 실행 버튼과 같은 경로로 실행이 큐에 들어갑니다. 최근 실행 5개의 상태와 실행 ID가 채팅에 보이고, 결과는 `get_graph_workflow_execution`으로 확인합니다.
- **이미지 생성 › 예약**에 연결하면 채팅이 자동 실행 목록(종류·다음 실행·실행 계정·멈춘 이유·실행 수)과 예약 실행 현황을 읽습니다. 자동 실행 만들기·고치기·일시정지·다시 켜기·바로 실행·삭제와 빈 실행 삭제는 카드로 제안하고, 적용해야 반영됩니다. 예약 실행 취소는 현재 화면 리비전과 실행 권한을 확인해 바로 실행합니다.
- 자동 실행은 마지막으로 저장한 계정으로 실행되므로, 저장 카드를 적용한 사람이 실행 계정이 됩니다. 다른 사람이 저장한 자동 실행의 바로 실행은 그 계정이나 관리자만 할 수 있습니다.

## 노드 추가 방식

### 빈 캔버스에서 추가

빈 곳을 우클릭하면 퀵 메뉴가 열립니다. 여기서 노드 추가 버튼을 누르면 모듈 목록이 뜹니다.

모듈 목록 탭:

- `시스템`: 텍스트, 이미지, LLM 호출, 최종 결과 등 기본 모듈
- `생성`: NAI, ComfyUI, Codex 등 생성 계열 모듈
- `커스텀 노드`: 로컬 파일 기반 커스텀 노드

검색창으로 모듈 이름, 설명, 엔진 타입, 카테고리를 찾을 수 있습니다.

### 대표 노드와 변형

기본 노드 47개는 추가 메뉴에서 대표 항목 24개로 묶어 표시합니다. 값, 텍스트, 랜덤, 참조, 이미지 태그, 논리, 조건, Base64, LLM, 생성, 게시 그룹은 노드 헤더의 변형 선택으로 세부 기능을 고릅니다. 기존 노드 이름으로 검색하면 해당 변형을 바로 추가할 수 있습니다. 예를 들어 정규식 치환을 검색해 추가하면 치환 모드로 시작합니다.

변형을 바꿔도 노드 ID·위치·사용자 지정 이름과 호환되는 입력·연결은 유지합니다. 기본 이름은 선택한 변형에 맞춰 갱신합니다. 유지할 수 없는 값이나 연결, 공개 실행 입력이 있으면 변경을 차단하고 정리할 항목을 안내합니다.

기존 워크플로우는 이번 메뉴 통합을 위한 마이그레이션 없이 열고 편집·저장·실행할 수 있습니다. 기존 모듈 ID, 실행 키와 포트 구조를 유지하며, 명시적으로 변형을 바꾸기 전에는 원래 모듈을 사용합니다. 사용자 제작 ComfyUI·커스텀 모듈과 다시와 노드는 통합 대상이 아닙니다.

### 포트에서 추천 노드 추가

노드의 입력/출력 포트를 끌다가 빈 곳에 놓으면 연결 가능한 추천 노드가 뜹니다.

추천 기준:

- 같은 데이터 타입이면 `exact`
- 문자열로 이어 받을 수 있으면 `string-bridge`
- 맞지 않는 포트는 추천에서 제외

이 방식이 제일 빠릅니다. 엉뚱한 노드를 줄여주니까, 삽질 덜 합니다.

## 연결 규칙

- 출력 포트 → 입력 포트로 연결합니다.
- 입력 타입과 출력 타입이 맞아야 합니다.
- 이미 값이 직접 입력된 포트도 연결 상태에 따라 실행 입력으로 처리될 수 있습니다.
- 고급 출력 포트가 있는 노드는 퀵 메뉴에서 고급 출력 모드를 켤 수 있습니다.

연결이 꼬였을 때는 노드 퀵 메뉴에서 `모든 연결 끊기`를 쓰면 빠릅니다.

## 노드 편집

노드를 선택하면 퀵 메뉴와 Inspector를 사용할 수 있습니다.

주요 작업:

- 노드 라벨 변경
- 입력값 직접 설정
- 입력값 지우기
- 이미지 입력 선택
- 선택 노드 실행
- 강제 재실행
- 노드 복제
- 노드 삭제
- 연결 삭제

특수 입력 UI도 노드 종류에 맞춰 뜹니다.

- LLM 호출 노드: 캐릭터 → 채팅 프로필의 **LLM 프로필**(API LLM)을 골라, 그 프로필의 연결·모델·온도·출력 길이·추론·추가 파라미터로 호출합니다. 노드의 온도·최대 토큰을 채우면 그 값이 프로필보다 우선합니다. 이전에 연결을 직접 고른 노드는 "연결: 이름 (이전 방식)"으로 그대로 동작하며, 이제 노드의 모델 값도 반영됩니다.
- LLM 프리셋 노드: 프리셋 타입과 이름 선택
- NAI 노드: 캐릭터 프롬프트, Vibe, 캐릭터 레퍼런스 입력
- Power LoRA 노드: LoRA 항목 배열 편집
- 일반 필드: 텍스트, 숫자, 불리언, JSON, 선택값 입력

### 생성 프리셋 노드의 캐릭터 외형

채팅 생성 프리셋을 실행하는 **생성 프리셋** 노드에서 [캐릭터 라이브러리](CHARACTER_LIBRARY.md)의 설정을 사용할 수 있습니다. 노드 카드나 Inspector의 **캐릭터 외형 설정** 선택기로 `character_setting_id`를 지정합니다. 채팅 프로필인 `profile_id`와는 함께 지정할 수 없습니다.

실행 시 설정의 최신 외형 태그를 프롬프트 앞에 넣습니다. 실행 계정에 `characters.view`가 필요하며, 설정의 기준 이미지는 `images.view`가 있고 연결된 `reference_image`가 없을 때만 사용합니다. 연결된 참조 이미지가 우선하고, 이미지 조회 권한이 없으면 설정에서는 태그만 사용합니다. 선택한 생성 프리셋의 참조 입력 규칙도 유지됩니다.

예약 실행도 같은 실행 경로를 사용합니다. 결과 메타데이터에는 사용한 `character_setting_id`가 기록됩니다. 현재 **워크플로우 실행 입력 폼에는 라이브러리 선택기가 없어 숫자 ID를 입력**해야 합니다. 생성 화면의 캐릭터 불러오기(값 복사)와 달리 이 노드는 실행할 때 설정을 읽습니다.

| 노드 클릭 | 노드 선택, 퀵 메뉴 열기 |
| 노드 우클릭 | 노드 퀵 메뉴 열기 |
| 빈 곳 우클릭 | 노드 추가 메뉴 열기 |
| 엣지 클릭 | 연결 선택 |
| `Ctrl/Cmd + C` | 선택한 노드/연결 복사 |
| `Ctrl/Cmd + V` | 최근 위치 또는 캔버스 중앙에 붙여넣기 |
| 자동 정렬 | 현재 그래프를 보기 좋게 재배치 |
| 초기화 | 캔버스 초안 리셋 |

## 검증 상태 확인

편집기 상단의 검증 아이콘은 저장·실행 전에 볼 핵심 신호입니다.

| 상태 | 의미 |
| --- | --- |
| ready | 실행 가능한 상태 |
| warning | 저장은 가능하지만 실행 전 확인 필요 |
| critical | 실행을 막는 치명 이슈 있음 |

검증 항목을 클릭하면 해당 노드나 포트로 이동합니다. 필수 입력 누락, 연결 누락, 결과 노드 누락 같은 문제는 여기서 먼저 잡습니다.

## 저장

저장 모달에서 다음을 정합니다.

- 워크플로우 이름
- 설명
- 저장 폴더
- 새 자식 폴더 생성
- 디버그 모드

저장 조건:

- 노드가 최소 1개 있어야 합니다.
- 치명 검증 이슈가 있으면 먼저 정리합니다.
- 저장 후에는 목록에서 버전, 노드 수, 연결 수, 결과 수를 확인합니다.

## 디버그 모드

디버그 모드를 켜면 실행 로그, 텍스트 출력, 중간 아티팩트, Comfy 요청 스냅샷을 저장합니다.

추천 사용:

- 새 워크플로우를 처음 만들 때
- 특정 노드 결과를 확인해야 할 때
- ComfyUI 요청 JSON을 추적해야 할 때

끄는 게 좋은 경우:

- 대량 반복 실행
- 중간 산출물이 너무 많이 쌓일 때
- 최종 결과만 보관하면 충분할 때

## 실행

1. Browse 모드에서 워크플로우를 선택합니다.
2. 실행 입력 필드를 채웁니다.
3. 검증 패널에서 치명 이슈가 없는지 확인합니다.
4. `실행`을 누릅니다.
5. 최근 결과와 실행 이력을 확인합니다.

워크플로우가 바뀌면 연결된 자동 실행이 `workflow_changed` 상태로 멈출 수 있습니다. 이 경우 예약작업 탭에서 다시 검토하고 켭니다.

## 결과 확인

실행 결과 패널에서 확인할 수 있는 것:

- 실행 목록
- 실행 상태
- 최종 결과
- 노드별 아티팩트
- 텍스트/중간 아티팩트
- 실패 메시지
- 재실행
- 실패 실행 재시도
- 실행 취소

최종 결과가 비어 있으면 `최종 결과` 노드를 추가하고 원하는 출력에 연결해야 합니다.

## 생성물 관리

워크플로우나 폴더를 선택하지 않은 Browse 화면에서는 생성물 관리 패널을 볼 수 있습니다.

탭:

| 탭 | 용도 |
| --- | --- |
| 생성 결과 | 이미지/비디오 같은 최종 생성물 관리 |
| 텍스트와 중간 아티팩트 | 로그, JSON, 중간 출력 확인 |

가능한 작업:

- 결과 선택
- 다운로드
- 감시 폴더로 복사
- 검색/필터
- 페이지 이동
- 삭제

삭제는 관리자 계정에서만 가능합니다. 페이지당 기본 표시 수는 50개입니다.

## 공개 워크플로우

공개 워크플로우는 로그인하지 않은 사용자에게 일부 실행/결과 화면을 제공할 수 있습니다. 공개 페이지로 열기 전에는 다음을 꼭 확인합니다.

- 공개 slug
- 노출할 marked field
- 큐 최대 요청 수
- 결과 표시 방식
- 아티팩트 디렉터리 정책
- 민감한 중간 출력 저장 여부

공개 페이지에는 내부 프롬프트, 토큰, 로컬 경로가 섞이지 않게 디버그 모드와 출력 노드를 특히 조심합니다.

## 좋은 워크플로우 기준

- 입력 노드가 명확합니다.
- 최종 결과 노드가 있습니다.
- 자주 바꾸는 값만 실행 입력으로 노출합니다.
- 중간 디버그 산출물과 최종 산출물을 구분합니다.
- 폴더 이름이 목적별로 정리되어 있습니다.
- 실패했을 때 어느 노드가 문제인지 바로 보입니다.

## 문제 해결

### 실행 버튼이 비활성화됨

- 검증 패널의 critical 이슈를 봅니다.
- 필수 입력값이 비었는지 확인합니다.
- 결과 노드 또는 연결이 누락됐는지 확인합니다.

### 원하는 노드가 추천에 안 나옴

- 포트 데이터 타입이 맞는지 확인합니다.
- 고급 출력 포트를 켜야 보이는 출력인지 확인합니다.
- 검색 탭에서 직접 찾아 추가합니다.

### 결과가 비어 있음

- 최종 결과 노드가 있는지 확인합니다.
- 최종 결과 노드가 실제 출력에 연결됐는지 확인합니다.
- 디버그 모드를 켜고 중간 아티팩트를 확인합니다.

### 자동 실행이 멈춤

워크플로우 구조가 바뀌면 자동 실행이 재검토 상태로 멈출 수 있습니다. 예약작업 탭에서 변경 내용을 확인한 뒤 다시 활성화합니다.
