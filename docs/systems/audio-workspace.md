# 음향 작업실

## 역할

효과음을 만들고 검수해서 내보내는 작업실입니다(상단 메뉴 **음향**). 예전에 따로 돌던 SFX 매니저(`stable-audio-sfx-manager`)의 작업 흐름을 CoNAI 안으로 옮긴 것입니다. 주문 → 후보 생성 → 듣고 채택·보류 → 메모·코멘트 → 간단 편집 → 내보내기 순서로 씁니다.

## 데이터

- 이미지 라이브러리와 따로 **`audio.db`**(데이터 폴더, user.db 옆)에 저장합니다. 처음 쓸 때 만들어집니다.
- 구조는 **프로젝트 → 그룹 → 후보**입니다.
  - 프로젝트마다 **받은 파일** 그룹이 하나 있습니다. 업로드나 "음향으로 보내기"로 들어온 파일이 먼저 쌓입니다.
  - 그룹의 `label`은 내보내기 파일명 규칙입니다(`footstep_snow_[00]` → `footstep_snow_01`). 원래 앱의 규칙 그대로입니다.
  - 후보의 출처는 `generated`(생성), `uploaded`, `imported`(데이터 URL·내 파일·이전 앱), `edited`(편집본, `parent_id`가 원본)입니다.
  - 후보는 검수 상태(`pending`·`selected`·`rejected`)와 메모, 편집 파라미터, 출처 스냅샷(프롬프트, seed, 워크플로, 서버, 주문)을 가집니다.
- 그룹 코멘트는 작업 요청 창구입니다(대기/완료, 리비전, 완료 메모).

## 파일 저장과 정리

- 파일은 **내용 해시 저장소** `uploads/audio/<해시 앞 2>/<다음 2>/<sha256>.<확장자>`에 둡니다. 같은 바이트는 한 파일만 저장하고 여러 후보가 함께 참조합니다.
- 받는 형식: flac, wav, mp3, ogg, opus, m4a, aac, weba(파일당 200MB). 들어올 때 ffprobe로 오디오 스트림을 확인하고 길이·샘플레이트·채널을 기록합니다.
- 들어오는 길은 업로드, 내 파일·채팅 첨부에서 "음향으로 보내기", 생성 결과, 편집 저장, 이전 앱 가져오기뿐입니다. 감시 폴더로는 받지 않습니다.
- `/uploads/audio`는 정적으로 열리지 않습니다. 재생·다운로드는 `/api/audio`(권한 `audio.view`)로만 합니다. 이미지 스캐너와 감시 폴더도 이 폴더를 건너뜁니다.
- 유지보수 연결:
  - **삭제**는 소프트 삭제입니다. 휴지통 보존 기간이 켜져 있으면 기간이 지난 후보를 지우고, 아무도 참조하지 않는 파일은 RecycleBin(출처 `audio`)으로 옮깁니다. RecycleBin에서 복구하면 후보 행도 다시 붙습니다.
  - **고아 정리**는 행 없는 파일과 참조 없는 파일 행을 찾습니다(1시간 유예).
  - **파일 검증**은 없어졌거나 크기가 다른 파일을 보고합니다.
  - **DB 백업**에 audio.db가 포함됩니다. DB 압축(VACUUM)은 images.db만 대상입니다.

## 생성

- 워크플로는 생성 화면에 **음향 종류**(`workflows.kind = 'audio'`)로 등록합니다. 이미지 생성 화면과 `list_workflows`는 기본으로 음향 워크플로를 숨깁니다.
- 음향 설정에서 워크플로마다 **역할 필드**(프롬프트·길이·seed)를 연결합니다(`audio_workflow_bindings`). 저장할 때와 주문 전에 서버별 `/object_info` 호환성 검사(노드, 모델 파일명, 최대 길이)를 합니다.
- 주문 1건 = 후보마다 큐 잡 1개입니다. seed는 기준값 + 순번이고, 비우면 2³¹ 미만의 랜덤 기준값을 씁니다. 주문 행을 먼저 쓰고 멱등 키로 큐에 넣어서, 중간에 꺼져도 다시 이어 넣습니다(기동 시 reconcile).
- 큐 실행기는 워크플로 종류가 `audio`일 때만 오디오 분기를 탑니다. ComfyUI의 `audio`·`files` 출력을 받아 오디오 저장소와 후보 행으로 보냅니다. 이미지 라이브러리와 생성 이력에는 쓰지 않습니다. 주문 없이 음향 워크플로를 돌리면 실패합니다. **기존 이미지 워크플로의 종류를 음향으로 바꾸지 마세요.**
- 채팅에서 주문하면 끝난 후보가 답변에 자동으로 붙습니다(`audioCandidateIds`).

## 편집과 내보내기

- 편집은 원래 앱의 필터 체인 그대로입니다: `atrim → (rubberband) → volume → afade → alimiter`. 미리듣기는 임시 렌더이고, 저장하면 24bit WAV 편집본이 새 후보로 생깁니다. 원본은 바뀌지 않습니다.
- 내보내기는 채택본만 그룹 라벨 파일명으로 내보냅니다. WAV/OGG를 고를 수 있고, 파일별 음량 정규화(기본 −16 LUFS, 2-pass, 원래 앱과 같은 선형 게인 폴백)를 합니다. 한 개면 파일 그대로, 여러 개면 ZIP입니다. 20개를 넘으면 백그라운드 작업(`audio-export`)으로 만듭니다. 기본값은 음향 설정에 저장합니다.

## 권한과 사람 전용 동작

- `audio.view`: 보기·재생·다운로드·코멘트 읽기. `audio.edit`: 정리·업로드·편집·검수. 주문에는 `generation.execute`도 필요합니다.
- **검수(채택·보류·미검수)와 검수 메모, 코멘트 작성은 웹 API에만 있고 MCP 도구가 없습니다.** 봇과 외부 MCP는 결과를 만들고 정리할 수 있지만 최종 검수는 바꿀 수 없습니다.

## 이전 앱 데이터 가져오기

관리자는 **설정 › 유지보수 › 데이터베이스 › 이전 음향 앱 가져오기**에서 원래 앱의 데이터 폴더(`sfx.sqlite3` + `audio/`)를 가져옵니다.

- 원본은 서버 폴더 경로로 지정하거나 zip(최대 1GB)으로 올립니다. 원본은 읽기만 합니다. DB는 복사본을 열고, 오디오는 저장소로 복사합니다.
- 미리보기(dry run)로 수를 먼저 보고 가져옵니다. 다시 실행해도 새것만 추가합니다. 프로젝트·그룹·코멘트는 예전 ID로 기억하고, 후보는 `legacy:<예전 ID>`로 구분합니다. 같은 이름의 프로젝트, 같은 라벨의 그룹이 있으면 합칩니다.
- 삭제 표시된 후보는 파일이 남아 있으면 소프트 삭제 상태로 가져오고, 파일이 없으면 수만 셉니다.
- 예전 워크플로는 목록으로만 보관합니다. 관리자가 하나씩 **음향 워크플로로 등록**하면 배치 크기 1, 역할 필드, 연결까지 만들어집니다. 서버·대기열·토큰·인증 설정은 가져오지 않습니다.
