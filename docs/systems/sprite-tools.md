# 스프라이트 도구

## 역할

라이브러리 영상에서 프레임을 뽑아 배경을 지우고 스프라이트 시트로 만드는 도구입니다(상단 메뉴 **스프라이트**, 영상 상세의 "스프라이트로"). 예전에 따로 돌던 `video-sprite-extractor`를 Node로 옮긴 것이고, 같은 탭에서 시트 여백 정규화와 애니메이션 변환도 합니다.

## 처리 흐름

1. ffprobe로 영상 정보를 읽습니다(회전 반영).
2. ffmpeg가 고른 프레임을 RGBA로 뽑습니다. 사전 크롭과 크기 조정(채움·늘림의 스케일)도 ffmpeg에서 합니다.
3. TypeScript로 픽셀 단계를 처리합니다:
   - 지정색 제거
   - 디스필과 가장자리 정리
   - 맞춤 여백(투명)
   - 자동 크롭(모든 프레임의 보이는 영역 합집합)
   - 연속 중복 프레임 제거
   - 타일링
4. PNG/WebP로 인코딩합니다(sharp).

- 픽셀 단계는 **워커 스레드**에서 돌아서 서버 응답을 막지 않습니다. 단일 파일 포터블 번들처럼 워커 스크립트가 없으면 메인 스레드에서 프레임마다 양보하며 돕니다.
- 스프라이트 작업은 런타임 작업(`sprite-extract`, `sprite-extract-batch`, `sprite-normalize`, `sprite-animation`)이고 한 번에 하나씩 돕니다.
- 최근 결과의 프레임은 임시 작업 공간에 1시간, 최대 4GiB까지 남겨 둡니다. 생성 후 크롭, 열·간격 변경, 다시 인코딩은 추출을 다시 하지 않고 이 프레임으로 합니다.

## 추출 화면

- 왼쪽 **영상 목록**에 영상을 1개부터 100개까지 넣습니다. 라이브러리에서 고르거나, 파일·폴더를 끌어다 놓거나 올리면 됩니다. 올린 영상은 일반 업로드처럼 라이브러리에 들어갑니다.
- 오른쪽 설정은 목록의 모든 영상에 똑같이 적용됩니다.
  - 추출: 영상마다 N컷, 또는 간격
  - 구간: 영상 전체, 또는 공통 구간. 공통 구간의 끝이 영상보다 길면 그 영상은 끝까지 씁니다.
  - 배경: 가장자리에서 배경색 찾기, 영상에서 색 찍기
  - 시트: 열·간격·포맷
  - 출력: 저장할 그룹, ZIP으로도 받기
- 가운데에서 고른 영상을 보며 "이 영상만 미리보기"로 결과를 확인한 뒤, "전체 생성"으로 목록 전체를 만듭니다.
  - 진행 중에는 목록에 영상별 상태(대기/진행/완료/실패/건너뜀)가 표시됩니다.
  - "지금 영상 끝나고 멈추기"를 누르면 처리 중인 영상까지만 만들고, 나머지는 건너뜁니다.
- 브라우저가 영상을 재생하지 못하면 오류 코드가 표시됩니다. "서버 프레임으로 보기"를 누르면 서버가 뽑은 정지 화면으로 구간 지정과 색 찍기를 계속할 수 있습니다(`GET /api/sprite/videos/:hash/frame?t=`).
- **설정 기억과 프리셋:**
  - 마지막 설정은 브라우저에 저장됩니다.
  - 프리셋은 모든 계정이 같이 쓰는 목록입니다(`runtime/config/sprite-presets.json`, `/api/sprite/presets`).
  - 라이브러리에 저장된 시트에서 설정을 그대로 불러올 수도 있습니다.

## 저장

- **라이브러리에 저장**하면 시트·애니메이션이 일반 생성 결과처럼 라이브러리에 들어가고 "스프라이트" 그룹(또는 고른 그룹)에 담깁니다.
- 적용한 옵션 전체가 파일 안 XMP(`conaiSprite:settings`)에 저장됩니다. `GET /api/sprite/settings/:hash`로 읽어서 같은 설정으로 다시 만들 수 있습니다.
- 프레임 ZIP은 다운로드만 하고 저장하지 않습니다.

## 원래 도구와 다른 점

- **지정색 여러 개:** 원래 도구는 ffmpeg `colorkey`가 알파를 덮어써서 마지막 색만 빠졌습니다. 이제는 색마다 투명도를 구해 가장 작은 값을 씁니다. 색이 하나면 ffmpeg 그래프 안에서 처리해 원래 결과와 같습니다.
- **맞춤 리사이즈 + 디스필:** 원래는 불투명한 검정 여백이 먼저 붙어서 디스필이 실패했습니다. 이제 여백은 배경을 지운 뒤 투명하게 붙입니다.
- **간격 방식:** 원래는 구간마다 한 프레임 뒤를 골랐습니다(`fps … round=near`). 이제는 `round((시작 + k × 간격) × fps)` 프레임을 정확히 고릅니다. 개수 방식은 원래와 같습니다.
- **디스필 일반화:**
  - 방식은 "지정색" 하나이고 디스필은 그 안의 옵션입니다(색 1개일 때만).
  - 마젠타는 원래 알고리즘 그대로입니다. 순색(초록·파랑 등)은 같은 색차 공식을 그 색에 맞춰 쓰고, 그 밖의 색은 채널 쌍별로 일반화한 색차를 씁니다.
  - 피사체와 반대 색 계열을 배경으로 쓰면 가장자리에 1px 정도 띠가 남을 수 있습니다. 원래 마젠타 공식도 같은 한계가 있습니다.
- **기본값 통일:** 웹과 MCP의 기본값이 웹 기준 하나로 맞춰졌습니다(허용치 10%/부드러움 5%, 마젠타 디스필 8%/92%, 정규화 여백 2, 애니메이션 WebP).
- AI 배경 제거(BiRefNet 등)와 크로마키(YUV)는 옮기지 않았습니다.

정확성은 원래 도구로 만든 골든 데이터(`backend/test/fixtures/av-golden`)와 비교해 확인합니다. 마젠타 디스필과 정규화는 픽셀까지 같습니다.

## 한도와 권한

- 프레임은 최대 256개, 시트 한 변은 16384px까지입니다. 정규화는 원래 도구의 격자·기준점·픽셀 손실 검사 규칙을 그대로 따릅니다.
- 영상 정보와 미리보기는 `images.view`, 실행은 `images.edit`, 라이브러리 저장은 `images.upload`가 필요합니다.
- MCP 도구는 [MCP 가이드](../GUIDE/MCP_GUIDE.md)의 "스프라이트" 표를 보세요.
