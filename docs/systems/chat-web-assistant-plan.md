# CoNAI 내부 웹 어시스턴트 개발 계획

작성: 2026-10-07

현재 채팅을 CoNAI 안에서 열린 페이지를 이해하고 입력을 보조하는 어시스턴트로 확장한다. 기존 채팅 엔진과 MCP 연결을 활용하며, 외부 사이트나 다른 브라우저 탭을 조작하는 기능은 추가하지 않는다.

## 구현 범위

1. 사용자가 현재 페이지를 채팅에 연결하면 페이지와 선택 항목을 인식한다.
2. 첫 편집 대상은 생성 페이지의 NovelAI 일반 입력과 ComfyUI 워크플로의 일반 marked field다. 프롬프트, 숫자, 선택 항목, 체크 항목을 지원하고 이미지 파일·복합 노드·인증 필드는 제외한다.
3. 모델이 필드 변경안을 만들면 채팅에서 변경 전후를 보여주고 사용자가 적용한다. 적용한 변경은 값이 다른 작업으로 바뀌지 않은 경우 되돌릴 수 있다.
4. 필드 입력과 실제 생성·저장·삭제를 분리한다. 새 화면 도구는 생성 요청이나 서버 데이터 변경을 수행하지 않는다.
5. 페이지 연결은 사용자가 선택하며 기본적으로 꺼져 있다. 연결하지 않은 요청에는 페이지 내용을 보내지 않는다.
6. 다른 채팅이나 새 프로필을 선택하면 페이지 연결을 해제한다. 같은 채팅의 페이지 이동은 현재 화면을 다시 전달하되, 이전 화면의 변경안은 적용할 수 없다.

## 화면과 채팅 연결

각 페이지는 공개 가능한 화면 요약과 편집 가능한 필드를 등록한다. 필드에는 안정된 ID, 표시 이름, 자료형, 현재 값, 허용 범위 또는 선택 목록을 포함한다. DOM 전체, localStorage 전체, 비밀번호, API 키, 토큰, 서버 경로는 수집하지 않는다.

이는 해당 설정·인증 필드를 등록하지 않는다는 뜻이다. 사용자가 일반 프롬프트에 직접 적은 민감한 내용을 자동으로 판별하거나 제거하는 기능은 없다. 연결한 일반 입력값은 선택한 채팅 프로필의 LLM 연결로 전달되며, 입력 제안의 변경 전후 값은 제안 카드와 함께 대화에 남는다. 페이지 조회의 전체 스냅샷은 API LLM의 저장된 도구 결과에서 제외한다.

채팅 요청에 해당 시점의 화면 스냅샷을 별도 항목으로 전달한다. 화면 내용은 사용자 명령이 아닌 참고 데이터로 취급한다. 기존 프로필의 페르소나, 채팅 기억, 요약에 화면 스냅샷을 영구 지시문으로 합치지 않는다.

현재 페이지 조회 도구와 필드 변경 제안 도구를 제공한다. 화면 변경은 프론트엔드의 등록된 상태 변경 함수로 수행하며, 임의 JavaScript, CSS selector, DOM 클릭, 자유로운 HTTP 호출을 받지 않는다.

## 적용 안전장치

| 경계 | 처리 |
| --- | --- |
| 계정과 권한 | 채팅·프로필 권한과 해당 페이지 접근 권한을 검사한다. 도구 호출 시 현재 계정 권한을 다시 검사한다. |
| 페이지 변경 | 브라우저 페이지 인스턴스, 경로, 선택 항목이 제안 시점과 같을 때만 적용한다. |
| 사용자 편집 | 변경 대상의 현재 값이 제안의 이전 값과 같을 때만 적용한다. 충돌 시 덮어쓰지 않는다. |
| 입력 검증 | 등록된 필드만 허용하고 자료형, 길이, 숫자 범위, 선택값을 검사한다. 여러 필드는 모두 검증한 다음 반영한다. |
| 중복 실행 | 같은 제안의 재적용을 막는다. 생성 작업의 중복 방지 범위는 계정별로 분리한다. |
| 응답 재생 | 오래된 제안, 페이지 연결 해제, 계정 변경, 페이지 이탈 후에는 적용할 수 없다. |
| 결과 표시 | 제안 생성과 실제 화면 적용을 구분한다. 실제 적용 결과는 화면 값으로 확인한다. |
| 되돌리기 | 적용 뒤 값이 유지된 경우만 이전 값으로 되돌린다. 이후 사용자 편집을 취소하지 않는다. |

## 기존 경로 보강

- API LLM의 도구 권한을 답변 시작 시점뿐 아니라 호출 시점에도 확인한다.
- API LLM 생성 요청의 공통 `mcp-local` 중복 방지 범위를 계정별로 분리한다. 재사용 대상의 소유자도 확인한다.
- 이번 화면 입력 도구는 변경 제안만 생성한다. 기존 생성·정리·삭제 도구의 전체 승인 체계 개편은 별도 범위로 두고, 화면 입력 테스트에는 해당 도구를 제공하지 않는다.
- 페이지 연결 중에는 현재 페이지 조회와 입력 제안 두 도구만 제공한다. 기존 프로필에 생성·정리·설정 권한이 있어도 해당 도구와 관련 없는 개인 파일 조회 도구를 제공하지 않아, 페이지 내용이 다른 데이터 조회나 부작용 도구 실행을 유도하는 경로를 막는다.
- 기존 Codex의 셸·파일·브라우저 제한과 HTTP MCP의 활성화·API 키 경계를 유지한다.

## 작업 순서

1. 현재 채팅 요청, 도구 제공, 제안 카드, 생성 페이지 입력 함수를 확인한다.
2. 공유 계약과 검증, 페이지 등록 및 변경 적용 경로를 구현한다.
3. 서버의 현재 페이지 조회와 필드 변경 제안 도구를 연결한다.
4. 채팅의 페이지 연결 UI와 변경 전후·적용·되돌리기 표시를 연결한다.
5. NovelAI와 ComfyUI 일반 필드를 등록한다.
6. 현재 로컬 LLM의 실제 주소와 모델 ID를 확인하고, 그 연결로 채팅과 도구 호출을 테스트한다.
7. 기존 검사, 중요한 권한·충돌 회귀 검증, 실제 화면 검증을 수행한다.
8. 결과와 사용 범위를 이 문서 및 채팅 안내에 반영하고 Graphify를 갱신한다.

## 검증 기준

- 연결한 페이지와 현재 선택 워크플로를 로컬 LLM이 올바르게 설명한다.
- 프롬프트·숫자·선택 필드를 바꾸는 요청으로 변경안이 생성되고, 적용 후 실제 화면 상태가 바뀐다.
- 페이지 이동, 선택 워크플로 변경, 입력값 변경, 중복 적용, 권한 회수 시 변경을 차단한다.
- 허용 범위를 벗어난 숫자, 알 수 없는 필드, 잘못된 선택값은 전체 변경을 거부한다.
- 적용 및 되돌리기로 생성 큐, 저장 API, 외부 서비스가 호출되지 않는다.
- 페이지 연결을 끄면 모델에게 화면 정보를 보내거나 화면 도구를 제공하지 않는다.
- 기존 채팅 및 프로필 설정이 계속 동작한다.

테스트에는 사용자가 지정한 로컬 Qwen 연결을 사용한다. 표시명만으로 모델을 추정하지 않고 실행 중인 연결의 모델 ID를 확인한다. 운영 데이터는 최소한으로 건드리며, 입력 테스트에서 이미지 생성이나 삭제는 실행하지 않는다. 필요한 회귀 검증은 기존 테스트에 추가하고 일회성 테스트 코드·하네스는 만들지 않는다.

## 진행 상태

- 구현 전에 계획 문서를 작성했고, 공유 계약·검증, 페이지 등록, 도구, 제안 카드, NovelAI·ComfyUI 입력 연결을 구현했다.
- 페이지 연결 중 다른 데이터 조회·생성·정리·설정 도구를 제외한다. API LLM의 호출 시점 계정 권한 확인과 생성 중복 방지의 계정 분리도 반영했다.
- 실행 중인 로컬 서버 `http://127.0.0.1:5000/v1`의 모델 ID `qwen3.8-27b-uncensored-hauhaucs-aggressive-mtp@iq4_xs`를 확인하고, 별도 테스트 런타임으로 실제 모델·브라우저 검증을 수행했다. 운영 런타임과 모델 서버는 재시작하지 않았다.

## 운용 범위와 남은 사항

- 첫 적용 범위는 1:1 채팅과 등록된 생성 입력이다. 다른 내부 페이지는 이름·경로 인식까지 지원하며, 이미지·노드·별도 모달·일반 DOM 조작은 포함하지 않는다.
- 화면 입력은 기존 수동 편집과 같은 상태 변경 함수를 사용한다. 기존의 로컬 입력 임시 저장은 동작하며, 생성·서버 워크플로우 저장은 별도의 사용자 동작이 필요하다.
- LLM의 답변 문장은 실행 증거가 아니다. 변경 카드, 적용 검증, 실제 화면 값이 기준이다. 모델이 잘못 제안해도 등록 필드·입력 범위·현재 값·권한 검증을 통과한 뒤 사용자 적용을 거쳐야 한다.
- 사용법은 `docs/GUIDE/CHAT.md`의 **현재 페이지 읽기와 입력 보조**에 기록했다. 일반 운영 런타임에 반영하려면 정상적인 재시작과 프로필의 페이지 조회·입력 제안 도구 허용이 필요하다.
- 테스트 연결에 잠시 복사한 인증 정보는 기존 설정 API로 제거하고 DB에서도 비어 있음을 확인했다. 테스트 DB를 정리·체크포인트했고, 테스트용 API·프론트엔드만 종료했다. 기존 운영 런타임과 Qwen 서버는 유지했다. 테스트 기록은 git에 포함되지 않는 `tmp/web-assistant-runtime`에 남겨 두었다.
- `python -m graphify update .`를 완료했다(13,718 노드, 44,087 간선). 기존 `backend/src/types/moduleGraph.ts` 구문 분석 경고와 일부 파일의 빈 추출 경고가 있어 해당 부분의 색인은 제한된다. 문서 추가분은 코드 전용 `update`의 색인 범위에 포함되지 않으며, 다음 전체 재빌드에서 함께 색인해야 한다.

## 기존 의존성의 보안 검토 후속 항목

2026-10-07 `npm audit --omit=dev --json`은 운영 의존성에서 취약 패키지 16개(Critical 1, High 12, Moderate 3)를 보고했다. 이번 변경에서 패키지 의존성이나 잠금 파일을 추가·변경하지 않았다. 전체 의존성 업그레이드와 호환성 검증은 별도 작업이 필요하며, 입력 기능 검증 통과를 운영 환경 전체의 보안 검증 통과로 해석하면 안 된다.

- `@modelcontextprotocol/sdk`: OAuth HTTP 클라이언트가 신뢰하지 않는 MCP 서버에 연결할 때 인증 정보가 다른 인증 서버로 전달될 수 있다는 High 공지가 있다. 패치 버전은 1.31.0이다. 이번 API LLM 채팅은 내부 `InMemoryTransport`로 연결하고 OAuth 클라이언트를 사용하지 않으므로, 확인한 입력 기능 경로는 공지의 공격 조건과 맞지 않는다. 이는 코드 경로와 공지를 비교한 판단이며 전체 사용처를 모두 검증했다는 의미는 아니다. [MCP SDK 공식 보안 공지](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h)
- `proxy-addr`: 일부 IPv4 매핑 IPv6 신뢰 서브넷 설정에서 전달 IP가 위조될 수 있다는 Critical 공지가 있다. 패치 버전은 2.0.8이다. 프로젝트의 `resolveTrustProxySetting`은 환경변수의 서브넷 문자열을 받을 수 있어, 운영 배포의 `TRUST_PROXY` 설정을 확인해야 한다. 로컬 입력 테스트만으로 운영 프록시의 노출 여부를 판단할 수 없다. [proxy-addr 공식 보안 공지](https://github.com/jshttp/proxy-addr/security/advisories/GHSA-jqcg-44mw-7w3h)
- 나머지 보고 대상에는 `axios`, `multer`, `sharp`, `pdfjs-dist`와 압축·파일 패턴 처리 관련 패키지가 포함된다. 보고 개수는 패키지 기준이며 실제 공격 가능성이나 서로 다른 취약점 개수와 같지 않다. 사용 경로와 수정 버전의 호환성을 확인한 뒤 패치해야 한다.
