# CoNAI 내부 웹 어시스턴트 개발 계획

작성: 2026-10-07

## 추가 확장 작업 — 페이지별 누락 보완

사용자 요청에 따라 일반 입력 보조 외에 아래 작업을 추가한다. 생성·수정·등록은 작업 내용과 저장 여부를 명시한 검토 카드에서 사용자가 적용한다. 등록된 기능과 기존 API만 사용하며 외부 사이트, 임의 HTTP 주소·JavaScript·인증 설정은 조작하지 않는다.

- 프롬프트 본문 생성·수정, 그룹 지정, 프리셋 생성·수정 및 프리셋 입력을 연결한다.
- 와일드카드 생성·수정, 항목·가중치·계층·체인 설정을 연결한다.
- Codex 생성 탭의 프롬프트·부정 프롬프트·모델·개수·비율·해상도와 이미지 입력을 연결한다.
- 일반·공유 ComfyUI에서 같은 marked field 어댑터를 사용한다. 이미지 입력, H3 Director·LoRA 복합 입력, 워크플로 선택·새로고침·등록·수정, marked field 등록·설정을 지원한다. 공유 페이지는 공개된 해당 워크플로의 사용 권한 범위를 유지한다.
- 페이지의 탭·선택 대상·지원 작업을 명시하고, 모달 편집이 열리면 그 편집기를 우선 연결한다. 제목만 읽을 수 있는 페이지는 읽기 전용임을 표시한다.
- 새 작업도 현재 계정·프로필·기능 권한을 재검사한다. 페이지 전환·수동 편집·다른 저장과 충돌하면 적용을 거부한다. 이미지 원본·인증 정보·서버 경로를 모델에게 전달하지 않는다.

기존 회귀 테스트에 중요한 권한·검증·충돌 사례를 추가하고, 실행 중인 로컬 Qwen과 별도 런타임의 실제 화면으로 생성·수정·등록 및 공유 페이지 입력을 검증한다. 작업 중 확인된 추가 페이지 누락도 기존 상태·API 경계 안에서 연결하고, 완료 여부와 실제 검증 범위를 기록한다.

현재 채팅을 CoNAI 안에서 열린 페이지를 이해하고 입력을 보조하는 어시스턴트로 확장한다. 기존 채팅 엔진과 MCP 연결을 활용하며, 외부 사이트나 다른 브라우저 탭을 조작하는 기능은 추가하지 않는다.

### 적용·권한·데이터 경계

- 1:1 채팅에서 사용자가 페이지를 연결한 요청에만 일곱 페이지 도구를 제공한다. 외부 사이트·임의 DOM·스크립트·URL·인증 설정·자동 생성 도구는 제공하지 않는다.
- 초안 작업은 **작업 적용**, 서버 쓰기는 **검토한 내용 저장**으로 구분한다. 초안은 적용 후 다른 편집이 없을 때 되돌릴 수 있다. 서버 저장은 자동 되돌리기를 제공하지 않는다.
- 페이지·모달·선택 대상·입력 전체의 리비전, 현재 계정·프로필·도구·기능 권한을 확인한다. 기존 레코드 수정은 카드 생성과 적용 시 원본 해시를 확인하고, 네이티브 PUT의 `If-Match` 검사로 저장 직전의 다른 변경도 거부한다. 프롬프트 사용 횟수는 보존한다.
- 이미지·파일은 권한 있는 목록 또는 사용자가 지정한 ID를 기존 API로 조회한다. 바이트·data URL·서버 경로·비밀 설정은 모델에게 전달하지 않는다. H3 업로드 중 페이지가 바뀌거나 적용이 실패하면 새 임시 입력 자산을 정리한다. 기존 비공개 노드 입력은 JSON 교체 시 보존한다.
- H3는 현재 노드의 실제 공개 입력 스키마와 숨김 설정, 모드별 이미지/영상/오디오 종류·슬롯·개수·최소 길이를 검사한다. LoRA는 현재 입력이나 실제 선택 목록의 항목만 사용한다.
- 영구 저장 요청이 서버에 제출된 뒤의 페이지 이동은 이미 완료된 쓰기를 취소하지 않는다. 같은 레코드의 다른 변경을 덮어쓰는 것은 원본 해시 검사가 막는다.
- 목록 최대 512개, 일반 필드 64개, 한 제안의 일반 필드 변경 24개, 프리셋/와일드카드 항목과 Comfy JSON 노드/marked field 128개, JSON 입력 200,000자 등 제한을 둔다. 큰 전체 자료는 네이티브 편집기로 처리한다.

### 실제 검증

별도 런타임과 실행 중인 로컬 Qwen3.8을 사용했다. 모델 답변 문장 외에 네이티브 화면 값과 저장 API 결과를 확인했다. 커밋할 변경만 내보낸 별도 사본에서 기존 채팅 테스트 182개, 백엔드·프런트엔드 타입 검사, 변경한 프런트엔드 파일의 ESLint, shared·backend·frontend 빌드를 통과했다.

- Codex 프롬프트·반복 2·16:9 입력 및 참조 이미지 등록.
- 프롬프트 생성 → 선택 → 본문·동의어 수정, 프리셋 생성/항목 교체, 와일드카드 생성/내용·가중치 수정.
- Comfy 워크플로 선택, H3 프롬프트·길이·FPS 수정, 라이브러리 이미지의 타임라인 등록 및 실제 64px 이미지 로딩, LoRA 가중치 수정.
- 새 워크플로 JSON과 두 marked field 등록 및 서버 저장. 기존 워크플로의 기본값·필수 여부·범위·순서 수정 후 저장.
- 별도 테스트 계정과 주소의 공유 페이지에서 H3 입력과 두 번째 이미지 등록, H3 길이 적용/되돌리기, 권한 있는 새 워크플로 편집기 열기와 조회.
- 기존 제안 테스트에 스키마·보호 데이터·리비전·저장 충돌 검증을 추가했다. 프롬프트 사용 횟수와 자동 관리 그룹 보호, 프리셋·와일드카드·Comfy PUT의 오래된 `If-Match` 거부를 확인했다.
- H3 스키마 깊이, 정규화 전후 스키마 비교, 프롬프트 수정 시 불필요한 해상도 변경, Comfy 되돌리기, 공유 등록 경로의 누락을 수정하고 해당 화면을 다시 확인했다.
- Comfy 서버·H3 모델 연결이 없는 입력용 fixture를 사용했으며 실제 이미지/영상 생성은 실행하지 않았다. 생성 결과의 품질·플러그인 호환성은 이 입력/저장 검증으로 보장하지 않는다.
- 테스트용 연결 키를 제거하고 DB에서 0건임을 확인한 뒤 압축·체크포인트했다. 테스트 API·UI·탭만 종료했고 운영 서버와 Qwen 서버는 유지했다.

### 남은 운용 범위

그룹 채팅의 페이지 조작, 코드/스크립트와 모듈 정의 편집, 계정·키·보안·백업 설정, 실제 삭제·생성 자동 실행, 파일 시스템이나 외부 사이트 조작은 이 확장의 대상이 아니다. 기본 설정/업로드/월페이퍼 등은 표에 명시한 초안 입력까지만 연결했다. NAI 바이브·참조의 세부 수치, 예약작업 편집, 월페이퍼 위젯 추가/삭제는 별도 어댑터가 필요하다.

정상 배포 빌드와 백엔드 재시작 후 프로필 조회 도구에서 `get_current_page`, `propose_page_changes`, `read_page_data`, `propose_page_action`을 허용한다. 노드 워크플로를 사용할 프로필은 `get_workflow_editor`, `list_workflow_modules`, `propose_workflow_changes`도 허용한다. Graphify의 코드 갱신과 문서 전체 재색인은 별개다.

## 1차 구현 범위

1. 사용자가 현재 페이지를 채팅에 연결하면 페이지와 선택 항목을 인식한다.
2. 첫 편집 대상은 생성 페이지의 NovelAI 일반 입력과 ComfyUI 워크플로의 일반 marked field다. 프롬프트, 숫자, 선택 항목, 체크 항목을 지원하고 이미지 파일·복합 노드·인증 필드는 제외한다.
3. 모델이 필드 변경안을 만들면 채팅에서 변경 전후를 보여주고 사용자가 적용한다. 적용한 변경은 값이 다른 작업으로 바뀌지 않은 경우 되돌릴 수 있다.
4. 필드 입력과 실제 생성·저장·삭제를 분리한다. 새 화면 도구는 생성 요청이나 서버 데이터 변경을 수행하지 않는다.
5. 페이지 연결은 사용자가 선택하며 기본적으로 꺼져 있다. 연결하지 않은 요청에는 페이지 내용을 보내지 않는다.
6. 다른 채팅이나 새 프로필을 선택하면 페이지 연결을 해제한다. 같은 채팅의 페이지 이동은 현재 화면을 다시 전달하되, 이전 화면의 변경안은 적용할 수 없다.

## 화면과 채팅 연결

각 페이지는 공개 가능한 화면 요약과 편집 가능한 필드를 등록한다. 필드에는 안정된 ID, 표시 이름, 자료형, 현재 값, 허용 범위 또는 선택 목록을 포함한다. DOM 전체, localStorage 전체, 비밀번호, API 키, 토큰, 서버 경로는 수집하지 않는다.

이는 해당 설정·인증 필드를 등록하지 않는다는 뜻이다. 사용자가 일반 프롬프트에 직접 적은 민감한 내용을 자동으로 판별하거나 제거하는 기능은 없다. 연결한 일반 입력값은 선택한 채팅 프로필의 LLM 연결로 전달되며, 입력 제안의 변경 전후 값은 제안 카드와 함께 대화에 남는다. 페이지 조회의 전체 스냅샷은 API LLM의 저장된 도구 결과에서 제외한다.

채팅 요청에 해당 시점의 화면 스냅샷을 별도 항목으로 전달한다. 화면 내용은 사용자 명령이 아닌 참고 데이터로 취급한다. 기존 프로필의 페르소나, 채팅 기억, 요약에 화면 스냅샷을 영구 지시문으로 합치지 않는다.

현재 페이지 조회 도구와 필드 변경 제안 도구를 제공한다. 화면 변경은 프론트엔드의 등록된 상태 변경 함수로 수행하며, 임의 JavaScript, CSS selector, DOM 클릭, 자유로운 HTTP 호출을 받지 않는다.

| 페이지 변경 | 브라우저 페이지 인스턴스, 경로, 선택 항목이 제안 시점과 같을 때만 적용한다. |
| 사용자 편집 | 변경 대상의 현재 값이 제안의 이전 값과 같을 때만 적용한다. 충돌 시 덮어쓰지 않는다. |
| 입력 검증 | 등록된 필드만 허용하고 자료형, 길이, 숫자 범위, 선택값을 검사한다. 여러 필드는 모두 검증한 다음 반영한다. |
| 중복 실행 | 같은 제안의 재적용을 막는다. 생성 작업의 중복 방지 범위는 계정별로 분리한다. |
| 응답 재생 | 오래된 제안, 페이지 연결 해제, 계정 변경, 페이지 이탈 후에는 적용할 수 없다. |
| 결과 표시 | 제안 생성과 실제 화면 적용을 구분한다. 실제 적용 결과는 화면 값으로 확인한다. |
| 되돌리기 | 적용 뒤 값이 유지된 경우만 이전 값으로 되돌린다. 이후 사용자 편집을 취소하지 않는다. |

## 기존 경로 보강

- API LLM의 도구 권한을 답변 시작 시점뿐 아니라 호출 시점에도 확인한다.
- API LLM 생성 요청의 공통 `mcp-local` 중복 방지 범위를 계정별로 분리한다. 재사용 대상의 소유자도 확인한다.
- 이번 화면 입력 도구는 변경 제안만 생성한다. 기존 생성·정리·삭제 도구의 전체 승인 체계 개편은 별도 범위로 두고, 화면 입력 테스트에는 해당 도구를 제공하지 않는다.
- 페이지 연결 중에는 현재 페이지 조회와 입력 제안 두 도구만 제공한다. 기존 프로필에 생성·정리·설정 권한이 있어도 해당 도구와 관련 없는 개인 파일 조회 도구를 제공하지 않아, 페이지 내용이 다른 데이터 조회나 부작용 도구 실행을 유도하는 경로를 막는다.
- 기존 Codex의 셸·파일·브라우저 제한과 HTTP MCP의 활성화·API 키 경계를 유지한다.

## 작업 순서

1. 현재 채팅 요청, 도구 제공, 제안 카드, 생성 페이지 입력 함수를 확인한다.
2. 공유 계약과 검증, 페이지 등록 및 변경 적용 경로를 구현한다.
3. 서버의 현재 페이지 조회와 필드 변경 제안 도구를 연결한다.
4. 채팅의 페이지 연결 UI와 변경 전후·적용·되돌리기 표시를 연결한다.
5. NovelAI와 ComfyUI 일반 필드를 등록한다.
6. 현재 로컬 LLM의 실제 주소와 모델 ID를 확인하고, 그 연결로 채팅과 도구 호출을 테스트한다.
7. 기존 검사, 중요한 권한·충돌 회귀 검증, 실제 화면 검증을 수행한다.
8. 결과와 사용 범위를 이 문서 및 채팅 안내에 반영하고 Graphify를 갱신한다.

## 검증 기준

- 연결한 페이지와 현재 선택 워크플로를 로컬 LLM이 올바르게 설명한다.
- 프롬프트·숫자·선택 필드를 바꾸는 요청으로 변경안이 생성되고, 적용 후 실제 화면 상태가 바뀐다.
- 페이지 이동, 선택 워크플로 변경, 입력값 변경, 중복 적용, 권한 회수 시 변경을 차단한다.
- 허용 범위를 벗어난 숫자, 알 수 없는 필드, 잘못된 선택값은 전체 변경을 거부한다.
- 적용 및 되돌리기로 생성 큐, 저장 API, 외부 서비스가 호출되지 않는다.
- 페이지 연결을 끄면 모델에게 화면 정보를 보내거나 화면 도구를 제공하지 않는다.
- 기존 채팅 및 프로필 설정이 계속 동작한다.

테스트에는 사용자가 지정한 로컬 Qwen 연결을 사용한다. 표시명만으로 모델을 추정하지 않고 실행 중인 연결의 모델 ID를 확인한다. 운영 데이터는 최소한으로 건드리며, 입력 테스트에서 이미지 생성이나 삭제는 실행하지 않는다. 필요한 회귀 검증은 기존 테스트에 추가하고 일회성 테스트 코드·하네스는 만들지 않는다.

## 1차 구현 당시 운용 범위와 남은 사항

- 현재 적용 범위는 1:1 채팅의 생성 입력, 이미지 라이브러리 보기 설정, 프롬프트 목록 검색·정렬, 이미지 메타데이터 초안이다. 그 외 내부 페이지는 이름·경로 인식까지 지원하며, 이미지 파일·노드·별도 모달·일반 DOM 조작은 포함하지 않는다.
- 화면 입력은 기존 수동 편집과 같은 상태 변경 함수를 사용한다. 기존의 로컬 입력 임시 저장은 동작하며, 생성·서버 워크플로우 저장은 별도의 사용자 동작이 필요하다.
- LLM의 답변 문장은 실행 증거가 아니다. 변경 카드, 적용 검증, 실제 화면 값이 기준이다. 모델이 잘못 제안해도 등록 필드·입력 범위·현재 값·권한 검증을 통과한 뒤 사용자 적용을 거쳐야 한다.
- 사용법은 `docs/GUIDE/CHAT.md`의 **현재 페이지 읽기와 입력 보조**에 기록했다. 일반 운영 런타임에 반영하려면 정상적인 재시작과 프로필의 페이지 조회·입력 제안 도구 허용이 필요하다.
- 테스트 연결에 잠시 복사한 인증 정보는 기존 설정 API로 제거하고 DB에서도 비어 있음을 확인했다. 테스트 DB를 정리·체크포인트했고, 테스트용 API·프론트엔드만 종료했다. 기존 운영 런타임과 Qwen 서버는 유지했다. 테스트 기록은 git에 포함되지 않는 `tmp/web-assistant-runtime`에 남겨 두었다.
- `python -m graphify update .`를 완료했다(13,718 노드, 44,087 간선). 기존 `backend/src/types/moduleGraph.ts` 구문 분석 경고와 일부 파일의 빈 추출 경고가 있어 해당 부분의 색인은 제한된다. 문서 추가분은 코드 전용 `update`의 색인 범위에 포함되지 않으며, 다음 전체 재빌드에서 함께 색인해야 한다.

## 내부 화면 확장 계획

1차 구현은 `e28d344e`로 커밋했다. 다음 확장은 새 페이지별 등록 함수를 연결하고 기존의 제안·검증·사용자 적용 경로를 재사용한다. 모델에 임의 DOM 조작을 허용하는 방식으로 범위를 넓히지 않는다.

| 단계 | 대상 | 허용할 동작과 경계 |
| --- | --- | --- |
| 이번 확장 | 이미지 라이브러리 | 현재 정렬·화면 폭별 열 수 인식 및 변경. 이미지 선택·다운로드·삭제·그룹 배정은 실행하지 않는다. |
| 이번 확장 | 프롬프트 목록 | 검색 입력 초안·정렬 기준·정렬 방향 변경. 적용 중인 검색어는 읽기 전용으로 구분한다. 검색 입력은 기존 Enter 동작으로 실행하고, 수집·분류·삭제는 실행하지 않는다. |
| 이번 확장 | 이미지 메타데이터 편집 | 현재 이미지의 프롬프트·네거티브 프롬프트·스텝·샘플러·모델·다운로드 형식 초안을 입력한다. 파일 저장·다운로드는 기존 버튼으로 실행한다. 로딩·이미지 교체·저장 중에는 연결을 제한한다. |
| 후속 확장 | 그룹·프롬프트 프리셋·와일드카드 편집 | 이름·설명·일반 필드 초안 지원. 모달과 채팅의 함께 사용, 열린 편집기 우선순위, 모달 닫기·재열기 때 제안 무효화를 먼저 해결한다. |
| 후속 확장 | 저장·일괄 작업 | 실제 저장·이동·삭제는 별도의 동작 계약, 권한 확인, 대상·변경 내용 확인, 동시 변경 검증 및 실행 기록을 갖춘 뒤 추가한다. |

이번 확장에서는 읽기 전용 필드를 명시해 조회용 설명·현재 상태를 입력 제안 대상으로 사용할 수 없게 한다. 페이지 종류와 허용 경로를 서버의 공유 검증에서 대응시키고, 이미지와 선택 그룹은 자원 ID로 구분한다. 라이브러리의 정렬 URL 변경은 같은 화면의 입력 변경으로 다뤄 되돌리기를 유지하되, 페이지 이탈·화면 폭 변경은 기존 제안을 무효화한다.

기존 채팅 테스트에 경로·읽기 전용 필드·자원 교체 경계를 추가했고, 별도 테스트 런타임에서 실제 로컬 Qwen으로 새 화면의 제안·적용·되돌리기를 확인했다. 이번 확장의 코드와 기능 검증은 완료했다.

| 확장 검증 | 결과 |
| --- | --- |
| 이미지 라이브러리 | Qwen이 `newest → oldest`, 열 수 `4 → 3`을 제안했다. 적용 후 URL·화면 정렬·열 수가 바뀌고 되돌리기로 최신순·4열을 복원했다. 정렬에 의한 URL 변경 이후에도 되돌리기가 유지됐다. |
| 프롬프트 목록 | Qwen이 검색 입력 `ceramic teapot`, 이름 정렬·오름차순을 제안했다. 검색 입력 적용·복원을 확인했고, 실제 검색 API가 `usage_count/DESC → prompt/ASC → usage_count/DESC`로 바뀌었다. 검색어 `q`는 비어 있어 입력 적용만으로 검색을 실행하지 않았음을 확인했다. 조회용 검색어·그룹은 제안 대상에서 제외됐다. |
| 메타데이터 초안 | Qwen이 프롬프트·네거티브 프롬프트·스텝·샘플러·모델·형식의 6개 필드를 제안했다. 실제 입력 적용·복원, 두 번째 이미지의 프롬프트 변경·복원을 확인했다. |
| 다른 이미지의 오래된 제안 | 첫 이미지에서 만든 미적용 제안은 두 번째 이미지로 이동한 뒤 적용 버튼이 비활성화됐다. 새 이미지의 입력값은 원래 빈 값으로 유지됐다. |
| 원본 보존 | 두 테스트 이미지의 SHA-256이 입력 테스트 전후에 같았고, `image_metadata_edit_revisions`, 생성 큐 및 생성 이력이 모두 0건이었다. 테스트 이미지는 기존 업로드 API로 별도 런타임에만 등록했다. |
| 모델의 이전 값 혼동 | 설명 문장에서 이전 값이 잘못 나온 사례를 관찰해, 제안 도구의 텍스트 응답에도 검증한 변경 전후 값을 포함했다. 재검증에서 두 번째 이미지의 빈 현재 값을 올바르게 설명했다. 실제 적용 판단은 계속 제안 카드와 현재 화면 검증에 따른다. |
| 회귀·정적 검사 | 채팅 테스트 176개, 확장 경계·검증된 도구 응답을 포함한 집중 검증 14개, 타입 검사, 변경 프론트엔드 파일 ESLint와 shared·backend·frontend 빌드를 통과했다. |

동시 실행한 개발 서버의 오래된 shared 번들을 재사용하지 않도록 선택 가능한 `CONAI_VITE_CACHE_DIR`을 추가했다. 개발 프록시도 기존 `VITE_API_BASE_URL`을 따르도록 해, 테스트 이미지 요청이 테스트 API로 전달되는 것을 확인했다. 일반 환경은 기존 기본값을 사용한다.

확장 테스트도 완료한 뒤 임시 모델 인증 정보를 제거하고 테스트 DB를 정리·체크포인트했다. 테스트용 API·프론트엔드·브라우저 탭만 종료했으며, 기존 운영 런타임과 로컬 Qwen 서버는 유지했다.

## 노드 워크플로 편집 확장

이번 대상은 `/generation?tab=workflows`의 **Editor**다. 빈 편집기에서 새 흐름을 구성하거나 현재 그래프를 수정하는 변경안을 만든다. ComfyUI API JSON의 원본 노드 정의 편집은 다른 계약이므로 이번 네이티브 그래프 편집과 구분한다.

- 노드 추가·삭제, 라벨·배치·활성 상태 변경, 선언된 일반 입력 설정·지우기, 연결 추가·삭제, 워크플로 이름·설명을 지원한다. 상수 입력 노드는 기존 실행 입력 설정도 지원한다.
- 현재 편집기와 등록 모듈을 읽는 도구를 추가한다. 모듈 ID·포트·입력 규격은 실제 등록된 정의로 검증하고, 모델이 모듈 정의나 실행 코드를 만들거나 바꾸는 경로는 열지 않는다.
- 도구에는 보호된 인증·코드·파일 경로 입력과 미디어 원본 값을 전달하지 않는다. 인증·코드·파일 경로 포트의 신규 연결도 보호한다. 미디어 포트의 일반 연결은 타입이 맞으면 허용한다. 기존 등록 모듈은 추가할 수 있으나 실행·서버 저장은 기존 사용자 버튼을 거쳐야 한다.
- 변경안은 노드·연결 작업과 검증 결과를 카드로 보여준다. 여러 작업을 모두 검증한 뒤 한 번에 편집기 초안에 반영한다. 없는 모듈·노드·포트, 잘못된 자료형, 중복 ID·연결, 단일 입력의 중복 연결과 순환 그래프는 거부한다.
- 입력이나 배치 등 편집 내용이 바뀌면 새 편집 리비전을 부여한다. 제안 생성 뒤의 수동 편집, 다른 워크플로 로드, 초기화·재진입은 이전 제안을 무효화한다. 적용 뒤 수정이 없을 때만 전체 초안을 되돌린다. 비공개 입력과 편집기의 기존 상태는 로컬에서 보존한다.
- 필수 입력·최종 결과 미완성은 초안 작업의 검증 안내로 표시한다. 기존 저장·실행 검증은 그대로 적용해 미완성 초안을 실행 가능한 그래프라고 표시하지 않는다.

구현과 검증을 완료했다. 새 도구는 `get_workflow_editor`, `list_workflow_modules`, `propose_workflow_changes`이며 조회 범위로만 제공한다. 편집기 연결·활성 답변·계정과 페이지 권한을 검사하고, 카드 적용·되돌리기 시 현재 프로필 권한과 모듈 인터페이스를 다시 확인한다. 권한 카탈로그에 `workflows.view`가 등록된 배포에서는 해당 기능 권한도 조회·제안·카드 적용·되돌리기마다 재검사한다. 모델이 리비전 UUID를 복사하지 않고 서버가 현재 요청의 리비전을 카드에 부여한다. 단일 변경안 안에서 삭제한 연결의 ID는 재연결에 사용할 수 있지만, 현재 남아 있는 연결과의 중복은 거부한다.

### 노드 확장 검증 결과 — 2026-10-07

- 기존 채팅 검사 179개 통과. 기존 제안 검사 파일에 원자적 노드 생성·재연결·삭제, 타입·순환·중복 검증, 비공개 입력 제외, 미디어 연결 허용/원본 입력 차단, JSON의 비밀 키 차단, 현재 요청 리비전 결속, 모듈 변경·권한 회수, 별도 워크플로 기능 권한, 카드 기록과 복원을 추가했다.
- 공유·백엔드·프런트엔드 빌드와 타입 검사 및 변경한 프런트엔드의 ESLint를 통과했다.
- 실제 로컬 Qwen3.8(`qwen3.8-27b-uncensored-hauhaucs-aggressive-mtp@iq4_xs`, 로컬 포트 5000)으로 빈 편집기에서 상수 텍스트 → 텍스트 변환 → 최종 결과를 제안하고 노드 3개·연결 2개를 적용했다. 실행 입력 라벨과 기본값도 저장 계약에 맞게 구성됐다.
- 노드 입력·실행 입력 라벨·배치를 변경하고 새 변환 노드를 삽입해 4개·3개로 재연결했다. 되돌리기로 원래 3개·2개와 입력값을 복원했다. 이어 기존 처리 노드를 삭제하고 앞뒤를 연결하는 제안을 적용했다.
- 동일한 빈 캔버스 초기화 후 이전 제안의 적용을 차단했다. 적용 후 수동으로 입력한 `manual source`를 이전 카드의 되돌리기가 덮어쓰지 않는 것도 확인했다. 편집 내용과 현재 실행 입력 값은 로컬에 보존했다.
- 채팅 적용 단계의 서버 저장 그래프는 0건이었다. 이후 테스트 환경의 기존 저장·실행 버튼으로 그래프 1개와 수동 실행 1건을 만들고, 테스트 모드에서 중지된 기존 그래프 실행 큐만 잠시 가동했다. 실행 상태 `completed`, 최종 결과 `Result: hi cat`을 API와 화면에서 확인했다. 이미지 생성·외부 서비스 실행은 하지 않았다.
- 테스트는 별도 런타임과 생산 빌드 서버에서 수행했다. 테스트 모델 연결 키를 제거하고 데이터베이스를 압축·체크포인트 처리했다. 실행 큐·API·UI 테스트 프로세스와 브라우저 탭도 정리했다.

모델이 과거 연결 ID를 잘못 쓰거나 잘못된 정규식을 제안할 수 있다. 도구는 그래프 구조와 공개 입력 규격을 검증하며, 모든 모듈의 처리 의미를 증명하지는 않는다. 카드에서 실제 변경을 확인하고 기존 저장·실행 검증과 결과 확인을 거친다. 로컬 모델 검증 중 리비전 복사 오류를 없애고 연결 ID 재사용 계약을 정리했으며, 접두어 처리는 실제 `prefix` 필드로 구성해 실행 결과를 확인했다.

코드 그래프는 `python -m graphify update .`로 갱신한다. 이 명령은 코드만 증분 처리하므로 변경한 가이드·계획 문서는 다음 전체 코퍼스 재구축에서 다시 반영해야 한다.

## 기존 의존성의 보안 검토 후속 항목

2026-10-07 `npm audit --omit=dev --json`은 운영 의존성에서 취약 패키지 16개(Critical 1, High 12, Moderate 3)를 보고했다. 이번 변경에서 패키지 의존성이나 잠금 파일을 추가·변경하지 않았다. 전체 의존성 업그레이드와 호환성 검증은 별도 작업이 필요하며, 입력 기능 검증 통과를 운영 환경 전체의 보안 검증 통과로 해석하면 안 된다.

- `@modelcontextprotocol/sdk`: OAuth HTTP 클라이언트가 신뢰하지 않는 MCP 서버에 연결할 때 인증 정보가 다른 인증 서버로 전달될 수 있다는 High 공지가 있다. 패치 버전은 1.31.0이다. 이번 API LLM 채팅은 내부 `InMemoryTransport`로 연결하고 OAuth 클라이언트를 사용하지 않으므로, 확인한 입력 기능 경로는 공지의 공격 조건과 맞지 않는다. 이는 코드 경로와 공지를 비교한 판단이며 전체 사용처를 모두 검증했다는 의미는 아니다. [MCP SDK 공식 보안 공지](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h)
- `proxy-addr`: 일부 IPv4 매핑 IPv6 신뢰 서브넷 설정에서 전달 IP가 위조될 수 있다는 Critical 공지가 있다. 패치 버전은 2.0.8이다. 프로젝트의 `resolveTrustProxySetting`은 환경변수의 서브넷 문자열을 받을 수 있어, 운영 배포의 `TRUST_PROXY` 설정을 확인해야 한다. 로컬 입력 테스트만으로 운영 프록시의 노출 여부를 판단할 수 없다. [proxy-addr 공식 보안 공지](https://github.com/jshttp/proxy-addr/security/advisories/GHSA-jqcg-44mw-7w3h)
- 나머지 보고 대상에는 `axios`, `multer`, `sharp`, `pdfjs-dist`와 압축·파일 패턴 처리 관련 패키지가 포함된다. 보고 개수는 패키지 기준이며 실제 공격 가능성이나 서로 다른 취약점 개수와 같지 않다. 사용 경로와 수정 버전의 호환성을 확인한 뒤 패치해야 한다.
