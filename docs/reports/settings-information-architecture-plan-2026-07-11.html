Frontend / UX review

CoNAI 설정 페이지 정비 계획

항목 재분류, 저장 방식 통일, 고급·위험 작업 분리를 중심으로 한 검토안

검토 기준: 2026-07-11 현재 구성: 9개 탭 문서 성격: 구현 전 검토안

요약

문제의 중심은 탭 개수보다 항목의 목적이 섞여 있다는 점이다.

현재 일반에는 언어·탐색 표시·삭제 보호·유사 이미지 검사·데이터 재매칭이 함께 있고, 미디어 생성/저장에는 생성 동시 실행 제어·이미지 저장·썸네일·비디오 최적화가 함께 있다. 사용자는 설정 이름을 알아도 어느 탭에 있는지 예측하기 어렵고, 한 탭 안에서도 저장 버튼이 여러 개라 변경 반영 범위를 파악하기 어렵다.

1순위
위험 작업과 일상 설정 분리
2순위
사용 목적 기준으로 재분류
3순위
저장·취소·상태 표현 통일

현재 구조에서 확인된 문제

분류와 탐색

  • 9개 탭이 모두 같은 깊이로 나열되어 중요도와 성격 구분이 없다.
  • 일반이 사실상 기본 설정, 표시 설정, 안전 설정, 유지보수 작업을 모두 수용한다.
  • 미디어 생성/저장의 생성 텀은 저장 옵션이 아니라 실행 정책에 가깝다.
  • 썸네일 품질은 미디어 탭에 있지만 실제 재생성 동작은 일반 탭에 있어 작업 흐름이 끊긴다.
  • 보안 탭의 인증 DB 복구 정보는 계정·권한 관리보다 시스템 복구 성격이 강하다.

조작과 피드백

  • 섹션 우측의 아이콘형 저장 버튼만으로는 저장 대상과 변경 여부가 즉시 읽히지 않는다.
  • 한 화면에 저장 단위가 최대 4개라 일부만 저장하고 이동할 가능성이 있다.
  • 고급 수치 입력과 일상 토글의 시각적 위계가 비슷해 초보 사용자의 판단 부담이 크다.
  • watcher, source, polling, RecycleBin 등 한·영 용어가 혼합돼 있다.
  • 해시 재생성과 같은 영향 큰 동작이 첫 탭에 노출되어 일반 설정처럼 인식될 수 있다.

제안 정보 구조

사용자가 “기능 이름”이 아니라 “하려는 일”로 위치를 예측하도록 8개 영역으로 재구성한다. 좌측 탐색에는 구분선과 그룹 제목을 사용하되 중첩 메뉴는 만들지 않는다.

1. 기본 설정
언어, 앱 기본 동작
2. 화면 및 탐색
테마, 밀도, 폰트, 목록 표현, 상단 네비 표시, 갤러리·등급 배지 표시
3. 라이브러리 및 가져오기
감시 폴더, 백업 소스, 메타데이터 추출, 유사·중복 검사
4. 미디어 처리
이미지 저장, 썸네일 생성·재생성, 비디오 최적화
5. 자동화 및 분석
WD Tagger, Kaloscope, 평가 가중치·등급, 분석 테스트
6. 생성 및 AI
예약·생성 동시 실행 정책, NovelAI/Codex 생성 텀, LLM 연결·프리셋
7. 연동
ComfyUI 등 외부 도구 패키지와 향후 연동 항목
8. 계정 및 시스템
계정·권한 그룹, 삭제 보호, 복구 정보, 데이터 재매칭·해시 재생성

화면·상호작용 정돈 원칙

저장 UX

  • 각 페이지 하단에 고정 저장 바: 변경 취소 / 변경사항 저장.
  • 서버 저장 단위가 달라도 사용자는 한 번의 저장으로 느끼게 묶고, 실패한 영역만 명확히 표시.
  • 탭 이동 시 미저장 변경이 있으면 유지 또는 확인. 저장 아이콘은 보조 상태로만 사용.

밀도와 위계

  • 기본 옵션은 바로 노출, 장치·경로·임계값 등은 고급 설정 접기 영역으로 이동.
  • 상태 요약과 편집 폼을 분리. 테스트·새로고침·실행 버튼은 설정 저장 버튼과 시각적으로 구분.
  • 동일한 카드 반복을 줄이고 제목 + 구분선 중심의 가벼운 섹션 사용.

안전성과 안내

  • 해시 재생성 등 위험 작업은 별도 유지보수 화면과 단계형 확인 사용.
  • 영향 범위, 처리 대상 수, 중단 가능 여부를 실행 전에 표시.
  • 관련 설정과 후속 실행을 연결: 예) 썸네일 품질 변경 후 “기존 썸네일 재생성” 제공.

탐색과 반응형

  • 데스크톱 좌측 탐색 유지. 모바일은 상단 선택기 또는 가로 스크롤 탭 대신 단일 드롭다운 권장.
  • URL에 현재 영역을 반영해 새로고침·공유 시 같은 위치 유지.
  • 항목 검색은 2차 단계에서 추가. 검색 결과는 해당 섹션으로 바로 이동.

정리·축소 후보

  • 중복 안내 축소: 섹션 제목, 버튼 툴팁, 스낵바에서 같은 “저장” 문구가 반복되는 부분을 공통 규칙으로 정리.
  • 기술 용어 정규화: 사용자 문구는 “감시 프로세스”, “원본 폴더”, “확인 주기”처럼 한국어 우선. 정확한 식별자가 필요한 곳만 영문 병기.
  • 의존성·데몬 상세: 평상시에는 준비 여부만 표시하고 경로·캐시·로드 상태는 진단 상세로 접기.
  • 테스트 도구: 자동화 설정의 기본 흐름과 분리된 “연결 및 동작 테스트” 섹션으로 묶기.

진행 단계

1
정보 구조와 라우팅 정리
새 영역 정의, 기존 설정 이동표 확정, URL 기반 활성 영역 지원. 데이터 모델과 API는 변경하지 않고 화면 구성부터 재배치.
2
공통 설정 셸 정비
페이지 제목, 섹션, 고급 접기, 상태 블록, 고정 저장 바, 미저장 변경 경고를 공통 컴포넌트로 통일.
3
위험 작업과 연관 작업 결합
유지보수 영역 분리. 썸네일 설정/재생성처럼 끊긴 흐름을 한 위치에 배치.
4
문구·상태·반응형 마감
한·영 혼용 정리, 오류·로딩·변경 상태 통일, 모바일 탐색과 긴 폼 검증.

완료 기준

  • 사용자가 주요 설정 10개를 탭 이름만 보고 예측 가능한 위치에서 찾을 수 있다.
  • 일상 설정 화면에 데이터 재매칭·해시 재생성 같은 위험 작업이 섞이지 않는다.
  • 한 화면의 변경사항을 저장하거나 취소하는 방법이 하나의 일관된 패턴으로 보인다.
  • 모든 기존 설정과 실행 기능이 누락 없이 새 구조에 매핑된다.
  • 데스크톱과 모바일에서 탐색, 긴 폼, 저장 상태가 깨지지 않는다.
  • 권한에 따라 보이지 않는 영역과 직접 URL 접근이 기존 보안 규칙을 유지한다.

구현 전 확인할 결정

  1. 계정 및 시스템을 한 탭으로 둘지 분리할지: 현재 기능량이면 한 탭 안의 “계정·권한 / 안전·복구 / 유지보수” 하위 섹션으로 시작하는 편이 단순하다.
  2. 저장 범위: 페이지 단위 통합 저장을 우선 권장하되, 서버 요청 일부 실패 시 재시도 정책을 정의해야 한다.
  3. 설정 검색 시점: 1차 개편에서는 구조 정리와 URL 이동을 완료하고, 검색은 실제 탐색 불편이 남을 때 2차로 추가한다.
