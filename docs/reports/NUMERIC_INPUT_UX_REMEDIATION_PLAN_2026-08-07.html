숫자 입력 UX 전면 개선 계획

좌우 드래그 변경을 완전히 폐기하고, 입력 중에는 값을 강제로 보정하지 않는 공통 숫자 입력으로 통합한다.

조사 완료 · 구현 전 계획

결론

전역 기본 UI는 − [직접 입력] + 형태의 스테퍼로 결정한다. 슬라이더는 값의 범위가 짧고 명확하며 대략적인 조절이 목적일 때만 사용한다. 숫자 입력 전체를 슬라이더로 바꾸면 큰 범위, 정확한 값, 소수, 음수, 선택적 빈 값을 제대로 다루기 어렵다.
58개드래그 입력 사용처
74개일반 number 입력
132개통합 전환 대상
46개소비 파일

별도의 명시적 슬라이더 5개는 image-detail-media-controls.tsx의 픽셀 미리보기 조절용이다. 이들은 숫자 필드 드래그가 아니므로 유지하되 모바일 조작 회귀만 확인한다.

현재 문제의 실제 원인

1. 입력 자체가 스크롤 제스처를 가로챔

scrubbable-number-input.tsx가 touch-none, setPointerCapture(), onPointerMove, 가로 이동량 계산을 사용한다. 모바일에서 입력 위로 스크롤을 시작하면 값 변경 동작으로 넘어갈 수 있는 구조다.

2. 빈 문자열이 즉시 0 또는 기본값으로 변환됨

공통 입력은 빈 문자열을 전달할 수 있지만 여러 소비처가 입력 순간 Number('') === 0, Number(value) || 기본값, 즉시 Math.min/Math.max를 적용한다. 그래서 기존 값의 마지막 숫자를 지우는 순간 0이나 기본값이 다시 나타난다.

3. 보정 책임이 컴포넌트와 소비처에 흩어짐

공통 드래그 입력은 blur/Enter에서 범위를 보정하지만, 일부 화면은 그보다 먼저 숫자화한다. 워크플로 제출 시점의 백엔드·프런트 보정도 별도로 존재해 화면별 체감이 달라졌다.

4. 일반 number 입력은 작은 기본 스핀 버튼에 의존

직접 사용 중인 type="number" 74개는 브라우저 기본 위/아래 버튼과 휠 동작을 따른다. 모바일 터치 대상이 작고 브라우저별 사용감도 일정하지 않다.

슬라이더를 기본값으로 채택하지 않는 이유

큐 등록 수, 이미지 크기, 스케줄 시간, 임계값, 좌표, ID처럼 정확한 값이 필요한 항목은 슬라이더로 조작하기 불편하다. 현재 픽셀 미리보기처럼 범위가 짧고 즉시 미리보기가 핵심인 항목만 슬라이더를 유지한다. 연속 조절이 특히 유용한 벽지 효과 값은 추후 슬라이더 + 숫자 스테퍼 조합을 별도 검토할 수 있지만 이번 전역 수정의 필수 범위는 아니다.

밀집 화면 폭 증가좌우 44px 버튼이 작은 툴바에 들어갈 때compact variant는 시각 폭을 줄이되 모바일 hit area는 유지하고, 툴바 배치를 별도 조정화면 확인

완료 기준

  • 숫자 입력을 좌우로 드래그해도 값이 변하지 않고 모바일 세로 스크롤이 정상 작동한다.
  • 구형 드래그 컴포넌트, scrubRatio, 드래그 안내 번역과 pointer drag 코드가 제품 소스에서 완전히 제거된다.
  • 기본값 1을 지울 때 입력 중 0 또는 기본값이 재삽입되지 않는다.
  • 보정은 blur/Enter/버튼 확정 시점에만 수행된다.
  • 모든 일반 숫자 입력이 동일한 −/직접입력/+ UI와 키보드 계약을 사용한다.
  • 선택형 빈 값, 필수값 복원, min/max, 소수, 음수, step이 각 도메인 계약대로 동작한다.
  • 워크플로 제출 전후의 숫자 min/max 보정과 최종 API payload 계약이 유지된다.
  • 현재 명시적 슬라이더 5개는 기존 목적과 동작을 유지한다.

범위에서 제외

  • 백엔드 숫자 검증·워크플로 payload 보정 정책 변경
  • 모든 숫자 필드를 슬라이더로 재설계하는 작업
  • 버튼 길게 누르기 자동 반복, 가속 증감, 마우스 휠 증감
  • 숫자 입력과 무관한 이미지 드래그, 캔버스 포인터 조작, 정렬 드래그 변경
  • 기존 픽셀 미리보기 슬라이더 5개의 시각 재설계

조사 메모

Graphify 그래프는 6ad42266 기준이고 현재 확인 커밋은 6646a4b4라 공통 컴포넌트와 후보 파일 탐색에만 사용했다. 최종 수량과 동작은 현재 소스에서 ScrubbableNumberInput, type="number", 숫자 즉시 변환 패턴을 직접 다시 검색해 확인했다.
