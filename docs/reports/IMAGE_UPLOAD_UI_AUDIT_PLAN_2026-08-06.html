결론

첨부 이미지에서 보인 현상은 서로 다른 버그가 아니라, 선택값을 모르는 공용 드롭 영역과 호출부가 따로 붙이는 미리보기가 결합해서 생긴 구조적 결과다. 단일/다중 모드를 명확히 나누고 공용 미디어 선택 표면을 만들면 세 화면을 한 번에 정리할 수 있다.

1. 이미지 로드 단일 필드 WorkflowFieldInput → ImageAttachmentPickerButton(uploadOnly) 빈 드롭 영역은 계속 남고, 파일명·큰 미리보기·제거 버튼이 아래에 별도 카드로 추가됨 직접 수정
2. 파일 업로드 페이지 UploadPageUploadSection 다중 선택 후 개수·용량과 최대 6개의 파일명/크기 행만 표시 직접 수정
3. 타 사이트 참고 UI 구현 대상 아님 드롭 영역은 유지하고 선택 파일을 작은 썸네일 타일로 식별 방향 참고

근본 원인

1. 공용 드롭 영역이 항상 빈 상태만 그림

DropSurface는 고정 높이 h-44의 버튼 안에 이미지 아이콘 하나만 렌더한다. 선택 파일, 미리보기, 제거 동작을 받을 속성이 없다.

frontend/src/features/upload/components/upload-page-sections.tsx:107

2. 단일 업로드 모드는 선택된 값을 피커에 전달하지 않음

uploadOnly 분기는 매번 빈 DropSurface를 반환한다. ImageAttachmentPickerButton 속성에도 현재 선택 이미지나 제거 콜백이 없다.

frontend/src/features/image-generation/components/image-attachment-picker.tsx:41, 450

3. 단일 필드 호출부가 미리보기를 아래에 별도로 추가

WorkflowFieldInput이 피커 아래에 파일명, InlineMediaPreview, 제거 버튼을 가진 별도 카드를 렌더한다. 첨부 1의 모습과 정확히 일치한다.

frontend/src/features/image-generation/components/workflow-field-input.tsx:117

4. 다중 업로드는 로컬 미디어 미리보기를 만들지 않음

선택 파일 배열은 존재하지만 각 파일을 이름·크기 텍스트 행으로만 출력한다. 이미지/비디오 미리보기용 object URL 생성 경로는 없다.

frontend/src/features/upload/components/upload-page-sections.tsx:214

5. 메타데이터 추출도 같은 단일 이미지 패턴

업로드 페이지의 「미리보기/추출」은 빈 드롭 영역을 유지한 채 선택 이미지의 큰 미리보기를 아래에 추가한다. 첨부 1과 같은 구조라 함께 정리해야 한다.

수정 계획

1공용 미디어 드롭 표면 분리

DropSurface가 업로드 페이지 파일 안에 있으면서 이미지 생성 기능에서도 가져다 쓰는 현재 의존성을 정리한다.

  • 신규 위치: frontend/src/components/media/media-file-drop-surface.tsx
  • 빈 상태, 드래그 활성 상태, 선택 상태 콘텐츠를 받을 수 있게 설계
  • 빈 상태는 기존 아이콘 버튼 동작과 크기를 유지
  • 선택 상태에서 교체/제거 버튼이 중첩 버튼이 되지 않도록 형제 요소로 구성

2단일 이미지 선택 영역 통합

  • ImageAttachmentPickerButton에 선택 이미지와 제거 콜백을 전달할 수 있는 선택 상태 API 추가
  • uploadOnly + 선택값 있음: 빈 드롭 영역 대신 InlineMediaPreview가 들어간 선택 표면 렌더
  • WorkflowFieldInput의 별도 파일명/미리보기/제거 카드 삭제
  • 클릭 또는 새 파일 드롭은 교체, 제거는 값 초기화
  • 내부 생성 화면과 공개 워크플로 화면에서 동일하게 적용

3업로드 페이지 다중 파일을 썸네일 그리드로 변경

  • 현재 파일명 행을 반응형 썸네일 타일로 교체
  • 이미지는 로컬 object URL + 기존 InlineMediaPreview 재사용
  • 비디오는 미리보기 가능 시 프레임, 불가능하면 명확한 비디오 아이콘 사용
  • 파일명·크기는 타일 하단/툴팁의 보조 정보로 유지
  • 타일별 제거 버튼 추가, 기존 「초기화」는 전체 제거로 유지
  • 현재 최대 표시 6개 정책은 우선 유지하고 초과 수량 안내를 보존

4미리보기/추출 단일 이미지 중복 제거

  • 파일 선택 전에는 기존 드롭 영역 표시
  • 선택 후에는 같은 자리에 이미지 미리보기와 교체/제거 동작 표시
  • 아래 결과 영역의 중복 큰 이미지 블록은 제거하고 파일 요약·추출 결과만 유지
  • 기존 object URL 생성/해제 로직을 그대로 활용

5공용 피커 사용처 회귀 확인

나머지 11개 호출부는 큰 드롭 영역이 상시 노출되지 않고 선택 모달이 즉시 닫히므로 구조 변경 대상이 아니다. 공용 컴포넌트 이동에 따른 열기, 업로드 탭, 시스템/Save 선택, 선택 완료만 확인한다.

검증 계획

자동 검증

  • npm run typecheck
  • cd frontend && npm run lint
  • npm run build:frontend
  • 신규 타깃 계약: 선택 상태가 별도 미리보기와 중복되지 않는지 확인
  • 신규 타깃 계약: 다중 선택이 썸네일 그리드와 개별 제거 경로를 갖는지 확인

화면 검증

  • /upload: 이미지 1개/3개/6개 초과, 이미지+비디오 혼합
  • /upload: 개별 제거, 전체 초기화, 재선택, 업로드 진행/완료
  • 미리보기/추출: 선택, 교체, 제거, 메타 추출 결과 유지
  • Comfy 심플 업로드 필드: 내부 생성 화면과 공개 워크플로 화면
  • 일반 피커: 업로드/시스템/Save 세 소스와 11개 관련 호출부 표본
  • 키보드 포커스, aria-label, 제거 버튼 클릭 전파 확인

완료 기준

  • 단일 이미지 선택 후 빈 드롭 아이콘과 별도 미리보기가 동시에 보이지 않는다.
  • 단일 이미지 영역에서 교체와 제거가 가능하고 드래그앤드롭도 유지된다.
  • 다중 업로드에서 각 이미지가 파일명보다 먼저 시각적으로 식별된다.
  • 파일명과 크기는 접근 가능한 보조 정보로 남는다.
  • 비디오가 섞여도 깨진 이미지가 아니라 미리보기 또는 명확한 대체 아이콘이 보인다.
  • object URL이 파일 교체·제거·화면 이탈 때 모두 해제된다.
  • 기존 업로드 API, 저장 옵션, 메타 추출, 시스템/Save 이미지 선택 동작은 바뀌지 않는다.

범위에서 제외

  • 백엔드 업로드 API 및 파일 저장 방식
  • 이미지 저장 옵션 변환 로직
  • JSON, 폰트, LoRA 폴더 등 이미지가 아닌 파일 선택 UI
  • 일반 이미지 피커 11개 호출부의 전체 레이아웃 재설계
  • 서버 저장 후 결과 카드의 별도 갤러리화

조사 메모

프로젝트의 Graphify 그래프는 b488f557 기준으로 현재 확인 커밋보다 오래되어 후보 탐색에만 사용했다. 최종 목록과 줄 번호는 현재 소스에서 직접 재검증했다.

이번 작업은 조사와 계획 문서 작성만 수행했다. 제품 코드는 수정하지 않았고 테스트·빌드·린트는 조사 전용 작업이라 실행하지 않았다.
