같은 Comfy 노드의 입력 필드를 한 블록으로 묶는 변경 계획

현재 필드마다 만들어지는 개별 카드를, 원본 Comfy 노드가 같은 필드끼리 하나의 노드 블록 안에 모이도록 바꾼다. 입력값 저장과 실행 요청 형식은 그대로 유지한다.

작성일 2026-08-07 대상 브랜치 alphatest 확인 커밋 6646a4b4 구현 미실행

결론

요청한 방향으로 변경 가능하며 백엔드 실행 구조를 바꿀 필요는 없다. 현재는 작성 모달, 내부 생성 화면, 공개 생성 화면이 모두 필드 배열을 그대로 순회해서 필드 수만큼 블록을 만든다. 표시 직전에 원본 노드 ID 기준으로 그룹화하고, 그룹 안에서는 기존 필드 입력 컴포넌트를 재사용하면 된다.

현재 동작 확인

1. 노드 입력 하나를 선택할 때마다 독립 marked field가 생성됨

buildWorkflowMarkedFieldFromInput()이 nodeId + input key로 필드 ID와 jsonPath를 만들지만, 원본 노드 ID와 제목을 별도 메타데이터로 저장하지 않는다.

frontend/src/features/image-generation/components/comfy-workflow-authoring-graph.tsx:367

2. 작성 모달의 Marked Fields가 필드마다 별도 블록을 렌더함

markedFields.map(...) 안에서 각 필드가 바깥 테두리, 접기 상태, 삭제 버튼을 가진 독립 블록이 된다. 같은 노드인지 확인하는 단계가 없다.

frontend/src/features/image-generation/components/comfy-workflow-marked-fields-editor.tsx:151

3. 실제 생성 화면도 필드 하나당 카드 하나를 만듦

내부 컨트롤러와 공개 워크플로 페이지가 모두 workflowFields.map(...)으로 WorkflowFieldDisclosureCard를 반복한다.

4. 카드 컴포넌트 자체도 “필드 하나”만 받도록 고정됨

WorkflowFieldDisclosureCard의 속성은 field와 해당 필드의 value 한 쌍이다. 따라서 호출부에서 묶지 않으면 같은 노드라도 카드가 합쳐질 수 없다.

수정 계획

1필드에 원본 노드 출처 기록

  • WorkflowMarkedField와 백엔드 MarkedField에 선택 속성 source_node_id, source_node_title 추가
  • buildWorkflowMarkedFieldFromInput()이 필드를 만들 때 현재 nodeId, nodeTitle 저장
  • 저장 직전 기존 필드도 원본 워크플로 JSON의 노드와 맞춰 가능한 경우 메타데이터 보강

2공용 노드 그룹 계산기 추가

  • 필드 배열을 한 번만 순회하는 groupWorkflowMarkedFieldsByNode() 작성
  • 메타데이터 우선, jsonPath 폴백, 실패 시 단독 그룹 규칙 적용
  • 그룹과 내부 필드 순서를 안정적으로 보존
  • 작성 화면과 생성 화면이 같은 함수를 써서 그룹 기준이 어긋나지 않게 함

3작성 모달의 Marked Fields를 노드별 블록으로 변경

  • 현재 markedFields.map(...)을 노드 그룹 순회로 교체
  • 노드 제목, 노드 ID, 선택한 필드 수를 그룹 헤더에 표시
  • 기존 필드 편집 UI는 그룹 내부 행으로 이동하고 라벨·타입·기본값·필수·범위·삭제 기능 유지
  • 그룹 헤더 드래그는 노드 그룹 전체 순서 변경, 필드 드래그는 같은 그룹 안에서만 순서 변경
  • 그래프에서 같은 노드의 필드를 추가하면 기존 노드 블록 안에 즉시 들어가게 함

4내부·공개 생성 화면에 공용 그룹 목록 적용

  • 중복된 두 workflowFields.map(...) 호출을 공용 WorkflowFieldGroupList로 교체
  • 필드가 둘 이상인 노드는 WorkflowNodeFieldDisclosureCard 하나로 렌더
  • 그룹 내부에서는 기존 WorkflowFieldInput을 재사용해 text, number, image, dropdown, LoRA, MiniMax 전용 입력 유지
  • 필수/설명/타입/오류 강조/값 있음 표시를 필드 행과 그룹 표면에 집계
  • 필드 하나인 그룹은 기존 WorkflowFieldDisclosureCard를 그대로 사용

5접기·접근성·번역 계약 보존

  • 그룹 전체 접기를 새로 덧붙이지 않고 각 필드의 기존 default_collapsed 동작을 내부 행에서 유지해 의미 변경 방지
  • 키보드로 각 필드 펼치기/접기, 삭제, 순서 변경 가능
  • 그룹 헤더에 연결된 필드 수와 오류 수를 접근 가능한 텍스트로 제공
  • 하드코딩 대신 한·영 번역 키로 노드/필드 수/오류 안내 추가

반드시 보존할 기존 기능

  • 입력값: draft와 queue payload의 키는 계속 개별 field.id를 사용한다.
  • Comfy 치환: 각 필드는 계속 자신의 jsonPath에 독립적으로 들어간다.
  • 검증: 필수 필드, 숫자 최소/최대, MiniMax 노드 검증은 개별 필드 기준을 유지한다.
  • 전용 입력: Power LoRA와 MiniMax H3 Director의 복합 node 입력은 현재 전용 UI를 그대로 쓴다.
  • 드롭다운: 자동수집 옵션·LoRA 목록 새로고침 props가 그룹 목록을 거쳐 각 입력까지 전달된다.
  • 이미지: 필드별 이미지 선택·교체·제거 콜백은 해당 field.id에 그대로 연결된다.
  • 공개 페이지: 내부 생성 화면과 공개 slug 화면이 같은 그룹 결과와 상호작용을 보여준다.

검증 계획

자동 검증

  • 그룹 헬퍼: 같은 노드 3필드 → 그룹 1개
  • 배열에서 떨어져 있는 같은 노드 필드도 한 그룹으로 합쳐지고 내부 순서 보존
  • 출처를 확인할 수 없는 필드는 서로 합치지 않음
  • 기존 필드(source_node_id 없음)의 jsonPath 폴백 검증
  • 그룹 렌더 전후 buildWorkflowPromptData() 결과 deep-equal
  • npm run verify:comfy-workflow-authoring-contracts
  • npm run verify:comfy-dropdown-auto-collect-contracts
  • npm run typecheck, cd frontend && npm run lint, npm run build:frontend

화면 검증

  • 작성 모달: 한 노드에서 1개/2개/5개 필드 선택·해제
  • 작성 모달: 그룹 순서 및 같은 그룹 안 필드 순서 변경
  • 내부 생성: 같은 노드 필드가 한 블록에 표시되고 값 입력·초기화 정상
  • 공개 생성: 내부 화면과 같은 그룹 구조
  • 필수값 누락, 숫자 범위, MiniMax 오류가 정확한 필드 행에 표시
  • 이미지, select, textarea, number, Power LoRA, MiniMax 노드 입력 표본
  • 모바일 폭에서 그룹 헤더, 긴 노드 제목, 필드 수 배지 줄바꿈
  • 키보드 포커스, 펼치기/접기, 삭제 버튼 aria-label 확인

완료 기준

  • 같은 Comfy 노드에서 선택한 여러 필드가 작성 모달과 생성 화면에서 바깥 블록 하나로 표시된다.
  • 다른 노드의 필드는 라벨이나 타입이 같아도 합쳐지지 않는다.
  • 기존 워크플로도 별도 데이터 마이그레이션 없이 노드 ID 기준으로 묶인다.
  • 필드 라벨·타입·필수·설명·기본 접기·삭제·순서 변경 기능이 유지된다.
  • 내부 생성과 공개 생성 화면이 동일한 그룹 규칙을 사용한다.
  • 그룹화 전후 queue payload와 최종 Comfy workflow JSON이 동일하다.
  • 기존 복합 노드 입력과 드롭다운 자동수집 기능이 퇴행하지 않는다.
